Desk view: thinking frame, lean-back frame, per-room drag layout

Three more polish items for the desk view:

1. Thinking frame (pixelAvatars.ts + PixelSeat.tsx):
   - THINKING_GRIDS table: 9 hand-authored 16x20 frames, one per role.
     Mouth row (10) shows a small "hmm" open, body stays roughly
     centered with asymmetric vest tokens. Used while the seat is
     thinking=true (and not speaking), swapped on the same 2 Hz tick.
   - All 9 pass the existing grid validator (16 cols, valid tokens).

2. Lean-back frame (pixelAvatars.ts + PixelSeat.tsx):
   - LEAN_BACK_GRIDS table: 9 hand-authored 16x20 frames. Body rows
     shift one column LEFT instead of right, suggesting the analyst
     sitting back after delivering a rebuttal.
   - PixelSeat runs a small state machine: when speaking transitions
     to false while still live, we arm a 1.5s lean_back window. The
     seat visibly settles before going idle. Reduced-motion users
     skip the settle.

3. Per-room layout (services/desk/roomLayout.ts):
   - localStorage-backed `Record<seatName, {x, y}>` keyed by user AND
     a roster hash (FNV-1a, order-insensitive). Different rosters
     (8 default seats vs 4 custom seats) have separate layouts.
   - Storage: `desk_room_layout_v1_<user>_<hash>`. Per-user like
     roleOverrides. Subscribers (DeskScene) re-render on edits.
   - DeskScene header gets a new "Edit room" button (aria-pressed).
     While on, the floor border goes amber, seats get cursor:grab,
     click-to-open-transcript is disabled, and pointerdown on a seat
     starts a drag. Pointermove on the floor follows the cursor
     (clamped 0..1); pointerup saves the final position via
     setSeatPosition.
   - "Reset" button appears next to "Edit room" only while editing;
     wipes the roster layout back to role-anchor defaults.
   - floorLayout() now accepts an optional `RoomLayout` argument and
     applies user overrides on top of the role anchors.
