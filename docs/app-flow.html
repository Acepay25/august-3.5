G.8 Boundaries that keep the stores honest

Provider secrets never ride in the notebook: ProviderConfigService encrypts each key with Electron safeStorage on desktop and fails closed when decryption fails; shared/providerRequestPolicy.cjs is the one host policy shared by renderer, dev proxy and Electron main. AI output is sanitized and zod-validated at the boundary (schemas/tradeAnalysis.ts). A write that cannot land is reported: the notebook's getNotebookWriteFailure records quota vs error, bytes and streak and refuses growth at the hard cap; a corrupt notebook gets a sidecar before the in-memory view is replaced; the payload store records its refusal and the transcript says the full result was not kept; artifacts are owner-scoped. Backups are namespaced: BackupService.createBackup carries profile/notebook/trades, and ExportService names the raw-localStorage prefixes for stores that bypass Preferences. There is no generic AI-response cache — only the desk-tool cache with its 30s TTL — so a “refresh” cannot silently serve an old answer.

Measured after stage 19: what the deletion did NOT remove

The prompt layer was the part the deletion never re-measured. Settings → Prompts had 27 overridable prompts, and a one-off source scan measured that 16 had no call site that reads them: every debate.* id, analysis.families, and the three postmortem.* ids. The app was handing the trader an editor for text it never sends, and one moderator fallback still instructed a model to “follow the Accuracy Mode checks” and to emit a debate envelope no parser can read — Accuracy Mode and the engine were both deleted, the registry was not. The gate pins the direction that breaks silently too: the 10 ids a real call site reads must KEEP that call site, so a refactor that starves a live prompt fails the suite — proved by renaming one getPrompt('analysis.master'… argument and watching five arms go red. Those 16 were a measured ceiling that ratchets down only — it now sits at 0: deleting an entry, with the prompt constants nothing else imports, lowers it, and nothing may raise it.

The harness note in a user-role turn had no live teacher. harnessTurn() still stamps HARNESS NOTE (this app, not the trader): onto user-role content at four desk-tool sites — tool results, a continue nudge, a clipped payload — and the only prompts that ever named that mark were the debate prompts, which nothing sends. A model was therefore receiving app-written text inside the trader's own turn with no instruction anywhere about whose words it was.
