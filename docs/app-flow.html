Measured after stage 19: what the deletion did NOT remove

The prompt layer was the part the deletion never re-measured. Settings → Prompts had 27 overridable prompts, and tests/promptsAreWired.test.ts measured that 16 had no call site that reads them: every debate.* id, analysis.families, and the three postmortem.* ids. The app was handing the trader an editor for text it never sends, and one moderator fallback still instructed a model to “follow the Accuracy Mode checks” and to emit a debate envelope no parser can read — Accuracy Mode and the engine were both deleted, the registry was not. The gate pins the direction that breaks silently too: the 10 ids a real call site reads must KEEP that call site, so a refactor that starves a live prompt fails the suite — proved by renaming one getPrompt('analysis.master'… argument and watching five arms go red. Those 16 were a measured ceiling that ratchets down only — it now sits at 0: deleting an entry, with the prompt constants nothing else imports, lowers it, and nothing may raise it.

The harness note in a user-role turn had no live teacher. harnessTurn() still stamps HARNESS NOTE (this app, not the trader): onto user-role content at four desk-tool sites — tool results, a continue nudge, a clipped payload — and the only prompts that ever named that mark were the debate prompts, which nothing sends. A model was therefore receiving app-written text inside the trader's own turn with no instruction anywhere about whose words it was.
