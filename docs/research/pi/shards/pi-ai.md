# pi :: pi-ai

**Files in shard:** 402 (read: 401, skipped with reason: 1)
**What this shard covers:** `@earendil-works/pi-ai` v1.4.0 — the reference repo's unified LLM API SDK (`packages/ai`). It is the layer between an agent loop and ~45 model providers: a normalized transcript type, one streaming event protocol, a provider/auth registry, ten wire-protocol transports (Anthropic Messages, OpenAI Completions/Responses/Codex, Google Generative AI/Vertex, Bedrock Converse, Mistral, Azure, and pi's own `pi-messages`), nine OAuth flows, a credential store, a generated model catalogue with a validated manifest, and ~185 test files. There is no agent loop, no scheduler and no UI in this shard — this is the *transport* layer only. What it contributes to a trading app is the "last mile" discipline: how a provider's quirks become data, how a failure is classified, how cost is computed, and how a transcript stays replayable.

### 1.2 Public entrypoints and top-level modules

#### `packages/ai/src/index.ts`
- **Purpose:** the core, side-effect-free public surface.
- **Key abstractions:** re-exports `types.ts`, `models.ts`, `models-store.ts`, `utils/{diagnostics,event-stream,identity,json-parse,overflow,retry,text,transcript,typebox-helpers,uuid,validation}`, `auth/{context,credential-store,helpers,types}`, `providers/faux.ts`, `session-resources.ts`, and the *types* of every provider's options object.
- **Data flow:** none — it is a barrel.
- **Non-obvious design decisions:** the file header states the rule explicitly: *"Core only, side-effect free: no generated catalogs, no provider factories, no api-registry, no OAuth implementations, no compat."* The generated model catalogue, the provider factories and the whole legacy global API live behind *other* entrypoints so a browser bundle that imports only `types.ts` pulls in nothing.
- **Edge cases & failure handling:** n/a.
- **Surprising:** `export * from "./providers/faux.ts"` — the test-double provider ships in the main entrypoint.

#### `packages/ai/src/types.ts` (908 lines) — the wire vocabulary
- **Purpose:** every type that crosses a provider boundary.
- **Key abstractions:** `ProviderRequestOptions`, `StreamOptions`, `SimpleStreamOptions`, `Message` = `SystemMessage | UserMessage | AssistantMessage | ToolResultMessage`, `AssistantMessageEvent` (the normalized stream event union), `Usage`, `Model` / `ImageModel` / `ClassifierModel`, `Tool`, `Context` vs `TranscriptContext`.
- **Data flow:** a `Context` (`{systemPrompt, messages, tools}`) is normalized once by `normalizeContext()` into a branded `TranscriptContext`; providers only ever see the transcript.
- **Non-obvious design decisions:**
  - `TranscriptContext` is branded with a `unique symbol` (`:785-796`) so a raw `Context` *cannot* reach provider code by accident — only `normalizeContext()` may produce one. This is a compile-time "you forgot to normalize" guard.
  - `Model.type` is **optional** and defaults to `"chat"` (`:849-853`); `utils/model-operations.ts:18-20` owns that default. Narrow with `isModelType()`, never by comparing `type` to a string.
  - `Usage.output` **includes** reasoning tokens; `Usage.reasoning` is the *subset* (`:467-471`).
  - `Usage.cacheWrite1h` exists so Anthropic's 1-hour cache writes can be priced at 2× (`:463-465`).
  - `SystemMessage` carries `sections` (named, patchable prompt sections) and `toolsAdded`/`toolsRemoved` (`:544-570`) — the prompt is part of the transcript, not a separate argument.
  - `ToolCall.argumentsError` (`:456`) keeps the model's own broken argument text so validation can report it back.
  - `AssistantMessage.rawStopReason` and `endTurn` are preserved "for debugging and does not currently affect agent control flow" (`:595-599`).
  - `NestedToolCalls` (`:611-631`) records calls a tool made to other tools, with `complete: false` when anything was dropped — a bounded, honest record.
- **Edge cases & failure handling:** `ToolResultMessage` is generic over `TDetails` but is `never` unless `TDetails` is JSON-compatible (`IsJsonCompatible`, `:487-650`) — a compile-time guarantee that a tool result can be persisted.

#### `packages/ai/src/models.ts` (1299 lines) — the `Models` collection and `createProvider`
- **Purpose:** the runtime registry: providers + auth + model reads + request dispatch.
- **Key abstractions:** `Provider<TApi>`, `Models` / `MutableModels`, `createModels()`, `createProvider()`, `RefreshModelsContext`, `calculateCost()`, `getSupportedThinkingLevels()`, `clampThinkingLevel()`, `hasApi()`, `modelsAreEqual()`.
- **Data flow:** `models.stream(model, context, options)` → `normalizeContext` → `lazyStream(...)` → `applyAuth` (resolve auth, merge headers, merge identity) → the owning provider's `stream` → `AssistantMessageEventStream`.
- **Non-obvious design decisions:**
  - **`refresh()` runs the provider's refresh TWICE**: once with `allowNetwork:false` to *restore the cached catalogue from the store*, then once with network allowed (`:589-596`). Offline boot therefore still shows the last-known models.
  - **Publication is generation-checked** (`:498-543`). `supersedeProviderRefresh` bumps a per-provider generation counter and aborts the previous controller; `publishProviderModels` refuses to write if the generation moved. A slow in-flight refresh can therefore never overwrite a newer one.
  - **Per-provider publication is serialized** through a promise chain (`:516-543`), and the chain tail is deleted when it drains so the map does not grow.
  - `getModels()` is **best-effort**: a provider whose `getModels()` throws yields *no models* rather than breaking the whole read (`:442-462`). Same for `getAllModels()`.
  - `mergeHeaders` (`:384-398`) deletes any existing key with the same *case-insensitive* name before setting the new one, so a caller can suppress a default header with `null`.
  - `calculateCost` **mutates** the `usage` object it is given and returns `usage.cost` (`:1236-1256`).
  - Cost **tiers** are request-wide: the highest matching `inputTokensAbove` tier's rates apply to the *whole* request (`:1239-1245`).
  - `clampThinkingLevel` walks **up** first, then down (`:1271-1290`), so asking for a tier the model lacks yields the nearest *higher* supported tier.
  - `applyAuth` ordering: explicit request options win per-field; the `Models`-only `transformHeaders` runs last (`:877-896`).
  - `login()` writes through `credentials.modify` and, if the signal aborts *before* the mutation starts, rejects — but a mutation already in flight is allowed to finish so a credential is never half-written (`:791-828`).
- **Edge cases & failure handling:** `ModelsError` codes are `model_source | model_validation | provider | stream | auth | oauth` (`:72`, `utils/models-error.ts:3`). `generateImages()` and `classify()` **never reject** — they return an error-shaped result (`:990-1025`).

#### `packages/ai/src/models.generated.ts` (309 lines) — **GENERATED**

## 2. Ideas worth stealing

*Convergence note: this shard covers only `pi`. `UNIQUE` below means "not observed in this shard"; confirm against `deepseek-harness` and `hermes-agent` before treating it as a genuine one-off.*

1. **Per-model capability flags instead of per-provider code branches.** Every provider quirk becomes a named boolean in a TypeBox schema with a documented default and an auto-detected fallback. `packages/ai/src/providers/compat-schema.ts:188-538`. *Why it transfers:* August's `GenericProviderService` has provider-specific branches for thinking, tool choice, cache control and error shapes. A `compat` record on the model (or the provider config) collapses those into data. **UNIQUE** (in this shard).
2. **The system prompt and the tool list live *in the transcript*, not in the request.** `packages/ai/src/types.ts:544-570` + `packages/ai/src/utils/transcript.ts:73-120`. A later system message patches a named *section* or adds/removes a tool; each provider either replays in place or collapses to one leading message. *Why it transfers:* August's `constants/promptRegistry.ts` + `utils/composePrompt.ts` could become a replayable log, so "change the system prompt mid-session" and "load a tool later" stop being special cases. **UNIQUE**.
3. **A table-driven context-overflow classifier, with silent-overflow detection and a non-overflow exclusion list.** `packages/ai/src/utils/overflow.ts:38-176`. *Why it transfers:* August needs ONE predicate for "the transcript is too big", and it must not confuse a 429 or a Bedrock throttle for an overflow. **UNIQUE**.
4. **Two-layer retry: an interruptible transport retry and a message-level retry with an explicit non-retryable list.** `packages/ai/src/utils/provider-retry.ts:99-128` and `packages/ai/src/utils/retry.ts:7-31, 205-255`. The SDK's own backoff ignores the abort signal, so pi re-implements it with an abortable sleep. *Why it transfers:* August's `GenericProviderService` has a 120 s timeout and retry built in; splitting "the socket failed" from "the turn failed" and naming quota errors as non-retryable is a direct copy. **UNIQUE**.
5. **A credential store whose only write path is a serialized read-modify-write, with the OAuth refresh inside the lock.** `packages/ai/src/auth/types.ts:65-94`, `packages/ai/src/auth/credential-store.ts:14-28`, `packages/ai/src/auth/resolve.ts:119-155`. The signal cancels only the *lock wait*; a refresh that has started runs to completion so a rotated token is never lost. *Why it transfers:* August's `ProviderConfigService` writes API keys; the same lock discipline applies to a provider key that can be rotated. **UNIQUE**.
6. **"A stored credential owns the provider" — no silent env fallback.** `packages/ai/src/auth/resolve.ts:27-32, 70-92`. *Why it transfers:* if August stores a key for a provider, a stale `process.env` key must not quietly take over. **UNIQUE**.
7. **`lazyStream`: a synchronous API whose async setup failures become stream errors, not throws.** `packages/ai/src/api/lazy.ts:60-86`. *Why it transfers:* August's `GenericProviderService` throws synchronously when auth is missing; wrapping the call in a stream that returns immediately would let the UI show "starting…" instead of a thrown error. **UNIQUE**.
8. **A per-model thinking ladder: a map, a support list, and a clamp that walks up before down.** `packages/ai/src/models.ts:1258-1290`, `packages/ai/src/providers/model-schema.ts:14-18`. `null` in the map means "unsupported". *Why it transfers:* August's `ReasoningEffort` union is exactly this idea in embryo; the missing half is the clamp and the `null` convention. **UNIQUE**.
9. **Cost is computed from a *model* price table with request-wide tiers and a 1-hour cache-write multiplier.** `packages/ai/src/models.ts:1236-1256`. *Why it transfers:* August's analysis/journal rows already carry `modelsUsed`; giving each model a tiered price table makes the per-call cost a derivation, not a guess. **UNIQUE**.
10. **A generated catalogue with a *validated manifest* (schema version, structure hash, per-file SHA-256) and a build gate that refuses stale data.** `packages/ai/scripts/model-data.ts:214-301` + `scripts/check-model-data.ts`. *Why it transfers:* August's `constants/models.ts` and `constants/prompts` are hand-edited; a manifest + validator would make "the catalogue is stale" a build failure rather than a support ticket. **UNIQUE**.
11. **Atomic, rollback-safe publication of generated data.** `packages/ai/scripts/hydrate-model-catalog.ts:66-80` — stage in `mkdtemp`, validate, then `renameSync`. *Why it transfers:* any generator that writes files August depends on. **UNIQUE**.

The error message includes the received arguments and the raw text, so the model can retry. *Why it transfers:* August's `validateToolCall` equivalent (zod) loses the model's original text; keeping it is a one-line change with a real payoff. **UNIQUE**.
13. **"Prefer" vs "require" constrained sampling, with the offending keyword named.** `packages/ai/src/api/constrained-sampling.ts:225-249`. *Why it transfers:* August's schemas are strict; a tool whose schema uses `$ref` would hard-fail against a strict provider. "Prefer" degrades gracefully, "require" fails loudly. **UNIQUE**.

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work — not in this shard, but the machinery to build it is here.** There is no cron, no scheduler and no "detect entry/TP/SL hit" logic in `packages/ai`. What *is* here is the pattern a monitor needs: `Models.refresh()` (`packages/ai/src/models.ts:498-625`) is a **generation-checked, abortable, per-provider refresh** that (a) restores the cached catalogue from the store *before* touching auth or the network, so offline boot still works, (b) resolves auth only for the network phase, (c) publishes the result through a **transactional, serialized, generation-checked** `context.publish()` so a superseded refresh can never write, and (d) reports per-provider errors and an `aborted` flag instead of throwing. A "poll for TP/SL hits" worker wants exactly those four properties. **The transferable abstraction is `RefreshModelsContext`/`ModelsPublication`** (`packages/ai/src/models.ts:76-104`): an immutable snapshot in, a guarded publication out.
- **Human-in-the-loop approval — not in this shard.** The closest thing is the **auth interaction protocol** (`packages/ai/src/auth/types.ts:119-161`): the *app* owns `prompt(prompt) => string` and `notify(event)`, the *SDK* owns the flow, and a pending prompt carries its own `AbortSignal` so an out-of-band event can cancel it. That split is exactly what an approval dialog needs — the domain code asks a question and gets an answer, and the UI owns how to ask. `packages/ai/src/auth/oauth/callback-server.ts:155-183` shows the race: whichever of two resolution paths wins cancels the other.
- **Post-mortem / reflection loops — not in this shard.** No rule accumulation, no expiry, no retirement. The nearest thing is the **catalogue self-correction** loop: `scripts/generate-models.ts` regenerates the catalogue, `scripts/model-data.ts` validates it against the manifest, and a mismatch is a hard failure. A "learning loop" for August needs the same three parts: a generator, a validator, and a manifest that says when the thing is stale.
- **Multi-agent — not in this shard.** This package is strictly one-model-one-stream. There is no debate, no subagent, and no orchestrator. The only multi-actor idea present is the **credential-store lock** (`packages/ai/src/auth/resolve.ts:119-155`), which is a worked example of "two callers want the same scarce resource; serialise and re-check under the lock" — a pattern any subagent scheduler would need.
- **Structured logs the model can query — partially, and usefully.** The model catalogue *is* a queryable structured record: one JSON file per provider, grouped by API, keyed `type:id`, plus a manifest with a structure hash and per-file SHA-256 (`packages/ai/src/providers/data/*.json`, validated by `packages/ai/src/scripts/model-data.ts:214-301`). That is the "no heavy database" answer — **file-per-record JSON, a manifest, and a validator** — and it is directly stealable as the shape of a queryable trade log or outcome journal. The transcript itself is the other queryable record: a `Message[]` with typed roles, tool calls and tool results, replayable and diffable.
- **Staying simple as features accumulate — the compat flag system is the device.** The repo's answer to "the feature count is becoming the product" is to turn each new quirk into a *data* flag rather than a new branch, and to keep a strict quarantine of the legacy surface: `packages/ai/src/index.ts:4-8` says the core entrypoint is *"side-effect free: no generated catalogs, no provider factories, no api-registry, no OAuth implementations, no compat"*, and `packages/ai/src/compat.ts:10-11` says the whole legacy global API is *"deleted with the coding-agent ModelManager migration"*. Two entrypoints, one of which is explicitly temporary. The `createProvider` factory (`packages/ai/src/models.ts:1077-1218`) is what makes 42 providers cheap: each new provider is ~15 lines.

## 4. Non-obvious decisions and gotchas

1. **A model with no `type` is a chat model.** `packages/ai/src/utils/model-operations.ts:18-20`. Comparing `model.type === "chat"` is wrong.
2. **`Usage.output` includes reasoning tokens; `Usage.reasoning` is the subset.** `packages/ai/src/types.ts:467-471`. Adding them double-counts.
3. **`calculateCost` mutates the `usage` object it is given.** `packages/ai/src/models.ts:1236-1256`. It does not return a new object.
4. **A stored credential suppresses the environment entirely.** `packages/ai/src/auth/resolve.ts:70-92`. And a *failed* refresh does not fall back to an env key — it raises `ModelsError("oauth")`.
5. **The OAuth signal cancels only the lock wait.** `packages/ai/src/auth/resolve.ts:105-155`. A refresh that has started ignores the signal and is bounded by a 15 s timeout, because the provider may already have rotated the token.
6. **`getEnvApiKey` deliberately skips `ANTHROPIC_AUTH_TOKEN`.** `packages/ai/src/env-api-keys.ts:78-82, 156`. It must be sent as `Authorization: Bearer`, not as an API key.
7. **`"<authenticated>"` is a sentinel, not a key.** `packages/ai/src/env-api-keys.ts:170, 190`; `packages/ai/src/compat.ts:218-232` refuses to pass it onward.
8. **A `null` header value DELETES a default header.** `packages/ai/src/models.ts:384-398` and `packages/ai/src/utils/headers.ts:11-23`. This is the "suppress a default" convention and it is not documented anywhere obvious.
9. **`clampThinkingLevel` prefers the nearest HIGHER supported tier.** `packages/ai/src/models.ts:1271-1290`. Asking for `xhigh` on a model that stops at `high` gives `high`; asking for `minimal` on a model that starts at `low` gives `low`.
10. **`Usage.cacheWrite1h` is optional and means only Anthropic.** `packages/ai/src/types.ts:463-465`; when absent, the whole write prices at the 5-minute rate (`packages/ai/src/models.ts:1248-1253`).
11. **The overflow detector must be checked *before* the retry detector.** A Bedrock throttle reads *"Too many tokens"* and would match the generic overflow pattern without the exclusion list (`packages/ai/src/utils/overflow.ts:80-84`).
12. **`partial` in a stream event is the live mutable message, not a snapshot.** `packages/ai/src/types.ts:798-812`. Mutating it is visible to the consumer; block events are **not contiguous** — correlate with `contentIndex`.
13. **A stream that returns is not the same as a stream that succeeded.** `packages/ai/src/types.ts:389-397`: a direct `streamSimple()` call may throw synchronously when auth is missing, but once a stream is returned, failures are *encoded in the stream*.
14. **Errored and aborted assistant messages are dropped on replay.** `packages/ai/src/api/transform-messages.ts:216-224`. Replaying them causes "reasoning without following item" errors upstream.
15. **An orphaned tool call gets a synthetic error result, not a dangling call.** `packages/ai/src/api/transform-messages.ts:188-207`.
16. **A system message between a tool call and its results is held back.** `packages/ai/src/api/transform-messages.ts:184-186, 237-241`. This prevents a duplicate tool result.
17. **Google's empty-but-signed text blocks must be sent.** `packages/ai/src/api/google-shared.ts:238-243`. Dropping them breaks the reasoning chain and produces "thought-only STOP" completions.
18. **A thought signature is only valid for the model that produced it, and only if it is valid base64.** `packages/ai/src/api/google-shared.ts:151-163`.
19. **Anthropic's `thinkingSignature` is either a signature or a redacted payload, never both.** `packages/ai/src/api/bedrock-converse-stream.ts:669-690`.
20. **Mistral's `finish_reason: "error"` is deliberately worded "server error"** so the retry classifier matches it (`packages/ai/src/api/mistral-conversations.ts:946`). A copy-paste of the wire string into a generic message would silently stop it being retried.
21. **OpenAI Responses' `max_output_tokens` has a floor of 16.** `packages/ai/src/api/openai-responses.ts:38, 380`.
22. **The OpenAI prompt-cache key is 64 characters, counted in code points.** `packages/ai/src/api/openai-prompt-cache.ts:1-8`.
23. **HTTP 504 on the OpenAI Decisions API is never retried** — Cloudflare answers 504 with an HTML page after ~5 s and retrying the same input hits it again. `packages/ai/src/api/openai-decisions.ts:146-158`.
24. **Any HTTP 413 counts as a context overflow**, regardless of body. `packages/ai/src/utils/overflow.ts:64-66`.
25. **A status code inside a request id is not a status code.** The retry pattern uses a negative lookbehind: `(?<![a-z0-9])(?:429|500|…)(?![a-z0-9])`. `packages/ai/src/utils/retry.ts:43`.
26. **The `compat` schemas all set `additionalProperties: true`.** `packages/ai/src/providers/compat-schema.ts:348, 413, 500, 510, 537`. A typo in a flag name is accepted silently.
27. **`hasToolRedefinitions` is deprecated but still exported.** `packages/ai/src/utils/transcript.ts:179-186`. Same for `getImageModel`/`getImageProviders`/`getImageModels` (`packages/ai/src/image-models.ts:31-49`) and the whole `src/compat.ts` surface.
28. **`src/models.generated.ts` and the 42 `providers/*.models.ts` are machine output** even though they are classified as source, and the header of each says so.
29. **The `models.data` manifest stamp is a fixed epoch for hydrated catalogs** so identical input produces identical bytes. `packages/ai/src/scripts/hydrate-model-catalog.ts:63-65`.
30. **The bedrock lazy loader is the only one with a variable specifier** (to keep the AWS SDK out of browser bundles) *and* the only one with a module override (for the Bun binary). `packages/ai/src/api/bedrock-converse-stream.lazy.ts:10-29`.

## 5. Weak spots

- **Two global mutable registries with different shapes and no owners.** `apiProviderRegistry` in `packages/ai/src/compat.ts:102` and `imagesApiProviderRegistry` in `packages/ai/src/images-api-registry.ts:24`, plus a third, `sessionResourceCleanups` (`packages/ai/src/session-resources.ts:3`). Two `Models` collections in one process share the api registry, and `resetApiProviders()` (`packages/ai/src/compat.ts:209-213`) clears state another collection may depend on. The `Models` design is explicitly per-collection; the compat layer is explicitly global. The seam is where the bugs live.
- **`models.ts` is 1299 lines and holds six unrelated concerns**: the `Provider` interface, the `Models` collection, the `createProvider` factory, cost calculation, the thinking-level ladder and equality helpers. `packages/ai/src/models.ts`.
- **The `Provider` interface has seven optional members** — `refreshModels`, `filterModels`, `filterAllModels`, `fetchDeferred`, `cancelDeferred`, `generateImages`, `classify` — each with a "never rejects" or "must not throw" contract stated only in prose (`packages/ai/src/models.ts:174-246`). A provider that violates one fails silently.
- **The overflow table will rot.** ~25 provider-specific regexes with a hand-maintained exclusion list (`packages/ai/src/utils/overflow.ts:38-84`). There is no test that every provider's real error text is matched; the coverage is implicit in the live tests.
- **`compat` has grown to roughly 90 boolean flags**, and every schema allows additional properties, so a typo is invisible (`packages/ai/src/providers/compat-schema.ts:188-538`). The mitigation is the explicit-override merge, but only for *duplicates*, not for typos.
- **The generated data is checked in but the generator is not hermetic.** `scripts/generate-models.ts` depends on models.dev, three OpenRouter listings, Vercel, NVIDIA and the Radius gateway; `--strict` turns a fetch failure into a build failure, and the non-strict path yields a *partial* catalogue that is then hashed and manifested as if it were whole.
- **`faux.ts` is 727 lines of test-double logic shipped in the main entrypoint** (`packages/ai/src/index.ts:35`). It is genuinely useful, but it is a second implementation of the stream protocol living next to the real one.
- **The compat surface is large and only nominally deprecated.** `packages/ai/src/compat.ts` (302 lines) + `packages/ai/src/legacy-api-aliases.ts` (108 lines) + `packages/ai/src/image-models.ts` (50 lines) + `packages/ai/src/oauth.ts` (10 lines) = ~470 lines of migration scaffolding, still exported from `package.json`'s `sideEffects` list. The plan says it is "deleted with the coding-agent ModelManager migration" — that migration is not visible from this package, so the scaffolding's end date is unenforceable from here.
- **The `ProviderStreams` contract is prose, not types.** "Must not throw", "never rejects", "error termination must produce an AssistantMessage with stopReason 'error' or 'aborted'" (`packages/ai/src/types.ts:389-397`) — all of it in doc comments, none of it enforced.
