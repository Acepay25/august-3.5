# pi :: pi-repo-root

**Files in shard:** 31 (read: 29, skipped with reason: 2)
**What this shard covers:** the *root of the pi monorepo* — the repository's constitution and its supply chain. This is not a code shard: it holds the contributor/agent contract (`AGENTS.md`, `CONTRIBUTING.md`, `SECURITY.md`, `README.md`), the identity and licence files, the lint/format config (`biome.json`), the TypeScript project layout (`tsconfig*.json`), the npm workspace manifest, the Nix packaging (reproducible offline builds with a content-addressed model-catalog pin), the two lockfiles (the root `package-lock.json` and the separate `install-lock/` used by the pi.dev installer), the test-runner scripts (`test.sh`, `pi-test.sh`/`.ps1`/`.bat`) and the shared Vitest base config, plus the 6,367-line `packages/coding-agent/CHANGELOG.md` — which, read as a design-history document, is the single richest artifact in this shard: it records *why* pi looks the way it does (compaction triggers, prompt-cache discipline, retry taxonomy, session durability, tool-truncation receipts, skill loading).

Everything here is **policy and plumbing, not behaviour**. The behaviour lives in the `packages/*/src` shards. What this shard proves is that pi's *shape* is the result of a deliberate, written-down core/extension split — and that August Trading's "feature count becoming the product" problem has a documented precedent for how to resist it.

## 1. File-by-file

### Tier 1 — load-bearing source: full entry

Seven files are typed `source` in the file list. They are the repo's actual executables: the packaging expression, the test runner, and the four scripts that launch pi from source.

#### `nix/package.nix`
- **Purpose:** the Nix derivation that builds pi as an offline, reproducible, self-contained install (a Node app plus its CLI wrapper), used by `nix run github:earendil-works/pi/stable`.
- **Key abstractions:** a two-stage derivation — `workspacePackages` (`nix/package.nix:36`) builds every workspace package from this checkout and `npm pack`s each into a `.tgz`; the outer derivation (`nix/package.nix:94`) then installs from `install-lock/` and **overrides the registry references with those local tarballs** via `packageSourceOverrides` (`nix/package.nix:81-92`).
- **Data flow:** `model-catalog.json` → `modelCatalogPin.revision` → `fetchurl` of `https://pi.dev/api/models/revisions/<rev>?types=chat,image,classifier` (`nix/package.nix:27-30`) → `node packages/ai/scripts/hydrate-model-catalog.ts` → `npm run build:offline` → `npm pack` per package → install from `install-lock` with local tarball overrides → `makeWrapper` the CLI.
- **Non-obvious design decisions:**
  - **The model catalog is content-addressed, and the hash is over a *projection*.** The pin file holds one field (`nix/model-catalog.json:2`), a sha256, used simultaneously as the `fetchurl` integrity hash and as the URL path segment. The comment at `nix/package.nix:27` says the hashed representation is "the typed catalog … `types=chat,image,classifier`" — so adding a classifier model changes the pin. `README.md:66-69` states the pin is *auto-replaced on `main`* when it no longer matches the checkout, and `npm run update:model-catalog-pin` refreshes it by hand.
  - **One lockfile serves two worlds.** The *root* `package-lock.json` is the development ground truth; `install-lock/` is the pinned tree the pi.dev installer uses. The Nix build reuses `install-lock` so the packaged binary and the installer ship the same dependency closure.
  - **PATH ordering is deliberate and commented.** `makeWrapper` *appends* Pi's own Node (`--suffix PATH`, `nix/package.nix:127`) and *prepends* Pi's own tool dependencies — fd, ripgrep, clipboard (`--prefix PATH`, `nix/package.nix:128-139`). The reason is stated at `nix/package.nix:120-124`: Node is on PATH only so Pi can find `npm`, and appending it means a shell started by the bash tool keeps the *user's* `node`/`npm` (mise, nvm). Pi's tools beat the user's; Pi's Node loses to the user's.
  - **The install check proves features work, not that the binary starts.** `installCheckPhase` (`nix/package.nix:145-165`) asserts `pi --version` equals the manifest version *and* force-`require()`s every native `.node` prebuild and the `photon-node` wasm — the comment at `nix/package.nix:155-157` says missing native dependencies must "fail the build rather than silently disabling clipboard support."
- **Edge cases & failure handling:** `importNpmLock` fails the build on a lock/shell mismatch; `fetchurl` fails on hash mismatch (the pin is therefore a supply-chain assertion, not a convenience); `autoPatchelfHook` is Linux-only (`nix/package.nix:112`); `libxcb` is a Linux-only build input for the TUI's native terminal support.
- **Surprising:** the derivation is 190 lines of Nix and it is the only place in the repo where the *runtime dependency closure* is materially pinned — npm installs deliberately do not pin transitives (see `CHANGELOG.md:324`).

#### `packages/coding-agent/vitest.config.ts`
- **Purpose:** the Vitest configuration for the coding-agent package (the biggest test surface in the repo).
- **Key abstractions:** `mergeConfig(baseConfig, defineConfig({...}))` — the shared base is `vitest.base.ts`; the package adds test env, reporters, and a source alias set.
- **Data flow:** config → `workspaceSourcePaths` aliases → test files import workspace packages *by source path*, never by built artifact.
- **Non-obvious design decisions:**
  - **Offline is the default, and opting in is a function call, not an env var.** `env: { PI_OFFLINE: "1" }` (`packages/coding-agent/vitest.config.ts:12`) with the comment "Tests run offline by default; opt in with `allowNetwork()` from `test/test-network-env.ts`." Network access is a *test-scoped capability*, granted per test, not a global switch.
  - **`silent: "passed-only"`** (`:15`) — passing tests print nothing; only failures and summaries are visible. A direct answer to "5,343 tests, how does anyone read the output."
  - **`unstubEnvs: true`** (`:13`) — Vitest restores stubbed env vars between tests, so one test's key stub cannot leak into the next.
  - **Reporter switch by CI detection** (`:14`): `github-actions` reporter under GITHUB_ACTIONS, `dot` otherwise.
  - **A native/wasm dependency is excluded from the dep optimizer** (`server.deps.external: [/@silvia-odwyer\/photon-node/]`, `:18-20`) — it cannot be inlined.
  - **Legacy package names still resolve.** The alias table maps both `@earendil-works/pi-ai` and `@mariozechner/pi-ai` to the same source (`:35-38`) — the package was renamed and old imports still work in tests.
- **Edge cases & failure handling:** 30 s test timeout (`:11`); `globals: true` so tests need no import of `describe`/`it`.
- **Surprising:** there is no `setupFiles` here — the isolation lives in `test.sh`, not in Vitest.

#### `test.sh`
- **Purpose:** the repo's canonical test entry point: runs the whole suite in an isolated, credential-free, hermetic environment.
- **Key abstractions:** `mktemp -d` sandbox root; a `cleanup()` trap; an allowlist `test_env` array; `env -i` as the final launcher.
- **Data flow:** create sandbox → build allowlist → `env -i "${test_env[@]}" npm test` (`test.sh:84`) → trap cleans up.
- **Non-obvious design decisions:**
  - **The test environment is an allowlist, not a denylist.** `env -i` (`test.sh:84`) wipes the entire inherited environment and re-adds only 20-odd names (`test.sh:40-63`). The comment at `test.sh:4` states the intent: "Isolate user resources, credentials, temporary files, and tool configuration."
  - **The allowlist covers git prompt-hijacking explicitly**: `GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_TERMINAL_PROMPT=0`, `GIT_ASKPASS=false`, `GIT_EDITOR=true`, `GIT_SEQUENCE_EDITOR=true` (`test.sh:53-58`).
  - **Cloud metadata endpoints are disabled**: `AWS_EC2_METADATA_DISABLED=true` and `PI_NO_LOCAL_LLM=1` (`test.sh:62-63`). A test must never accidentally reach a real LLM or a real cloud credential service.
  - **The cleanup refuses to delete anything it did not create.** `cleanup()` (`test.sh:17-33`) checks the path matches `"$temp_parent"/pi-test.*`, is a directory, is not a symlink, and contains the marker file `.pi-test-owned`; otherwise it prints "Refusing to remove unverified test directory" and **flips the exit status to 1** (`test.sh:26-27`, `:31`). The marker file is created by `touch` at `test.sh:12` specifically so cleanup can prove ownership.
  - **Windows child-process survivability is handled explicitly**: `SystemRoot`, `SYSTEMROOT`, `WINDIR`, `COMSPEC`, `PATHEXT` are re-added if present (`test.sh:66-70`) because `env -i` would break child-process launching on native Windows.
  - **Corporate proxies are respected without inheriting anything else**: only `NODE_EXTRA_CA_CERTS` is passed through (`test.sh:72-75`), because a self-signed proxy CA otherwise breaks every HTTPS test.
  - **CI detection is preserved, but only for reporting**: `CI` and `GITHUB_ACTIONS` are the only other inherited names (`test.sh:77-80`).
- **Edge cases & failure handling:** the trap preserves the original exit status (`local status=$?` at `test.sh:18`) and re-raises it at `test.sh:33`; a failed cleanup turns a green run red.
- **Surprising:** the script does *not* unset API keys — it never lets them in. `pi-test.sh` (below) unsets them from an existing environment; `test.sh` prevents them from existing.

#### `pi-test.sh`
- **Purpose:** run the coding agent **from source** (no build step) for manual driving; supports `--no-env` to strip every provider credential from the process.
- **Key abstractions:** `--no-env` flag; a resolver file-URL; `node --import <resolver> <cli.ts>`.
- **Data flow:** parse `--no-env` → optionally unset 36 credential env vars → convert the resolver path to a file URL → `node --import` the CLI.
- **Non-obvious design decisions:**
  - **`--import` takes a *module specifier*, not a path.** The comment at `pi-test.sh:39-40` is explicit: "raw paths break on #, ?, %". The fix is `node -p 'require("node:url").pathToFileURL(process.argv[1]).href'` — a path is not a specifier, and a Windows path with `#` or `%` corrupts the specifier.
  - **The credential list is a deliberate allowlist of what to *remove*, and the comment points at the canonical source**: `pi-test.sh:23` says "(see packages/ai/src/env-api-keys.ts)". The list covers 16 provider keys (Anthropic, OpenAI, Gemini, Groq, Cerebras, xAI, OpenRouter, ZAI, Mistral, MiniMax ×2, AI Gateway, OpenCode, Copilot), plus 4 forge/registry tokens (GH, GitHub, HF), plus 13 Google/AWS/Azure cloud vars.
  - **`${ARGS[@]+"${ARGS[@]}"}`** (`:41`) — the `+` form so an *empty* argument list does not expand to a single empty string under `set -u`.
- **Edge cases & failure handling:** `set -euo pipefail` at `:2`; the script exits with node's own exit code.
- **Surprising:** the script is documented as runnable "from any directory" (`packages/coding-agent/README.md:96`) because it resolves `SCRIPT_DIR` from `BASH_SOURCE` and always invokes the absolute `cli.ts`.

#### `pi-test.ps1`
- **Purpose:** the Windows equivalent of `pi-test.sh`, with the same `--no-env` semantics.
- **Key abstractions:** `$forwardArgs` list; `$envVarsToUnset` array; `[System.Uri](...).AbsoluteUri` for the resolver URL.
- **Data flow:** parse args → optionally `Remove-Item Env:<name>` for 36 vars → build a `file://` URI → `& node --import $resolverUrl $cliPath @forwardArgs`.
- **Non-obvious design decisions:**
  - **The same specifier-vs-path problem, solved with .NET**: the comment at `pi-test.ps1:46` says "--import takes a module specifier, so pass the resolver as a file URL (Windows paths are not specifiers)" and the code uses `([System.Uri](Join-Path $scriptDir "...")).AbsoluteUri` (`:47`).
  - **Env removal uses `Remove-Item -ErrorAction SilentlyContinue`** (`:55`) so a missing variable is not an error.
  - **`$ErrorActionPreference = "Stop"` at the top** (`:1`) and an explicit exit-code check (`:50-52`) — PowerShell does not fail a script on a non-zero native exit code by default, so it is checked and re-thrown.
- **Edge cases & failure handling:** the `Remove-Item` loop tolerates absent variables; the script forwards `$LASTEXITCODE` faithfully.
- **Surprising:** it is the *only* place in the repo that shows how to make a native Windows command's exit code fail a PowerShell script — a pattern most CI wrappers get wrong.

#### `pi-test.bat`
- **Purpose:** a one-line shim so Windows users can double-click or `cmd` into `pi-test.ps1`.
- **Key abstractions:** none — it is a 12-line wrapper.
- **Data flow:** `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "%SCRIPT_DIR%pi-test.ps1" %*` → propagate `%ERRORLEVEL%`.
- **Non-obvious design decisions:**
  - **`-ExecutionPolicy Bypass`** — a signed-script policy would otherwise block a repo-local `.ps1` on a locked-down corporate machine. The `ExecutionPolicy` here is a *launch-time* decision, not a machine-wide weakening.
  - **`-NoProfile`** — the user's PowerShell profile must not alter the harness.
  - **It probes for `powershell.exe` first** and exits 1 with an actionable message ("Install PowerShell or run pi-test.ps1 directly") if absent (`pi-test.bat:5-10`).
  - **`exit /b %ERRORLEVEL%`** (`pi-test.bat:12`) — the batch file's own exit code is the PowerShell script's.
- **Edge cases & failure handling:** `setlocal` at `:2` prevents env leakage into the caller.
- **Surprising:** it hardcodes `powershell.exe` (Windows PowerShell 5.1) rather than `pwsh` (PowerShell 7) — see §5.

#### `vitest.base.ts`
- **Purpose:** the shared Vitest configuration for every package in the monorepo — one alias table mapping every workspace specifier to its **source** file.
- **Key abstractions:** `workspaceSourcePaths` (`:4-27`) — a frozen map of package name → absolute path of the package's `src/index.ts`; and the default export, a `defineConfig` whose `resolve.alias` array derives from that map.
- **Data flow:** package specifier → regex alias → workspace source file. No build step is required for a test to exercise the current source of a sibling package.
- **Non-obvious design decisions:**
  - **Tests always run against source, never against a stale `dist/`.** This is the single most load-bearing line in the file: it makes it *impossible* for a test to pass against a build that predates the source it is testing. The build tsconfig (`packages/coding-agent/tsconfig.build.json`) deliberately points the other way — at `../agent/dist/index.d.ts` — so a package compiles against its dependencies' *published shapes* while its tests compile against their *sources*. Two path maps, two purposes, both explicit.
  - **Wildcard subpath aliases are regex-based**: `/^@earendil-works\/pi-ai\/utils\/(.+)$/` → `${workspaceSourcePaths.aiUtils}/$1.ts` (`:45-48`), with the same for `api/` and `providers/` (`:49-55`).
  - **The legacy package identity is still aliased** (`:35-38` in the package config; here `:44` maps `@earendil-works/pi-ai/oauth`).
- **Edge cases & failure handling:** `fileURLToPath(new URL(..., import.meta.url))` (`:5`) instead of `__dirname` — the same "don't use `__dirname`" rule that `AGENTS.md:22` states for asset resolution in the coding agent.
- **Surprising:** the file exports the paths object *by name* so that individual package configs can add their own aliases without re-deriving paths — `packages/coding-agent/vitest.config.ts:3` imports `{ workspaceSourcePaths }` from it.

### 1.1 The CHANGELOG as a design-history document

The 654 KB changelog is the only artifact in this shard that records *reasons*. It is structured per release as `### New Features` (a bolded, prose "why it matters" summary) / `### Breaking Changes` / `### Added` / `### Changed` / `### Fixed` / `### Removed`, with an issue/PR link on most bullets (`AGENTS.md:105-118` codifies the exact format, including the `([#123](…))` and `([#456](…) by [@user](…))` attribution forms).

Read strategically — the full version-header index (130 releases), the head (1.4.0 → 1.0.1), lines 100-430, lines 965-1160 (0.84.0, a dense breaking-changes release), the tail (0.10.0 → 1.4.0's oldest), plus a complete index of every `**New Features**` bullet across all 130 releases — it yields this design narrative, which is the most transferable material in the shard:

- **Compaction triggers were narrowed to exactly two.** "Removed proactive compaction (aborting mid-turn when threshold approached). Compaction now triggers in two cases only: (1) overflow error from LLM, which compacts and auto-retries, or (2) threshold crossed after a successful turn, which compacts without retry" (`CHANGELOG.md:5971`). "Compaction retry uses `Agent.continue()`: Auto-retry after overflow now uses the new `continue()` API instead of re-sending the user message, preserving exact context state" (`:5973`). "Block input during compaction: User input is now blocked while auto-compaction is running to prevent race conditions" (`:5985`). "Session compaction indicator: When resuming a compacted session, displays 'Session compacted N times'" (`:5981`).
- **Summaries stopped having a fixed cap.** "Summaries now use the model's output limit, and `compaction.reserveTokens` only controls when compaction starts" (`:36`); the same release removed `reserveTokens` from `generateSummary()` entirely (`:28`).
- **The summariser must not see more than the thing it summarises.** "Changed `serializeConversation()` (compaction, branch summaries, bug reports) to omit thinking blocks; replayed thinking is often not in the live context, so including it could make a summarization request larger than the context it summarizes and fail" (`:137`).
- **Compaction must not fail silently.** "Compaction error handling: `generateSummary()` and `generateTurnPrefixSummary()` now throw on LLM errors instead of returning empty strings" (`:5415`).
- **Compaction must not include abandoned branches.** "Fixed compaction incorrectly including entries from abandoned branches, causing token overflow errors. Compaction now uses `sessionManager.getPath()` to work only on the current branch path, eliminating 80+ lines of duplicate entry collection logic" (`:5416`).
- **The prompt cache is a first-class citizen.** "Anthropic tools added or redefined mid-conversation are now defined inline in the conversation, so redefining a tool under the same name keeps the prompt cache instead of resending the full tool list" (`:304`). "Fixed runs started by `pi.sendMessage(…)` removing system prompt sections added in `before_agent_start` after their first tool call, which changed the prompt mid-run and broke the provider prompt cache twice per run" (`:145`). "Fixed OpenAI Responses models losing the prompt cache on every deferred tool load after a tool was removed" (1.4.0 Fixed). "Fixed prompt submission slowing down with session length, because resolving the session's model selection looked up the model catalog once per assistant message" (`:401`).
- **Prompt size is a measured budget, not a vibe.** "Codemode costs far fewer prompt tokens: with the default tools and codemode active, a GPT-5.6 request shrinks from about 5,300 to 3,300 tokens" (`:351`) — a ~40 % reduction (`:331`). "Reduced context-limit request failures by estimating input at 3.5 characters per token instead of 4" (`:216`) — a *measured* constant, not the usual 4.
- **A dynamic tool description breaks the cache.** "MCP servers with the default `codemode` exposure no longer appear in the `codemode` description … so it no longer changes when MCP servers connect or change their tools … Servers are listed instead in an `mcp_servers` system prompt section with a one-line summary, updated at the start of each prompt" (`:392`). "The first prompt no longer waits for MCP servers without `direct` tools. They connect in the background" (`:393`).
- **A truncated tool call poisons the whole transcript.** "Fixed sessions breaking after recovery from a response cut off at the output limit: the truncated tool call was omitted but its tool results were kept, so providers rejected every later request" (1.4.0 Fixed). This is an *invariant*: a persisted assistant message must never be in a state that invalidates the conversation that follows it.
- **A malformed tool call must fail loudly.** "Fixed tool calls whose final arguments are malformed JSON silently running with only the fields parsed before the error; they now fail validation and show the model the raw arguments it sent" (`:103`).
- **Truncation comes with a receipt.** "Tool output truncation: All tools now enforce consistent truncation limits with actionable notices for the LLM" (`:6041`); "Output files (full text of truncated tool output, binary MCP resources, codemode images) are now readable only by the user" (`:263`) — the full text goes to a file and the path is named in the result.
- **A wrong exit code is a lie.** "Fixed print mode (`-p`) exiting 0 without a warning when the final response was cut off at the model's output token limit; it now prints the partial text, writes a warning to stderr, and exits 1" (`:147`).
- **Cancelled is not finished.** "Added `aborted` to `agent_settled` session, extension, and JSON events, so integrations can tell a cancelled run from a finished one" (`:188`); "Added `durationMs` to the tool render context and to `tool_execution_end` extension events" (`:183`).
- **Streaming must emit deltas only.** "Changed JSON and RPC `message_update` events to emit only `assistantMessageEvent` deltas, removing the cumulative `message` and `assistantMessageEvent.partial` fields that caused quadratic output growth" (`:978`).
- **The transcript's memory is a budget too.** "Fixed memory retained per rendered message in the transcript; a long assistant message keeps about a fifth of the heap it kept before" (`:370`).
- **Usage accounting must survive compaction.** "Footer shows full session stats: Token usage and cost now include all messages, not just those after compaction" (`:5404`); "Skip error messages in usage calculation: Context size estimation now skips both aborted and error messages, as neither have valid usage data" (`:5987`).
- **Skills load on demand, not into the prompt.** "Skills are listed in system prompt with descriptions, agent loads them via read tool when needed" (`:5921`); "Pi skills now use `SKILL.md` convention" (`:5905`); skills are validated against the Agent Skills standard — name must match the parent directory, lowercase, ≤64 chars; description required, ≤1024 chars (`:5731`).
- **One creation path for every session.** "Session runtime API: `createAgentSessionRuntime()` and `AgentSessionRuntime` provide a closure-based runtime that recreates cwd-bound services and session config on every session switch. Startup, `/new`, `/resume`, `/fork`, and import all use the same creation path" (`:2868`).
- **Services return diagnostics; the app decides.** "Unified diagnostics: Arg parsing, service creation, session option resolution, and resource loading all return structured diagnostics (`info`/`warning`/`error`) instead of logging or exiting. The app layer decides presentation and exit behavior" (`:2871`).
- **Sessions are durable, atomic, and lane-based.** "Replaced the inherited pi-agent-core harness session model with the v4 lane-based `Session`, `SessionStorage`, and `SessionRepo` APIs, including durable operation records, global facts, shared sequence numbers, and tree-scoped lane views" (`:1044`); "Added the inherited required pi-agent-core `FileSystem.renameFile()` operation for atomic JSONL publication" (`:1047`); "Fixed inherited JSONL session forks and torn-tail repairs to publish atomically, avoiding partially written or corrupted sessions after interrupted writes" (`:1091`).
- **Concurrency is explicit, not incidental.** "Fixed concurrent in-memory credential mutations losing unrelated provider updates by serializing their read-modify-write sections" (`:1120`); "Added `CredentialSynchronizationError` for credential changes that commit successfully but fail to synchronize local model state" (`:1054`); "Fixed concurrent `models-store.json` reads forming a file-lock convoy and delaying startup" (`:1110`).
- **The retry taxonomy is a long, explicit list.** Each of these was a provider error that *ended the turn* until it was classified as retryable: `server_busy` / "servers are currently busy" (`:214`), "Selected model is at capacity" (`:314`), Mistral `finish_reason: "error"` (`:215`), "The service is temporarily unavailable" (1.3.0 Fixed), "Unable to forward upstream stream" (1.3.0 Fixed), "The upstream provider returned an error" (`:155`), Bedrock "The pending stream has been canceled" (1.0.4 Fixed), Z.AI "Prompt exceeds max length" as a context overflow (`:404`), and "The service is temporarily unavailable" (1.3.0 Fixed). Retries also accumulate usage from *all* attempts, not just the last (`:6164`).
- **The tool-result contract is shared between built-ins and user tools.** "Extension tool signature change: `ToolDefinition.execute` now uses `(toolCallId, params, signal, onUpdate, ctx)` parameter order to match `AgentTool.execute` … This makes wrapping built-in tools trivial since the first four parameters now align" (`:3928`).
- **Presentation transforms are separate from content.** "Added chainable `pi.registerMarkdownTransformer()` hooks for display-only transformation of user and assistant Markdown" (`:1055`); "Added `pi.registerToolRenderer()`, which chooses how calls to a tool are drawn, **including tools that are not registered**" (`:298`).
- **Terminals get a state machine.** "Added program status reporting with OSC 7501: terminals and agent dashboards that support it see whether Pi is **working, blocked on a dialog or login, done, or failed**. `PI_PROGRAM_STATUS=1|0` overrides detection" (`:174`, `:187`).
- **Streaming-friendly collapse.** "Tool output display: When collapsed, tool output now shows the last N lines instead of the first N lines, making streaming output more useful" (`:5847`); bash "streams output in real-time … the TUI displays live progress with the last 5 lines visible" (`:5843`).
- **Hard caps on agent-generated output.** "a script fails once its output passes 16 Mi characters or 100000 items" (`:310`); "Fixed codemode scripts that patch built-ins … crashing pi and leaving the tool call unsettled. Built-ins are now frozen before the script runs" (`:243`); "Fixed codemode blocking the process for seconds to minutes after scripts with many `text()` calls; joining the output items was quadratic" (`:146`).
- **Ambiguity is an error, not a coin flip.** "Fixed `--model` choosing a provider by catalog order when several providers offer the match; Pi now prefers the provider with credentials and otherwise reports the ambiguity" (1.3.0 Fixed); "Fixed bare exact `--model` IDs shared by multiple providers choosing the first catalog entry instead of the sole authenticated provider or a clear ambiguity error" (`:1098`); "`--provider` without `--model` being silently ignored … it now fails with an error" (`:361`).
- **Session identity.** "Entry IDs: Session entries now use short 8-character hex IDs instead of full UUIDs" (`:5396`); sessions live in `~/.pi/agent/sessions/<encoded-cwd>/` (`:5436`); "Session file validation: `findMostRecentSession()` now validates session headers before returning, preventing non-session JSONL files from being loaded" (`:5414`); branches record `branchedFrom` in the session header (`:6141`).
- **Pinning is a product decision, and it was reversed.** "Removed `npm-shrinkwrap.json` from the published package. npm installations no longer pin transitive dependencies, and library consumers can now override them. Use the pi.dev installer for pinned installations" (`:324`).
- **Message delivery semantics are named.** "Queue API replaced with steer/followUp: The `queueMessage()` method has been split into two methods with different delivery semantics" (`:5101`); "Changed the session to count as busy while a run starts, including during `before_agent_start` handlers" (`:121`); "Added `AgentOptions.shouldStopAfterTurn` for gracefully stopping after a completed turn before queued messages or another model call are processed" (`:1074`).
- **The agent's own house rules.** "Status messages spam chat log: Rapidly changing settings … Sequential status updates now coalesce into a single line" (`:5405`); "Never run `npm run build` or `npm test` unless requested" is written into `AGENTS.md:33`.

## 2. Ideas worth stealing

> **Convergence labels.** I read only the `pi` repo-root shard, so cross-repo convergence is *unverified here* and is the orchestrator's to confirm. `UNIQUE` below means "observed only in this shard's files", not "only in pi". Where pi itself applies the same idea in two independent packages I say so.

1. **Make "the core is minimal" a written, enforceable doctrine, and route every feature request through an extension boundary.** `CONTRIBUTING.md:7-9` ("If your feature does not belong in the core, it should be an extension. PRs that bloat the core will likely be rejected") plus `README.md:19` ("skips features like sub-agents and plan mode") is a complete, 2-sentence answer to August Trading's "feature count becomes the product" problem — stated as policy, not aspiration, and it *names the two features it refuses to ship*. **Why it transfers:** August already has a rich extension surface (tools, skills, bots, automations); what it lacks is a written rule about which of them are core. UNIQUE here.
2. **Ship one policy file that governs both humans and agents, and make the agent's contract executable-by-reading.** `AGENTS.md` is written *to* the agent (no emojis, answer the question first, say whether you agree) and is picked up automatically by running an agent from the repo root. **Why it transfers:** August's `AGENTS.md` is currently a human/agent hybrid; splitting "how an agent must behave here" into one file that both readers honour is a one-hour change with outsized effect. UNIQUE here.
3. **Test the harness in a hermetic, allow-listed environment rather than a denylisted one.** `test.sh:40-84` rebuilds the environment from scratch (`env -i`) with HOME/TMP/XDG redirected into a `mktemp` sandbox, git prompt-hijacking disabled, and cloud metadata endpoints off. **Why it transfers:** August's suite runs against the developer's real machine; a `test.sh` with an explicit allowlist would make "a test accidentally hit a live provider" structurally impossible. UNIQUE here, but strongly convergent with hermetic-CI practice generally.
4. **Isolate "run the agent from source" from "run the tests", and give the manual path a credential-stripping switch.** `pi-test.sh`/`.ps1`/`.bat` run the CLI through a TS source resolver with no build step, and `--no-env` unsets 36 provider/cloud credentials. **Why it transfers:** August has a "boot-probe" and "render-probe" that drive a real app — giving them a `--no-env`-equivalent (a run that proves the app works with no keys configured) is cheap and would catch a whole class of "works on my machine because a key was set". UNIQUE here.
5. **Treat the model catalogue as a content-addressed artifact, pinned by the hash of a *projection* of it, and auto-refresh the pin when the projection changes.** `nix/model-catalog.json` holds one sha256; `nix/package.nix:27-30` uses it as both the URL and the integrity hash, and `README.md:66-69` says the pin is replaced on `main` whenever it no longer matches the checkout. **Why it transfers:** August's model list is runtime-configured (per `AGENTS.md`, providers live in Preferences) — a *pinned, hash-verified* catalogue snapshot for offline/replayable runs (backtests, evals) would make a historical run reproducible. UNIQUE here.
6. **Make the packaging gate prove a feature works, not that the binary starts.** `nix/package.nix:145-165` asserts the version *and* force-`require()`s every native prebuild, so "clipboard support was silently disabled" fails the build. **Why it transfers:** the direct analogue of August's `render-probe` philosophy ("assert the rendered row, not that the component returned"), generalised from the renderer to every packaged capability. Convergent *within* pi (same idea in the Nix install check and in the standalone-binary path).
7. **One tool-execution signature for built-in and user-authored tools.** `CHANGELOG.md:3928` — `ToolDefinition.execute` was deliberately re-ordered to `(toolCallId, params, signal, onUpdate, ctx)` to match `AgentTool.execute` "so wrapping built-in tools is trivial since the first four parameters now align". **Why it transfers:** August has model-authored tools (`toolForge`) and built-in tools; if their signatures differ, every wrapper/decorator/audit layer is bespoke. UNIQUE here.
8. **Treat tool output truncation as a *receipt*, not a deletion: write the full text to a user-only file and name the path.** `CHANGELOG.md:263` + `:6041` — truncated output goes to a file the model can be pointed at, with a user-only permission. **Why it transfers:** August already has a "spill receipt" in `utils/harnessMarks.ts`; pi's version is the same idea applied at the *tool* layer rather than the prompt layer, and it pairs with a *uniform* truncation limit across all tools ("consistent truncation limits with actionable notices for the LLM"). UNIQUE here.
9. **Return structured diagnostics from every service and let the app layer decide how to present and whether to exit.** `CHANGELOG.md:2871` — arg parsing, service creation, session option resolution and resource loading all return `info`/`warning`/`error` diagnostics "instead of logging or exiting. The app layer decides presentation and exit behavior." **Why it transfers:** August's services mostly log-and-continue or throw; a diagnostics return type would let the UI show a recoverable warning instead of a generic error toast — and would make the existing "surface the failure, don't swallow it" rule (`MemoryFilesService.getNotebookWriteFailure`) a general pattern rather than a local one. UNIQUE here.
10. **Classify provider errors into an explicit, growing retry taxonomy — and treat a *new* error string as a bug until it is classified.** The changelog records a long tail of provider errors that each ended the turn until classified: `server_busy`, "Selected model is at capacity", Mistral `finish_reason: "error"`, "The service is temporarily unavailable", "Unable to forward upstream stream", Bedrock "The pending stream has been canceled", Z.AI "Prompt exceeds max length". **Why it transfers:** August already has `utils/runStatus.ts` with error classification; the transferable idea is that the taxonomy is a *table with a row per provider error string*, and that "we hit an unclassified error" is treated as a defect (a new row), not as a generic failure. UNIQUE here, but convergent with the general "one status vocabulary" pattern.
11. **Make the "truncated but not finished" state impossible to persist.** `CHANGELOG.md` (1.4.0 Fixed): a response cut off at the output limit kept its tool results but dropped the tool call, "so providers rejected every later request". The invariant: a persisted assistant message must be structurally valid for every request that follows it. **Why it transfers:** this is the single most important correctness rule for August's `Message` persistence, where a partially-written assistant turn is exactly the kind of thing that poisons a resumed conversation. UNIQUE here.
12. **Publish a JSON Schema for every configuration file, and validate on load.** `CHANGELOG.md:112` (1.2.0) — `$schema` added to `settings.json`, `models.json`, keybindings and themes, with the schemas served at `https://pi.dev/schemas/*.schema.json` and theme validation applied at *startup* as well as at reload. **Why it transfers:** August's `settings.json`-equivalent (Preferences) has no published schema; a schema would let the UI and the model both validate the same config, and would let a bad config fail loudly at boot rather than at first use. UNIQUE here.

## 3. Trading-specific findings

This shard is the repo root. It contains **no trading logic, no trade log, no scheduler and no backtester** — those live in the `packages/*` shards. So most of the six questions are answered "not in this shard". What *is* in this shard is a set of transferable mechanisms:

- **Long-lived monitoring & scheduled work — not in this shard.** No cron, no scheduler, no job store, no catch-up logic. The closest structural analogue is the *self-update* path (`pi update --self`, "Managed install marker is missing or invalid", "managed installs keeping every old release; `pi update` now keeps only the new release and the one it updated from", `CHANGELOG.md:200`) — i.e. a job that must be idempotent and recoverable, which is exactly the property August's scheduled automations need. Read the `pi-agent` / `pi-scripts-ci` shards for the real answer.
- **Human-in-the-loop approval — partially in this shard, and it is pi's sharpest design decision.** pi ships **no permission system at all** (`README.md:90`, `SECURITY.md:50`), and instead documents three containerisation patterns. The *approval* surface exists as extension hooks: `tool_call` can **block**, `tool_result` can modify, and `ctx.ui.select()/confirm()/input()/notify()` are the interactive primitives (`CHANGELOG.md:5955-5963`). The approval record is the **session JSONL** — the `tool_call`/`tool_result` entries with `isError` (`:5743` restructured `ToolResultEvent` to expose full tool result data). So: *the audit trail is the conversation itself, not a separate ledger.* That is a direct, stealable answer to "what audit trail survives a decision" — but note it works only because the transcript is append-only and durable (`:1044`, `:1091`).
- **Post-mortem / reflection loops — not in this shard.** The nearest artefacts are the compaction summary (a *narrative* summary of the run, not a rule) and the `before_compact` hook (`:5515`), which lets an extension observe and inject at the moment of summarisation. No skill retirement, no rule expiry, no consolidation gate. That is pi's answer in principle — **there is no automatic post-mortem loop; the harness leaves reflection to the user or to an installed package.**
- **Multi-agent — answered, and the answer is "not in core".** `README.md:19`: pi "skips features like sub-agents and plan mode." Multi-agent exists only as an **example** (`CHANGELOG.md:5729`): parallel mode streams updates from all tasks, chain mode shows all completed steps during streaming, and the usage footer shows a turn count. The generalisation worth stealing: *the multi-agent implementation is a sample, not a core module — the core only provides the primitives it needs.* Note also `reachesTools` (`:126`) — a tool declares which other tools a call may reach, which is how pi models a tool that *contains* sub-agents.
- **Structured logs the model can query — answered, and it is the strongest trading-adjacent idea in this shard.** pi's answer is **JSONL, one file per session, append-only, published atomically**: sessions live at `~/.pi/agent/sessions/<encoded-cwd>/` (`:5436`), entries carry 8-char hex IDs (`:5396`), publication goes through a required `FileSystem.renameFile()` for same-filesystem atomicity (`:1047`), and "JSONL session forks and torn-tail repairs publish atomically, avoiding partially written or corrupted sessions after interrupted writes" (`:1091`). The v4 session model adds "durable operation records, global facts, shared sequence numbers, and tree-scoped lane views" (`:1044`). Alongside it: a vendor-neutral **telemetry** package with "composed span starters" and typed AI-request schemas (`:1072`), and a `chord/telemetry-sqlite` entry point for users who want a real database. So: **file-per-record JSONL by default, SQLite optional.** That is precisely the "their equivalent of a trade log without a heavy database" the brief asks about.
- **Staying simple as features accumulate — fully answered in this shard, and it is the shard's main contribution.** Four mechanisms, all in prose and config: (1) the core/extension split (`CONTRIBUTING.md:7-9`); (2) the auto-close contribution gate that forces a maintainer to *reopen* a well-written issue before it is worked (`CONTRIBUTING.md:25-48`); (3) the "name what you refuse to build" line in the README (`README.md:19`); (4) the `check` gate that runs *no* tests but checks pinning, import hygiene, entry graphs, the install lock, types and a browser smoke (`package.json:21`) — a gate shaped around *drift* rather than around features. The pattern across all four: **pi's defence against feature creep is social and documentary, not architectural.** That is worth stating plainly to August's owner, who may expect a technical answer.

## 4. Non-obvious decisions and gotchas

Things a reader would get wrong:

1. **pi has no sandbox and no permission system, on purpose.** `README.md:90` and `SECURITY.md:50`. The security model is "the local user account is the boundary" (`SECURITY.md:10-16`), and the repo's answer to a user who wants more is *containerisation*, not a feature. Prompt injection is declared unfixable and out of scope (`SECURITY.md:22-24`, `:56`); "malicious model output" is out of scope (`:60`).
2. **`pi-test.sh` and `test.sh` are not two ways to run the same thing.** `test.sh` runs the *test suite* in a hermetic sandbox; `pi-test.sh` runs the *agent* from source in your real environment (and can strip your keys with `--no-env`). Confusing them is the natural mistake.
3. **The `check` gate mutates the tree.** `package.json:21` starts with `biome-check.mjs --write` — a lint gate that also *formats*. It also **does not run tests** (`AGENTS.md:32`). "The gate passed" therefore means "types, pins, imports, entry graphs, install lock and a browser smoke are fine", not "it works".
4. **Two tsconfig `paths` maps that point in opposite directions.** Root `tsconfig.json` maps every workspace package to its **source**; `packages/coding-agent/tsconfig.build.json` maps them to their **`dist/*.d.ts`**. Tests therefore see live source, a published build sees published shapes. Copying one of these maps into a new project without knowing which direction it points is a silent-wrong-answer bug.
5. **`erasableSyntaxOnly: true` in `tsconfig.base.json` is a hard architectural constraint**, not a style preference: no `enum`, no parameter properties, no `namespace`, no `import =` anywhere in `packages/*/src` (`AGENTS.md:24`). The repo runs under Node's type-stripping mode.
6. **The credential list is duplicated in three places** — `packages/ai/src/env-api-keys.ts` (canonical, named in `pi-test.sh:23`), `pi-test.sh:24-58`, and `pi-test.ps1:26-44`. Two of the three are hand-maintained copies in two languages.
7. **The Nix wrapper puts the user's `node` ahead of Pi's own** (`nix/package.nix:120-139`) but Pi's `fd`/`ripgrep`/clipboard ahead of the user's. Both orderings are deliberate and commented; the reason is that a bash tool started by the agent must find the user's `npm`.
8. **The model-catalog pin hashes a *projection* of the catalogue, not the catalogue.** `?types=chat,image,classifier` (`nix/package.nix:28`) — so a change to image models only changes the pin if it changes the typed representation. The `revision` is simultaneously the URL segment and the sha256.
9. **`.gitignore` contains model data that exists locally.** `packages/ai/src/providers/data/` is ignored; `AGENTS.md:28` warns both never to stage it *and* never to look for it in git history. An agent that "checks the repo for the model list" will find nothing.
10. **The `pi` npm package ships its `docs/`, `examples/`, `schemas/` and `CHANGELOG.md`** (`packages/coding-agent/package.json:23-30`) — the documentation is part of the artefact, and the installer's lock root has exactly one dependency.
11. **`pi-test.bat` hardcodes `powershell.exe`** (Windows PowerShell 5.1) with `-ExecutionPolicy Bypass`, not `pwsh` — even though the project also ships PowerShell 7-compatible detection logic elsewhere (`CHANGELOG.md` 1.4.0: "Windows shell detection missing PowerShell outside `PATH` … pi now checks `%ProgramFiles%\PowerShell\7`"). The shim is behind the product.
12. **The changelog's older issue links point at a different repository** (`badlogic/pi-mono`) than the current one (`earendil-works/pi`) — the project was renamed mid-life, and roughly half the 6,367 lines' links resolve to the old org.
13. **`.npmrc`'s `min-release-age=2`** is an npm feature that blocks resolving a package published in the last 2 days. It is a registry-compromise defence, and it is one line.

## 5. Weak spots

Fair reading — these are references, not saints.

1. **The linter is configured to permit exactly what the prose forbids.** `AGENTS.md:18` says "No `any` unless absolutely necessary", but `biome.json:9` sets `noExplicitAny: "off"` (and `noNonNullAssertion: "off"` at `:7`). The written rule has no mechanical backing, so it holds only where a reviewer remembers it. The same gap exists for "no inline imports" (`AGENTS.md:21`) — nothing enforces it.
2. **The credential list is triplicated.** `packages/ai/src/env-api-keys.ts` is canonical, but `pi-test.sh` and `pi-test.ps1` each keep a hand-copied 36-entry list in a different language. A new provider key added to the canonical file will silently remain *present* in the `--no-env` runs of whichever script was not updated — the failure mode is a test that spends real tokens.
3. **`test.sh`'s environment allowlist is hand-built.** Twenty-odd variables, each with a comment, plus a separate Windows-inherited set (`test.sh:66-70`) and a separate proxy pass-through (`test.sh:72-75`). Any new environment variable that changes behaviour must be added in the right place, and omission fails silently rather than loudly.
4. **`npm run check` writes to the tree** (`biome-check.mjs --write`) and does not run tests. A gate that both mutates and verifies can report "clean" about a file it just changed, and a green `check` says nothing about behaviour.
5. **The 6,367-line changelog is the only design-history artefact and is not navigable.** It mixes a breaking API rename with a typo fix under identical headings, and its two repository identities mean half the issue links no longer point where a reader expects. For a project whose entire thesis is "the core is minimal", the record of *why* is 650 KB of append-only prose with no index.
6. **The Nix darwin-x64 pin is a declared dead end.** `flake.nix:5-9` pins `nixpkgs-26.05-darwin` because unstable dropped Intel macOS — a branch that will be removed, with no removal plan, and a second nixpkgs input that must be maintained forever.
7. **Version numbers are duplicated across three manifests and kept in sync by a script.** Root `package.json` says `0.0.3`; the published package says `1.4.0`; `install-lock/package.json` says `1.4.0`. `scripts/sync-versions.js` is the only thing holding them together — a script, not a type or a schema.
8. **`pi-test.bat` targets Windows PowerShell 5.1**, which is end-of-life-adjacent, while the product itself detects and prefers PowerShell 7.
9. **The `check` script's ordering is a `cd` chain** (`package.json:20-21`: eleven `cd packages/X && npm run build` steps) rather than a topological build — correct today because the chain is hand-ordered, and it will break the first time a package is inserted in the wrong place.
