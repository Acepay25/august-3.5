# deepseek-harness :: dsh-agent-skills

**Files in shard:** 40 (read: 40, skipped with reason: 0)
**What this shard covers:** the reference repository's **agent-skill corpus** — 19 skill directories under `.agents/skills/`, each a `SKILL.md` with YAML frontmatter (`name`, `description`) plus optional `references/` and `templates/` subtrees, and one non-Markdown asset (a Python GIF encoder + its unittest). These are *prose-as-executable-policy* artifacts: they are what a Claude-style agent reads before doing documentation, code review, performance work, error handling, i18n, or UI work in this repo. This is the richest part of the repo for August Trading, because the skills encode a **rule-lifecycle** (create → keep → archive → reject → retire), a **verification culture** (negative controls, quiescent teardown, "delete what you could not reproduce"), and a **feature-accumulation defence** (doc budgets, "complete effect path", archive-don't-delete). None of the runtime harness code lives here.

### Tier 1 — load-bearing source: full entry

### `.agents/skills/record-browser-gif/scripts/encode_gif.py`
- **Purpose:** encode a Playwright WebM video *or* an ordered directory of browser screenshots into a **verified** GIF, and print a JSON summary of what was actually encoded.
- **Key abstractions:**
  - `fail(message) -> NoReturn` — the single error exit; raises `SystemExit(f"error: {message}")` so every failure reads `error: …` on stderr (`:19`).
  - Argument validators `positive_float` / `positive_int` / `nonnegative_float` — each rejects `nan`/`inf` explicitly via `math.isfinite`, and `nonnegative_float` exists *only* so `--start` can be `0` while `--end` cannot (`:25-58`).
  - `parse_durations(value, frame_count)` — one duration applies to all frames; a list must match the frame count exactly, else fail (`:61`).
  - `require_binary(name)` — resolves `ffmpeg`/`ffprobe` via `shutil.which` and fails if absent; it **never installs** (`:72`).
  - `run_json(cmd)` / `probe_stream(ffprobe, path)` / `video_duration(ffprobe, path)` — `ffprobe` wrappers; `run_json` also asserts the parsed value is a JSON *object* (`:81-121`).
  - `stream_int(stream, key, path)` — a positive-int reader that fails loudly rather than returning `0` (`:124`).
  - `ffconcat_quote(path)` / `write_concat_manifest(path, frames, durations)` — writes an `ffconcat` manifest that materialises the last frame's hold by appending the final file a second time (`:134-145`).
  - `build_parser()` — the whole CLI contract (`:148`): `input`, `output`, `--pattern`, `--durations`, `--start`, `--end`, `--speed`, `--final-hold`, `--fps` (default 10), `--max-width` (default 1200), `--colors` (default 128, allowed 4–256), `--max-bytes` (default `DEFAULT_MAX_BYTES = 5 MiB`), `--force`.
  - `main()` — validate → encode → **re-probe the output and verify it** → print JSON (`:193`).
- **Data flow:** resolve `input`/`output` → check existence, `.gif` suffix, overwrite intent, colour/fps bounds → resolve `ffmpeg`/`ffprobe` → branch on video vs frame-directory → build an `ffmpeg -vf` filter graph (`trim`+`setpts`+`fps`+`scale`+`tpad` for video; `concat` demuxer for frames; then `palettegen`/`paletteuse` with bayer dithering) → run ffmpeg → **probe the encoded GIF** → assert duration within tolerance, width ≤ `--max-width`, `nb_frames ≥ 2` (i.e. it is genuinely animated), byte size ≤ `--max-bytes` → print the summary.
- **Non-obvious design decisions:**
  - **Container duration, not stream duration.** `video_duration()` reads `format=duration` because *Playwright WebM omits stream duration* (`:114-121`). A reader would normally use the stream's duration; this is the one place the author was burned by the container.
  - **The output is verified, not assumed.** After encoding, the file is re-probed and four invariants are asserted (duration, width, animation, size) before success is reported (`:300-315`). The tolerance is `max(0.2, 2 / fps)` seconds — generous enough for GIF frame quantisation, tight enough to catch a wrong trim (`:306`).
  - **`-n` unless `--force`.** ffmpeg is invoked with `-n` (never overwrite) by default and `-y` only when the user passed `--force` (`:288-291`). A failed run therefore cannot clobber a prior artifact.
  - **Palette is generated with `stats_mode=full`** over the whole clip, not per-frame, so a colour ramp does not flicker between frames (`:273`).
  - **`tpad=stop_mode=clone`** implements the final hold by cloning the last frame, and `expected_duration = (end-start)/speed + final_hold` — the *expected* value is computed up front so the post-hoc probe can compare against it (`:231`, `:264`).
  - **Mode-inappropriate flags are rejected.** `--pattern`/`--durations` require a directory; `--start`/`--end`/`--speed`/`--final-hold` require a video file (`:217-253`). The script refuses to guess which mode the caller meant.
  - **Output must not equal an input** — neither the video (`:220`) nor one of the frames (`:253`).
  - **Frame dimensions must be identical** across the storyboard, checked by probing *every* frame and comparing the set of `(width, height)` pairs (`:245-252`).
  - **The final frame's hold is written twice into the manifest** (`write_concat_manifest` appends `frames[-1]` again) because the concat demuxer treats the last file's duration specially — a classic ffmpeg gotcha.
- **Edge cases & failure handling:** every failure path calls `fail()` with a user-correctable message; `nan`/`inf` arguments are rejected before they reach ffmpeg; empty or empty-part `--durations` is rejected; fewer than two frames is rejected; a selection shorter than two output frames is rejected *before* encoding (`:229`); a missing binary is reported rather than installed; `ffmpeg` non-zero exit is reported with its return code; the temp dir (`tempfile.TemporaryDirectory`) holds the manifest and is removed even on failure.
- **Surprising:** this is the only executable source in the shard, and it is *not* covered by the repo's CI — the skill itself says "These local media tests do not run in repository CI" (`record-browser-gif/SKILL.md`). It is also the only place in the shard with a hard byte budget, and that budget (5 MiB) is *lower* than GitHub's 10 MB attach limit the skill text cites, i.e. the tool is stricter than the platform it feeds.

## 2. Ideas worth stealing

> Convergence labels are assessed from this repo only; the lead must cross-check `pi` and `hermes-agent` before calling anything CONVERGENT.

1. **A skill is a frontmatter record whose `description` is a retrieval query, not a title.** Every skill's description is "Use when …, including …, to …" — e.g. `dsh-ci-test-reliability/SKILL.md:3` ("Use when adding or changing tests with those risks, investigating flaky CI, or reviewing test isolation"). That is a *when-to-load-this* sentence an agent can match against a task. August Trading has a 300-line `AGENTS.md` and `docs/plan/`; it has no per-task, retrieval-shaped rule cards. **UNIQUE (mechanism); the *idea* of scoped rule cards is likely CONVERGENT.**
2. **Every note/rule gets a supersession audit when a new one is added.** `dsh-archive-agent-notes/SKILL.md:16` — "Every new Agent Note triggers a scoped audit of active notes covering the same decision, mechanism, or rejected alternative… archive qualifying implemented triplets in the same PR". This is the mechanism that keeps a decision corpus from becoming a graveyard. **UNIQUE.**
3. **Rejected decisions are a first-class, *retained* artifact — kept only when the losing idea is still tempting.** `dsh-archive-agent-notes/SKILL.md:26` ("Rejected — keep only as a guardrail") with the calibration "keep folding the compaction package split — 426 words: the temptation to merge the packages remains meaningful". August's `docs/plan/open-items.md` has no rejected state at all. **UNIQUE.**
4. **"Do not archive toward a quota" + calibration examples instead of a word threshold.** `dsh-archive-agent-notes/SKILL.md:29` and the 533-deleted vs 596-kept examples. The rule is *semantic*, the examples are the calibration. **UNIQUE.**
5. **The "complete effect path" test for any declared feature.** `dsh-find-simplifications/SKILL.md:22` — trace producer → transformations → provider/endpoint support → observable result; "A field copied everywhere may still have no setter, no reader, or only implementations that reject it." Directly targets August's `toolForge` (user/model-authored tools) and any flag threaded through `Message`/`WireAuditEntry`. **UNIQUE.**
6. **A machine-checked word budget per standing document, with a fixed escalation order.** `dsh-doc/SKILL.md:97` — `scripts/doc-budgets.manifest.json` compares against ceilings; the policy is *relocate → condense → raise*, and "ceilings are guardrails, not reduction targets: at or below target, retain at least 5% headroom". This is a ready-made answer to August's own AGENTS.md bloat. **UNIQUE.**
7. **"Delete what you could not reproduce."** `dsh-doc/SKILL.md:45` — the only admissible evidence for an operation claim is having run it; claims that need unavailable keys must *name a verification owner* instead of asserting the behaviour. Applies verbatim to every `npm run …` claim in August's AGENTS.md. **UNIQUE (as a policy statement).**
8. **A `kind` → exactly-one-template registry for documents, where adding a kind also requires adding a check.** `dsh-doc/SKILL.md:51` + `metadata-links-i18n.md:34-46` (the mechanical derivation order). August's `docs/plan/` and `docs/analysis/` have no such registry, so docs drift between shapes. **UNIQUE.**
9. **The flake-masking blacklist.** `dsh-ci-test-reliability/SKILL.md:102-112` — "increasing a timeout without identifying the awaited state; adding retries; making all files serial; swallowing an error or unhandled rejection; weakening an assertion; normalizing away unstable behavior; adding a sleep before cleanup or assertion" are **not** root-cause fixes, with one documented exception (documented transient external-provider tests). This is the guardrail August needs for `render-probe`/`boot-probe`/`installer-smoke` flake. **UNIQUE (as an explicit list).**
10. **Host-resource isolation is a separate axis from process isolation.** `dsh-ci-test-reliability/SKILL.md:27` — ports, predictable paths, sockets, DBs, inherited children survive Vitest worker isolation. August's `dev` server on port 3000, the Electron installer smoke and the Capacitor WebView origin quota are all in this class. **CONVERGENT (well-known practice; this repo states it sharply).**
11. **Windows is a first-class test lane with named, specific divergences.** `dsh-ci-test-reliability/SKILL.md:66-72` — env var names are case-insensitive; file handles are released asynchronously so a rename needs a bounded retry; NTFS's 100-nanosecond mtime ticks make "restore mtime and assert still valid" a different assertion on each OS. August ships a Windows Electron installer. **UNIQUE (as a written rule set).**
12. **Every changed acceptance rule needs a negative control: a deliberately invalid case that fails through the real runner.** `dsh-code-review/SKILL.md:54`. **CONVERGENT (test orthodoxy), but the "for each changed acceptance rule" framing is sharper than most.**
13. **"Catching limits exception propagation, not mutations."** `dsh-error-handling/SKILL.md:18` — only the owner of the affected state may declare safe continuation; "Logging alone is not recovery." This is the sentence August's `MemoryFilesService.getNotebookWriteFailure()` pattern embodies, stated as doctrine. **UNIQUE (as prose).**
14. **Feedback-surface selection by *message lifetime*.** `dsh-client-ui-ux/SKILL.md:36-38` — a transient outcome uses an app-wide Toast hosted by something that outlives the reporting surface (a toast rendered by the panel unmounts with the panel); a failed operation keeps its data visible; in-place notices are for surface-tied states. **UNIQUE.**
15. **A hard mobile acceptance width (390 CSS px) plus a decision order that forbids hiding conflicts.** `dsh-responsive-ui/SKILL.md:10-16`. August has a Capacitor mobile shell and a `render-probe` that Tab-focuses fields but never resizes. **UNIQUE.**
16. **A visual-evidence artifact is mandatory for GUI changes, and it is bound to one commit.** `record-browser-gif/SKILL.md:12` + `:134` — record from the PR's real tree with a real model round; immediately before publishing, re-read the live head and **stop and re-record if it moved**. This is a *proof-of-revision* mechanism: the artifact is tied to a SHA, and the publish step re-verifies the binding. **UNIQUE.**
17. **Verify the artifact, not the command.** `encode_gif.py:300-315` — after encoding, re-probe the output and assert duration, width, animation (≥2 frames) and byte size before reporting success. Plus "a failed deletion keeps its row" style guarantees. **UNIQUE.**
18. **The "complete proposition" prose rule.** `dsh-prose-standard/SKILL.md:28` — preserve actor/action, condition/timing/ordering, modality, negative guarantee, ownership, side effect and failure mode; "A smaller word count alone is not an improvement." **CONVERGENT (writing rules are universal), but this specific clause list is a good checklist.**
19. **A "reasoning-transcript leakage" purge with an auditable probe set.** `dsh-trim-cot-leakage/SKILL.md:12` + `recall-batteries.md:11` — the one test ("could a reader at HEAD resolve every reference?") plus grep batteries that must be calibrated against a known positive *and* a near-miss negative before a corpus result is trusted. **UNIQUE.**
20. **The four overcorrection traps** (`references/examples.md:233`) — flipping an obligation into an endorsement; promoting a hypothetical to a shipped feature; deleting a true fact with the transcript; dropping "measured" while keeping the number. Every AI-assisted cleanup process needs this. **CONVERGENT-ish, well articulated here.**
21. **Evidence selection by diff scope, and "do not repeat a passing check".** `dsh-pre-push-checks/SKILL.md:22`, `:29`, `:43` — one `change-scope` command names the dirty layers; each layer gets the narrowest check that would fail for the regression; a passing check is not re-run because a commit happened. August has 10 named gates and no scope→gate mapping. **UNIQUE.**
22. **A bilingual sidecar with per-section hashes.** `metadata-links-i18n.md:74` — a `*.i18n.yaml` records a hash pair per heading section so two people editing different sections merge cleanly, and `--write` refuses to run bare so a bulk re-record is always explicit. The *pattern* (a machine-checked "these two are equivalent" record) transfers to any twin-source pair. **UNIQUE.**
23. **A mandatory proposal skeleton for any non-trivial change.** `dsh-find-simplifications/SKILL.md:59` — `Problem / Proposal / Alternatives considered / Acceptance criteria / Risks`, plus concrete consumer evidence, the removed maintenance cost, the capability given up, and observable acceptance conditions. **CONVERGENT (ADR orthodoxy).**
24. **"Never route handling by parsing messages."** `dsh-error-handling/SKILL.md:14` — typed failures with stable discriminants; machine identity separated from display text. **CONVERGENT, and exactly August's `utils/runStatus.ts` discipline.**

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work — not in this shard**, *except* one very relevant archived decision: DSH deliberately traded calendar recurrence and **missed-occurrence replay** for a *bounded fixed-rate schedule*, deleting a parser, an evaluator, a cross-record gate, durable variants and backlog states (`dsh-find-simplifications/references/historical-patterns.md:19`). August's `services/automation/` cron + run-history + streak-breaker is exactly this machinery; the reference suggests a deliberately simpler alternative is defensible if the capability given up is *stated*.
- **Human-in-the-loop approval:** the shard has no approval-flow skill, but it encodes the *audit-trail* pattern August needs — a decision artifact bound to a **commit SHA**, re-verified against the live head immediately before publication (`record-browser-gif/SKILL.md:134`), plus "Required evidence exists" (`dsh-code-review/SKILL.md:36`) and "Negative controls" (`:54`). For August's skill-draft approval (the `approveSkillDraft` → file-write path) the transferable rule is: *the approval record must name the artifact and its revision, and the writer must re-verify the binding before mutating.*
- **Post-mortem / reflection loops:** this is the shard's richest answer. DSH's Agent Notes are a four-status corpus (`proposed` / `implemented` / `rejected` / `archived`) with a **retention rule keyed to future decision value, not size or age** (`dsh-archive-agent-notes/SKILL.md:22-27`), **rejected notes kept as guardrails** against re-litigating a tempting mistake (`:26`), a **supersession audit triggered by every new note** (`:16`), and a **frozen, hash-sealed archive** (`:57-60`). Measured corpus size here: **3,809 Agent-Note files, 2,774 of them archived.** The gates that stop bad rules accumulating are: status semantics, the "no quota" rule, the supersession audit, and the seal.
- **Multi-agent:** DSH has **no debate engine**. Multi-agent appears in exactly two places: *divide independent domains among subagents* for a broad survey (`dsh-find-simplifications/SKILL.md:16`), and *the orchestrator does not do the work itself* — it spawns a subagent whose entire working set is a pre-generated briefing (`dsh-translate-docs/SKILL.md:20`). Debate is replaced by independent-domain surveys plus an aggregator; the value of parallel agents is **breadth over independent domains**, not adversarial adjudication. This is a direct answer to "where does debate add value" — for DSH, nowhere.
- **Structured logs the model can query:** not implemented in this shard, but the *pattern* is visible in the documentation machinery the shard governs — **generated catalogs** (config catalog, tool catalog, bundle catalog) published from a manifest rather than hand-maintained, and a **manifest as an explicit allowlist** (`website-sync.md:31`). August's equivalent of a queryable structured log would be a generated catalog owned by a generator, not a hand-written list.
- **Staying simple as features accumulate:** the answers are (a) the doc-budget manifest with a relocate→condense→raise escalation (`dsh-doc/SKILL.md:97`); (b) "delete implemented notes that are small or mechanical" rather than archive them (`dsh-archive-agent-notes/SKILL.md:22`); (c) the complete-effect-path test (`dsh-find-simplifications/SKILL.md:22`); (d) "Do not archive toward a quota" (`:29`); (e) one narrow skill per job, each with a retrieval-shaped description — 19 skills in this repo, each with a single `name` + `description` and no overlap by construction. The meta-cost: the repo now needs skills *to manage its skills* (`dsh-archive-agent-notes`, `dsh-find-simplifications`, `dsh-trim-cot-leakage`, `dsh-prose-standard`, `dsh-doc` all audit the others).

## 4. Non-obvious decisions and gotchas

1. **`.agents/skills/agent-experience/SKILL.md` is a git symlink, not a file.** `git ls-files -s` shows mode `120000`; its "content" is the relative target path. A reader doing `Get-Content` gets the path, not the skill. Anyone auditing skill files mechanically will double-count or miss it.
2. **The skill `description` is a trigger, and the skill body is explicitly "guidance, not a complete checklist".** `dsh-code-review/SKILL.md:8`, `dsh-prose-standard/references/examples.md:19`. The skills are *advisory scaffolds*, not gates — the enforcement lives in the `pnpm run verify-*` scripts the skills name. **Stealing the prose without the gates buys aspirations, not behaviour.**
3. **Every skill names its "owning rules" and refuses to duplicate them.** `dsh-client-ui-ux/SKILL.md:11` says styling ownership "lives in docs/web-styling.md and the ui-primitives catalog — this skill adds judgment on top of those rules, not a second copy of them." The corpus is explicitly de-duplicated by reference; that is why it stays readable.
4. **`dsh-doc`'s "Summary says what the subject does" rule forbids identity narration.** "The seam registers `ctx.x` and appends `x/event` records" is banned; "you can save a note per message and it survives restarts" is the wanted shape (`dsh-doc/SKILL.md:79`). This is unusually strict and directly applicable to August's README/comment prose.
5. **The doc standard mandates a "Dev Note" section — the one sanctioned slop zone — while simultaneously forbidding it from becoming a queue.** `dsh-doc/SKILL.md:83` vs `structure-hierarchy.md` "Dev Note ownership". A blank Dev Note must say `None.` This is the single most transferable structural idea *and* the single biggest trap.
6. **`dsh-archive-agent-notes` forbids archiving *proposed* notes and forbids deleting a note whose rationale still owns or constrains anything.** The criterion is "Classify the decision, not the mechanics of its implementation: a mechanical rename or type extraction can still record lasting naming, compatibility, or ownership rules" (`:24`). Size is explicitly not the test.
7. **`dsh-ci-test-reliability` says a `describe`/case timeout *overrides* the runner's `--testTimeout`**, so a value below the lane budget lowers what CI already granted — and the same literal reads as a widening on a host with a smaller default (`:71`). Subtle, and it invalidates the usual "raise the timeout" reflex.
8. **`dsh-trim-cot-leakage` bans `\bthis PR\b` etc. in durable prose but explicitly *keeps* issue references, merged-PR citations inside notes, suppression justifications, measured bounds and runtime old/new wording.** The keep-list is as long as the ban-list; an unaided purge deletes the keeps (the examples document exactly that failure).
9. **`record-browser-gif` forbids splicing frames from separate runs and requires re-reading the live PR head before attaching.** The binding is `git rev-parse HEAD` at record time versus the head at publish time — the artifact proves *a commit*, and the publish step re-proves it still is that commit.
10. **The encoder rejects invalid arguments *before* writing, and the test asserts the output file does not exist** (`test_encode_gif.py:61`). Failure is defined by observable state, not by exit code alone.
11. **`encode_gif.py` reads the *container* duration, not the stream duration, because Playwright WebM omits the latter** (`:114-121`). A reader copying this code to any other container must re-check.
12. **`dsh-pre-push-checks` explains that a missing `pull_request` workflow run usually means the PR is `CONFLICTING`** — GitHub creates no runs for a conflicting PR — and explicitly warns against empty commits / `--allow-empty` / draft bounces as the "fix" (`:141-149`).

## 5. Weak spots

1. **Almost everything here is prose, not enforcement.** The skills say "run `pnpm run verify-…`", but the skills themselves are not executable and most rules ("balanced" prose, "future decision value", "a short review with one substantiated blocker") cannot be machine-checked at all. The reference compensates with a large bespoke `verify-*` script surface — which is itself a maintenance burden and a place for new drift.
2. **Heavy, brittle cross-referencing.** Every skill points at `../../notes/README.md`, `../../../packages/…/README.md`, `docs/defensive-patterns/general.md` and sibling skills by *relative path*. Moving or renaming any of those silently breaks the skill corpus; nothing in this shard validates the link graph (the doc gates only cover `docs/`).
3. **The skill corpus now needs skills to manage the skills.** `dsh-archive-agent-notes`, `dsh-find-simplifications`, `dsh-trim-cot-leakage`, `dsh-prose-standard` and `dsh-doc` all audit each other's output, and `dsh-doc` explicitly ships a *slop checklist* to hunt duplication produced by the others. The corpus is 3,809 note files with 2,774 archived — the archive discipline works, but the surface area keeps growing.
4. **The visual-evidence path has no CI protection.** `encode_gif.py` is the only executable source in the shard, and the skill says outright that its media tests "do not run in repository CI". The artifact-producing tool is the least-guarded part of the system.
5. **Some rules are unfalsifiable in a way that hides their cost.** "Balanced" prose, "future decision value", "readability" — an auditor can neither automate nor falsify them, so the review cost lands on humans while the "verified" label stays. And the `record-browser-gif` policy ("real server, real API key, real model rounds") is a heavy ritual for a two-pixel UI tweak.
6. **`dsh-doc`'s own structure creates a dumping ground.** "Dev Note is the only slop zone" is immediately followed by "must not become a second writable queue" — the rule is self-contradicting in practice, and every page must end with a `Dev Note` even when there is none (`None.`).
