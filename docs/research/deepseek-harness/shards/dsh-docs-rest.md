# deepseek-harness :: dsh-docs-rest

**Files in shard:** 69 (read: 58, skipped with reason: 11)
**What this shard covers:** The entire `docs/` tree of the DeepSeek Harness — the curated, load-bearing contract documents (agent turn/step lifecycle, tool execution pipeline, capability seams, session log and persistence model, API gateway, testing policy, styling standard, glossary) and the large machine-generated catalogues (plugin config, model-facing tool schemas, module peer-dependency graph, session persistence event catalogue + schema fingerprints, npm dependency inventory), each paired with a reviewed Chinese mirror and a per-file bilingual-pairing hash record. There is **no source code** in this shard. That is the point: everything here is the harness's *stated* contract, and most of the stealable design decisions live in the prose, the table rows and the Mermaid diagrams rather than in the implementation.

## 1. File-by-file

### Tier 1 — load-bearing documents: full entry

#### `docs/agent-lifecycle.md`
- **Purpose:** The visual companion to `architecture.md#turn-flow`: one Mermaid sequence diagram of exactly what happens in a turn, who owns it, and where it ends.
- **Key abstractions:** the turn/step vocabulary — `turn/start` … `step/start` … `step/end` … `turn/end`; the four waterfalls (`agent/pre-step`, `agent/request`, `llm/stream`, `tools/*`); the durable-vs-live split (`session/event` = replayable facts, `agent/*` = live coordination).
- **Data flow:** user input → agent inbox → driver claims "pending next-step input plus one queued prompt" → `system-prompt/assemble` → `agent/pre-step` (authoritative accept/reject) → `agent/request` → `prepareCall(config, signal)` → commit `system/message` + `user/message` → freeze the request from the log → stream → `assistant/message` **or** `assistant/attempt` → tool loop → `step/end` → optional next step → `agent/turn-stopping` → `turn/end`.
- **Non-obvious design decisions:**
  - The `assistant/message` event records **every successful provider call, including content-less and `max-tokens` finishes**, and embeds the exact compact timed stream. Empty content stays out of *derived history*, but the call is still durable (`docs/agent-lifecycle.md:83`). A turn that produced nothing is still evidence.
  - A failed/retried/cancelled/stream-error attempt that reaches settlement without a surface message records `assistant/attempt` — durable, but it does **not** add model history (`:83`).
  - `agent/pre-step` is **authoritative**: a rejected proposed step, an empty first batch, or a pre-step failure means the claimed batch stays removed and the open turn spends **no step at all** (`:85` region). A turn can exist with zero steps.
  - Retries happen *inside the open step*: they re-prepare the call and reconcile the same rendered assembly **without repeating pre-step or user admission** (`:87` region). Re-admitting the user message on retry is a bug, not a feature.
  - Cancellation during either async phase (assembly or `prepareCall`) commits **neither** the system prompt nor the users (`:52` region) — partial admission is explicitly impossible.
  - `dsh-compaction-basic` uses `agent/pre-step` for *pressure* before request derivation, and `agent/request-error` **only** for a canonical context overflow (`:85`). Compaction retries only when pruning or summarization advances the surface replacement generation; otherwise the original request error stays authoritative.
- **Edge cases & failure handling:** "a hard process loss before settlement leaves no durable attempt stream" (`:85` region) — the doc names this gap rather than papering over it. Live `agent/assistant-stream` chunk frames are transient; replay reads either durable settlement.
- **Surprising:** the doc ends with a *maintenance mode* line — "curated Mermaid sequence; exact event signatures live in the generated Cordis catalog" (`:91`). The prose deliberately does not restate signatures; it points at the generator.
- **Why it matters for August Trading:** this is the clearest statement anywhere in the shard of "**model-visible means logged**" applied at the turn level. A failed provider call, an empty answer and a `max_tokens` stop are three *different* durable facts, and the app can only reconstruct the model's context from them.

#### `docs/tool-execution-pipeline.md`
- **Purpose:** One Mermaid flowchart of where policy, hooks, sandboxing, filesystem guards, result rewriting, final-outcome observation and UI rendering run — explicitly "without changing the loop" (`:6`).
- **Key abstractions:** the ordering `tools/pre-execute` (waterfall) → **monotonic guards** → `ctx.approval` → `tools/execute` (around dispatch) → tool body → `fs/write-intent`/`fs/edit-intent` gate → tool-owned events → `ToolDefinition.projectContent` → `tools/post-execute` (waterfall) → registry outer normalization → `ToolDefinition.finalizeContent` → `tools/result` (synchronous notification) → durable `tool/result` event → `additionalContexts` FIFO.
- **Data flow:** the model's tool-call block becomes a `tool/call` session event *before* execution; the UI pending card is drawn from `presentCall(args)`; the completed card from `presentResult(args, result)`.
- **Non-obvious design decisions:**
  - **Monotonic guards** sit *after* the pre-execute waterfall and can only deny or abstain — "identity protected" (`:29` region). A guard can never transform a call.
  - `ctx.approval` is a **one-shot prompt**; "absent or unanswerable: deny" (`:27` region) — the approval seam fails **closed**.
  - The registry **losslessly snapshots** the candidate result and normalizes a snapshot failure into `isError` *before* the visible definition's `finalizeContent` callback enforces its synchronous content-only invariant (`:63`).
  - `tools/result` is a *synchronous notification* observing a frozen, lossless-JSON outcome (`:52` region) — the authoritative result is immutable by the time anyone sees it.
  - `additionalContexts` are injected as a `user/message` **after** the recorded tool results (`:50` region), preserving call/result adjacency.
  - PTC mode routes the reserved `run_code` transport and its serialized sub-calls through the same pipeline; sub-calls carry the parent token, log `tool/ptc-dispatch`, return denials as binding rejections, and **omit** `additionalContexts` so adjacency survives (`:66` region).
- **Edge cases & failure handling:** every dotted edge in the diagram is an explicit throw path, and all of them funnel into `normalized` — a throwing pre/post waterfall, a throwing guard, a throwing wrapper, a throwing `projectContent` — so a policy crash becomes an `isError` result rather than a broken turn.
- **Surprising:** "This lets hooks span tool families without coupling the tools to one policy service" (`:64` region) — the point of the waterfall design.
- **Why it matters for August Trading:** the ordering *approval → monotonic guard → execute → post* and the "throw becomes `isError`, never a lost turn" rule map directly onto a desk-tool pipeline.

#### `docs/architecture.md`
- **Purpose:** The ordered map a reader must have before touching `packages/` — composition, core packages, events, turn flow, session log, capability seams, and a "where does new behaviour go" table.
- **Key abstractions:** profile (named composition in `$DSH_HOME/profiles`) vs bundle (a distribution format for Cordis config rows); the three event domains (session events = durable, `agent/*` = live, capability events = policy); the core-package table mapping each package to its `ctx` key; the "extension point" table at `:144`.
- **Data flow:** a running `dsh` is a plugin tree composed at boot from ordered layers — profile bundles → `cordis.patch.yml` → home patch → `--patch` overlays. A patch targets a row **by id** and replaces its whole config, or inserts new rows (`:29` region). Any row printed by `dsh --profile web --dump-config` can be replaced by a patch.
- **Non-obvious design decisions:**
  - "**There is no privileged core to patch**" (`:11`) — every part, *including the model adapter, the tool registry, the session log and the agent loop itself*, is a plugin, so each is replaceable from configuration.
  - **"Model-visible means logged"** (`:124`): every model request must be reconstructable from the log; new model-visible inputs require session events; plugins that change existing message content must register *pure message projections*.
  - The projection seam is **mandatory**: a host reader "either requires this service during activation or fails explicitly when the registry or required key is absent" — contributors may keep `ctx.inject(['sessionProjections'], …)` but may not silently default a missing host value (`:130` region).
  - Session format generations are **immutable**: "committed generation paths are never renamed, replaced, or deleted"; a write-open encodes, verifies and *exclusively publishes* the final version-named successor beside the unchanged source (`:120` region).
  - "only agent-loop-published sessions persist" — forking at a turn boundary is `ctx.agents.create({ sessionId, seed, meta: { parentSession, seedLength } })` (`:152` region).
- **Edge cases & failure handling:** migration "inserts a missing interrupted `turn/end` only for the bounded released restart already sealed by a later `turn/start`" — an interrupted tail is otherwise the *handle consumer's* responsibility (`:120` region).
- **Surprising:** the "where new behaviour goes" table (`:144` onwards) is a *map*, not a guide: 21 rows, each naming one `ctx` key. It is the anti-feature-creep device.

#### `docs/glossary.md`
- **Purpose:** "Domain vocabulary for DeepSeek Harness uses one canonical term per concept" (`:3`) — the repo's own claim that ambiguity in the vocabulary is the first source of drift.
- **Key abstractions and the decisions each one makes:**
  - **seam** (`:9`) — a swappable capability with three roles: Service Definition (a Cordis `Service`, "never a TypeScript `interface`"), one or more Service Providers, one or more Consumers. "The seam is the complete capability, never one role; reserve the term for that meaning and name a constituent by its role, class, service, contract, or extension point."
  - **scope** (`:13`) — flat, two levels: global or owned by exactly one scope key. Scoped registrations **do not inherit down to subagents**; subtree behaviour is expressed with *lineage data* (`parentSession`, durable `delegationDepth`, runtime `subagentDepth`), never with scope structure. "shadowing" = most-specific-wins name resolution, the mechanism behind per-agent personas and per-agent tool variants.
  - **restriction** — `tools.restrict` filters the *global* tool set for one scope (composed by intersection); scope-local registrations merge after that filter. "A filtered-away global tool is absent from the prompt AND refuses execution, indistinguishably from a nonexistent one."
  - **setup window** (`:19`) — the creation slot where a creator composes an agent's scoped world: after scope and agent object exist, before the agent or session is published. "Setup registers; it never drives the agent."
  - **goal** (`:25`) — one durable completion objective attached to an existing session, with a revisioned `active`/`paused`/`blocked`/`complete` phase and a goal-round cap; `blocked` retains a **policy code and explanation**. "A goal is state, not a scheduler or a separate conversation; the session log remains its source of truth."
  - **goal activation** (`:27`) — process-local permission to admit another goal round, `armed` or `disarmed`; "deliberately absent from durable replay, so resume and fork require a later human-authorized resume mutation through `/goal` or the model tool before automatic work."
  - **human command** (`:31`) — a slash-prefixed instruction interpreted by a human-facing adapter through `ctx.commands`, "without becoming a model message". "Command output is UI state unless the handler separately mutates a durable domain."
  - **loop hierarchy** (`:35`) — turn (one drain of admitted input) → step (one model request + the tools it caused) → round (an outer policy iteration containing a turn) → exchange (consecutive turns from a turn whose first step admits human input until the next such turn; turns woken by notices stay in the preceding exchange).
  - **Ralph** (`:44`) — one foreground fresh-agent workflow run toward an **immutable objective**; "a model-facing tool policy composed from workflow and subagent primitives, not a same-session goal, agent-loop mode, scheduler, or generic workflow-script feature". A **Ralph handoff** (`:48`) is "the normalized bounded structured report passed from one continuing Ralph round to the next, containing status, summary, evidence, next steps, and blocker text. It supplements the shared workspace rather than replacing it as authority."
- **Surprising:** the glossary is written to *prevent* vocabulary drift, and it explicitly reserves "seam" so that it cannot be diluted.

#### `docs/testing.md`
- **Purpose:** The tier-by-tier testing policy that keeps a green suite meaningful.
- **Key abstractions:** six tiers — unit (`pnpm run test`), coverage gate (`test:coverage`), real-API e2e (`test:e2e`), owner-local expected output (`test:expected`), performance benchmarks (`test:bench`), snapshot (`test:snapshot`), web browser snapshot (`test:web`).
- **Non-obvious design decisions:**
  - **Per-file 100% coverage on `packages/*/*/src`** and the reframe: "An uncovered line is often dead code the gate flags for deletion, not a missing test to bolt on. Line coverage is necessary, never sufficient — it proves lines ran, not that the feature works as shipped." (`:10`)
  - A per-file 100% bar is *exempted* when the environment cannot support it — `packages/shell/pwsh-local/src` self-skips without a real `pwsh` and `vitest.config.ts` exempts the file, while CI runners ship `pwsh` and enforce the full bar (`:10`).
  - **"The with-key policy: inference is cheap here"** (`:23`) — "We are DeepSeek — do not ration real-API tests. A no-key test proves plumbing; only a with-key run proves the agent works against a real model." Highest value = smoke tests that boot a shipped `dsh` profile, send one prompt, and check the world; they catch the "green unit tests, broken product" class mocks cannot.
  - **"Prefer the real implementation over a mock"** (`:27`) — mock only the expensive/nondeterministic boundary; keep everything downstream real. A hand-rolled stand-in "proves the bridge moves bytes, not that the shipping tool behaves as asserted."
  - **"Verify the world, not the self-report"** (`:33`) — "an e2e assertion re-runs the command or re-reads the file externally; a keyword probe on the agent's own output lets a cheating agent pass."
  - **"Test the real entry path"** (`:35`) — product-visible plugins need a non-unit REAL-composition test through the Loader; and "a guard only guards if the regression fails it", with the proof protocol: introduce the regression, watch red, revert.
  - **"Test resolution: source plane only"** (`:39`) — bare workspace imports resolve to `src`, never through package `exports` to built `lib/`, because "stale artifacts there load a second copy of module singletons."
  - **"When a snapshot test is required"** (`:45`) — "Every non-trivial model-, protocol-, or human-visible change adds or updates a keyless recorded-session scenario in the same PR; package, e2e, mock-only, and rationale evidence does not replace the assembled transcript."
- **Edge cases & failure handling:** "A spec passing only alone has a test defect, not an unstable runner" (`:25`) — process isolation only; ports, predictable paths and inherited children are *not* isolated, so every acquired resource must be owned through teardown.
- **Surprising:** the repo's flagship test tier is a **recorded-session snapshot**: the highest recorded parent generation supplies both the user input and the model replay and then serves as the expected persisted result. Replay/record/refresh all select each parent/child role's highest generation.

#### `docs/session-format-status.md`
- **Purpose:** Distinguish the checkout *writer*, the *accepted compatibility baseline*, and the *latest published* Session format — three different numbers that people routinely conflate.
- **Key abstractions:** `latestFinalizedVersion: 4` (a finalized yaml block) and `latestReleasedVersion: 4 / evidenceTag: dsh-v0.2.0-rc.2` (a release yaml block); `SESSION_FORMAT_VERSION` in `packages/core/session/src/types.ts` as the only hand-maintained writer number.
- **Non-obvious design decisions:**
  - "A package version, codec export name, fixture filename, or projection-cache version is not the writer authority" (`:12` region).
  - "No separate released boolean is maintained" — release status is *derived* by comparing the writer constant with the verified release record (`:16` region).
  - **"An alpha, beta, or release-candidate product publication establishes released Session-format obligations. GitHub's prerelease flag does not make persisted user data disposable. A missing release record is not evidence of non-publication."** (`:24`)
  - "Never lower it on the development trunk" (`:44` region) and "do not advance this release record before publication" (`:42` region).
  - A keyless documentation-standard test checks record structure, bilingual equality, evidence-tag and writer-path consistency, and "that the documented release does not exceed the checkout writer" — "This keyless check does not query GitHub or prove that the record is up to date."
- **Surprising:** the doc has a "Dev Note: None." section — a deliberate slot so the record stays a *record*.

#### `docs/deepseek-llm-api-wire-extensions.md`
- **Purpose:** Every DeepSeek-Harness-specific HTTP header and additive JSON field the adapter sends, and — much more interestingly — a complete, reusable **at-least-once delivery protocol** with a durable watermark.
- **Key abstractions:** `DeepSeekLlmApiExtensionRegistry` (one provider per top-level extension name; empty/padded names, duplicates and collisions with the base request "fail before HTTP dispatch"); the `prepare()`/`accept()` two-phase body-extension transaction; `dsh_plugin_packages` and `dsh_session_log`.
- **Data flow (the `dsh_session_log` protocol):** the adapter serializes the complete base body (including the exact `messages`) *first*, then asks registered providers to prepare fields against that immutable body; prepared JSON values are detached from provider-owned state, merged as top-level siblings, and serialized into the same HTTP body. After HTTP 2xx, the adapter runs the prepared `accept()` transaction **before reading the SSE body**. The session-log field carries `afterSeq` / `throughSeq` / a contiguous `events` run, bounded by `maxBytes` (8 MiB default, UTF-8 counted including header and numeric fields).
- **Non-obvious design decisions:**
  - "Prepared JSON values are **detached from provider-owned state**" — the provider cannot mutate what it handed over.
  - A contributor whose preparation fails is **omitted from that request**, with only its first failure logged, while the other fields still go out; a field that collides with a base field **prevents the request**.
  - If the merged body fails to serialize, the adapter sends the **base body without any extension field**, "skips the acceptance transaction so contributors resend their state on a later request", and logs the omitted field names (`:33` region).
  - "**Acceptance records endpoint-level HTTP success; it does not assert that an SSE stream completed or that the endpoint persisted an extension.**" (`:39`)
  - The sender folds the greatest matching `throughSeq` for the *current session id and format generation* (`:154`), so "concurrent accepted requests cannot move the cursor backward and a watermark from another generation cannot authorize the current suffix."
  - "A resumed process rebuilds the cursor from the durable log. A fork ignores inherited watermarks that name another Session, and therefore uploads its own inherited prefix from sequence zero… before advancing under the child id." (`:154`–`:156`)
  - "**A crash after endpoint acceptance but before local persistence may resend an already accepted range; uncertainty produces duplicates, never a sequence gap.**" (`:156`) "There is no independent upload store or truncation path; `maxBytes` bounds each request's field instead." (`:156`)
  - `dsh_plugin_packages` is deduplicated on exact `(name, optional version)` pairs and sorted by name then version, "with a locale-independent text comparison and absent versions first"; "Receivers must accept absent versions, must not collapse the array by package name, and must not infer package activation from array order."
  - The `x-deepseek-harness-compact: 1` header marks a request whose purpose is `compaction` — the provider can tell a summarisation call from a normal one.
- **Edge cases & failure handling:** credential failure happens *before* anonymous-user-id resolution, "so an unauthorized request neither sends these headers nor creates the identity file."
- **Surprising:** "The base request remains usable without either the registry or a particular contribution; field absence means that contribution did not apply to that request" (`:160` region) — extensions are strictly additive and independently degradable.
- **Why it matters for August Trading:** this is the cleanest small implementation of **at-least-once delivery with a monotonic, durable, generation-scoped watermark** in the whole shard.

#### `docs/api-gateway.md`
- **Purpose:** Current-state reference for the Typert API Gateway: how business services declare unary and stream Remote methods, how the build generates Host/Client contracts, and how calls reuse the Connection RPC.
- **Key abstractions:** `@Remote` / `@RemoteScope` decorators; `TypertRemoteService` / `bindTypertRemote()`; `TypertLookupMap` (wire identity ↔ Host object); `TypertContextMap`; `RemoteStream<Out, In>`; the four-package split (`typert-protocol` / `typert-generator` / `typert-registry` / `api-gateway`) plus `api-remote-access` and `client-connection`.
- **Data flow:** build time — the Host `ts.Program` is the *only* seed for the generator, which emits `typert.host.js`, `typert.host.d.ts`, `typert.remote-client.js`, `typert.remote-client.d.ts` and a `.d.ts.map`; run time — `connection.rpc.call('/api', '<namespace>/<method>', { args }, signal)` → HTTP `POST /api/<ns>/<method>` → Connection trust check → Gateway resolves descriptor + live service from the *current* registry (never caches business objects) → validates `args` against the descriptor → resolves lookups/contexts → invokes.
- **Non-obvious design decisions:**
  - **"The Gateway requires the fields in `args` to match the descriptor exactly"** (`:130`) — missing *or extra* argument fails.
  - "for a call whose Peer principal is not the owner it then resolves the resources the call touches and asks `ctx.remoteAccess.decide()`, so **a refused call resolves no lookup and activates no Agent**" (`:130`).
  - "**A strict endpoint withdrawn on the Host also does not degrade to SRC inference, preventing a hot unload from silently weakening validation.**" (`:134`)
  - The Session Controller's lookup resolver "reuses a live Agent, automatically resumes ordinary cold sessions, deduplicates concurrent resumes, and rejects identities owned by subagent routing"; a resume failure and an ownership fence raise a `RemoteError` carrying `session/not-found` or `session/agent-busy`, "which the Gateway encodes onto the wire unchanged; only an unclassified throw folds into `gateway/internal`" (`:132`).
  - "Lookup policy is configured per key, so all `agent` or `session` parameters share the cold-resume behaviour… **the business method must not guess whether the object came from restoration.**" (`:142` region)
  - Strict analysis forbids generic methods, destructuring, defaults, rest and optional parameters — because the generator must produce a strict schema.
  - The Client uses **concrete functions on ordinary objects, not a JavaScript Proxy** (`:60` region).
  - Boundaries: session event streams, pagination, incremental reduce, projection and entity substreams "must not masquerade as Remote methods or enter invocation descriptors" (`:138` region).
- **Edge cases & failure handling:** unloading a Client contribution removes descriptors and concrete methods together, aborts in-flight calls, and makes stale method handles retained by external code reject further calls.
- **Surprising:** there is a documented **SRC development fallback** (running from source without the compiler plugin) that is deliberately *weaker* — it parses parameter names from the live function, does no type analysis, and the Client "refuses to mount SRC descriptors that lack strict codecs" (`:112` region). The dev path is explicitly less safe, and the client side refuses it.

#### `docs/capability-seams.md`
- **Purpose:** The map of every service the harness exposes: core spine services, swappable capability seams, bundle/composition points and standalone services — with the owning package, the known implementations, the direct consumers and a one-line note per row.
- **Key abstractions:** the `ctx` key as the stable identity; a service classified as `core` | `seam` | `bundle` | `service`; the three seam roles.
- **Data flow:** not a flow document — a *dependency* document. The generated Mermaid graph (lines 11–608) is edges; the table (from ~`:611`) is the readable form.
- **Non-obvious design decisions (rows worth stealing):**
  - `ctx.approval` (`:691`) — "One-shot permission decisions dispatched over the `approval/request` waterfall; answerers are listeners (the ACP bridge for its own agents), **absence fails closed to `unavailable`**."
  - `ctx.permissionPresets` (`:695` region) — "User-facing preset table (`workspace-write`/`danger-full-access`) bundling the sandbox-mode and approval-policy knobs; a switch writes one `permission/preset` event through to both knob events."
  - `ctx.schedule` (`:682`) — "**Stores tasks independently of Session activation and queues due messages in the original Session.**"
  - `ctx.goals` (`:683`) — "Folds revisioned objective state from the session log and keeps live continuation activation process-local."
  - `ctx.subagents` (`:696`) — six providers (spawn-in-process, fork-in-process, acp, codex, claude-code, dsh-sdk); "one activation manager owns both lifecycles."
  - `ctx.sessionQuery` (`:666`) — "The interface supplies exact reads, filters, and traces; its concrete backend adds full-text reconciliation, ranking, snippets, and cursor generations, while **the model consumer owns workspace authority and cursor-free rendering**."
  - `ctx.toolResultPruner` (`:633`) — "**Rewrites oversized current tool results through replayable single-node surface replacements before summary compaction.**"
  - `ctx.storage` (`:661`) — "Backends register side by side under names; data forms (domain first) mount on the hub and translate typed operations into opaque KV-unit primitives."
  - `ctx.sandboxPolicy` — "The one home for the deployment default mode + workspace root… Both enforcing families read it so bash and fs cannot confine to different roots."
  - `ctx.messageFeedback` — "Owns per-assistant-message feedback in the canonical Session log, target validation, per-item compare-and-set… **Feedback stays outside model history**; log export follows the consumer policy."
  - `ctx.spillStore` — "The backend saves oversized tool text and returns a model-facing locator plus retrieval hint; spill-policy is the `tools/post-execute` consumer that decides when to spill."
  - `ctx.agentTeams` — "Owns the implicit-root roster, direct peer inbox delivery, shared task DAG, and continuable-child lifecycle."
- **Edge cases & failure handling:** the row for `ctx.credentials` — "Consumers resolve per operation, so a rotated credential reaches the very next request; the settings controller exposes value-free views and write-only storage."
- **Surprising:** the seams are *not* uniform. Some rows are `seam` with two providers (`ctx.fs` = local / sandbox / ssh), some are `core` with none. The `ctx.web` row's note: "Search and fetch providers register into one `ctx.web` seam; **tool-web owns the stable model-facing names**" — the seam moves, the model's vocabulary does not.

#### `docs/AGENTS.md` (the documentation standard)
- **Purpose:** The repo's own documentation constitution: document structure, Markdown tiers, writing rules and `verify-doc-budgets` ceilings.
- **Key abstractions:** the **tier taxonomy** (`:15`) — "Each fact has one home: the tier whose job it is; elsewhere, link there." Twelve tiers from root `AGENTS.md` (standing orders) through `architecture.md` (ordered map), `subsystems/`, Agent Notes (the *why*), `defensive-patterns/`, `postmortem/`, persistence history, `cookbook/`, `user/`, package README, generated reference, skills — each with an explicit "does NOT belong there" column.
- **Non-obvious design decisions:**
  - "A document's subject and tree position fix its scope: describe its own subject at appropriate detail and direct children only by purpose, responsibility, and high-level behavior… **Document type does not widen that scope.** A reference may be exhaustive only about its own subject." (`:8` region)
  - "Postmortem is the only tier where war-story narrative belongs" (`:11` region) — everything else must state current state.
  - "**Current state, not history.** Keep history in commits, PRs, Agent Notes, postmortems, or scoped persistence records." (`:39` region)
  - "**One physical line per paragraph** (`verify-md-wrap`)" and "Fenced `ts` blocks must compile (`doc-typecheck`)" (`:41`–`:42` region).
  - A `ts type-equiv` fence is a *paste of a source declaration + its original JSDoc* that a gate re-extracts from source and diffs — so a documented type cannot drift from the code (see `docs/development.md:196` region for the manifest mechanics).
  - **Wordcount budgets** (`:49`): `scripts/doc-budgets.manifest.json` sets ceilings; `pnpm run verify-doc-budgets` rejects excess or missing files. "Ceilings are guardrails, not reduction targets. At or below target, retain at least 5% headroom; above target, freeze the ceiling until relocation or condensation brings the document under target."
  - **The slop checklist** (`:61`): duplicated rules; history outside its tier; implementation-status annotations in prose ("Status rots"); hand-restated catalogs; reasoning transcripts; rationale repeated beside sibling methods; paragraph walls; emphasis inflation; spec-speak in implemented notes.
- **Surprising:** the *published* rule is that a doc must not contain "**implemented!**" or "future: …" — the repository layout and package manifests carry status instead. And the doc that says this is itself a long doc with a "Doc Note" convention elsewhere.

#### `docs/development.md`
- **Purpose:** Contributor setup (a tutorial) followed by a contributor reference (layout, env, git, CI, daily commands, profile runs, TODO tags, verbatim type docs).
- **Key abstractions:** the **Host/Client two-aggregate TypeScript layout** (`:69`) — "Host and Client stay two aggregate programs because both sides declaration-merge the cordis `Context` interface under the same keys with different services; one program seeing both merges reports a collision." Three disciplines follow: `tsconfig.base.json` never gains `include`/`files`; a repo-wide `ts.Program` seeds an aggregate explicitly, never the root solution; a new package is registered in exactly one aggregate (only three split packages carry both leaf configs).
- **Non-obvious design decisions:**
  - The build is a **scheduled dependency graph**, not a script list: `DSH_GATE_CONCURRENCY` bounds concurrent steps, `DSH_GATE_FAIL_FAST=1` stops at the first failure, otherwise "a failure skips only its dependents, so independent errors are all reported."
  - "`pnpm run build` and `build:artifacts` embed the root package version, the seven-character source commit, and a dirty marker when Git reports local changes" and "Each successful `build` or `build:artifacts` writes a gitignored record that binds the exact public values to the Vite output… release packing and built Web tests reject a missing record or artifacts changed by a later partial build."
  - `lefthook` (`:137`) is a *fast local checkpoint only*: pre-commit verifies staged pairing records, lints staged files, checks whitespace, checks pi-ai provider metadata, and runs the vendor manifest guard — "the hooks intentionally do not run tests, snapshots, documentation checks, builds, or hygiene. Contributors run the checks relevant to the changed behavior once; CI owns exhaustive coverage."
  - Three TODO tags with an explicit urgency contract (`:196`): `FIXME` = "should block a new release", `TODO` = "fixed soon, once we have the resources", `XXX` = "someday maybe, no commitment" — "Pick the tag that matches the urgency so anyone scanning the code can tell a release blocker from a someday-maybe."
  - Worker-count policy: "`os.availableParallelism()` reports host CPUs rather than a container's CPU quota, so uncapped defaults oversubscribe shared hosts" — CI keeps the runner's CPU count.
- **Edge cases & failure handling:** the `type-equiv` / `public-api` projection rules (`:196` region) — a `public-api` fence keeps public fields, constructor, accessors, methods and original JSDoc but omits bodies and private members; comparison ignores whitespace and non-JSDoc comments but **requires every original JSDoc comment**.

#### `docs/cordis-primer.md`
- **Purpose:** The five Cordis ideas a harness plugin author needs before reading the generated service/event reference.
- **Key abstractions:** plugin = an object that implements `Service`; context = a repository of services keyed `ctx.<key>`; `inject` = declared service dependency (load order expressed as service requirements, "rather than manual boot sequencing"); typed events via TypeScript declaration merging; registrations are **reversible effects**.
- **Non-obvious design decisions:**
  - The dispatch-mode table (`emit` / `waterfall` / `parallel` / `serial` / `bail`) is "part of the event's public contract", and new events document it with an `@mode` tag "so the generated catalog can check declarations against dispatch sites."
  - `ctx.waterfall` is **around-middleware** (`:29`): a listener receives `(...args, next)`; call `next()` to delegate, return without `next()` to short-circuit. "For single-decision events, short-circuiting is the design. A policy listener can return without `next()` when it owns the decision, while a listener that only annotates or observes must delegate."
  - "Use `prepend: true` only when the listener must run before ordinary registrations."
  - "Every registration should have a disposer… **If teardown order matters, keep the related work in one effect so disposal unwinds in the intended sequence.**"
  - "Prefer events for interception and policy; prefer service methods for direct capability calls."

#### `docs/event-producer-consumer.md`
- **Purpose:** The generated matrix of every harness-owned event: mode, declaration site, dispatchers, listeners — plus a table of *undeclared* event strings seen in package source.
- **Key abstractions:** the event declaration sites themselves are useful: `agent/pre-step` is declared at `packages/core/agent/src/runtime-types.ts:320`; `agent/request` at `:337`; `agent/request-error` at `:353`; `agent/assistant-stream` at `:363`; `agent/turn-stopping` at `:381`; `agent/error` at `:393`; `agent/inbox/inserted` at `:288`, `/claimed` at `:299`, `/discarded` at `:307`; `agent/status` at `:280`; `agent/created` at `:261`; `agent/disposed` at `:270`.
- **Non-obvious design decisions:** the matrix includes "contained dispatch sites that deliberately bypass `ctx.emit`, such as subagent lifecycle containment" (`:8` region) — a declared event can be dispatched by a nested emitter and the catalog still finds it.
- **The undeclared table** (`:95`) is the interesting part: it lists event *strings* that appear in package source but are **not declared** in any `EventMap` — `internal/config`, `internal/dispatch`, `internal/plugin`, `internal/service`, `internal/status`, `internal/update`, `loader/volatile-update`, `slots/changed`. Each has a dispatcher column and a listener column, several with `-` (dispatched but never listened to, e.g. `internal/dispatch` ← `terminal-bash`; or listened to but never dispatched, e.g. `internal/service` ← `gateway`). This is a **static lint of the event vocabulary** — dead event strings are visible.
- **Edge cases & failure handling:** `session/event` has 30+ consumers, `agent/pre-step` 15, `tools/execute` 6 — the matrix is the tool for noticing that a widely-listened event has grown too many listeners.

## 2. Ideas worth stealing

> Cross-repo convergence could not be verified from this shard (the `pi` and `hermes-agent` shards are separate), so every item is marked `UNIQUE` **to this repo as far as this shard shows**.

1. **`UNIQUE` — "Model-visible means logged" as a hard architectural law.** Every model request must be reconstructable from the session log; a new model-visible input requires a new session event. `docs/architecture.md:124`. *Why it transfers:* August Trading already has a `WireAuditEntry`; the harness goes further and makes the **durable log the single source of the model's context** (`deriveMessages()` projects history from it), so a transcript is a replay, not a transcript. For a trading app this is the difference between "the model said X" and "I can prove the model saw X".
2. **`UNIQUE` — Durable "attempt" events that are not model history.** A failed, retried, cancelled or stream-error provider call is recorded durably as `assistant/attempt` but adds nothing to the model's context. `docs/agent-lifecycle.md:83`. *Why it transfers:* a provider failure is exactly the fact a trading app most needs (and most often loses) — and it must not pollute the next request.
3. **`UNIQUE` — Turn = drain, Step = one model request + its tools, and a turn may contain zero steps.** `docs/glossary.md:35`–`:37`, `docs/architecture.md:96` region. *Why it transfers:* August's `turnStatus` vocabulary would gain a level: a turn that was rejected at pre-step still happened and is still auditable.
4. **`UNIQUE` — Three-layer "one home per fact" documentation tier taxonomy with a machine budget.** `docs/AGENTS.md:15` and `:49`. Twelve tiers each with an explicit "does NOT belong there", plus a `verify-doc-budgets` manifest with a 5%-headroom rule. *Why it transfers:* August's `AGENTS.md` is already a rules file; the missing half is the *ceiling* and the *tier table* that tells a contributor which file to put a new fact in.
5. **`UNIQUE` — Approval fails closed, is one-shot, and is answered by listeners.** `docs/capability-seams.md:691`; the durable events are `approval/asked`, `approval/decided`, `approval/policy`. *Why it transfers:* August's trade-plan approval and skill-approval paths could share one "no listener ⇒ deny" rule instead of each path inventing its own timeout behaviour.
6. **`UNIQUE` — At-least-once delivery with a monotonic, generation-scoped watermark, and "uncertainty produces duplicates, never a sequence gap".** `docs/deepseek-llm-api-wire-extensions.md:154`–`:156`. *Why it transfers:* August's `session-query`/audit-log and any "export my journal" feature can use the same three rules — fold the greatest matching watermark per (entity, generation); a resumed process rebuilds the cursor from the durable log; a fork ignores inherited watermarks naming another entity.
7. **`UNIQUE` — Prune tool results *before* summarising, via replayable single-node surface replacements.** `docs/capability-seams.md:633` (`ctx.toolResultPruner`) and `docs/agent-lifecycle.md:85`. *Why it transfers:* August's compaction pass currently has to choose; the harness's ordering (prune → then summarise) is cheaper and keeps the summary focused on the parts pruning could not shrink.
8. **`UNIQUE` — Cap the model-facing tool vocabulary at the seam, not the provider.** `docs/capability-seams.md` row for `ctx.web`: "tool-web owns the stable model-facing names" while `ctx.web` owns the providers. *Why it transfers:* August's `deskToolCatalogue` and `getKeyLevelsTool` are already seams; the harness's rule — *the model-visible name belongs to the consumer tool, the backend belongs behind the seam* — is a rule worth writing down.
9. **`UNIQUE` — A "where new behaviour goes" map with one row per extension point.** `docs/architecture.md:144`–`:165` (21 rows). *Why it transfers:* a direct antidote to August's feature creep, and cheap to maintain: one table, one `ctx` key per row.
10. **`UNIQUE` — The with-key testing policy: "a no-key test proves plumbing; only a with-key run proves the agent works."** `docs/testing.md:23`. *Why it transfers:* August's `render-probe` and `skill-approval-probe` are exactly this idea, but the harness states the *policy* and the cost argument ("inference is cheap here") explicitly, which makes it a decision rather than a preference.
11. **`UNIQUE` — A static lint of the event vocabulary, including event strings that are dispatched but never listened to.** `docs/event-producer-consumer.md:95`. *Why it transfers:* August could emit the same table for its own "one canonical module" list and find dead `utils/` imports.
12. **`UNIQUE` — The "slop checklist" as a reviewable list, not a style guide.** `docs/AGENTS.md:61`. Eight named failure modes, each with a one-line test. *Why it transfers:* the most directly stealable artefact in the shard, because August's `AGENTS.md` already carries a similar narrative and could be compressed into a checklist an agent can actually audit against.

## 3. Trading-specific findings

**Long-lived monitoring & scheduled work** — partially in this shard. `ctx.schedule` "stores tasks independently of Session activation and queues due messages in the original Session" (`docs/capability-seams.md:682`); the model-facing tools are `schedule_create` / `schedule_delete` / `schedule_list` / `schedule_update` and they accept `after_seconds`, an explicit absolute `at`, a bounded fixed-rate `every_seconds`, daily and weekly local times in an **explicit IANA zone**, and a five-field cron expression (`docs/tool-catalog.md:36`). Management uses the Host **storage domain**, and due messages resume the original Session. Retention is explicit and bounded: `deliveryHistoryDays` (default 30) and `deliveryHistoryRecords` (default 200), "the older of this cap and the window wins, and the newest records survive… Pruning happens when an acknowledgment is appended, and `lastDelivery` is always retained" (`docs/config-catalog.md:2703`). The durable event is `schedule/change`. *No catch-up-for-missed-runs, idempotency key, or breaker-after-empty-runs mechanism appears in this shard* — the closest analogue is the delivery-history window plus "last delivery always retained".

**Human-in-the-loop approval** — `ctx.approval` is a seam whose decisions are dispatched over the `approval/request` waterfall; "answerers are listeners (the ACP bridge for its own agents), **absence fails closed to `unavailable`**" (`docs/capability-seams.md:691`). The durable audit trail is three events — `approval/asked`, `approval/decided`, `approval/policy` (`docs/persistence-catalog.md` event roots) — so the question, the answer and the standing policy are all replayable. A second layer, `ctx.permissionPresets`, exposes `workspace-write` / `danger-full-access` presets that "bundle the sandbox-mode and approval-policy knobs; a switch writes one `permission/preset` event through to both knob events" (`docs/capability-seams.md`, `ctx.permissionPresets` row). The sandbox policy home is deliberately singular: "Both enforcing families read it so bash and fs cannot confine to different roots."

**Post-mortem / reflection loops** — the harness has *no* self-improvement rule-accumulation loop; it has three durable feedback channels instead. `ctx.messageFeedback` owns "per-assistant-message feedback in the canonical Session log, target validation, per-item compare-and-set… **Feedback stays outside model history**" (`docs/capability-seams.md`). `ctx.sessionFeedback` records a session-level remark as a log-only `feedback/record` event. `ctx.goals` folds "revisioned objective state from the session log" with a `blocked` phase that "retains a policy code and explanation" and a goal-round cap (`docs/glossary.md:25`); the model-facing `tool-goal` "requires direct-human root authority" for create/edit/pause/resume, "complete and blocked also accept the exact current goal round", and "the default blocked lower bound is three admitted rounds" (`docs/tool-catalog.md:35`). The anti-bloat device is the **goal activation** flag: continuation permission is process-local and "deliberately absent from durable replay, so resume and fork require a later human-authorized resume mutation" (`docs/glossary.md:27`). Nothing here accumulates "lessons" — that is the gap August Trading already occupies.

**Multi-agent** — there is **no debate primitive**. The harness has a *provider seam* instead: `ctx.subagents` with six providers (spawn-in-process, fork-in-process, ACP, Codex, Claude Code, dsh-SDK) and "one activation manager owns both lifecycles" (`docs/capability-seams.md:696`). The `subagent` tool returns a child id promptly, and control is separate: `list_agents`, `send_message`, `interrupt_agent` are three *globally named* tools registered once, while each provider-bound `tool-subagent` instance registers its own delegation name (`docs/tool-catalog.md:41`–`:42`). The Ralph pattern is the closest thing to a debate loop and it is explicitly **not** one: "one foreground fresh-agent workflow run toward an immutable objective… a model-facing tool policy composed from workflow and subagent primitives" (`docs/glossary.md:44`); each round is a fresh child with **no** parent or prior-child conversation seed, and cross-round state travels through the shared workspace plus one bounded "Ralph handoff" (status, summary, evidence, next steps, blocker text) that "supplements the shared workspace rather than replacing it as authority" (`docs/glossary.md:48`). The team variant (`ctx.agentTeams`) adds an implicit-root roster, a shared task DAG and "direct peer inbox delivery" over continuable children; the model-facing surface is nine tools (`spawn_teammate`, four `team_task_*`, `wait_agent`, `send_message`, `interrupt_agent`, `list_agents`) and the shipped base bundle **keeps the package disabled**.

**Structured logs the model can query** — `ctx.sessionQuery` is a seam (interface + SQLite backend) supplying "exact reads, filters, and traces"; the backend "adds full-text reconciliation, ranking, snippets, and cursor generations, while the model consumer owns workspace authority and cursor-free rendering" (`docs/capability-seams.md:666`). The model-facing surface is five read-only tools — `session_search`, `session_trace`, `session_event_read`, `session_event_search`, `session_event_trace` — which "hide provider cursors and authorize every result from the immutable calling agent session" (`docs/tool-catalog.md:40`). Storage is deliberately light: a `ctx.storage` hub with `storage-json` and `storage-sqlite` backends "registered side by side under names", and a `ctx.storageDomain` that "waits for every configured backend, then publishes the domain form as one lifecycle-bound service" (`docs/capability-seams.md:661`). The session log itself is JSONL — `session.jsonl[.zstd]` for v0, `session.vN.jsonl[.zstd]` for v1+, with committed generation paths "never renamed, replaced, or deleted" (`docs/architecture.md:120` region). For oversized payloads, `ctx.spillStore` saves the text and returns "a model-facing locator plus retrieval hint".

**Staying simple as features accumulate** — three mechanisms stack: (a) the **tier taxonomy** with one home per fact and an explicit "does NOT belong there" column (`docs/AGENTS.md:15`); (b) **wordcount budgets** with a machine manifest, a 5% headroom rule and a "relocate → condense → raise the ceiling with justification" escalation path (`docs/AGENTS.md:49`); (c) the **extension-point map** (`docs/architecture.md:144`). On the feature side, the seams keep the *model-visible* surface stable while backends multiply, and the completeness guards (the tool catalog boots every `packages/*/tool-*` plugin and fails if one is missing from the boot manifest) make "a new capability that nobody documented" a build failure rather than a discovery.

## 4. Non-obvious decisions and gotchas

1. **A turn can have zero steps.** `agent/pre-step` rejecting the first claim "closes a durable turn without a step" (`docs/agent-lifecycle.md:50` region; `docs/architecture.md:96` region). If you count turns by counting model requests you will over-count.
2. **A rejected claimed batch stays removed.** The input is consumed even though the step never happens (`docs/agent-lifecycle.md:50` region). "Rewind and retry" is not the default semantics.
3. **Retries do not re-admit users.** A retry re-prepares the call and reconciles the retained rendered assembly "without repeating assembly, `agent/pre-step`, or user admission" (`docs/agent-lifecycle.md:87` region; `docs/architecture.md:100` region). Re-sending the user message on a retry is a bug.
4. **Empty content is not the same as no call.** `assistant/message` records content-less and `max-tokens` finishes; only the *derived history* drops the empty content (`docs/agent-lifecycle.md:83`).
5. **Compaction has two triggers with different meanings.** `agent/pre-step` = general pressure (prune then summarise); `agent/request-error` = canonical context overflow only. And "Recovery runs within the open step and retries only when pruning or summarization advances the surface replacement generation; otherwise the original request error remains authoritative" (`docs/agent-lifecycle.md:85` region).
6. **Approval is asked *before* monotonic guards, but "owner policy that must not be reordered remains a registered guard"** (`docs/tool-execution-pipeline.md:63` region). The ordering is a policy decision, not an accident.
7. **A throwing tool pipeline never loses the turn.** Every dotted throw edge normalises to `isError` *before* `finalizeContent` runs; `tools/result` then observes a frozen, lossless-JSON outcome (`docs/tool-execution-pipeline.md:63` region).
8. **A scope-restricted tool is absent from the prompt AND refuses execution, "indistinguishably from a nonexistent one"** (`docs/glossary.md:17` region). You cannot detect the restriction by asking the model.
9. **A withdrawn strict endpoint does not degrade to the weaker dev path.** "A strict endpoint withdrawn on the Host also does not degrade to SRC inference, preventing a hot unload from silently weakening validation" (`docs/api-gateway.md:134`).
10. **A refused remote call "resolves no lookup and activates no Agent"** (`docs/api-gateway.md:130`) — authorisation precedes object resolution, not after.
11. **The `session` lookup silently cold-resumes.** Business code "must not guess whether the object came from restoration" (`docs/api-gateway.md:142` region) — a method that assumes a live object will be wrong on the first call after a restart.
12. **The delivery watermark is scoped to a format generation.** "A watermark from another generation cannot authorize the current suffix" (`docs/deepseek-llm-api-wire-extensions.md:154`), and "absence means historical format v0" — the watermark event itself carries `sessionFormatVersion` so a v0 session is distinguishable from a missing event.
13. **"Acceptance" means HTTP 2xx, not "the work happened".** "Acceptance records endpoint-level HTTP success; it does not assert that an SSE stream completed or that the endpoint persisted an extension" (`docs/deepseek-llm-api-wire-extensions.md:39`).
14. **A merged body that fails to serialise sends the *base* body and skips acceptance**, so contributors resend on a later request (`docs/deepseek-llm-api-wire-extensions.md:33` region). A failed extension degrades to no extension, never to a broken request.
15. **The approval seam's "no listener" case is `unavailable`, not "allowed"** (`docs/capability-seams.md:691`).
16. **The tool catalog is generated by *booting* each plugin**, not by static analysis, "because a tool schema is not statically knowable (runtime-spread enums, concatenated descriptions, config-driven names, raw-JSON-Schema MCP tools)" (`docs/tool-catalog.md:11` region). Tool names can be load-time config (`tool-subagent`'s `toolName`), so a deployment may expose a package under a different name — the catalog records the shipped aliases.
17. **Two TypeScript aggregates, never one.** Host and Client both declaration-merge the Cordis `Context` under the same keys, so one program seeing both reports a collision (`docs/development.md:69`).
18. **The generated Chinese mirrors of *generated* catalogs are machine translations with a "reviewed counterpart" banner.** `docs/persistence-catalog.zh.md:1` still carries the *English* generator comment. The "reviewed" claim is inherited, not earned.

## 5. Weak spots

1. **The "one home per fact" rule is not actually enforced on the biggest artefacts.** `docs/AGENTS.md:15` states the rule, but the wordcount budget (`:49`) covers only standing documents — while `config-catalog.md` is 4,801 lines, `persistence-catalog.md` 9,140, `persistence-schema.json` 26,177. The same facts (what a tool requires, which package owns which `ctx` key) are restated in the tool-catalog map, the seam table, the config catalog and the event matrix, so the "home" is in fact four places. A reader who needs "what does `tool-schedule` require" must open the tool catalog, the seam table and the config catalog to be sure.
2. **The bilingual-pairing tax is enormous and its value is weakest exactly where the volume is.** 22 hash-record files, a `--write` verification script, and 100% Chinese mirrors of *machine-generated* catalogs whose content is an English template plus data. The pairing record proves the two files agree byte-for-byte per heading — it cannot prove the Chinese is *correct*, and for `config-catalog.zh.md` / `persistence-catalog.zh.md` the "review" is a translation of a generated file nobody reads.
3. **The rules and the corpus disagree with each other.** `docs/AGENTS.md` bans "implementation-status annotations in prose… Status rots", yet `docs/session-format-status.md` exists purely to hold a version/release-status table, and `docs/graph-atlas.md` + every generated file end with a "Maintenance mode: generated/curated" line — a status annotation in prose. The repo's own "slop checklist" would fail a line in its own catalogue. Relatedly, `docs/testing.md` demands a snapshot scenario for every non-trivial human-visible change, which is a very large recurring cost that no budget or window bounds.
4. **The tool catalog's correctness depends on booting plugins in a generator context.** A tool whose schema differs under the generator's default config than in production is documented wrongly, and the completeness guard only proves a package was *booted*, not that the booted shape is the shipped shape. The per-package "Deployment note" column is the human backstop, and it is a column in a generated table.
5. **`ctx.userQuestions` and `ctx.goals` have no listed direct consumers in the seam table**, and the seam table's own classification is generated by a heuristic in `scripts/gen-doc-graphs.ts` ("interface, implementation and consumer roles are classified in the script"). A service misclassified as `core` rather than `seam` silently loses its "three roles" discipline, and nothing in CI would notice.
6. **The approval seam is a waterfall with listener-based answerers but no described audit UI or expiry.** The durable events (`approval/asked`/`decided`/`policy`) exist, but this shard contains no policy for a pending approval that is never answered other than "absence fails closed" — an unanswered approval silently becomes a denial with no escalation.
