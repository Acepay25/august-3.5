# deepseek-harness :: dsh-notes-archived-bugfix

**Files in shard:** 546 (read: 364, skipped with reason: 182 — all 182 skips are tier-3 generated `.i18n.yaml` records; see §1 Tier 3)
**What this shard covers:** The whole `.agents/notes/archived/bug-fix/` corpus of the DeepSeek Harness (DSH): 182 archived "Agent Note" documents, each shipped as a triple — an English note (`.md`), a Chinese mirror (`.zh.md`), and a generated bilingual-pair consistency record (`.i18n.yaml`). Every note has the same shape (Problem → Decision → Alternatives considered → Consequences, plus a `Status:`/`Archived:` header and a `Verification`/`Testing` section where relevant), so the shard is a catalogue of **decisions the maintainers made and recorded**, not code. This is the closest thing DSH has to a design-decision log: it is where the reasoning behind 182 bug fixes survives after the code moved on. For August Trading the shard is worth mining for (a) the *shape* of the note template itself, (b) the recurring decision patterns (fail-loud boundaries, compensating transactions, durable-vs-ephemeral split, "one owner per fact"), and (c) a large number of concrete UX/streaming/reliability rules.

**Reading protocol used:** English notes were read **in full** (every note, every line). Chinese mirrors were opened **line by line** with long lines truncated to ~44 characters for budget; every section heading and every alternative was visible, and parity against the English sibling was confirmed note by note. The `.i18n.yaml` records were **not** read line by line (tier 3): a head peek confirmed all 182 share one generated format — a header comment, the regeneration command, and the two git blob hashes of the English and Chinese sides.

## 2. Ideas worth stealing

**Convergence note.** This shard only covers `deepseek-harness`. I checked the other two reference repos for an equivalent artefact: `pi` has no `.agents/notes` tree (only `.pi/{prompts,skills,extensions}` and package READMEs) and `hermes-agent` has none either (no "Alternatives considered" section anywhere in its markdown). So the *note corpus itself* is UNIQUE to DSH. A few techniques below are plausibly convergent at the technique level; the lead should cross-check `pi`/`hermes-agent` before claiming convergence.

1. **The note template itself: Problem → Decision → Alternatives considered → Consequences, with a mandatory measurement.** — *what*: every archived fix is a five-part record, and the "Alternatives considered" section names the rejected option **and the reason**, not just the chosen one. Many notes also carry the measured number that motivated the change (203px of caret separation, 12.2 s → 7.2 s render, 4,180 ms → 8.7 ms terminal ingestion, 459 ms → 5.46 ms list reconciliation). — *where*: `.agents/notes/archived/bug-fix/2026-07-28-themed-scrollbars-and-reserved-gutter.md` (a 18 KB note whose whole "Alternatives" section is eight measured alternatives), `2026-07-31-composer-text-layers-share-one-scrollport.md` (the 203/202/203px measurement), `2026-08-03-tui-long-session-render-costs.md` (12.2 s → 7.2 s, 796 ms → 17 ms per keystroke). — *why it transfers*: August's `docs/plan/` already carries open items, proposals and an implementation record; adding a per-decision note whose **rejected alternatives and the measurement** are mandatory turns "what we did" into "why we did it, and what we would have to reverse to change it". The alternatives section is the part August's plan corpus is missing.
   — **UNIQUE** (no equivalent corpus in the other two repos).

2. **A machine-checked bilingual pair.** — *what*: every note ships in English and Chinese, and a generated `.i18n.yaml` records the git blob hash of each side plus the command that re-records them; a `verify-translation-pairing` script enforces the pair. — *where*: `2026-08-23-win32-utf16-nul-truncation.i18n.yaml` (the header) and every other `.i18n.yaml` in this shard. — *why it transfers*: only if August localises; the *mechanism* (a generated record holding both sides' hashes so a human edit to one side is detected) is the transferable part, and it generalises to any "two artefacts must stay in step" pair.
   — **UNIQUE**.

3. **Semantic durability barriers, and a durable "outcome unknown" verdict.** — *what*: persistence flushes at *semantic* boundaries (before a request is derived, after `request/header` but before the adapter stream, after the recorded `tool/call` but before the tool body), and crash repair distinguishes `TOOL_NOT_STARTED` (retryable) from `TOOL_OUTCOME_UNKNOWN` (retry only for read-only or idempotent work; verify external state or ask the human first). — *where*: `2026-07-21-semantic-session-checkpoints.md`; the same two codes reappear in `2026-08-09-filesystem-absence-observation.md` and `2026-09-19-failed-step-tool-results.md`. — *why it transfers*: this is the shape an August Trading agent needs when a tool call submits an order or writes a journal entry: on crash, "we do not know whether this executed" must be a first-class, durable verdict — never a blind retry. The same note's `keepInbox` parking contract is the pattern for "the trader's queued intent survives the interruption".
   — **UNIQUE** (the vocabulary is DSH's; the *concept* may be convergent).

4. **Separate the model-facing projection from the human-facing projection.** — *what*: the model sees a compacted "surface" (a range replaced by one checkpoint), while the human transcript is projected from *append-origin* events and never loses a message the reader has already read; a landed compaction contributes one dim marker instead of erasing the history it shadowed. Both frontends implement the same split, and the client pins the checkpoint vocabulary by a **type-only import of a cordis-free leaf** so renaming the plugin id is a compile error. — *where*: `2026-07-29-human-transcript-append-origin.md` (terminal) and `2026-07-30-web-transcript-log-ordered-projection.md` (browser, with the `packages/compaction/compaction/src/checkpoint.ts` leaf and the `TS2322` proof). — *why it transfers*: August's conversation holds the trader's own reading of a market and the model's; a context-budget mechanism must never be able to *delete* what the trader has already read, and the two views must be separate projections of one log, not two copies.
   — **UNIQUE**.

5. **Keep the stable prompt prefix stable; put the volatile facts last.** — *what*: the summarisation call is a *prefix extension* of the warm request (the compaction instruction moves from the front to a trailing `user` message, and `system`+`tools`+the shadowed region are replayed verbatim) so the provider's KV cache hits; and the environment facts (checkout path, Web URL, session cwd) live in a prompt **suffix** (`HARNESS_SOURCE` 10000, `WEB_SURFACE` 10100, `DEPLOYMENT_PERSONA_SUFFIX` 10200) so identical deployments produce an identical prefix. — *where*: `2026-07-21-compaction-summary-prefix-cache-reuse.md`; `2026-09-06-environment-prompt-suffix.md`. — *why it transfers*: August builds prompts per analysis (`constants/prompts/`, `utils/composePrompt.ts`); the per-run facts (selected symbol, current position, the trade plan under review) belong at the *end* of the prompt, not the beginning, and a summariser must reuse the routed prefix rather than a freshly rendered transcript. The note is honest that cache hits are not measured — August should measure them.
   — **UNIQUE**.

6. **Plan/commit instead of copy-on-write to keep a fold atomic.** — *what*: the token meter copied the whole priced surface on every event so a throw would leave the caller's state untouched — charging every well-formed event O(surface) and accumulating O(S²). Split into `plan` (all fallible steps, against a read-only surface) and `commit` (an infallible in-place `push`/`splice`), so retry identity comes from *ordering* rather than from allocation. — *where*: `2026-08-24-token-meter-surface-fold-plan-commit.md` (the copy was ~99.9% of an append's cost; 100 µs at a 50k-node surface). — *why it transfers*: August's own AGENTS.md insists on a "no write-ref" memory surface; the same plan/commit split applies to any projection over the trade log (positions, P&L folds, per-session statistics) where a partially-applied write would be worse than a thrown error.
   — **UNIQUE**.

7. **Every turn end gets a user-visible reason, and the reason is read from the durable event.** — *what*: the TUI renders a notice for every `turn/end` kind including the merge-extensible unknown, and a `max-tokens` truncation gets its own persistent row with no fabricated token numbers; a message footer (copy/branch/clock) is granted only inside a turn that has a `turn/end` in the window, read from the durable event rather than inferred from `running`. — *where*: `2026-07-24-tui-turn-end-stop-reason-notices.md`, `2026-08-12-max-tokens-turn-end-notice.md`, `2026-08-05-turn-tail-actions-require-a-completed-turn.md`, `2026-08-20-turn-error-survives-same-turn-retry-history.md`. — *why it transfers*: August already owns a canonical run-status vocabulary (`utils/runStatus.ts`); the transferable rule is that the *durable* turn-end event is the only authority for "did this analysis finish, and why", and a truncated answer must be visibly truncated rather than reading as a normal completion.
   — **UNIQUE** (the vocabulary converges with August's existing module; the rule is DSH's).

8. **A fixture that cannot fail is worse than no test.** — *what*: the approval scenario's recorded command is a 200-token blob because the model compresses any regular payload (the first recording turned "alpha 400 times" into a one-liner that proves nothing); the question composer's recorded question is longer than needed because the layout invariant is unfalsifiable without wrapping copy; the approval geometry test asserts the region *is* scrolling and reads the cap off the live draft scrollport rather than hardcoding px; the trigger-menu test polls for a stale-only row to disappear before clicking. — *where*: `2026-07-30-approval-panel-command-cap.md`, `2026-07-27-question-composer-rows-do-not-shrink.md`, `2026-07-30-tui-diff-card-redundant-path-header.md`. — *why it transfers*: August's `render-probe` is the same idea taken further (it counts *rendered rows*), and August's analysis probes would benefit from the same discipline: a probe whose fixture cannot reproduce the failure shape is a false gate.
   — **UNIQUE**.

9. **"Verified fail-before" as a note convention.** — *what*: many notes state, per fix, that the regression test was checked to fail without the fix ("Verified fail-before: without the cap the region reports `scrolls: false`…", "reverting the fix reproduces the exact `duplicate loader entry id` boot failure"). — *where*: `2026-08-12-fix-pwsh-terminal-overlay-dup.md`, `2026-08-29-code-runtime-python-reply-backlog-and-surrogate-count.md` (one per case), `2026-08-26-pi-ai-grant-payload-json-image.md`. — *why it transfers*: August's test suite is large; a test that passes before and after the change is dead weight, and this convention makes the gate's value auditable note by note.
   — **UNIQUE**.

10. **One selection rule per fact, owned by one package.** — *what*: the child's output selection lives in one file (`assistant-output.ts`), because three consumers had selected independently and diverged; the session-row identity guard enumerates *every* field because a hand-written enumeration that misses one field serves a stale object forever; the tool-runtime restriction exempt set means "what this scope registers itself", not "the global layer". — *where*: `2026-08-10-subagent-empty-terminal-message-output.md`, `2026-08-10-session-row-identity-covers-the-preset.md`, `2026-08-10-child-agents-join-their-parent-preset.md`. — *why it transfers*: August's trade-plan validation, run-status and risk-reward modules are already single-owner by AGENTS.md; the *failure mode* here (a memoised row whose identity guard omitted a field, so a confirmed switch was never seen) is exactly the class of bug August's `utils/canonical single-source modules` rule is meant to prevent, and this note shows the failure in the wild.
    — **UNIQUE**.

11. **Bound the work a model can start, per owner, before the producer runs.** — *what*: `LocalJobRegistry` owns `maxConcurrentJobsPerOwner` (default 10); admission happens before the producer executes and before a job id is allocated, and a `stopping` producer still occupies capacity until its `done` settles (a cancellation request is not resource release). — *where*: `2026-08-11-bounded-background-job-admission.md`. — *why it transfers*: August runs Monte Carlo, backtests and web workers from an agent that can start background work across turns; `maxParallelToolCalls` cannot bound work that stays live after the step returns. The capacity table (running/stopping occupy; terminal states release) is directly reusable.
    — **UNIQUE**.

12. **Model-facing recovery text is normalised at the tool boundary; the code is preserved and the source is chained as `cause`.** — *what*: two producers emitted different wording for the same condition, and one leaked whether the rejected operation would have overwritten a target; the tool boundary replaces every message with one stable sentence (`cannot modify "<path>": file has not been read — read the file, then retry`) while keeping the structured code and the original error as `cause`. — *where*: `2026-09-03-normalized-unread-fs-tool-diagnostic.md`. — *why it transfers*: August's model-facing tool errors should be one instruction per failure class, not one per producer, and the diagnostic must not leak facts the model should not have (e.g. "your write would have overwritten an existing position").
    — **UNIQUE**.

13. **Validate at the field, and keep "absent" distinct from "invalid".** — *what*: one rule defines a legal API key (after trimming, non-empty, every character in `[\x21-\x7E]`), enforced in the browser, in each resolver and on every credential read, because a non-ASCII character *cannot* travel in an HTTP header for any provider. A second, narrower "you pasted an environment line" rule runs **only in the browser**, because the environment stays the escape hatch for a gateway that issues an odd-shaped key. A blank field means *keep what is stored*, not *invalid*. — *where*: `2026-08-06-api-key-format-validation.md`. — *why it transfers*: August's provider config (`services/infrastructure/ProviderConfigService.ts`, `types/provider.ts`) is runtime-configured and encrypted on desktop; the rules here (one rule, every layer, absence ≠ invalidity, heuristics only where the human is) transfer directly, and the "a deterministic fault must not be retryable" corollary matters: a bad key is not a transport blip.
    — **UNIQUE**.

14. **Authority is granted by declared type, never by a field name.** — *what*: attachment authorisation and ZIP export inferred ownership from common payload field names, so an unknown ignorable event could authorise an image read or export file bytes; both now select content by built-in event type and treat everything else as opaque. — *where*: `2026-09-19-declared-session-attachment-carriers.md`. — *why it transfers*: anything August reads from a session, a provider or a plugin must be authorised by the *kind* of record it is, not by a field that happens to be present.
    — **UNIQUE**.

15. **The negative guarantee belongs at the registry, not in each contributor.** — *what*: a minimal preset cannot disable "every known prompt contributor" (new contributors reopen the prompt); instead a `complete` persona section is restored as the *sole* system-prompt section after the assembly waterfall, discarding every dynamic contribution — a negative guarantee expressed at the one place that assembles. — *where*: `2026-08-10-minimal-preset-owns-rl-composition.md`. — *why it transfers*: August's `constants/promptRegistry.ts` + `utils/composePrompt.ts` is exactly that assembly point; the transferable idea is "an agent that must see *only* this prompt is expressed by a positive constraint at the registry, not by disabling contributors one at a time".
    — **UNIQUE**.

16. **Say what was deliberately not added.** — *what*: the glob note refuses a model-facing `list` tool because it would add permanent schema and prompt tokens plus ordering/pagination/symlink/escaping/UI/snapshot contracts for no security benefit; the API-key note refuses to verify a key over the network at save time; the PTY note refuses to accept every nested structured card. — *where*: `2026-07-27-glob-sampling.md` ("The tool surface does not grow"), `2026-08-06-api-key-format-validation.md`, `2026-09-05-nested-terminal-cards.md`. — *why it transfers*: August's `docs/plan/` already tracks scope; this is the missing column — the *surface* a proposal adds, counted in permanent prompt/schema tokens and new contracts.
    — **UNIQUE**.

17. **Bounded, escalating shutdown with a user-controlled escape.** — *what*: the first signal starts a graceful disposal plus a referenced 5 s backstop; a second signal during a pending shutdown forces immediate exit; normal completion sets `process.exitCode` and lets Node drain (an immediate `process.exit()` can hit the Windows libuv async-handle assertion). — *where*: `2026-08-03-cli-signal-shutdown-escalation.md`, `2026-07-31-fail-loud-releases-the-terminal.md` (a failed boot must release the terminal: a latch, not an uninstall, keeps the first rejection the reported one, and the timeout timer stays *referenced* so Node cannot exit 0 on the failure it is reporting). — *why it transfers*: August's Electron shell and Capacitor app need the same shape: a crash must not strand the terminal or a SQLite write, and a second Ctrl+C must mean "stop waiting now".
    — **UNIQUE**.

18. **Recovery is a projection, not a reconnection.** — *what*: pending Queue and steering input survive a Host restart by *folding* the durable event stream (the standard `inbox` projection) rather than enumerating live agents, so a cold Session's pending work is visible without resuming an agent; one domain-owned fold serves live pushes, cold history, reconnect and cache. — *where*: `2026-08-17-durable-web-queue-recovery.md`. — *why it transfers*: August's app can be killed (mobile backgrounding, Electron close) with a scheduled analysis or a queued trade plan in flight; recovery must reconstruct from the durable log, not depend on a live runtime object.
    — **UNIQUE**.

19. **A human-owned durable state the model cannot lift.** — *what*: a paused goal is a *user* control: the model-side `update_goal resume` rejects a durable paused goal with `GOAL_TOOL_RESUME_PAUSED`, and the model prompt states that the user owns the resume. — *where*: `2026-09-01-host-goal-pause-aborts-turn.md`, `2026-09-03-user-owned-goal-pause-activation.md`. — *why it transfers*: in a trading app, "pause the automated scan", "stop auto-trading", "stop the scheduled digest" must be states the *model* cannot undo in the same turn — the analogue of `GOAL_TOOL_RESUME_PAUSED` for a trading control.
    — **UNIQUE**.

20. **A delegated agent may not ask the human.** — *what*: `UserQuestionService.ask()` authenticates the live agent through `ctx.agents.roots()` and fails a runtime-owned child with `DELEGATED_CALLER` before any provider dispatch; runtime ownership is the authority, not durable lineage, because a lineage-bearing session resumed without an owner is a runtime root. — *where*: `2026-08-01-ask-user-delegated-caller-guard.md`. — *why it transfers*: if August ever spawns analyst subagents, the rule "a child cannot open a human interaction it cannot own" is what keeps a one-shot delegation from hanging forever; the neutral error text ("put the unresolved question in your final result") is the right shape.
    — **UNIQUE**.

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work — not in this shard.** The scheduling/cron subsystem lives in the `dsh-workflow-jobs-schedule` shard. What this shard contributes to it: a *bounded* background-job admission policy (`2026-08-11-bounded-background-job-admission.md`), a durable "queued intent survives a restart" reconstruction (`2026-08-17-durable-web-queue-recovery.md`), a user-owned pause that aborts the live turn (`2026-09-01-host-goal-pause-aborts-turn.md`), a "the same action can be resumed but the outcome may be unknown" classification (`2026-09-19-failed-step-tool-results.md`), and a bounded, escalating shutdown (`2026-08-03-cli-signal-shutdown-escalation.md`). No catch-up-for-missed-runs, no idempotency ledger, and no breaker-after-empty-runs appear in these 182 notes.
- **Human-in-the-loop approval — the strongest transfer in the shard.** The approval takeover card is the closest thing in DSH to August's trade-plan approval surface, and the note is a design manual for it: the cap applies to the *text region* (justification + the paired command) and not to the card, so the refuse/allow row is in the card at every content length; the cap is one value with two consumers (`--dsh-composer-text-max-height`) so the two composer states cannot drift; the scroll region is its own tab stop, because a keyboard-only user must be able to finish reading what they consent to; and the command is *not* truncated or ellipsised, because "hiding its tail asks the user to consent to text they cannot read" (`2026-07-30-approval-panel-command-cap.md`). The companion rule — an unavailable control stays visible, focusable and hoverable with `aria-disabled` and a tooltip, because a disappearing control cannot explain the boundary requirement (`2026-08-02-message-fork-actions-require-completed-turn-tail.md`) — applies verbatim to August's gate rows. A second approval-shaped fact: a *runtime-owned child agent may not open a human interaction at all* (`2026-08-01-ask-user-delegated-caller-guard.md`).
- **Post-mortem / reflection loops — mostly elsewhere, but the vocabulary is here.** The settlement-reflection machinery is in another shard. This shard supplies the two verdicts a trading post-mortem needs: `TOOL_NOT_STARTED` (safe to retry) versus `TOOL_OUTCOME_UNKNOWN` (may have side effects — verify external state or ask the human before deciding) (`2026-07-21-semantic-session-checkpoints.md`, `2026-09-19-failed-step-tool-results.md`). It also supplies the "a rule must not accumulate without a gate" pattern in its non-trading form: the compaction checkpoint is an *English engineering register* with exact literals preserved, so a multilingual conversation cannot let a transient conversational register persist across compaction cycles (`2026-07-31-english-compaction-checkpoints.md`).
- **Multi-agent.** DSH has no debate engine; it has *delegation with fixed semantics*, and this shard documents the edges that matter: every model-authored child→parent message uses one fixed delivery (Steer) so ordering cannot invert (`2026-08-17-subagent-message-settlement-ordering.md`); a child joins its parent's composition by a synchronous bind, not a re-mount, so it gets the parent's *exact* generation (`2026-08-10-child-agents-join-their-parent-preset.md`); one canonical selection rule owns the child's output so three consumers cannot diverge (`2026-08-10-subagent-empty-terminal-message-output.md`); the parent completes its catalog from child headers and descriptors without preparing the child's own catalog (`2026-09-19-session-local-subagent-migration.md`); and a child may not ask the human (`2026-08-01-ask-user-delegated-caller-guard.md`). Where "debate" would add value, the notes show the *cost* framing: a "quiet" delivery mode and a "next-turn" delivery mode were both refused because each let ordering vary by deployment.
- **Structured logs the model can query.** The substrate is an append-only JSONL session log with an event-per-record shape, a projection framework (live drive + cold fold + reconnect baseline + cache), and a search/classification fold over the same log (`2026-07-17-…`/`2026-09-15-linear-session-list-cache.md`, `2026-08-12-full-session-turn-step-counts.md`, `2026-08-17-durable-web-queue-recovery.md`). Two transferable rules: (a) the *model-facing* view and the *human-facing* view are separate projections of one log, so the reader's history is never erased by a compaction (`2026-07-29-human-transcript-append-origin.md`, `2026-07-30-web-transcript-log-ordered-projection.md`); and (b) whole-session figures belong in a durable projection, not in the loaded window, so paging does not change what the reader is told (`2026-08-12-full-session-turn-step-counts.md`). For August this maps onto a journal: the trader's reading of a trade and the agent's summary of it must be two projections of one append-only record, and any statistic shown next to the conversation should be whole-session, not window-scoped.
- **Staying simple as features accumulate.** The recurring discipline is *refusing a new surface* and *expressing a negative guarantee in one place*: no model-facing `list` tool (`2026-07-27-glob-sampling.md`); one owner per agent contract, with the launcher carrying no plugin knowledge (`2026-08-20-plugin-owned-shipped-preset-root.md`); the shipped preset root moved *into the plugin* so the squash, the reload freeze and the dump divergence "stop being possible rather than being corrected"; and the "complete section" trick that replaces disabling contributors one by one (`2026-08-10-minimal-preset-owns-rl-composition.md`). The `dsh-web` surface is a useful negative case: several notes record features that were *not* built (no account or settings screen behind the collapsed sidebar, no second model-facing picker, no in-app settings for the setup card, no durable dismissal flag for onboarding).
- **A trading-specific hazard this shard names explicitly.** "a manual pause is a user control" (`2026-09-03-user-owned-goal-pause-activation.md`) and "an action whose outcome is unknown must not be blindly retried" (`2026-07-21-semantic-session-checkpoints.md`) are the two rules that separate a trading agent from a chat agent. In a trading app the analogue of a `SIGKILL`-ed subprocess is an order whose ack was lost; the analogue of the collapsed sidebar's control rail is a "stop auto-trading" switch that must remain reachable when the panel is collapsed.

## 4. Non-obvious decisions and gotchas

- **A listener can never be correct in motion.** The composer's two text layers (a transparent-glyph textarea over a painted backdrop) were kept in step by mirroring `scrollTop`; that is correct *at rest* and impossible *during* a gesture, because the `scroll` event runs after the compositor fact it reacts to (measured 203/202/203px of caret separation on chromium/firefox/WebKit). The fix was structural — one scrollport holding both layers — not a better listener (`2026-07-31-composer-text-layers-share-one-scrollport.md`).
- **A negative standard property silently kills the positive one.** Declaring `scrollbar-width`/`scrollbar-color` *and* the `::-webkit-scrollbar*` pseudo-elements makes Chromium and Safari discard every WebKit rule for that element, hover included — so the hover tokens were dead code on the engine most users run. The standard properties must therefore live inside `@supports not selector(::-webkit-scrollbar)` (`2026-07-28-themed-scrollbars-and-reserved-gutter.md`).
- **A memoised row's identity guard is a security surface.** The session-row memo compared a hand-enumerated field list and omitted `agentPreset`, so a confirmed preset switch was judged "unchanged" and the stale object was served forever — the chip then dropped the stage and sent no RPC at all. Adding a field to the row type now silently breaks every reader that memoises it (`2026-08-10-session-row-identity-covers-the-preset.md`).
- **"Rejected because it is a parameter" beats "rejected because it is wrong".** Two decisions in this shard turn on *where* a rule lives: the API-key shape heuristic runs only in the browser because a false positive in a resolver leaves the user no working path, while a false positive in the browser leaves the environment open (`2026-08-06-api-key-format-validation.md`); and the client-side CSS predicate is mirrored rather than shared because the client/host source-plane split forbids the dependency (`2026-08-06-api-key-format-validation.md`, `2026-09-07-pi-ai-settings-catalog-recovery.md`).
- **The presence of a token is not a theme.** Four `--dsw-alias-*` names in the feedback-note stylesheet were not defined by the theme; an undefined custom property invalidates the whole declaration at computed-value time, so the textarea shipped with no border and no surface (`2026-08-13-feedback-note-editor-popover.md`).
- **`isEnabled()` asserts nothing on a `contenteditable` div.** Playwright's enablement check ignores both `aria-disabled` and `contenteditable`, and `fill()` throws instead of waiting, so a read-only composer looked enabled and a CI-load race dropped edits (`2026-08-26-composer-gesture-editable-gate.md`).
- **A "successful" tool call can have no output.** A `max-tokens` step appends an empty-content `assistant/message` that hosts usage and never reaches the surface; three independent consumers selected it as the child's answer, so a truncated child reported `[]` instead of its real partial text (`2026-08-10-subagent-empty-terminal-message-output.md`).
- **Compaction can erase the user's history without losing a byte.** The durable log still held every message; the *projection* did the erasing. Two frontends had the same defect for the same reason, and each fix introduced a new edge (a pagination hole, then a fold failure) — the notes cross-reference each other precisely here (`2026-07-29-human-transcript-append-origin.md`, `2026-07-30-web-transcript-log-ordered-projection.md`).
- **A "successful" Windows file-open can have opened nothing.** `Invoke-Item` asks a different resolver than the shell does and exits 0 when it finds no application; Explorer's exit code 1 records the *delegation*, not the outcome, so accepting it cannot turn a wrong target into a success (`2026-09-22-windows-open-through-shell-resolution.md`).
- **Two rules can both be right and still be incompatible.** The Web diff card's neutral context lines and its exact `+A -R` footer needed the same derivation, and the TUI's version needed a bounded comparison that degrades to a coarse replacement; the Web version bounds at 256 edits and the TUI at 1000 — the same underlying decision, implemented twice because the surfaces are different packages (`2026-07-31-tui-diff-context-line-accounting.md`, `2026-09-14-web-diff-context.md`).

## 5. Weak spots

- **The corpus is a firehose.** 182 notes live in one directory with no index, and finding "what is the current decision" means following `supersedes` links by hand. A note is archived but its subject is often still live, so "archived" here means "decided", not "obsolete" — a reader who treats the directory as history will miss current behaviour. A generated index (subject → current owning note) would cost almost nothing.
- **The note taxonomy and the directory taxonomy disagree.** The directories are `archived/{architecture,bug-fix,feature,process,simplification,testing}` while each note carries `Status: implemented` and an `Archived:` date; "archived bug-fix, status implemented" is two overlapping schemes for the same lifecycle, and the note body then carries a third (`## Deferred`, `## Related`, "this note supersedes that note").
- **Some notes are changelogs wearing a decision's clothes.** `2026-07-31-code-runtime-python-settlement-fixes.md` is 72 KB of 18 independent corrections with their own alternatives lists, and `2026-07-28-themed-scrollbars-and-reserved-gutter.md` is 18 KB about one CSS cascade; a reviewer cannot review either as one decision, and the "Alternatives considered" section becomes a list of 15 equal-weight paragraphs.
- **The bilingual pairing is only as current as its last verification.** The `.i18n.yaml` records the git blob hash "as of the last confirmed-consistent state", so a human edit to one language silently invalidates the pairing until `verify-translation-pairing --write` is run; nothing in the note body warns the reader that the pair may be stale.
- **The prose is load-bearing in places a machine cannot check.** Several decisions rest on wording ("the model's pre-call text announces a report that never arrives", "a user who configured some other provider was taken over"), and the evidence is a human reading the transcript. Those are the right decisions, but they are the ones a future refactor can quietly undo.
- **The archived notes are still the only record of *why* the code looks odd, and the code does not point back.** A `utils/runStatus.ts` in August has the same problem in miniature; DSH's notes are rich but nothing in the source cites the note that produced the shape, so the reasoning is one directory away from the code it explains.
