# deepseek-harness :: dsh-notes-archived-arch

**Repo:** `deepseek-harness` (read-only checkout at `C:/Users/rober/AppData/Local/Temp/harness-research/deepseek-harness`)
**Shard:** `.agents/notes/archived/architecture/` — the harness's archived *architecture* Agent-Note corpus, 2026-06-11 → 2026-09-24.
**Files:** 555 = 185 English notes (`.md`) + 185 Chinese translations (`.zh.md`) + 185 generated bilingual-pair sidecars (`.i18n.yaml`).
**Reading tier:** this shard contains **no `source` file** — every file is `docs` (Tier 2) or `generated-vendored` (Tier 3). All 185 English notes were read line-by-line except **17** large ones (>15 KB), which were read head+tail (first 95–150 lines + last 60–110 lines; the head and tail together cover the note's Problem, Decision and Consequences, and the omission is marked per file in the status ledger). The 185 Chinese files and 185 sidecars were opened and structurally verified against their English sibling (heading-tree comparison, `Status`/`Archived` parity, and a 6-line-shape check) — see §1.2/§1.3 and the status TSV for exactly what was done per file.

**What this shard is.** It is the harness's design record, not its code. Every note answers the same four questions in the same order: **Problem → Decision → Alternatives considered → Consequences**, and every note is a *decision with a status line* (`implemented`, sometimes superseded) and an `Archived:` date. The corpus is unusually high-quality for a repo's own notes: each decision states what it refuses to do, what it costs, and which later note owns the follow-up. Together the 185 notes describe how a mature agent harness keeps a session log authoritative, keeps provider/model plumbing neutral, keeps plugins composed rather than hard-wired, and refuses to grow a second copy of anything.

## 2. Ideas worth stealing (ranked)

1. **One durable log, and "model-visible ⟺ already logged" as a law.** Every note keeps coming back to this: the session log is the authority; the projection is a cache; the client is a projection of the projection. August Trading's transcript currently lives in React state + Preferences/localStorage, and `compactForWire()` is a *transport* rewrite. DSH's rule is stronger and cheap: a reduction the model saw (a pruned tool result, an offloaded image) is itself a durable record (`surfaceOp: replace`), so replay reproduces exactly what was sent. For a trading app this is the difference between "the journal shows what I logged" and "the journal shows what the model actually saw".
2. **Sparse central prompt-section ordering.** `ctx.systemPrompt.getSectionOrder(name)` returns a unique integer (≥10 apart) and nothing else declares a number. August's `constants/promptRegistry.ts` + `utils/composePrompt.ts` are already close to this — but per-domain prompt files still carry their own ordering intuition. One allocation service with a tie-break rule (code-unit name) would remove the whole class of "which prompt wins" bugs, and the note shows the cost is one file plus one gate.
3. **Retention as a shared library with exact omission metadata.** `ItemRetainer`/`TextRetainer` answer one question ("what did we keep, what did we omit") and return exact counts; the tool owns the prose. August's `utils/harnessMarks.ts` already demands "how much was kept vs existed" — the DSH version adds the *structure* (one retainer, UTF-8-safe cuts, `Omitted = none | exact | unknown`) so backtest output, chart ranges and tool results cannot each invent a truncation marker.
4. **The capability-seam triad: interface / provider / consumer, plus policy as an event gate.** The provider implements the mechanism, the consumer never depends on the provider, and cross-cutting policy (read-before-write, freshness) is an *optional* plugin that participates through events — so dropping the policy leaves the feature usable but unconstrained, and the policy itself performs no I/O (the provider's CAS makes the guarantee real). This is the single most transferable structural idea in the shard: August's provider layer (DeepSeek/OpenAI/generic), tool layer, and validation layer all want exactly this shape.
5. **One mechanism per independent fact.** A recurring rule (`2026-07-12-agent-scope-runtime-design`): one opaque key, one registry entry, one transaction, one resolver, one promise. Every duplication in the notes came from inventing a second mechanism for a fact that already had one. August has a documented history of exactly this drift (the `riskReward` vs `BacktestingService` split is a *deliberate* exception and says so).
6. **Event payload objects, not positional arguments.** Twelve agent events converted to "exactly one payload object carrying the subject, the fields and the signal", with the dispatcher injecting the subject so the scope key and the payload cannot diverge. August's `types/progress.ts` / `types/message.ts` events would benefit from the same shape, and the "injected subject wins even over a payload that carries an `agent` field" rule is a nice enforced invariant.
7. **Presets resolve the rows they can prove will start — by disk walk, never by import.** The measured result (238 ms → 0.7 ms per roster read; 2.45 s → 9 ms for three concurrent reads) came from *not* asking the module resolver about plainly-installed packages. August's provider/model list and preset rows are the same problem: prove resolvability by looking, not by importing, and report every failing row at once rather than one per reload.
8. **Snapshot-based observation instead of per-question reads.** One process-table read answers tree + session + liveness; but signalling deliberately keeps a *fresh* per-identity fence, because a cached observation defeats PID-reuse protection. "Cheap for the hot path, fresh for the dangerous decision" is a rule worth copying to any polling loop in August (market-data polls, provider health, background jobs).
9. **Advisory catalogs, never whitelists.** A model list drives selectors and diagnostics and never rejects a request; an unlisted model id still goes through. August's `ProviderConfigService` + `/models` route already leans this way — the note adds the rule that the *request* is the durable truth about what was used, not the UI's selection state.
10. **A naming contract as a design artifact.** "`SDK` means one thing"; "name the role that exists" (`Store` / `Registry` / `Runtime`); one vocabulary per family with no alias or compatibility package. August's `utils/` and `services/` layer is large enough that this contract is worth writing down before the next rename wave — with the explicit warning that renaming at scale is churn (239 files) and should be done in one window or not at all.

## 3. Trading-relevant findings

1. **The journal must record the evidence the model saw, not just the verdict.** DSH made image offload a *durable surface fact* and states the invariant plainly: "model-visible input is reconstructable from the session log". August's `TradeAnalysis` already carries `sourceRunId` and `modelsUsed`, but nothing records *which* evidence set (which chart window, which tool outputs, what got pruned by `compactForWire`) produced a verdict. Adding that to the analysis row is the DSH pattern verbatim, and it is what makes "why did the agent advise this entry?" answerable after a week.
2. **Advisory provider/model catalogs.** August's `/models` route and `ProviderConfigService` should offer models for UX without whitelisting them: a hand-declared OpenAI-compatible gateway must be usable with any model id, and a stale catalog must not fail a correct endpoint (DSH: "a model the catalog had not caught up with failed with `UNKNOWN_MODEL` even against a correct endpoint"). August's current runtime-configured provider model already does this; the finding is to *keep* it and to treat the UI list as advisory in the docs.
3. **Budgeted evidence, with exact omission counts.** Backtest output, Monte Carlo percentiles and chart payloads are exactly "bounded model-facing output". DSH's `TextRetainer`/`ItemRetainer` give one answer for "kept vs omitted", including the UTF-8-safe cut. August's `services/analysis/monteCarlo.worker.ts` and `utils/harnessMarks.ts` are the natural consumers: a clipped backtest should name how many runs were dropped, not just "truncated".
4. **Write batching for the journal.** August's SQLite writes (per-row inserts) pay a transaction each; DSH coalesces durable appends in a fixed 200 ms window with a single-flight drain and a `flush` barrier used by retirement and teardown — and it is explicit that the window is *not* an fsync SLA. August's trade-log writes are the same shape (many small rows in a burst), so a bounded batch plus one explicit flush at session end is a cheap win.
5. **Distinguish an identity from an offset.** `SessionSeq` vs `SessionLogOffset` is a two-brand rule that paid for itself in the projection cache (a stale cache could seed a fold from a row that was never authoritative). August's trade journal has the same hazard — a trade *id* versus a row *index* versus a *count* — and its `decidedAtOf()` fallback pattern (one place for the legacy read) is the same discipline applied to time.
6. **Reconstructability beats convenience.** DSH chose "one failed attempt and a retry" over a second, unlogged projection for image overflow, because the unlogged projection broke the invariant that a dispatched request is derivable from the log. For August, the analogue is: if the agent's view is clamped (window shortened, sample capped, provider switched), record the clamp as part of the row rather than applying it invisibly at render time.

## 4. Weak spots in the reference material

1. **These are decisions, not implementations.** Every claim about behaviour ("the implementation is smaller", "the loop's hot paths stay allocation-free") is asserted, not demonstrated, from inside the shard. The corroboration lives in other shards (tests, source), so the corpus is trustworthy about *intent* and silent about *reality*.
2. **The supersession graph is the real cost of the corpus.** 185 notes with dozens of "partially supersedes" chains; several notes are authoritative for one section and obsolete for another (e.g. the session-persistence note owns the seam but not the Zstandard encoding). There is no single index that says which note wins for a given question, so reading the corpus correctly is itself an engineering task.
3. **Pre-release renaming churn.** The naming-contract note renames 239 files (fixtures, goldens, docs, Python) for no user-visible benefit, and the bilingual corpus doubles the maintenance for every one of those edits. It is the clearest cautionary tale in the shard: naming is worth a contract, but the *cost* of a repo-wide rename is paid in a window that may not come again.
4. **Some measurements are host-specific or explicitly estimates.** The macOS `ps` table (14.33 ms for 795 processes), the 2.45 s roster read and the 61.8 MiB restore are measurements on one machine; the chat-navigation note labels its table "work-count estimates, not timing measurements". The *decisions* are sound; the numbers are not portable evidence.
5. **Known gaps are recorded but left open.** "Nothing disposes an agent" (per-preset cost), the projection-cache "poisoned home" incident (a bootstrap that wrote bad documents before validation), three experimental providers still declaring `dsh-mcp-client` as a dependency (issue #4628), and a `verify-package-dependencies` gate that selects no experimental package. Honest, but they show the corpus accumulates open seams faster than it closes them.
