# deepseek-harness :: dsh-notes-archived-process

**Files in shard:** 636 (read: 212, skipped with reason: 424)

**Reading note.** All 212 **English** Agent Notes were read in full; the decisions they record
are summarised one line per file in §1 (tables A and B). The remaining 424 files are the
**second and third copies** of those same notes (a Chinese `.zh.md` twin and a generated
`.i18n.yaml` pairing record). They were not read line by line; each was verified
mechanically instead — the pairing record's two blob hashes were checked against
`git hash-object` of the two files on disk (212/212 live), and every translation twin was
checked for title, language switcher and an exactly matching heading count (212/212). Their
per-file verdicts are in §1 "Tier 3". No file in the shard is unlisted.

**What this shard covers:** the repo's entire **archived Agent Note corpus** — 212 decision
records, each mirrored three times on disk: an English `.md`, a Chinese `.zh.md` translation
twin, and a generated `.i18n.yaml` bilingual-pairing record. The notes live under
`.agents/notes/archived/process/` (120 notes) and `.agents/notes/archived/simplification/`
(92 notes). They are *decision records*, not prose: each has a fixed skeleton
(`Problem` → `Decision` → `Alternatives considered` → `Consequences`), a `Status:`
(enum, dateless), an `Archived:` date, and an English/中文 switcher. Read as a set they are
the clearest available statement of the harness's engineering constitution: *mechanical gates
over prose*, *verify-don't-generate where the truth is static, generate-where-it-is-not*,
*every invariant gets a command that exits non-zero*, *delete rather than deprecate*,
*the docs corpus is itself gated*. The trading-relevant material is indirect (scheduling,
approval weighting, session-log representation, agent-loop state machine) and is called out
in §3.

**dead surface** in a live system and removes it, and each states the *evidence* that the
surface was dead.

## 2. Ideas worth stealing

Convergence flags: this shard covers **one** repository, so nothing here can be certified
`CONVERGENT` from this shard alone. Items marked *(likely convergent)* are ones the other two
reference repos plausibly share and that should be checked against the `pi` and
`hermes-agent` shards before being claimed as convergent. Everything else is **UNIQUE** to
this repo.

1. **Every mechanically checkable promise gets a command that exits non-zero.**
   *What*: the repo's constitution — "agents follow enforced gates far more reliably than
   prose conventions, and 'a lot of work' is not a cost argument when agents do the labor".
   *Where*: `.agents/notes/archived/process/2026-06-11-quality-gates.md:12`, with the full
   gate list at `:16` (max-strict TS, oxlint + type-aware rules, jscpd clone detection,
   per-file 100 % coverage, publint, workspace constraints, NodeNext consumer typecheck).
   *Why it transfers*: August Trading already runs a lint ratchet, a coverage gate and a
   release gate; what it lacks is the *principle* — every documented trading rule (R:R
   floor, ATR stop band, plan-validation refusal, settlement semantics) should have a
   command that fails CI, not a paragraph in `AGENTS.md`.
   *UNIQUE to this repo* (the formulation is; the practice is common). *(likely convergent)*

2. **Generate the reference from the artifact the model actually receives.**
   *What*: the tool-schema catalogue is produced by **booting each tool plugin** and reading
   `ctx.tools.schemas()` — "the exact `ToolSchema[]` the model is sent" — because a static
   parse "would produce a doc that lies" (runtime enum spreads, concatenated descriptions,
   config-chosen names, raw `ctx.tools.register()`).
   *Where*: `.agents/notes/archived/process/2026-07-02-tool-schema-catalog.md:14`, the crux
   at `:16`–`:25`, the completeness guard at `:29`.
   *Why it transfers*: August Trading's "desk tool catalogue" / prompt docs should be
   harvested from the registry the model is handed, with a completeness guard that fails the
   generator when a new tool package is not registered.
   *UNIQUE to this repo*.

3. **Detect drift in pasted definitions instead of trusting the paste.**
   *What*: `verify-type-equiv` checks that every type pasted into a doc still matches the
   source declaration **structurally and by JSDoc**, with a manifest enforcing 1:1
   block↔entry correspondence and an orphan scan that fails closed.
   *Where*: `.agents/notes/archived/process/2026-06-20-core-data-structures-catalog.md` —
   the `ts type-equiv` mechanism section and its *Verification lesson*.
   *Why it transfers*: August Trading pastes JSON schemas, prompt fragments, risk constants
   and outcome-engine shapes into `docs/plan/` and `AGENTS.md`; those pastes drift silently
   today.
   *UNIQUE to this repo*.

4. **Word budgets as a ratcheting gate, not a one-off limit.**
   *What*: "A doc at or below its target keeps at least 5 % headroom as its ceiling ratchets
   down; a doc above target keeps a frozen ceiling that prevents growth until it reaches the
   target."
   *Where*: `.agents/notes/archived/process/2026-07-04-doc-tiers-and-budgets.md:18`.
   *Why it transfers*: August Trading's `docs/plan/` corpus has exactly the accretion the
   note describes ("repeated rules, retold incidents, duplicated package maps"); a ratchet
   forces the relocation decision at the moment content is added.
   *UNIQUE to this repo*.

5. **If it is in the vocabulary, something produces it.**
   *What*: three vocabulary variants with no producer were deleted, and the admission policy
   is now explicit — a variant is added "when something first emits them, not declared in
   advance".
   *Where*: `.agents/notes/archived/simplification/2026-07-04-prune-producerless-vocabulary-variants.md`.
   *Why it transfers*: August Trading's trade types, signal kinds, outcome kinds and
   automation kinds are all merge-extensible enums; each producerless variant is a
   permanent obligation on every implementer and consumer.
   *UNIQUE to this repo*.

6. **One canonical record stream — no mirrors.**
   *What*: four `agent/*` boundary mirrors, then the token-stream mirror, then the steering
   mirror were removed so `session/event` is "the single live boundary/transcript stream";
   "the mirrors made consumers choose between two sources of truth for the SAME durable fact".
   *Where*: `.agents/notes/archived/simplification/2026-06-20-remove-agent-boundary-mirror-events.md:10`
   and `:16`; also `2026-07-02-remove-stream-chunk-mirror.md` and
   `2026-07-04-remove-agent-steering-mirror.md`.
   *Why it transfers*: August Trading's trade journal and its UI/agent surfaces should read
   one record; a parallel "activity" table is exactly this anti-pattern.
   *UNIQUE to this repo*.

7. **A blocked condition is `pending`, not `failure`.**
   *What*: a completed evaluation publishes `pending` when the work is blocked by a
   *reversible* condition (a draft, insufficient points, an unresolved `CHANGES_REQUESTED`),
   and only an evaluation error publishes `error`; the publisher's own health is a separate
   job.
   *Where*: `.agents/notes/archived/process/2026-09-09-blocked-weighted-approvals-remain-pending.md:10`,
   `:16`, `:26`.
   *Why it transfers*: a trade plan waiting on a broker fill, a missing quote, or a human
   decision must not be recorded as a failed trade; and the *gate that reports* the state
   must be separable from the *thing being reported*.
   *UNIQUE to this repo*.

8. **Approve with weight, and let weight be delegated.**
   *What*: an approval is worth `min(2, 1 + 4 × ownedLines / totalLines)` of the changed
   production lines the reviewer owns; `/delegate @user` transfers the sender's weight once,
   to a named recipient, for that PR only, and dismisses the sender's own review so GitHub's
   state stays consistent.
   *Where*: `.agents/notes/archived/process/2026-09-11-production-blame-approval-weight.md`;
   `.agents/notes/archived/process/2026-09-15-pr-approval-delegation.md`.
   *Why it transfers*: August Trading's human-in-the-loop approval for consequential actions
   could use ownership-weighted authority plus an explicit delegation path, instead of a
   flat "one approval" count.
   *UNIQUE to this repo*.

9. **A reviewed artifact, an explicit consent, and a fail-closed escape.**
   *What*: the plan-mode exit tool carries the reviewable plan in its argument, asks the
   human `Approve` / `Keep planning` with free text, and "only one `Approve` selection with
   no custom text consents"; an absent provider, a failed review or disposal mid-review
   "fails closed and leaves manual `/plan off` as the human escape path".
   *Where*: `.agents/notes/archived/simplification/2026-07-22-plan-specific-collaboration-state.md:34`, `:36`.
   *Why it transfers*: this is the shape of a human approval gate for a trading action —
   the artifact travels with the request, consent is explicit and unambiguous, and the
   failure mode is closed rather than permissive.
   *UNIQUE to this repo*.

10. **Bounded fixed-rate scheduling with latest-only catch-up.**
    *What*: the recurring selector is only `every_seconds` (≥ 300), "No missed occurrences
    are enumerated, persisted, or replayed", the five-minute minimum is a **per-rule**
    property rather than a global admission gate, and all overdue records join **one**
    batch with one shared decision time.
    *Where*: `.agents/notes/archived/simplification/2026-08-09-bounded-fixed-rate-schedule.md:16`,
    `:18`, `:20`.
    *Why it transfers*: a direct template for August Trading's scheduled automations and
    price alerts — do not replay a backlog of missed intervals, and never let one
    automation's cooldown throttle another's.
    *UNIQUE to this repo*.

11. **Scheduled work delivers conversationally, and claims only what it knows.**
    *What*: a due reminder waits for the agent's idle phase and calls `followup()`; it never
    steers, never interrupts the current turn, and "dispatch does not claim model success,
    user acknowledgement, or an external notification"; the narrow crash window stays
    at-least-once.
    *Where*: `.agents/notes/archived/simplification/2026-08-09-conversational-schedule-delivery.md:16`, `:18`.
    *Why it transfers*: an automated trade-log entry or alert should appear in the normal
    transcript and must not fabricate a "success" badge — the same "second meaning of
    delivery" trap.
    *UNIQUE to this repo*.

12. **Buffer-free telemetry: read the canonical log at the moment you need it.**
    *What*: the coordinator keeps no per-event copies; on-demand capture reads the canonical
    session log after a handoff cursor and deep-copies then, because the retained copy
    "grows without a bound for a long-lived session that never records feedback".
    *Where*: `.agents/notes/archived/simplification/2026-08-06-buffer-free-feedback-telemetry.md`.
    *Why it transfers*: the same argument applies to August Trading's journal/insights
    pipeline — do not keep a shadow copy of every trade event waiting for a signal that may
    never arrive.
    *UNIQUE to this repo*.

13. **Prove the process, not just the product.**
    *What*: the simplification skill was measured as two matched arms over three owner
    domains, blind-reviewed, with the result reported honestly — the baseline yielded more
    durable proposals, so the revision's benefit is "complementary discovery", not
    superiority; the study's limits are enumerated.
    *Where*: `.agents/notes/archived/process/2026-09-19-evidence-led-simplification-surveys.md`.
    *Why it transfers*: before August Trading adopts a "find simplifications" workflow, run
    it against a baseline and report the yield honestly, including the cases where it loses.
    *UNIQUE to this repo*.

14. **Make the deployment state its own composition.**
    *What*: raw execution requires `--config <path>`; a bare launch against a neutral base is
    rejected because "a process that settles successfully but has no usable entry point hides
    a missing deployment decision".
    *Where*: `.agents/notes/archived/simplification/2026-08-03-explicit-config-dsh-entrypoint.md`.
    *Why it transfers*: the trading analogue is a plan/profile that must state its
    instruments, risk limits and provider before anything runs.
    *UNIQUE to this repo*.

15. **A menu exists to disambiguate between targets.**
    *What*: when one action remains, the anchor gesture *is* that action and no popover
    renders; when the underlying flow has no hole to fill, no button is drawn at all.
    *Where*: `.agents/notes/archived/simplification/2026-07-31-one-route-to-add-a-workspace.md`.
    *Why it transfers*: a small, transferable UI rule for August Trading's action rows.
    *UNIQUE to this repo*.

16. **No arbitrary authoring over the wire.**
    *What*: preset authoring became a host-side copy plus "open the files", because the
    shape check leaned on a YAML dialect that includes `!!js` — "so 'shape-checked text' was
    still arbitrary code on the next mount"; the invariant is directional (no browser payload
    may *select* an arbitrary filesystem target).
    *Where*: `.agents/notes/archived/simplification/2026-08-08-copy-only-preset-authoring.md`.
    *Why it transfers*: August Trading's tool/prompt registry edits should be copy-and-edit,
    not free-text-over-the-wire.
    *UNIQUE to this repo*.

17. **A deterministic, read-only change-scope report.**
    *What*: one command resolves an explicit `--base`/`--head` and writes a versioned JSON
    report of committed, staged, unstaged and untracked paths; "the command never guesses or
    fetches a base, queries a hosting provider, or selects tests".
    *Where*: `.agents/notes/archived/process/2026-09-27-explicit-change-scope-report.md`
    (see §1 for the exact path).
    *Why it transfers*: the same discipline (deterministic scope, no guessing, no silent
    side-effects) is what an "evidence selection" helper for August Trading's CI should have.
    *UNIQUE to this repo*.

18. **Require a decision record for every non-trivial change, with the alternatives.**
    *What*: "Every non-trivial change adds or updates at least one Agent Note in the same PR",
    with a mandatory `Alternatives considered` section — "a decision recorded without what it
    beat invites the re-litigation Agent Notes exist to prevent".
    *Where*: `.agents/notes/archived/process/2026-07-19-require-agent-notes-for-non-trivial-changes.md:14`;
    the format gate in `2026-07-05-uniform-agent-note-format.md`.
    *Why it transfers*: August Trading's `docs/plan/` is a plan corpus but not a *decision*
    corpus; the "what did we reject and why" field is the missing half.
    *UNIQUE to this repo*.

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work.** No price monitoring lives in this shard, but
  the **scheduling** machinery is fully specified and directly transferable: a bounded
  fixed-rate vocabulary with a 300 s floor and **latest-only catch-up**
  (`2026-08-09-bounded-fixed-rate-schedule.md:16`), no cron/tz machinery, no global admission
  gate, and one shared batch for all overdue records (`:18`). Delivery is **conversational**:
  the reminder waits for idle, calls `followup()`, never steers, and claims only that the
  follow-up was queued — "dispatch does not claim model success, user acknowledgement, or an
  external notification"; the crash window stays at-least-once
  (`2026-08-09-conversational-schedule-delivery.md:16`, `:18`). Persistence underneath uses a
  single flush controller per live session with a fixed, non-resetting batching window, a
  `session/flush` barrier, and a retry pause that restores the complete ordered batch
  (`2026-07-23-collapse-persistence-flush-state.md`). *Idempotency, catch-up and a breaker
  after empty runs are all explicitly decided.*

- **Human-in-the-loop approval.** Two mechanisms, both worth copying. (a) A **plan review**
  where the reviewable artifact rides in the tool argument, the human answers
  `Approve` / `Keep planning` with optional free text, only an unambiguous `Approve` consents,
  and every other path fails closed with a manual escape
  (`2026-07-22-plan-specific-collaboration-state.md:34`, `:36`). (b) A **weighted approval
  commit status** that distinguishes an unmet, reversible merge condition (`pending`) from a
  failed evaluation (`error`), with the publisher's own health reported by a separate job
  (`2026-09-09-blocked-weighted-approvals-remain-pending.md:10`, `:16`). Weight is derived
  from **ownership of the changed lines** (`2026-09-11-production-blame-approval-weight.md`)
  and can be **delegated once** to a named reviewer (`2026-09-15-pr-approval-delegation.md`).
  The audit trail survives as durable events plus a status description; deleting a delegation
  command is recomputed from current comments, so the record stays inspectable.

- **Post-mortem / reflection loops.** The loop is *editorial*: an outcome becomes a new
  decision record, and a superseded record may be **consolidated into its successor only
  after the successor preserves every unique rationale, alternative, consequence and
  verification contract** (`2026-07-19-require-agent-notes-for-non-trivial-changes.md`),
  with the Chinese counterpart and pairing record removed in the same change. The
  stop-bad-rules-accumulating gate is the producerless-vocabulary rule (a variant without a
  producer is deleted) plus the invariant-companion rule: a package publishes a runtime check
  only when it can compare **independently diverging** observations — 209 "explained-empty"
  companions were deleted for exactly this reason
  (`2026-08-28-omit-unneeded-invariant-companions.md`). A removal note becomes the current
  owner only once the feature is absent from code, config, schemas, formats, docs and tests.

- **Multi-agent.** Debate is not the model here — subagents are **continuable children**
  addressed by name. The lessons: (i) merge the control service into the runtime service,
  because "sibling plugin presence" deciding execution semantics is the bug
  (`2026-07-26-merge-subagent-control-service.md`); (ii) one messaging operation with fixed
  Steer scheduling instead of a quiet send plus a waking follow-up
  (`2026-08-30-team-send-message-steer.md`); (iii) **separate the axes** — sandbox mode
  (enforcement), approval policy (permission) and plan mode (collaboration stance) must not
  share an abstraction, or "a user's explicit sandbox selection appears to succeed while
  silently doing nothing" (`2026-07-22-plan-specific-collaboration-state.md`); (iv) the
  model-visible result must carry the address the model can actually use — a **name**, not a
  UUID (`2026-09-15-model-agent-availability-and-team-targets.md`). Debate adds nothing;
  durable, resumable child sessions and one addressing vocabulary do.

- **Structured logs the model can query.** The session log is the answer: **append-only**,
  one canonical stream, no mirrors (see §2 item 6), JSONL + Zstandard frames, with a
  `SessionEventMap` vocabulary and a generated catalog. Simplifications that matter for a
  query layer: trace-only rows are folded into load-bearing events rather than kept
  (`2026-06-20-collapse-trace-only-session-events.md`), request headers use **canonical full
  snapshots** instead of a delta codec ("deltas are an encoding optimization, not a
  reconstructability requirement", `2026-07-12-simplify-session-log-representation.md`), the
  surface is a plain `readonly number[]` instead of pseudo-linked nodes, and the bilingual
  pairing record uses a **section-keyed** hash so unrelated edits never conflict
  (`2026-09-23-section-keyed-translation-pairing-records.md`, with a measured 46 % conflict
  reduction over 2 016 replayed merges).

- **Staying simple as features accumulate.** The simplification corpus is the answer, and it
  is a **systematic vocabulary of cuts**: one public stop primitive
  (`2026-06-20-public-agent-stop-api.md`), one title pipeline
  (`2026-07-22-tui-titles-from-session-title-service.md`), one schedule vocabulary, one
  route to add a workspace (`2026-07-31-one-route-to-add-a-workspace.md`), one editor family
  per preset (`2026-08-10-default-presets-single-editor.md`), one external-plugin
  distribution path (`2026-08-09-remove-repository-plugin.md`), and a whole product surface
  (TUI) removed when it had no shipped composition
  (`2026-08-04-remove-tui-package.md`). The stated principle: re-add a cut thing **with its
  first real consumer**, because "re-adding a seam method with a live consumer is cheap and
  better-designed than the speculative version, because the consumer pins the contract".

- **A note on scope.** This shard contains **no** trading-specific implementation: no
  exchange integration, no order lifecycle, no position/PNL model, no broker adapter. The
  findings above are process findings that transfer; anything about price/TP/SL detection
  lives in another shard.

## 4. Non-obvious decisions and gotchas

1. **The corpus is triple-mirrored, and the mirror is mandatory.** Editing an English note
   obliges the same change to update the `.zh.md` twin **and** re-record the `.i18n.yaml`
   pairing record (`2026-07-02-bilingual-docs-and-pairing-gate.md`). A drift is detected
   mechanically, but "when the two sides disagree, no mechanical rule picks a winner — the PR
   review does".

2. **The pairing record stores git *blob* hashes, not commit hashes** — because a same-PR
   edit has no commit hash yet, so a commit-hash record cannot express "consistent as of the
   state this PR introduces" (`2026-07-02-bilingual-docs-and-pairing-gate.md`). I verified
   this on disk: all 212 archived records are whole-file blob hashes, and every one still
   matches `git hash-object` of the two files.

3. **The newer section-keyed record format is NOT in these archived files.** The
   section-keyed decision (`2026-09-23-section-keyed-translation-pairing-records.md`) replaced
   the whole-file format, but it post-dates this archive: all 212 records here are whole-file
   hashes. Do not read the archived notes as evidence about the current format.

4. **The notes live under `archived/` — they are historical, not contracts.** Many describe
   features that no longer exist (a TUI package, `dsh-cli-demo`, stdio and Echo agents, an
   implicit `dsh` TUI, the SDK project toolchain). Each states its own supersession. Reading
   one note without its successors gives the wrong answer.

5. **Supersession is a chain, and it is long.** For example: the TUI package was decided, then
   kept, then deleted (`2026-08-04-remove-tui-package.md`); the readline front door was
   retired and then the whole surface removed
   (`2026-07-20-retire-readline-front-door.md`); `dsh`'s implicit TUI default became an
   explicit `--config` requirement (`2026-08-03-explicit-config-dsh-entrypoint.md`). The
   `Related` / `Supersedes` sections are the index; there is no generated supersession graph
   in this archive.

6. **The Agent Note format is gated, and the grandfather is deliberate.** `Status:` is a
   dateless enum that must agree with the folder; the `Alternatives considered` section is
   mandatory; proposal-era headings are banned in `implemented/`. Pre-format notes whose
   alternatives were not reconstructible carry the permanent comment
   `agent-note-format: alternatives-not-recorded` — "an honest gap on the record rather than
   fabricated rationale" (`2026-07-05-uniform-agent-note-format.md`). So the *presence* of
   that section is not uniform across the corpus.

7. **A note's own classification is path-encoded, not prose.** `{lifecycle}/{class}/date-topic.md`
   with a closed set of six classes; a note about how the repo is organized is a `process`
   decision even though it reads like architecture
   (`2026-06-20-agent-note-classification.md`).

8. **Several notes contradict a general rule on purpose.**
   `2026-08-08-automatic-translation-pairing-merges.md` records a merge driver that was
   later retired; `2026-08-19-remove-knip.md` records the removal of a gate that a later
   archived note (`2026-08-19-knip-config-cleanup.md`) still assumes exists. The archive is a
   timeline, not a snapshot.

## 5. Weak spots

1. **The corpus is enormous and self-referential.** 212 notes × 3 copies = 636 files and
   ~2 MB for a product that publishes nothing yet. The notes argue for *fewer* surfaces
   everywhere else while being themselves the largest surface in the repository. There is no
   index (the index was deliberately deleted as a merge hotspot,
   `2026-07-19-remove-generated-agent-note-index.md`), so discovery is tree navigation plus
   search.

2. **The bilingual corpus is a large, recurring cost centre — the repo says so itself.**
   The translation notes measure the price precisely: "a small English prose edit routinely
   cost tens of times its proportional share of tokens and minutes"
   (`2026-07-26-briefed-minimal-translation-updates.md`), which is why they later moved
   routine translation to a one-shot path and made the heavy path manual-only
   (`2026-08-08-lightweight-routine-documentation-translation.md`). The lesson generalises:
   the *second copy* is the expensive part, and the fix was to stop treating it as a
   first-class artefact.

3. **Gating has its own accretion curve.** `doc-sync` grew to 24 chained members with two
   hand-maintained member lists that drifted (one gate was in the chain but not in CI's
   list), and the fix was a scheduler
   (`2026-07-21-doc-sync-through-gate-scheduler.md`). Several gates exist only to police
   other gates. The corpus documents the failure mode without fixing the trend.

4. **Individual notes are too long for "one decision per record".** The fs-seam note
   (`2026-06-26-fsspec-style-fs-seam.md`) and the freeze-evidence note
   (`2026-09-06-agent-request-freeze-evidence.md`) run well past 10 KB and bundle several
   decisions, which weakens the discipline the format was designed to enforce.

5. **One simplification claim is explicitly not measured.** The
   `2026-09-19-evidence-led-simplification-surveys.md` study reports nine durable proposals
   and states plainly that "their future implementation checks were not run" and that "source
   reductions are estimates, not implemented diffs". A corpus that praises measurement
   elsewhere has one note that is not — honest, but it is the corpus's own soft spot.
