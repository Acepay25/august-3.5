# deepseek-harness :: dsh-scripts

**Files in shard:** 413 (read: 375, skipped with reason: 38)
**What this shard covers:** the entire `scripts/` tree of the DeepSeek Harness monorepo — the build, release, CI and verification layer that sits *around* the product. It contains no runtime product source: every file is either a build/CI script (262) or a test (151). The set is best understood as the harness's **quality-control surface**: gate runners, generated-document/catalog producers, schema and persistence verifiers, packaging and release machinery, a large family of "the gate must fail loudly" regression specs, and a recorded-session snapshot corpus. The through-line is that *every* rule is enforced by a script that can be run by one person on a laptop, and every script that could silently narrow its own corpus contains an explicit guard against doing so.

---

## 1. File-by-file

### Tier 1 — load-bearing source: none

This shard contains **no** `source`-typed files. Every one of the 413 files is typed `build-CI` (262) or `tests` (151) by the pre-computed classification: the shard is the harness's build/CI/verification layer, not its runtime product. The Tier-2 table below therefore carries every file that was read.

### Tier 2 — bulk: one row per file

Files above ~11 KB were read as head + full declaration/test-index + tail (the depth is noted where it matters); files at or below that size were read in full. The 38 files that were *not* read line by line — three binary OOXML fixtures, four large generated JSON/Python artefacts and the 31 recorded snapshot files — are listed in Tier 3 with the reason.

## 2. Ideas worth stealing

1. **Every gate that could narrow its own corpus carries an explicit anti-narrowing guard.** `scripts/coverage-exempt.spec.ts` proves that each coverage-exempt suite's positional filter and its exclude glob select the *same* non-empty file set; `scripts/locale-dictionary-parity.spec.ts` asserts the compared-pair count only *grows* so a broken discovery cannot hide a real asymmetry; `scripts/verify-client-ui-i18n.ts` carries a `MINIMUM_CLIENT_UI_SOURCES = 450` floor for exactly the same reason. **UNIQUE** to this repo. This is the single most transferable idea here: any August Trading gate that filters a corpus (a doc-link gate, a "dead control" sweep, a coverage exemption) should assert that its own filter still selects a non-empty, non-shrinking set.

2. **A canonical fingerprint that ignores source ordering, so "did the persisted shape change?" is a hash comparison.** `scripts/persistence-schema-model.ts:184` `canonicalizeSchema` partitions the type graph (bisimulation-style colouring) so reordered declarations, duplicated subtypes and differently factored recursive aliases all canonicalize identically; `schemaDigest` (`:282`) hashes that form. Compare with `scripts/persistence-changes.ts:553` — a schema change is only accepted with a written explanation and *recorded validation evidence*, and the placeholder text `TODO: explain this change.` is rejected. **UNIQUE.** August Trading's `TradeAnalysis` schema, the trade-log record and the notebook format all change over time; a source-order-independent digest plus a mandatory evidence field is a much better "did the stored data shape change?" test than a hand-written migration note.

3. **Sealed, append-only archives with an immutable content manifest.** `scripts/archived-agent-notes.ts:186` `extendArchiveManifest` appends hashes for new artifacts but refuses to let an existing seal change or vanish, and `:76` `validateArchiveManifestExtension` refuses any transition except three explicitly authorized hash pairs. **UNIQUE.** The same shape applies to August Trading's *rule/lesson* store: a retired rule's bytes should be frozen and hashed, and a later edit must be a new rule, not a rewrite of a retired one.

4. **One gate, one graph, and a `--check` mode that fails when the committed artefact is stale.** `scripts/gen-tool-catalog.ts` boots the tool plugins so runtime registration is the source of truth; `scripts/gen-config-catalog.ts` classifies every package and resolves referenced types without collisions; `scripts/gen-client-catalog.ts` reads the client slot surface *lexically* and emits a data module the host can read without importing a client runtime. Every generator has a `--check` mode. **UNIQUE.** The transferable pattern: derive the documentation/tool/rule catalogue from the *running* system rather than from a hand-maintained list, and make the gate fail on drift instead of regenerating silently.

5. **A "record the change or it did not happen" evidence trail for every compatibility decision.** `scripts/persistence-changes.ts` requires, for each type change, a decision (`same-version` / `version-bump`), a description, an explanation and an evidence link; `scripts/persistence-finalization.ts:112` loads *finalized* baselines with a digest check so a recorded snapshot cannot be edited after the fact; `scripts/persistence-releases.ts` verifies a pinned prerelease archive with no Git, no network and no source extraction. **UNIQUE.** August Trading's outcome/lesson pipeline is exactly this shape waiting to happen: a "why did this rule change?" record that is itself digest-checked.

6. **Bounded worker budgets derived from one shared function, with the reason in the source.** `scripts/parallelism.ts:14` caps local runs at 12 workers (48 for Vitest forks) because `os.availableParallelism()` reports *host* CPUs rather than a container's quota; every tool's explicit override still wins. `scripts/run-gates.ts:122` `runAggregate` and `:186` `defaultConcurrency` use it and print the source of the budget in the start line. **UNIQUE.** August Trading's `npm run test` and its render-probe would both benefit from one shared, explained default rather than each picking its own.

7. **Partitioned, weighted test scheduling instead of one giant suite.** `scripts/coverage-partitions.ts:342` `assignWeightedPartitions` seeds the heaviest files into *different* partitions and balances total weight, not file count; the coordinator then merges the partitions and only the complete merged inventory can enforce per-file thresholds. `scripts/coverage-fork-diagnostics.ts` adds exit metadata to a forked worker *without* changing Vitest's scheduling or failure handling. **UNIQUE.** The transferable idea for a large trading app: a long suite (e.g. backtests) is best split by *cost*, not by file count.

8. **The approval/publish decision is made against the registry, never against a list.** `scripts/release/publish.ts:176` `publishRelease` decides per package: a transient registry code (`:32` — E409/E429/E5xx/ETIMEDOUT/ECONNRESET/EAI_AGAIN) is retried up to four times with 2 s spacing, but a version already published with *different* content is a hard error. **UNIQUE.** The analogous August Trading rule: an approval that has already been granted must not silently re-approve a changed artefact — compare a content hash, refuse on mismatch.

9. **Fail closed on the shapes a checker does not understand.** `scripts/verify-export-jsdoc.ts` documents its own exemptions ("framework slots, constructors, inherited contracts, augmentations, and source re-exports keep their docs at the declaring contract") and states that *unknown forms fail closed*. `scripts/verify-no-unknown-casts.ts` rejects a *new* `as unknown as` while retiring recorded ones by syntax fingerprint. `scripts/verify-config-source-ownership.ts` says explicitly that its check "is not full YAML analysis" so nobody mistakes it for one. **UNIQUE.** Honesty about the limit of a checker is a rare and valuable property.

10. **The published set is decided by reachability, not by a manifest.** `scripts/verify-product-use.ts` resolves the real Loader composition (profiles, presets, overlay patches, dynamic mounts) and computes which packages and source modules are actually *reached*; `scripts/verify-default-product-isolation.ts:61` does the same for the default product, so an experimental package cannot reach the shipped surface through a manifest that merely names it. **UNIQUE.** August Trading has the same failure mode — a service that is "not in the default bundle" but is reachable because some default component imports it.

11. **A closed vocabulary for the decision record itself.** `scripts/agent-note-tree.ts:19` fixes the note classes to six values, and `:41` `walkAgentNoteTree` returns `{notes, errors}` where any unknown folder is fatal; the format gate (`scripts/verify-agent-note-format.ts`) then requires lifecycle-specific sections, a canonical `Status:` line, and rejects a legacy marker. **UNIQUE.** A decision log with a *closed* set of kinds and a *closed* set of headings is greppable; a free-form one is not.

12. **Bilingual documentation as a first-class, mechanically-checked artefact.** `scripts/translation-pairing-record.ts:42` stores a 16-hex hash per heading section per language, so an edit to one section changes one record line and merges with Git's default text merge; `scripts/translation-brief.ts` maps a change to the *narrowest safe* granularity (code-fence-only splice → changed Markdown units → heading sections → whole document) and refuses a mechanical splice when the prose also changed; `scripts/paired-markdown-derivatives.ts` treats a partial or reordered Chinese match as primary so the caller fails closed. **UNIQUE.** The generalisable idea is the *granularity ladder*: an automated updater should do the smallest safe edit and refuse anything larger, rather than rewriting the whole document.

## 3. Trading-specific findings

This shard is the *tooling* layer, not the trading runtime, so the six trading questions mostly belong to other shards. What this shard does contain:

- **Long-lived monitoring & scheduled work — not in this shard, but the reliability patterns transfer.** There is no cron/monitor code here. The closest analogues are the *scheduled-task-shaped* verifiers: `scripts/session-snapshot-corpus-policy.ts:41` asserts that a baseline/current *majority* of recorded generations is retained and that a refresh may not remove every direct migration input; `scripts/release/publish.ts:32` distinguishes a *transient* registry failure (retried, with backoff) from a *terminal* one (hard stop) — exactly the distinction a scheduled trade-monitor needs between "the broker was briefly unreachable" and "the order was rejected". The corpus policy is also a good model for a scheduled job's catch-up rule: a persisted baseline plus a majority rule beats a wall-clock schedule.

- **Human-in-the-loop approval — the approval *record* is the interesting part.** `scripts/archived-agent-notes.ts:76` seals content by hash and refuses any change to a sealed artefact, and `scripts/release/publish.ts:176` refuses to publish a version whose bytes differ from what was already published. Combined with `scripts/verify-plugin-record-callers.ts` (a release package must *declare* its events in the event map; only experimental packages may write ad-hoc records), this gives a two-part rule: a consequential action is allowed only from a declared surface, and its record is immutable once written.

- **Post-mortem / reflection loops — the "bad rules accumulate" problem is solved by digesting and expiring.** `scripts/persistence-changes.ts` requires an explanation and recorded evidence for every change to the persisted shape, `scripts/persistence-finalization.ts:112` freezes a *finalized* baseline with a digest, and `scripts/persistence-schema-model.ts:282` gives every shape a content hash. The corollary is the anti-accumulation rule: a rule whose text is edited in place is indistinguishable from a rule that was never evaluated, so a rule store needs content hashes and a finalize step. August Trading's `services/learning/` skill/rule lifecycle has no equivalent of `persistence-finalization.ts` today.

- **Multi-agent — not in this shard.** The nearest evidence is the recorded-snapshot corpus: `scripts/snapshots/python-sdk-single-exe/advanced/` holds the parent turn plus two *child* sessions (a direct child and a workflow child) with their own `subagent/descriptor` records, and `scripts/fixtures/python-snapshot-workflow-order.mjs` exists specifically to prove the parent records its handoff *before* the child runs. `scripts/session-fixture-layout.ts` then canonicalises the packed rows. The debatable-but-reasonable design is in the snapshot: the direct child and the workflow child are separate sessions with separate logs, so the parent's log stays small and the child's context is independently replayable.

- **Structured logs the model can query — the session log is JSONL, and it is the model-visible artefact.** Every recorded snapshot in `scripts/snapshots/python-sdk-single-exe/**` is a `.jsonl` of typed records (`turn/start`, `step/start`, `assistant/message` with a `stream` of typed chunks, `tool/call`, `tool/result`, `request/header`), plus a `result.json` that records the *event type sequence* and the *notification method sequence* rather than the payload. `scripts/session-query-spill-command.spec.ts` then proves the query path end-to-end: a spilled session is a real file on disk and `grep -Fq session_event_search "$file"` finds the event inside it. The design point worth stealing: the *index* of a run (which event types fired, in what order) is stored separately from the *payload*, so a summary can be compared without diffing megabytes.

- **Staying simple as features accumulate — the repo's answer is "make the feature count a checked number".** `scripts/doc-budgets.manifest.json` + `scripts/verify-doc-budgets.ts` cap the word count of seven standing documents (AGENTS.md at 2080 words, docs/AGENTS.md at 1430, docs/architecture.md at 2410) and fail if a budgeted file is *missing* — a renamed doc must update the manifest in the same change. `scripts/verify-package-readme-limitations.ts:16` fixes one canonical limitations heading and requires every package README to carry it (or to be on an explicit whitelist). `scripts/verify-package-readme-summaries.ts` caps a README summary at 100 words. The mechanism is a ratchet: the ceiling only goes down, and raising it requires a written justification in the same PR.

## 4. Non-obvious decisions and gotchas

1. **`scripts/clean.ts` resolves the *parent* of a deletion target, not the target itself.** `rm` unlinks a final symlink, but if the *ancestor* is a symlink the deletion crosses the repository boundary. The comment in the file says so explicitly. A reader who "simplifies" `realpath(path)` → `realpath(dirname(path)) + basename(path)` reintroduces a data-loss bug.

2. **`scripts/build-exe-for-python-sdk-staging.ts:73` `materializeStagedLinks` drops one symlink rather than dereferencing it.** The deploy target sits *inside* the deployed project, so pnpm links the project into its own `node_modules`; dereferencing would copy the payload into itself. The entry is unlinked instead.

3. **`scripts/benchmark-npm-resolution.ts` runs npm with `--package-lock-only` against a loopback registry that 500s every tarball request**, and then asserts `archiveRequests === 0`. The point is to measure *resolution*, not download.

4. **`scripts/pnpm-invocation.ts` and `scripts/executable-packaging.ts` never use a shell.** A `.js/.cjs/.mjs` `npm_execpath` goes through `process.execPath`; anything else is executed directly. `scripts/install-lefthook.spec.ts` even uses a `pnpm.cmd` path containing spaces and `;`/`$` metacharacters to prove it.

5. **`scripts/change-scope.ts` sets `core.fsmonitor=false` and `GIT_OPTIONAL_LOCKS=0` before touching Git.** Without the first, a configured filesystem monitor would be *executed* by a read-only scope query (the spec asserts the side-effect file does not exist); without the second, the query mutates the index.

6. **`scripts/verify-config-source-ownership.ts` is a one-line regex, and says so.** Its own docstring says "not full YAML analysis". A reader who assumes it is a YAML validator will trust it too far.

7. **`scripts/translation-pairing.ts --cached` reads the Git *index*, not the working tree**, so the git hook can check the staged bytes without a corpus scan. The mode is named `--cached` for that reason.

8. **`scripts/verify-no-top-level-await.ts` exempts a package `bin` by name and a shebang by its own reason** — a process entry is allowed to `await` at module scope; a library module is not, because it cannot be lowered to the synchronous CommonJS wrapper the browser-worker image loads.

9. **`scripts/persistence-schema-model.ts` treats names and source locations as *metadata*.** The digest is over the canonical graph only, so moving a declaration or renaming a type does not change the persisted shape. `schemaDigest` still differs when a *source annotation* is added — the annotation is part of the promise, not the shape.

10. **`scripts/verify-v3-event-vocabulary.ts` says "remote freshness was not checked"** in its own success message. It compares against an explicitly pinned *local* commit. A reader who assumes it validates the current upstream vocabulary will be wrong.

11. **`scripts/run-web-snapshots.ts` runs the serial browser owners first, then excludes them from the parallel pool.** A test that owns a port is never run beside another.

12. **`scripts/test-fixture-cleanup.ts` exists because Windows `rmSync` follows MOUNT_POINT junctions into their targets.** The fixtures junction the real `scripts/`, `node_modules/` and tsx package directories, so a naive recursive delete would delete the repository's own directories. The fix unlinks every symlink first and then retries the removal 50 × 200 ms, because Windows releases child-process and antivirus handles asynchronously.

13. **`scripts/verify-export-jsdoc.ts` fails CLOSED on unknown forms.** A checker that silently skips what it cannot parse is worse than no checker, because the gap is invisible.

14. **`scripts/persistence-changes.ts` and `scripts/verify-translation-pairing.ts` both treat a *missing* input as a failure with a remediation message**, not as an empty pass. A gate that passes because its corpus vanished is a gate that has stopped working.

## 5. Weak spots

1. **The scale of the gate layer is itself a risk.** This shard alone contains 262 build/CI scripts and 151 specs; `scripts/ci-workflow.spec.ts` (88 KB) and `scripts/run-gates.spec.ts` (60 KB) parse every workflow YAML and pin the job inventory. The repo's own defence is the `dsh-ci-test-reliability` skill and the "own every port and temp path" rule in `scripts/AGENTS.md` — but the surface area is large enough that a contributor can plausibly break CI without touching product code. August Trading should take the *technique* (a gate that re-measures its own census) and not the *volume*.

2. **Some gates are conservative by design in ways that will rot.** `scripts/verify-concrete-terms.ts` and `scripts/verify-repository-references.ts` both maintain hard-coded exclusion lists and a blocked-term string assembled as `'prove' + 'nance'` so the repository's own source does not contain the banned token. These are correct today and brittle the moment the vocabulary moves; they also have no owner or expiry.

3. **The bilingual documentation machinery is disproportionate to the product.** `scripts/translation-brief.ts` (23 KB), `scripts/translation-pairing.ts` (17 KB), `scripts/translation-links.ts` (14 KB), `scripts/translation-pairing-record.ts` (13 KB), plus a 37 KB prompt snapshot and a 74 KB terminology table embedded in it, all exist to keep an EN/ZH corpus in sync. That is a large, self-maintaining subsystem whose only product is a second language — a poor trade for a product that is trying to stay small.

4. **Several generators read a sibling's output rather than one shared source of truth.** `scripts/persistence-schema.ts` synthesises a throwaway roots file and builds its own TypeScript program; `scripts/persistence-changes.ts` reads a committed `docs/persistence-schema.json`; `scripts/render-persistence-schema.ts` renders from the inventory. The "source of truth" is the *committed JSON*, which is generated — so a broken generator can produce a self-consistent but wrong world, and only a second, independent reading (the review/evidence requirement) catches it.

5. **The coverage partitioning is elaborate for a repository whose coverage is enforced per-file on a merged inventory.** `scripts/coverage-partitions.ts` (33 KB) plus `scripts/coverage-fork-diagnostics.ts` plus `scripts/coverage-uncovered-locations.cjs` plus `scripts/coverage-exempt.ts` plus `scripts/coverage-file-times.ts` plus `scripts/coverage-canonical-locations.ts` is six scripts to make one number go up. A weighted-partition idea is worth taking; this much machinery around it is not.

6. **Recorded snapshots are large and their review story is thin.** `scripts/snapshots/python-sdk-single-exe/advanced/result.json` is 111 KB of expected event sequences, and `scripts/smoke-python-runtime.py` refreshes it with `--update-snapshots` after "reviewing the behavior" — a human instruction, not a mechanism. A snapshot corpus of this size invites the exact failure the repo elsewhere guards against: a blessed-but-wrong baseline.
