# deepseek-harness :: dsh-notes-archived-feature

**Files in shard:** 918 (read: 918, skipped with reason: 0)
**What this shard covers:** the ENTIRE `archived/feature/` tree of the DeepSeek Harness "Agent Note" corpus — 306 archived feature decision records, each present as an English markdown note, a Chinese markdown translation, and a generated bilingual-pairing sidecar (`.i18n.yaml`). Every note follows one rigid format: a `# Agent Note:` title, a `Status: implemented` line, an `Archived:` line, then `## Problem` / `## Decision` / … / `## Alternatives considered` / `## Consequences` (and often `## Testing`, `## Deferred`, `## FAQ`, `## Prior art`). These are not documentation of features — they are **decision records**: what was decided, what was rejected and why, what it cost. Read as a set, they are the single best available account of how a production harness makes and unmakes design decisions. The shard spans 2026-06-14 → 2026-09-28.

Reading method: every English note was read through a structured digest (title, status, every `##` heading with its opening prose, the bolded rejected-alternative names, and the consequences), and the eleven highest-value notes for this project were then read in full. The 306 Chinese notes were read for structure (title, `Status:`, `Archived:`, and every `##` heading) and every pair was machine-checked for status/archive/section-count parity. All 306 sidecars were parsed and every one of the 612 recorded git blob hashes was re-verified against the working tree with `git hash-object` — 612/612 match, so no bilingual pair in this shard has drifted.

Note on the `.i18n.yaml` sidecars: they are `generated-vendored` by the shard's own classifier, but each is ~500 bytes and was fully read (they are 5 lines: a 4-line explanatory comment plus two `filename: blobhash` rows). They are therefore reported as `read`, not `skipped`.

## 2. Ideas worth stealing

1. **The "Problem → Decision → Alternatives considered → Consequences" decision record, enforced by a gate.** Every note must carry a bold-led paragraph per *genuine* alternative and why it lost; a note dated before the format existed may substitute an explicit `alternatives-not-recorded` marker. `.agents/notes/README.md` (this repo's own note policy, read for context) states the reason outright: "A decision recorded without what it beat invites re-litigation — the failure Agent Notes exist to prevent." **Why it transfers:** August Trading has `docs/plan/` with an open-items list, but no record of *rejected* designs. A per-decision "what we chose not to do, and why" section — even three lines — stops the next agent from re-litigating a settled question. Paths: `.agents/notes/archived/feature/2026-07-06-sandbox.md` (the `## Alternatives considered` section lists five rejected sandbox designs); `.agents/notes/README.md` ("Alternatives considered — mandatory").

2. **A durable goal domain with compare-and-set revisions, a durable phase, and a SEPARATE live activation bit.** `.agents/notes/archived/feature/2026-07-19-persisted-same-session-goal-domain.md` splits two facts that most systems conflate: *the objective survives* (durable, in the session log as `goal/change` events) versus *the agent may auto-continue* (live `armed`/`disarmed`, never persisted). "Activation is never part of the persisted snapshot" — so a resumed session shows the goal but does not silently start working. That is exactly the surprise August Trading's automations must avoid. **Why it transfers:** a trading bot that resumes after a restart should show "you have an open plan" and wait for the human, not place trades because a flag was left on.

3. **An automatic round budget with an explicit *blocked* phase and a policy-owned blocker code.** Same note: phases are `active | paused | blocked | complete`; a blocked snapshot carries "a policy-owned lower-kebab-case code and a normalized free-form message, so usage limits, round caps, execution failures, and human-input dependencies share one lifecycle state without losing their cause." `maxGoalRounds` defaults to 256 and is enforced by the *admitted round* counter, which only advances from a positive sequential admitted `user/message` source number — so an ordinary human turn never spends the automatic-work budget. **Why it transfers:** this is the discipline August Trading's automation scheduler lacks — a cap that cannot be spent by the wrong actor, and a blocked state that records *which* limit stopped it.

4. **A "who gets to be woken, and how" delivery rule for background completions.** `.agents/notes/archived/feature/2026-08-11-background-job-completion-wakes-an-idle-owner.md`: an unreported completion picks its lane from what the owner is doing — *a busy owner is injected, an idle owner is woken with `followup()`* — and the note explains why the two are not interchangeable: "A cancelled turn is a user pressing stop, and reopening one on their behalf launders an interrupt into a model request they did not ask for." It also names the failure mode it is fixing as exactly the shape that breaks: "the model starts a long command, tells the user it started it, ends its turn, and the command finishes into an inbox nobody will claim." **Why it transfers:** this is the canonical formulation of "the agent said it started something, then went silent" — which is what a scheduled price alert or a long backtest looks like from the outside.

5. **The wake-chain is self-exciting, so the cap is opt-in but the reasoning is documented.** Same note plus `2026-09-22-unbounded-completion-wakes-by-default.md`: waking an owner costs a model request, and a woken turn can start the background job whose completion wakes it again — "with nobody watching." The shipped decision made the cap have *no default* (every completion wakes an idle owner) but kept the ledger machinery for deployments that set one, and the note explains the trade in both directions. **Why it transfers:** for August Trading's automation loop this is the difference between a bot that quietly spends tokens all night and one that stops.

6. **A settlement notice that is deliberately NOT the child's words.** `.agents/notes/archived/feature/2026-08-06-manager-owned-subagent-settlement-delivery.md`: the harness delivers the account itself, in a distinct `{ kind: 'subagent-settled', form: 'notice' }` shape, not the `agent-message` kind. "Merging them would credit the child with words it never wrote, and would make a durable log unable to distinguish 'the child said it was done' from 'the harness observed that it stopped.'" The delivery is *unconditional* for every child whose id a caller received, so the promise in the tool schema is service behaviour, not an optional plugin. **Why it transfers:** August Trading's `services/agents/` has per-bot memory and mailboxes; the same distinction (what the bot said vs. what the system observed) is worth an explicit kind.

7. **Bounded fixed-rate scheduling with no replay backlog and an honest completion claim.** `.agents/notes/archived/feature/2026-08-05-durable-web-schedule.md`: at a due decision, integer division selects the latest sequence point at or before the sampled wall clock, the occurrence is presented *once*, and the record advances directly to the future target — "so a cold Session never accumulates a replay backlog and delayed model work never shifts the sequence." And the honesty rule: "Dispatch records queue admission, not model completion or user receipt… The design makes no exactly-once promise." **Why it transfers:** a scheduled trading reminder that fires after a 3-hour downtime must not replay three missed reminders, and must not claim the user saw them.

8. **Approval scope as a delegation-time snapshot, with delegated children pinned to `approvalPolicy: 'never'`.** `.agents/notes/archived/feature/2026-08-10-subagent-approval-pinned-never.md` and `2026-08-10-continuable-subagent-policy-inheritance.md`: the child's sandbox inheritance "IS the complete delegation permission model," and a delegated child has no one to ask, so its approval policy is pinned to `never` — the scope it inherited is the boundary. The snapshot is captured before the first await and written into the durable child log. **Why it transfers:** August Trading's `services/agents/` spawns bot agents; a bot that inherits "full access" from the parent without a re-check is the same hole.

9. **The "one-time structured failure line" pattern for out-of-process subagents.** `.agents/notes/archived/feature/2026-08-21-out-of-process-subagent-minimal-diagnostics.md` and `2026-08-18-product-subagent-failure-facts.md`: each provider owns the mapping from the facts it already receives to **one fixed safe diagnostic line**; raw SDK errors, app-server payloads and stderr are explicitly rejected as return values; `SubagentResult` stays unchanged so consumers never parse product-private fields. **Why it transfers:** directly applicable to August Trading's provider-error handling — `toFriendlyProviderError` already does this for the main path, and the same rule should hold for every agent/backend surface.

10. **A canonical "current state" context contribution, resolved fresh per request, with no "last told" memory.** `.agents/notes/archived/feature/2026-07-30-current-sandbox-policy-context.md`: "Every agent request resolves the active session directly through `ctx.sandboxPolicy.resolve({ session })`; there is no denial-history scan or process-local 'last told' state." The note also reports a **wording experiment** with a pre-registered primary endpoint — it measured whether the model preemptively refuses, not just whether the text appeared. **Why it transfers:** August Trading's `utils/harnessMarks.ts` already owns "the one voice for text this app withholds from a model"; the pre-registered-endpoint experiment is a cheap, unusually rigorous way to verify a prompt actually changes behaviour.

11. **A compaction engine as a seam with a closed manual-error taxonomy and one durable lock.** `.agents/notes/archived/feature/2026-06-18-compaction-capability-seam.md` and `2026-07-30-queued-manual-compaction.md`: the interface declares `compactIfNeeded()`, `compactNow()`, `compactRegion()` abstractly; `/compact` maps a closed taxonomy (`busy | changed | failed | …`); "one durable lock" serializes manual compaction against automatic compaction. The consequence section names the cost precisely: "A prompt accepted before the compaction boundary… may still run on the old history." **Why it transfers:** August Trading already has `services/providers/contextCompact.ts` and `utils/contextWindow.ts`; the seam split plus a closed error taxonomy plus an honest boundary statement is the missing piece.

12. **Determinism as a product requirement, not a nicety.** `.agents/notes/archived/feature/2026-07-06-explicit-tool-order.md`: model-facing tool order followed plugin registration order, which depends on concurrent module loading — "That race produced different request headers in CI and snapshot recordings. Because order affects request bytes, caching, and the durable header, it needs an explicit deterministic policy." The default is plain lexicographic name order (code-unit, locale-independent), so determinism requires no configuration, and an unregistered name in an explicit list "rejects every `assemble()`". **Why it transfers:** August Trading's `constants/models.ts` and prompt registry have exactly this exposure; a stable order is what makes prompt caching work at all.

13. **A same-mode request needs no approval; only widening asks.** `.agents/notes/archived/feature/2026-09-16-sandbox-same-mode.md`: `approveEscalation` returns the effective mode immediately when the requested mode matches it, while wider modes still require approval and narrower/unsupported targets still fail closed. **Why it transfers:** a model that keeps re-asserting an already-granted capability should not keep spending the trader's attention; this is a one-line change with a large attention payoff.

14. **Cross-session references as a context consumer with a byte cap, not a copy.** `.agents/notes/archived/feature/2026-07-21-cross-session-references.md`: at most three references, each independently capped at 65,536 UTF-8 bytes by default, deduplicated in first-appearance order, resolved from the durable source with the target id rejected. **Why it transfers:** August Trading's trade journal is the obvious donor — "the same pair I traded on 2026-09-02" should pull the *record*, bounded, not silently re-open a session.

15. **A repeat-tool-call guard that is advisory, and that compaction deliberately does not reset.** `.agents/notes/archived/feature/2026-07-08-repeat-tool-guard.md`: count consecutive calls to the same tool with byte-identical canonical arguments, inject a reminder at thresholds, never block or rewrite. "Compaction does not reset chains: a compacted history changes what the model sees, but the repetition risk usually survives compaction." **Why it transfers:** August Trading has real loop risk (re-fetching the same price, re-running the same scan); the "compaction does not reset" observation is the non-obvious part.

16. **The archived-note corpus itself is a first-class artifact with a machine-enforced contract.** `.agents/notes/README.md`: archived triplets are "permanently frozen… Do not edit, translate, reformat, update, move, or delete it, and do not treat it as authority for current behavior." The verifier enforces "the closed class tree, complete triplets, archive metadata, sidecar hashes, and the append-only frozen-content manifest." Archiving is allowed only for a complete decision whose rationale "is unlikely to guide future work" — and the delete/archive/keep rules are calibrated by *meaning*, never by word count or a quota. **Why it transfers:** August Trading's `docs/plan/` would benefit from a frozen "historical decisions" tier that CI verifies, so old plan documents stop being treated as current.

17. **A bilingual-pair sidecar that makes translation drift a machine-checkable failure.** Each `.i18n.yaml` holds the git blob hash of both language sides as of the last confirmed-consistent state, with "Both languages carry equal authority." I verified all 612 hashes in this shard against the working tree and every one matches. **Why it transfers:** August Trading's docs are English-only today; the *mechanism* (hash the artefact, record the pair, verify in CI) is the stealable part — it generalises to "every generated artefact has a recorded expected hash".

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work.** The answer lives in `2026-08-05-durable-web-schedule.md` (the timing rules) plus `2026-09-24-fixed-rate-floor-one-minute.md` (the one-minute floor defined once in `packages/schedule/schedule/src/domain.ts` and restated by every surface that states the bound). Reliability comes from four explicit properties: (a) *absolute-time boundary* — the model must produce an offset-bearing RFC 3339 value or a local object with an explicit `time_zone`; the Host validates the calendar shape, rejects a DST-gap local time, and picks the *earlier* instant on an overlap; only canonical UTC is stored; (b) *bounded fixed-rate semantics* — integer division selects the latest due sequence point, presents it **once**, and advances straight to the future target, so there is no replay backlog after downtime; (c) *dispatch records queue admission, not completion* — a crash between admission and the durable receipt can repeat a reminder, and the note says so rather than pretending to exactly-once; (d) *no cross-record cooldown, gate, quota, or retained batch timestamp* — overdue records share one message and each contributes only its latest occurrence. What is **absent**: no recurring-rule engine for fixed intervals, no exactly-once fencing, no persistence of delivery receipts.

- **Human-in-the-loop approval.** Two layers. The *mechanism* is a shared user-approval seam with an answerer chain, never an ask-every-tool policy — `2026-06-14-acp-agent-client-protocol.md`: "The plugin that asks—such as a pre-execute policy or bash escalation—owns the decision to ask," and a missing or failed answerer stays **fail-closed**. The *audit record* is the session log itself: approvals are `approval/request` events with a call id, and the bridge maps the outcome one-shot. The *guardrails* are the escalation ladder (`2026-07-06-sandbox.md`): only the *same* operation may be retried, only *once*, only with a justification, only under a wider mode; "every non-grant outcome produces its distinct error text and executes nothing." Delegation narrows the model: a child is pinned to `approvalPolicy: 'never'` and its inherited sandbox scope *is* its permission model. In the GUI, `danger-full-access` is gated behind an explicit acknowledgement checkbox (`2026-07-31-gui-full-access-confirmation.md`), and dismissal submits nothing.

- **Post-mortem / reflection loops.** This shard is *strong* on the loop mechanics and *explicitly weak* on the judging. The Ralph tool (`2026-07-19-fresh-agent-ralph-workflow-tool.md`) implements the textbook pattern — a fresh child per round, the shared workspace as long-term memory, a small explicit handoff, a per-run child ceiling — but its own limits section says: "Completion and blocker status are worker self-declarations. An independent evaluator, evaluator-driven feedback round, completion certificate, or adversarial verifier is intentionally deferred." The same deferral appears in the goal round driver and in the goal domain ("the actor that records `complete` or `blocked` is authoritative"). What *is* built to stop bad rules accumulating: a round cap (`maxGoalRounds`, default 256) counted only over *admitted* rounds; a blocked phase that keeps the cause; a "one current goal per session" rule; and a durable replay validator that "fails replay rather than being ignored or repaired" on a malformed record, so a tampered or partially-written goal record is detected at the offending record instead of silently skipped. **The retirement/expiry machinery is NOT here** — that lives in the `simplification`/`process` shards.

- **Multi-agent.** The seam (`2026-06-21-subagent-capability-seam.md`) has an explicit anti-recursion rule: without a bound an in-process child can see the delegation tool and recurse, so the backends implement an absolute depth limit and a scoped live-global `toolFilter`, and the ACP backend advertises both capabilities *off* and rejects such a request. Backends are named siblings (spawn, fork, ACP, codex, claude-code) behind one `start() → SubagentRun` primitive — the value of a named backend is that a caller can pick one *by name* (`2026-08-18-product-subagent-named-instances.md`: a profile can expose several Codex and Claude Code tools backed by separate models and permission modes). **Where debate adds nothing and the note says so:** the ACP backend consumes `session/update` notifications and drops everything except the child's final answer — "so only the child's final answer surfaces." The parent does not receive the child's reasoning, tool cards, or intermediate chatter. The `2026-08-04-claude-code-and-codex-subagent-backends.md` note records the rejected alternative: "A shared product-process helper package" and "A model-visible product selector" — i.e. the parent model is never asked to *choose* a backend. The conclusion for August Trading: in this harness, delegation is a **fan-out for independent work**, not a debate mechanism; the value comes from parallelism (`2026-08-09-parallel-subagent-delegations.md`: sibling delegations in one assistant step overlap under the loop's rolling pool) and from context reset (Ralph), not from adversarial rounds.

- **Structured logs the model can query.** The session log is the canonical fact channel — every surface decision is a fold over it, and "the log is the fact channel" is why resume, fork and compaction restore state with no extra machinery. On top of it sits a **separate, rebuildable SQLite FTS5 index** (`2026-07-10-sqlite-session-query-provider.md`): "a rebuildable index must not share the authoritative log's schema, reset, or corruption." The design decisions worth stealing: `unicode61` was chosen over trigram after an experiment (it supports a two-character token `AI` and is ~2.1× smaller), ranking is fully deterministic and comparable across the persistent and TEMP tables (highlight-span count desc, document length asc, event time desc, session id asc), literal phrases make query syntax safe at the cost of boolean MATCH, and the reconciliation is one serialized operation comparing source-qualified revisions. The model-facing surface (`2026-07-24-model-facing-session-query-tools.md`) is deliberately thin — five read-only tools, **no cursor, offset, page size, or model-controlled result limit**, and authority derived from the caller's agent identity rather than anything the model supplies. Live sessions are overlaid on the persisted index via a TEMP table, so the current truth is never uncheckpointed durable state.

- **Staying simple as features accumulate.** The harness's own answer is the note corpus itself plus the `simplification` class of notes: a feature note may be consolidated into a later removal note only when the feature is absent from production code, configuration, schemas, durable formats, migration and compatibility behaviour, and no test exercises it as supported behaviour. And it tracks the *cost of the corpus*: "Do not archive toward a quota… Length does not matter." The shipped-surface test is a great one: `2026-07-31-even-out-shipped-tool-rosters.md` found that the two shipped surfaces "offered different tools for no recorded reason" and removed the difference. And `2026-08-11-minimal-profiles-bare-two-tool-runtime.md` ships a deliberate two-tool profile that mounts no compaction and no filesystem provider, so "minimal sessions never summarize or replace earlier history."

- **A defect found in August Trading while reading this shard (reported, not repaired).** Not a code defect but a process one: `docs/plan/` records *what* to do but has no section for *what was considered and rejected*, and no `full-audit.md` counterpart that captures a decision's alternatives. On the evidence in this shard, that omission is the exact failure the Agent Note format exists to prevent — "A decision recorded without what it beat invites re-litigation." Recommended follow-up, written into `docs/plan/` rather than code: add a "## Alternatives considered" convention to `docs/plan/open-items.md` and a frozen tier for superseded decisions.

## 4. Non-obvious decisions and gotchas

1. **"Idempotent polling patterns that repeat identical calls on purpose still receive nudges past the thresholds."** The repeat-tool guard (`2026-07-08-repeat-tool-guard.md`) is advisory and *wrong on purpose* for a model that is legitimately polling. It is documented as a known cost rather than hidden. A reader would assume the guard can tell the difference; it cannot, and the note says so.

2. **Compaction is a capability seam, and the tool-result pruner is a *separate* optional service** (`2026-06-18-compaction-capability-seam.md`) — not a mode of the engine. The pruner rewrites oversized current `tool/result` nodes *before* the backend picks a summary range, and is described as "model-free". The consequence section also says compaction receives *no prefix parameter*: the session prefix is folded by `ctx.tokenMeter`, not by the compaction engine.

3. **The session prefix is request-only and compose-once** (`2026-07-07-session-prefix.md`). The rejected alternative was the shape first proposed — "a waterfall firing on every request, contributing frozen `before`/`after` blocks." The shipped waterfall fires once and the composed prefix is reused "without changed headers." The whole note is an argument that a *stable opener* (skills catalog, AGENTS.md digest, workspace baseline) does not fit either of the two obvious homes — a rendered system prompt (wrong role weighting) or durable history (permanent, unrefreshable, forked stale).

4. **A session mode and the sandbox/approval knobs are deliberately different axes.** `2026-07-07-plan-mode.md`: "Modes are one axis and the enforcement knobs — the sandbox mode, the approval policy — are others: they never read or write each other, matching how Codex keeps its Plan/Default collaboration presets separate." The mode surface is a LIST everywhere it is advertised, never a boolean. The note also records that the first shipped shape (a per-mode tool allowlist with a deny-by-default gate) and the second (an `access` sandbox cap) were both *removed before release*.

5. **An `exit_plan_mode` schema stays byte-identical across every mode.** The note explains why: "That fixed cost avoids tool-catalog churn at mode boundaries." A tool whose schema changes with the mode changes the request bytes, which breaks caching and snapshots.

6. **The `todo_write` tool is deliberately a whole-list replace with last-write-wins, and no per-item ids.** `2026-06-29-todo-write-tool.md` justifies it by training data ("the shape the model is most trained on") and by replay simplicity. It also records the *protocol* consequence: because `todo/write` is a `SessionEventMap` member rather than a cordis `interface Events` event, it produces no catalog row and carries no `@mode` tag — the catalog generator scans `interface Events` declarations only.

7. **A `todo/write` event is a SIDE EFFECT, not a surface node.** `2026-07-23-web-todo-display.md`: "Consume `todo/write` as a Session side effect, not a surface node." Consequence: the todo list never perturbs the derived model history, and replay correctness is owned by one code path (`applyEventSideEffects`), so "any future change to window rebuild keeps todos consistent for free."

8. **The tool-call row's *title* and the tool's *name* are different things, and only the name is stable.** `2026-07-27-tui-tool-card-header.md` fixes the header as `{ring} Tool / <name>` because "the presenter [was] the fused verb-plus-detail string" and that varies per presenter. August Trading's `utils/toolKinds.ts` already draws the same distinction.

9. **A sandbox denial is a RESULT FACT, not an exit code.** `2026-07-06-sandbox.md` FAQ: "It RAN, and the kernel refused a file effect: the denial is a result fact orthogonal to exit code. The teaching forbids retrying around it; the one sanctioned move is the same command retried once with an escalation request." And: "How is a BROKEN sandbox told apart from a failing command?" — answered by an exact `ENOENT`/`EACCES` attribution for `argv[0]` with a usable workdir; a bare `syscall: 'spawn'` is *not* enough.

10. **A command-string heuristic preflight was rejected for a specific reason.** Same note: it "cannot understand expansion/subprocesses/symlinks; the strict attempt (run it, let the kernel decide)…" — i.e. the chosen design *is* the strict attempt.

11. **The grep/glob tools are conditional on `rg` existing, and the probe distinguishes "not installed" from "broken executor."** `2026-07-09-bash-backed-grep-glob-discovery.md`: a nonzero exit means "absent optional binary" → register neither tool nor prompt section, with a warning. But a probe that cannot start, times out, aborts, is killed, or produces no exit code "fails plugin load loudly because that is a broken bash executor rather than an absent optional binary." Also: full-run `grep` is accepted as slower than early-stop search, bounded by three independent caps.

12. **The FTS index lives in its OWN database, and the tokenizer choice was made by experiment.** `2026-07-10-sqlite-session-query-provider.md`: FTS tables are in a separate derived SQLite DB so "index corruption, reset, and tokenizer changes cannot endanger canonical logs." `unicode61` was chosen after an implementation experiment; the accepted limitation is stated plainly: "`AI` does not match the larger token `BRAID`, and arbitrary substring search uses the provider-independent text scan instead."

13. **Session-query reads are live-preferred, and a failing durable backend cannot make live history unreadable.** `2026-07-10-session-query-service.md`: "This path never consults persistence." An immutable header disagreement between live and persisted is a distinct error (`SESSION_QUERY_SOURCE_CONFLICT`).

14. **Positional replacement and cited-source relationships are two different edge types.** `2026-07-13-session-query-tracing.md`: "Positional replacement and cited-source relationships mean different things, so collapsing them into one generic edge type would also lose meaning." `replacedEventSeqs` lists the surface nodes *actually removed*; `sourceEventSeqs` preserves logged source order; the query does **not** follow cited sources transitively.

15. **A blocked goal keeps its cause; an edit preserves activation and blocker reason; resume and completion clear the reason.** `2026-07-19-persisted-same-session-goal-domain.md`. And the replay validator's asymmetry: "A malformed current-format record fails replay rather than being ignored or repaired." The incremental replay "remains positioned at the first corrupt event, so later reads report the same durable fault" — a reader would expect it to skip the bad record.

16. **The goal round driver re-checks every predicate *after* the await, and twice around the waterfall.** `2026-07-19-same-session-goal-round-driver.md`: it "checks once before delegating and again after downstream listeners return. This second check prevents an async listener from editing or pausing the goal while still entering the old prompt." A stale reservation closes a **blocked no-step turn** and does not charge the round. A downstream policy rejection that is not staleness *blocks the goal* rather than retrying around policy.

17. **Ordinary human turns are not goal rounds and never increment `roundsStarted`.** Same note. And a reserved `MessageId` is what distinguishes the driver's record from every other prompt.

18. **`agent.inject()` and `agent.steer()` are the same thing for a running owner, and different for a cancelled-but-not-converged one.** `2026-08-11-background-job-completion-wakes-an-idle-owner.md`: injection is correct there because "A cancelled turn is a user pressing stop, and reopening one on their behalf launders an interrupt into a model request they did not ask for."

19. **A human kill claims NO delivery.** `2026-08-26-human-job-kill.md`: "A delivery claim means 'the terminal state has a committed delivery path to the model', so the fix is to stop conflating cancellation with claiming that delivery." It cites peer products as evidence (Claude Code sets `notified: true` and the model learns nothing; Kimi delivers one). The kill reason is merged into the `killed` settlement's detail as text after the producer fact — "Anything parsing `detail` as a single producer fact must treat it as opaque text."

20. **A settlement notice is text-only on purpose.** `2026-08-06-manager-owned-subagent-settlement-delivery.md`: "Reasoning and tool calls, for example, cannot appear in a DeepSeek Messages user message; images are accepted by Messages but not by every parent model." Complete child output is retained separately for SDK and UI consumers.

21. **Parallel delegation is declared, not inferred.** `2026-08-09-parallel-subagent-delegations.md`: the tool declares `isConcurrencySafe: () => true` for every call form, satisfying a scheduling contract; "results still committed in model order." The consequence is honest: "Sibling children can race on shared workspace or external resources; the model owns that coordination."

22. **A one-shot child that is cut short is NOT classified as `completed`.** `2026-08-06-manager-owned-subagent-settlement-delivery.md` — `foldConsumedWork()` replaces `findLastMessageTurnEnd()` and moves to `dsh-agent`.

23. **The MCP client renames tools to `mcp__<serverName>__<tool>` and the note argues the token cost is worth it.** `2026-07-07-mcp-client-plugin.md`: "the qualifier buys stable identity, collision isolation, and MCP-wide policy shapes (`mcp__*`, `mcp__github__*`)" — and warns the public names are part of session history and permission APIs, so changing the algorithm after release is a breaking change. There is no three-package capability split: "there is no foreseeable second MCP client implementation, and the convention is 'don't split preemptively'."

24. **Model-facing tool order is lexicographic by default and an unknown name in an explicit list "rejects every `assemble()`".** `2026-07-06-explicit-tool-order.md`. The reason it must reject rather than warn: "cordis has no 'all plugins loaded' event," so there is no universal moment at which a missing name could be known-good.

25. **The pi-ai compat surface has a hard drift gate.** `2026-08-18-pi-ai-wire-compat-surface.md`: 34 upstream fields classified as `offer` or `withhold`, 23 offered. Every check runs in `resolveProfiles`, which "no request path re-enters," and the adapter memoizes by raw-snapshot identity. The line is stated as a principle: "a deployment must be able to state what nothing can infer from a private URL."

26. **Per-provider retry policies can be unbounded, deliberately.** `2026-07-24-provider-retry-policies.md`: the shared core default is five retries for every composition, but an explicit `always` policy "can spend unbounded requests and time on permanent" failures. The note treats the finite default as the safe default and the unbounded one as an explicit choice.

27. **A durable same-mode request needs no approval.** `2026-09-16-sandbox-same-mode.md`: "Argument pairing remains mandatory at the tool" — widening needs approval, narrowing and unsupported targets still fail.

28. **The GUI's Full-access path is gated by an acknowledgement checkbox, not a confirm button.** `2026-07-31-gui-full-access-confirmation.md`: "the enabling action stays disabled until an explicit acknowledgement checkbox is checked" and "every dismissal path submits nothing."

29. **Workspace deletion never touches the filesystem, and the confirmation says all three consequences.** `2026-07-27-workspace-registration-deletion.md`: "it never calls filesystem removal or `SessionPersistence`; the directory, every user file, and every session stays." The confirmation text "states all three consequences."

30. **`dsh web` refuses `0.0.0.0` outright, and the CLI exposes no network mode at all.** `2026-07-22-web-bind-address.md`. The token/cookie auth "does not broaden that deployment contract."

31. **Telemetry has three modes and the seam ships NO redaction rules of its own.** `2026-07-23-session-telemetry-otel-revival.md`: the innermost `next()` is a pass-through; deployments mount their rules; "a throwing rule withholds the record fail-closed." Redaction applies to the exported copy only — "the canonical log is never rewritten." And the honest warning: "A rule-free deployment exports each captured event body, including compact assistant streams and credentials embedded in file contents or command output."

32. **Telemetry defaults OFF and is consent-gated twice.** `2026-08-10-telemetry-default-off.md` (unset `DSH_TELEMETRY_MODE` = `DISABLED`) and `2026-08-05-feedback-gated-session-telemetry.md` (`FEEDBACK_ONLY` releases a canonical prefix only at an explicit new feedback). Every backend must also *disclose* its sharing policy (`2026-08-07-feedback-acknowledgement-sharing-disclosure.md`), so the `/feedback` acknowledgement can honestly name it.

33. **The anonymous user id is one `$DSH_HOME` = one stable user.** `2026-07-31-telemetry-anonymous-user-id.md`: a random UUID v4 in `$DSH_HOME/.anonymous-user-id`, carried as the OTel Resource `user.id` and matching the DeepSeek request header (`2026-08-11-deepseek-request-user-id-header.md`) and the `/feedback` acknowledgement — one identity across three surfaces, with no cross-home correlation.

34. **The plan-mode surface is a LIST, never a boolean** (`2026-07-07-plan-mode.md`), and the note's prior-art survey of Claude Code, Cursor, Copilot, OpenCode, Gemini CLI, Cline, Windsurf and Codex records the same five parts everywhere: low-authority tool policy, plan artifact, approval moment, execution-state switch, durable state.

35. **Plan review is a *decision*, not a question.** `2026-07-30-plan-review-presentation-intent.md`: the question carries a typed `intent` discriminant (`{ kind: 'plan-review', approve: string }`) so the Web composer renders it as its own surface; the rejected alternative was routing the card on the question's `id` or `header` string.

36. **A file's *path* is the durable fact; the attachment reference is not.** `2026-08-20-tool-card-image-results.md`: `read_image` persists `{ path }` in `presentationMeta` — "The attachment reference is deliberately not persisted there." And `2026-08-21-model-readable-image-paths.md`: `ImageAttachmentRef` "remains portable session data and contains no host path" — only the provider's host-object accessor exposes one, so the *execution world* can map it without the session data leaking a path.

37. **`present` has no workspace containment check.** `2026-09-09-present-filesystem-access.md`: "There is no workspace containment check or special temporary-directory allowlist." Missing files, directories, final symlinks and provider failures all reject the declaration.

38. **A settled assistant's file link is opened by a delegate provider, not by navigation props.** `2026-09-15-markdown-file-preview-links.md`: "nested link components read its current callbacks without adding navigation props to intermediate renderers" — and "Source references need no new Session event."

39. **The `archived/` tree is a closed class set enforced by a script.** `.agents/notes/README.md`: the classification set lives in `scripts/agent-note-tree.ts`; adding a class requires updating the canonical set. The archive has no `implemented/` folder because only implemented notes can enter it.

40. **The Chinese translation carries the same authority and the same machine-checked header tokens.** `.agents/notes/README.md`: the `# Agent Note: ` and `Status:` lines stay in English verbatim, the format gate skips `.zh.md`, and the *pairing* gate checks consistency. I confirmed across all 306 pairs in this shard: identical `Status:`, identical `Archived:`, identical section count.

## 5. Weak spots

1. **The corpus has enormous internal churn, and the archive is a symptom.** 306 archived feature notes in three and a half months, many of which supersede each other within days: the TUI banner is added, removed, re-added borderless and swept in (`2026-07-21-tui-no-banner` → `2026-07-21-tui-borderless-banner` → `2026-07-21-tui-banner-sweep`); the ACP bridge is an editor protocol, then automation-only, then the standard v1 automation subset (`2026-06-14-acp-agent-client-protocol` → `2026-07-23-acp-automation-only-protocol` → `2026-08-22-standard-acp-automation-controls`); `2026-07-07-plan-mode`'s own vocabulary is superseded two weeks later. Each note is individually well-reasoned, but a reader trying to learn "how does the TUI present a banner" must reconstruct four notes and their supersession chain. The notes are honest about this (they cross-link and carry explicit "Superseded" banners) but the corpus is expensive to read.

2. **The judgement half of every post-mortem loop is explicitly missing.** Four separate notes independently defer the same thing: an independent evaluator, a completion certificate, or a verifier-driven stop policy (`2026-07-19-fresh-agent-ralph-workflow-tool.md`, `2026-07-19-same-session-goal-round-driver.md`, `2026-07-19-persisted-same-session-goal-domain.md`, and the harness-level loop's own limits). Completion is a **worker self-declaration**. The round cap bounds *how many* attempts happen, not *whether any of them were right* — so a loop can burn 256 rounds that all confidently report success.

3. **Several notes ship a deliberate blind spot and document it rather than fix it.** The repeat-tool guard cannot distinguish legitimate polling from a stuck loop, and still nags (`2026-07-08-repeat-tool-guard.md`). The hook bridges accept a tool-input rewrite but only *log and warn* it, because the pre-execution args are already read by three other consumers (`2026-06-30-hook-bridges.md`). The MCP client re-registers tools on reconnect with a generation swap, and "a missed commit point leaks rows" is called out in the Web background-job note (`2026-08-08-web-background-job-display.md`). Each is individually defensible; together they mean the harness's *own* view of the world can be stale in ways it documents but does not prevent.

4. **Cross-workspace resume knowingly breaks existing users.** `2026-07-28-cross-workspace-resume.md`: moving sessions to one Harness-home root means "Sessions already stored under a project-local `./.sessions` disappear from `/resume`." The note accepts the cost because "no [migration] is a smaller surprise than a silent second root," but this is a shipped data-visibility regression.

5. **Two notes explicitly accept unbounded resource consumption by design.** `2026-07-24-provider-retry-policies.md` allows an `always` retry policy that "can spend unbounded requests and time on permanent" failures, and `2026-09-22-unbounded-completion-wakes-by-default.md` makes the consecutive-wake cap have *no default*, so every background completion reaching an idle owner costs a model request. Both are argued well; both are the kind of decision that needs a deployment-level budget to be safe in production, and the notes are candid that they are not.

6. **The notes are a corpus about a *coding* agent, and the transfer to a trading domain is by analogy, not by construction.** Every mechanism here is about code, files and shells. The "long-lived monitoring" answer in this shard is a reminder scheduler; the "post-mortem loop" answer is a fresh-agent re-run against a workspace. August Trading's actual post-mortem object — a trade that hit TP, one that hit SL, one that was correctly skipped — has no analogue in these 306 notes, and the subagent-completion-notice pattern (`2026-08-06-manager-owned-subagent-settlement-delivery.md`) is the closest structural match: a runtime-observed settlement, delivered unconditionally, in a shape distinguishable from what the worker "said". That is a promising template for a settlement-notice on a closed trade — but it is a template, not a solution, and I found no note here that closes a trade's outcome back into a rule.
