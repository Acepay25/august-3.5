# deepseek-harness :: dsh-credentials-identity-settings

**Files in shard:** 98 (read: 98, skipped with reason: 0)
**What this shard covers:** the credential, identity and settings capability family of the DeepSeek Harness monorepo — the `credentials` seam (a reference/record store whose configuration only ever *names* secrets), the `credentials-local` provider (a private, comment-preserving, hot-reloadable YAML document layered under the environment), the `authorization` seam (human-in-the-loop credential acquisition flows with a commit-confirmation contract), the `deepseek-account` / `deepseek-account-platform` packages (a concrete browser-PKCE account/billing integration built on those seams), the `anonymous-user-id` identity primitive, and the `settings` package (a schema-validated, layered, redacted configuration surface). Nothing here is a model-facing prompt or an agent loop; it is the substrate those things sit on — how a secret is named, stored, rotated, redacted, and handed to a plugin.

### `packages/credentials/credentials/src/index.ts`
- **Purpose:** the Service Definition for the credential-reference capability seam (`ctx.credentials`) — the abstract provider over **two disjoint key spaces** that answer two different questions.
- **Key abstractions:** `CredentialProvider` (`:171`), `credentialRef` (`:29`), `isCredentialRefName` (`:45`), `isCredentialKeySegment` (`:58`), `credentialKey` (`:69`), `parseCredentialKey` (`:85`), `credentialKeyScope` (`:101`), `credentialKeyId` (`:113`), `ResolvedCredential` (`:118`), `CredentialRecordInfo` (`:126`), `CredentialRecordEntry` (`:141`).
- **Data flow:** configuration names a `CredentialRef` (a POSIX identifier, `REF_PATTERN` at `:19`); a provider resolves it to a `{value, source}` per call, or a `CredentialKey` (`<scope>/<id>`, `KEY_SEGMENT_PATTERN` at `:22`) to a durable `CredentialRecord` owned by a plugin.
- **Non-obvious design decisions:**
  - **Two grammars, provably disjoint** (`:19`, `:22`). The `/` in a `CredentialKey` is what keeps it out of `REF_PATTERN`, so a record address can never be mistaken for an environment-variable name. `credentialRef(CODEX)` therefore *throws* (`packages/credentials/credentials-local/tests/records.spec.ts:59-70`).
  - **The scope is the owner, not the domain** (`src/types.ts:17-30`). A record's payload is written in its owner's format; two plugins serving the same provider name would otherwise read each other's payload, and a record left by an uninstalled plugin could not be told apart from a live one.
  - **Resolution is per-operation and never cached** (`:188-199`). "That per-operation read is what makes a changed credential reach the next operation without a restart" — the hot-rotation mechanism is the *absence* of a cache.
  - **An empty stored value is absent everywhere** (`:176-180`). `resolve` skips it, `describe` reports it unconfigured — a blank can never masquerade as a configured secret.
  - **Records never layer** (`:161-168`). Nothing can shadow a record, so *presence is the whole fact*; an `api-key` record carrying neither a key nor env values is a deliberate statement ("the owner confirmed ambient authentication"), not a blank.
  - **`modifyRecord` is the only record write path** (`:227-241`) because a correct write depends on the current value: a token refresh is read-decide-replace under one lock.
  - **A "probe" function beside every constructor** (`:45`, `:58`). `isCredentialRefName` / `isCredentialKeySegment` let a consumer holding an arbitrary settings-dict key ask "could this ever be addressable?" *before* building a key, so an out-of-grammar unit reads as "nothing stored" rather than as a thrown error.
- **Edge cases & failure handling:** `credentialRef` and `credentialKey` throw `TypeError` with the offending segment; `parseCredentialKey` refuses anything that is not exactly two segments. `listRecords()` returns addresses and tags only — never a value.
- **Surprising:** `fanOut` (`:283-300`) is a hand-rolled contained dispatch rather than `ctx.emit`, with a `jscpd:ignore` comment naming the deliberate symmetry with the settings seam — the *shape* is the reviewed contract, and extracting it would couple the two seams' event semantics.

### `packages/credentials/credentials/src/types.ts`
- **Purpose:** the client-safe type surface of the seam — the two key brands, the stored-record union, the reference view crossing the Remote wire, and the two Cordis event declarations.
- **Key abstractions:** `CredentialRef`, `CredentialKey`, `ApiKeyRecord`, `GrantRecord`, `CredentialRecord`, `CredentialInfo`; events `credentials/reference-updated` and `credentials/record-updated`.
- **Data flow:** types only; nothing here reaches a Host-only symbol, so a Client compilation face reads exactly the signature the Host emits.
- **Non-obvious design decisions:** **`CredentialInfo` has no slot a value could ride in** — "the view has no slot a value could ride in, which is what lets the whole read half cross the Remote wire" (`types.ts:88-95`). The two update events stay **separate** because the grammars are disjoint: a listener receiving both spaces on one event could not tell which space a subject belongs to (`types.ts:99-118`).
- **Edge cases & failure handling:** listener failures are contained on both events on the same terms.
- **Surprising:** `GrantRecord.payload` is `unknown` — "the seam never reads, validates, or reshapes it: it is written in the owning plugin's format and only that plugin can interpret it. The single constraint is that it survives a JSON round trip" (`types.ts:55-66`).

### `packages/credentials/credentials-local/src/index.ts`
- **Purpose:** the file-backed credential provider over `$DSH_HOME/.credentials.yaml`, layered over the environment: **file > inherited process env > project `.env` > home `.env`**.
- **Key abstractions:** `LocalCredentialProvider` (`:517`), `resolveSpec()` (`:88`), `parseCredentialsDocument()` (`:192`), `renderFlatLayoutMigration()` (`:245`), `CredentialsDocument` (`:170`), `Config` (`:64`), `CREDENTIALS_FILENAME` (`:61`), `DOCUMENT_VERSION = 1` (`:167`).
- **Data flow:** boot → `assertOwnerOnly` → `loadInitial()` (read + optional flat-layout migration under the file lock) → `parseCredentialsDocument` → replace both snapshots wholesale. Writes (`set`/`unset`/`modifyRecord`/`deleteRecord`) run through one exclusive `operations` promise chain, then `withFileLock(...)` → `reconcileFromDisk()` (re-read + fold) → mutate → `renderRef`/`renderRecord` → `writeFileAtomic(..., {mode:0o600, dirMode:0o700})` → publish exactly one `credentials/reference-updated` or `credentials/record-updated`.
- **Non-obvious design decisions:**
  - **Writes patch, reloads replace** (`:428-500` vs `:857-882`). A write edits the parsed YAML *tree* so comments and untouched entries survive byte-for-byte; a reload swaps the parsed snapshot wholesale so a deleted entry never lingers in memory. Two strategies for two different jobs, deliberately.
  - **Diagnostics never quote a value** (`:159-165` `describeYamlError`). The YAML parser's own error message embeds the offending source line — which in this document *is the secret*. Only the error code and line/column leave the parser. The whole file obeys "a key name is safe to print, a value is not" (`:203-207`).
  - **A strict document, not a dotenv file** (`:192-240`). Inside `refs` and `records` everything is *rejected* rather than skipped, because "a silently ignored entry reads as 'the credential I stored has no effect'". An unknown *top-level* key is tolerated, kept on disk, and warned about by name only.
  - **Records keep the owner's payload verbatim** (`:403` `assertJsonValue`). Unknown payload fields ride along (an owner's SDK gains fields between releases); a payload that cannot survive a JSON round trip (`.inf`, alias cycle, `Date`, `bigint`, `NaN`) is refused on the way *in* and on the way *out*.
  - **`describe()` says `writable: true` for every reference** (`:634-643`). A `set` writes the managed file, which outranks every fallback; an `unset` re-exposes the fallback.
  - **One exclusive operation chain** (`:733-741` `enqueue`). Watcher reloads and line edits run one at a time in queue order so an edit can never render from text a concurrent reload is busy replacing; a rejected write does not poison the queue.
  - **The lock wait is sized by the slowest *possible* holder** (`:112` `DOCUMENT_LOCK_WAIT_MS = 30_000`). A record mutation runs the caller's decision *while holding the lock*, and that decision includes an OAuth refresh round trip — so every writer of the document (including plain ref writes and record deletes) waits 30s rather than the file-work default of 2s.
- **Edge cases & failure handling:**
  - Boot on a document that exists but cannot be trusted **fails the plugin's activation** — never treated as "no credentials stored" (`:786-810`). A live reload that fails keeps the last good snapshot and warns (`:840-855`).
  - `assertOwnerOnly` (`:127-150`) refuses a document readable beyond its owner on POSIX and tells the user to `chmod 600`; on Windows the check is **skipped rather than faked**.
  - Disposal is a two-stage drain (`:578-604`): a `closed` flag refuses new work, the queued operations are awaited, and the watcher is closed *with a re-attached error listener* because chokidar's straggler write-settle poll stats the file this teardown is deleting, which Windows reports as EPERM, and an `'error'` emission with no listener is rethrown as an uncaught exception.
  - `reconcileFromDisk` runs before **every** write, so an external edit the watcher missed is folded in rather than overwritten.
  - `deleteSectionEntry` (`:480-497`) removes a comment block that annotated the *first* entry of a section, because the YAML parser attaches that comment to the section's map rather than to the pair — leaving it behind would silently re-annotate whichever entry became first.
- **Surprising:** `set` with an empty string is refused — "an empty value means 'no key', which is why an empty string in the file is rejected: removing a key deletes it, it does not blank it" (`:645-650`).

### `packages/credentials/authorization/src/index.ts`
- **Purpose:** the Service Definition for the `ctx.authorization` seam — a registry of plugin-owned flows that obtain a credential only a human can supply (sign-in, one-time code, account pick).
- **Key abstractions:** `AuthorizationService` (`:189`, `static inject = ['credentials']` at `:191`), `AuthorizationFlow` (`:125`), `AuthorizationSession` (`:90`), `AuthorizationInteraction` (`:151`), `AuthorizationRequest` (`:168`), `AuthorizationError` (`:62`), `AuthorizationDeclinedError` (`:79`).
- **Data flow:** `registerFlow()` stores a flow keyed by `CredentialKey`; `begin({key, method, interaction, signal})` validates → claims the key slot → runs `flow.run(session)` → the flow commits through `ctx.credentials.modifyRecord` → the seam confirms the commit → returns `{status:'authorized'}` or `{status:'cancelled'}`. A `finally` block releases the key and then emits `authorization/settled`.
- **Non-obvious design decisions:**
  - **The interaction travels with the request, not the registry** (`:151`). The surface that started the attempt is the one that renders the prompts, so there is no "which of two open pages owns this prompt?" ambiguity and a headless caller simply supplies an interaction that declines.
  - **Commit confirmation, not commit detection** (`:361-440`). The seam watches `credentials/record-updated` *during* the attempt and then re-reads `describeRecord`. Presence alone would let a re-authorization pass a stale record off as freshly obtained — the single most valuable idea in the shard (`src/index.ts:403-436`).
  - **A human's "no" is an outcome, not a breakage** (`:79`, and the `observed.declined` flag at `:389-393`). A declined prompt settles as `cancelled`; a prompt failure that is *not* a decline stays a flow failure (`:420-427`).
  - **Withdrawal settles the attempt even if the flow ignores the signal** (`:369-379`). `Promise.race([running, withdrawn])` releases the key immediately; the orphaned run is left to finish on its own, and a record it still manages to commit is treated as a record the human did authorize. A deliberate "a wedged key is indistinguishable from a busy key" escape hatch.
  - **`commit()` is a session method with a cancel-race guard** (`:383-393`): `attempt.committing = true` makes the write survive a cancellation that arrives *after* the commit was admitted, so an OAuth refresh that already started is not thrown away half-way.
- **Edge cases & failure handling:** `NO_FLOW`, `UNKNOWN_METHOD`, `ALREADY_IN_FLIGHT`, `DUPLICATE_FLOW`, `NOT_COMMITTED`, `CANCELLED`, `DECLINED` are all stable string codes. A pre-aborted request signal returns `cancelled` *before* claiming the key, but only after key/method validation, so a bad request still hears about it (`:296-302`). A withdrawn attempt's orphaned promise is explicitly `.catch()`-ed so it cannot become an unhandled rejection. Listener failures on `authorization/settled` are contained in both the sync-throw and async-reject paths (`:337-359`).
- **Surprising:** the whole `settle()` fan-out is hand-rolled rather than delegated to `ctx.emit`, with a `jscpd:ignore` comment explaining the deliberate symmetry with the credentials seam (`:330-336`). The key is released *before* `authorization/settled` fires, so a listener that reacts by starting the next attempt is not refused.

### `packages/credentials/authorization/src/types.ts`
- **Purpose:** the wire-safe vocabulary of the authorization seam, deliberately free of cordis/Service imports so browser type chains can consume it without pulling in the Context augmentation.
- **Key abstractions:** `AuthorizationMethod`, `AuthorizationNotice`, `AuthorizationPromptOption`, `AuthorizationPrompt` (a union of `text` | `secret` | `select` intersected with `{signal?}`), `AuthorizationStatus` (`'authorized' | 'cancelled'`), `AuthorizationSettlement` (status **plus** `'failed'`), `AuthorizationOutcome`, `AuthorizationEntry`.
- **Data flow:** pure types; the `AuthorizationPrompt` union is consumed by `AuthorizationSession.prompt` / `AuthorizationInteraction.prompt`.
- **Non-obvious design decisions:** `AuthorizationSettlement` exists *only* for the event stream — a failure reaches its own caller as a thrown error, so a watcher that did not start the attempt (a second browser tab) would otherwise have no way to tell a refusal from a breakage (`types.ts:69-74`). `secret` differs from `text` only in presentation; `select` answers with the option's `id` (`types.ts:52-66`). Each prompt carries **its own** `AbortSignal` so a flow racing a typed code against a browser callback can withdraw the losing question while the attempt continues (`types.ts:44-52`).
- **Edge cases & failure handling:** a notice never carries a secret; a prompt is the only channel that can.
- **Surprising:** the vocabulary is "deliberately smaller than any one provider's" — a surface that can render one flow renders all of them.

### `packages/credentials/deepseek-account-platform/src/index.ts`
- **Purpose:** the concrete browser-PKCE account provider — the one real consumer of the `credentials`, `authorization` and `credentials-local` seams, and therefore the most instructive file in the shard.
- **Key abstractions:** `PlatformAccount` (`:84`), `Config` (`:23` interface / `:52` schemastery schema), `Attempt` (the private attempt record), `KEY`/`DEVICE` credential keys (`:17-18`).
- **Data flow:** `startSignIn` → `ctx.authorization.begin(...)` (so the authorization seam owns the attempt lifecycle) → the registered flow's `run(session)` calls `this.run(session, attempt)` → `auth_init` (PKCE challenge + state) → register a **temporary** `/oauth/callback` route on the shared web server → wait for the browser → `auth_exchange` → `session.commit({kind:'grant', payload:{version, token, issuer}})` → the authorization seam confirms the commit → the provider redirects the browser to the completion URL. Profile/balance/bonus reads go through `details.ts`; sign-out through `logout.ts`.
- **Non-obvious design decisions:**
  - **The provider registers an authorization flow and then drives it from the outside** (`:139-149`, `:402-448`). The flow's `run` rejects unless a local attempt exists; `startSignIn` creates the attempt and *then* calls `ctx.authorization.begin`. The seam owns "one attempt at a time per key" and the commit contract; the provider owns the protocol.
  - **The credential lifetime is an `AbortController` that is *replaced*, not aborted** (`:107`, `:508-512` `invalidateDetails`). Every read captures `this.detailsLifetime` and compares identity afterwards (`if (this.detailsLifetime !== lifetime) return null`), so a credential change mid-flight discards the result instead of publishing it.
  - **A cached profile is bound to the grant token it was read with** (`:101-106`, `:277-288` `cacheProfile`). A cached identity therefore cannot answer for a credential that has since changed.
  - **The stored grant is issuer-bound** (`:19`, `:372-382`). A grant whose `issuer` differs from the configured `platformOrigin` is a *protocol* error, and at init a mismatching grant is deleted locally (`:167-176`) so the harness starts signed out rather than sending a foreign grant to a new environment.
  - **Client identity headers are provider-owned** (`:317-319`, `deepseek-account/src/index.ts:155-170`). Deployment configuration may name them, but the caller's `AccountClientMetadata` always wins; the embedded session keeps the deployment values and the consuming client composes its own identity on top.
  - **`resolveToken` is origin-exact and mock-aware** (`:384-400`). A `dsh_mock_` token is refused outright; a loopback issuer cannot authenticate the official production API; a non-production `inferenceOrigin` requires a grant issued by the configured platform origin.
  - **`expireCredential` re-checks the stored grant before deleting it** (`:328-343`). The removal only happens if the record still holds *that* token *and* that issuer and the lifetime is still current — so a late 401 cannot clear a replacement credential.
  - **The `removing` promise coalesces concurrent removals** (`:109`, `:328-330`, `:462-464`): one removal, one `signed-out` event, and `resolveToken` returns `undefined` for the whole window.
- **Edge cases & failure handling:** a *business* code (`biz_code !== 0`) is a `protocol` failure with a generic message — a `TODO(product-error-ui)` marks the copy as undefined (`protocol.ts:206-209`). A commit failure is reported as `storage` and does not redirect to success. A callback with a wrong/missing `state` is 400; a callback that arrives after the attempt moved past `waiting-browser` is 410. A commit *admitted* before cancellation completes, and the provider holds cancellation and disposal until the admitted write lands.
- **Surprising:** `getState()` reports `credential-stored` — "Stored-account presence is not a claim that the server has validated its token" (`deepseek-account/src/types.ts:39`). And `getPlatformSession()` **never issues a profile request** — it reuses the last successful profile read's stable ID, so an unknown ID leaves `userId` null ("temporary-storage mode") instead of delaying the caller.

### `packages/credentials/deepseek-account-platform/src/protocol.ts`
- **Purpose:** the validated HTTP surface of the Platform protocol — origin validation, browser-URL validation, header admission, the bounded response reader, and the error taxonomy.
- **Key abstractions:** `PlatformAuthError` (`:6`), `AccountUnauthorizedError` (`:12`), `platformOrigin()` (`:22`), `browserUrl()` (`:40`), `platformHeaders()` (`:62`), `requestPlatform/requestAccount/requestUnnotifiedBonuses/requestBonusNotified/logoutAccount` (`:93`, `:109`, `:123`, `:138`, `:159`), `loginOrigin()` (`:248`), and the zod schemas `envelope`/`initialization`/`exchange` (`:76-82`).
- **Data flow:** `platformRequest` → `fetch(..., {redirect: 'error', signal})` → status checks → a **streamed** body read with a 64 KiB cap → JSON parse → envelope validation → `biz_code` check → `biz_data`.
- **Non-obvious design decisions:**
  - **The response body is read as a stream with a hard size cap** (`:186-196`). A 64 KiB limit with a `body-limit` stage label means a hostile or broken endpoint cannot exhaust memory; the diagnostic records the *stage*, never the body.
  - **Every failure carries a stable code, never a body** (`:6-14`). `SignInErrorCode` is `no-response | network | protocol | expired | storage`, and the message is literally `account: <code>`.
  - **`callerCancelled` distinguishes a user cancel from a timeout** (`:167-170`): a `TimeoutError` reason is *not* a caller cancellation, so a timeout stays a logged failure while a cancel stays silent. This one predicate is what makes "successful requests, caller cancellation, and normal account state changes are silent" true.
  - **The browser URL is validated, not forwarded** (`:40-60`). The origin must match, the path must be the fixed `/dsh/authorize` or `/dsh/authorized`, and user-info and fragments are rejected. The rejection diagnostic names *which* rule failed (`originMismatch`, `pathMismatch`, `hasCredentials`, `hasFragment`) but never the destination.
  - **Deployment headers are admitted through a reserved-name blocklist** (`:62-74`): `authorization`, `x-dsh-auth-token`, `host`, `content-length`, `transfer-encoding`, `connection`, `content-type` are provider-owned, and duplicates (case-insensitively) are refused.
  - **`redirect: 'error'`** (`:175`) — a redirect is a failure, so a deployment cookie can never be forwarded to another host.
- **Edge cases & failure handling:** HTTP 401 *with* an `x-dsh-auth-token` header is `expired` (a rejected credential); a 401 on an unauthenticated exchange is a plain `protocol` failure, because an unauthenticated failure must not be read as "the stored credential died" (`tests/authorization-response.spec.ts:11-20`). Response code `40003` is `expired` only when the request carried a grant.
- **Surprising:** `loginOrigin` (`:248-262`) accepts only `http://localhost|127.0.0.1|[::1]:<explicit port>` — a *browser-accessible* origin for local or SSH-forwarded login. The path, query, fragment and user-info are all refused, and port `0` is refused.

### `packages/credentials/deepseek-account-platform/src/details.ts`
- **Purpose:** the Platform Web profile and wallet queries, projected for account UI consumers.
- **Key abstractions:** `profile()` (`:31`), `projectProfile()` (`:37`), `accountPayload()` (`:46`), the `queries` map (`:57-75`), `readAccountDetail()` (`:80`), `readUnnotifiedBonuses()` (`:98`), `sendBonusNotified()` (`:120`).
- **Data flow:** the shared response reader unwraps `biz_data`; this module validates it against a zod schema and projects it into the client-safe `AccountDetails` shape.
- **Non-obvious design decisions:**
  - **The decimal grammar matches big.js, not a naive number regex** (`:12-13`): `/^-?(?:\d+(?:\.\d*)?|\.\d+)(?:e[+-]?\d+)?$/i` — an omitted integer or fraction part and a decimal exponent are legal, so `0E-16` and `5.0000000000000000` stay valid, and the **original string is retained** rather than re-parsed to a float. The comment says the grammar is "the same one Platform's Web client already passes to big.js".
  - **Profile and balance are separate queries with separate outcomes** (`:57-75`, and the `AccountDetails` type's `status: 'ready' | 'failed'`). A failed balance never becomes a zero balance, and a failed profile never blanks a good balance.
  - **Only four profile fields are projected** (`:37-44`): id, name, avatar, contact. The response's own token is discarded ("response tokens and other fields are discarded").
  - **Contact masking is preserved verbatim** (`:40`) — "retains Platform masking without rewriting it".
- **Edge cases & failure handling:** a malformed payload throws `protocol` (and logs a field-path/code diagnostic, never a value). An unauthorized rejection is re-thrown as `AccountUnauthorizedError`; every other failure becomes `{status:'failed'}`.
- **Surprising:** bonus metadata (`campaign`, `amount`, `currency`, `granted_at`) is `z.custom<...>()` — forwarded **without validation** as opaque JSON, because it is metadata the owner will not interpret; but `order_id`, `msg`, `title` and `expires_at` *are* validated.

### `packages/credentials/deepseek-account-platform/src/logout.ts`
- **Purpose:** bounded, memory-only revocation of a token already removed from local credentials.
- **Key abstractions:** `LogoutRetryPolicy` (`:6`), `revokeAccount()` (`:16`).
- **Data flow:** up to `maxRetries + 1` attempts; between attempts it waits `delayMs * 2^(attempt-1)` (1, 2, 4, 8, 16 seconds by default); each request is bounded by `requestTimeoutMs`.
- **Non-obvious design decisions:** **a remote failure never restores the local login.** The captured token is revoked in the background; the local grant is already gone. The retry loop's `catch` is deliberately empty with a comment: "HTTP, business, and transport failures consume one attempt without restoring credentials."
- **Edge cases & failure handling:** the provider lifetime aborts both the in-flight request and the pending delay, and an already-aborted signal starts no work at all.
- **Surprising:** the delay uses `node:timers/promises`' `setTimeout` with `{signal, ref: false}` so a pending backoff never keeps the process alive.

### `packages/credentials/deepseek-account-platform/src/types.ts`
- **Purpose:** the platform provider's client-safe type surface — a two-line re-export of the account service's view types.
- **Key abstractions:** re-exports `AccountView` and `SignInAttemptView` from `@deepseek-ai/dsh-deepseek-account/types`.

### `packages/credentials/deepseek-account/src/index.ts`
- **Purpose:** the Account Service Definition shared by platform, API, and model consumers — an abstract seam over "read account state, start/cancel a browser login, sign out".
- **Key abstractions:** `DeepSeekAccount` (`:32`), `PlatformSession` (`:20`), `mergePlatformCookies()` (`:127`), `desktopClientHeaders()` (`:144`), `platformClientHeaders()` (`:155`), `platformWireLocale()` (`:172`).
- **Data flow:** the seam defines the *operations*; the provider owns persistence and the login lifecycle. `PlatformSession` is Host-only and never crosses the account RPC.
- **Non-obvious design decisions:**
  - **The service maintains no second credential index** — "The service defines account operations without maintaining a second credential index. The provider owns persistence and login lifecycle checks."
  - **`platformWireLocale` is one shared normalization** (`:172-174`): "A consumer whose request body carries that same wire locale reuses `platformWireLocale` so the header and body cannot disagree." One function, two call sites, no possibility of drift.
  - **The client-identity headers are exactly five, and the bundle ID is intentionally empty** (`:155-170`).
  - **`mergePlatformCookies` merges by name, case-sensitively** (`:127-138`) so a routing override replaces only the cookie it names and leaves the rest.
- **Edge cases & failure handling:** every abstract method's doc names its null/empty contract (`getProfile` returns `null` if signed out *or* if the grant changed during the query).
- **Surprising:** `getDeviceIdentity()` returns device/account IDs and an OS version string **without creating a device or returning credentials** — a credential-free identity read.

### `packages/credentials/deepseek-account/src/account-tasks.ts`
- **Purpose:** the account sign-out policy over the latest logged request route.
- **Key abstractions:** `isRunningAccountTask()` (`:12`), `installAccountTaskCancellation()` (`:20`).
- **Data flow:** on `deepseek-account/signed-out`, every *running* Agent whose `session.requestContext()?.provider === 'deepseek-account'` is cancelled with `{kind:'hook', reason:'deepseek-account/signed-out'}` and `{keepInbox: true}`. On `agent/error` with `LlmError` code `ACCOUNT_SIGN_IN_REQUIRED`, the seam emits `deepseek-account/model-sign-in-required`.
- **Non-obvious design decisions:** **cancelling a task retains its inbox** (`:33`) — the agent's work is not lost, only its run. And the predicate uses the *latest bound request route* rather than the agent's identity, so only work that actually used the account route is interrupted.
- **Edge cases & failure handling:** the installation lives inside `ctx.inject(['agents'], ...)`, so it detaches with its owning plugin (`tests/account-tasks.spec.ts:38-45`).
- **Surprising:** "Before a new turn binds its first request, this predicate still sees the previous turn's provider" — a documented, accepted imprecision.

### `packages/credentials/deepseek-account/src/types.ts`
- **Purpose:** the client-supplied request identity and the client-safe account state.
- **Key abstractions:** `AccountClientMetadata`, `SignInAttemptId`, `SignInErrorCode`, `SignInAttemptView`, `AccountLinks`, `AccountView`, `AccountUserId`, `AccountProfile`, `AccountWallet`, `AccountDetails`, `AccountBonusOrderId`, `AccountBonusNotification`, `AccountBonusBatch`; events `deepseek-account/session-expired` and `deepseek-account/model-sign-in-required`.
- **Key decision:** `SignInAttemptView.phase` is an **eight-value union** (`initializing | waiting-browser | exchanging | committing | succeeded | cancelled | expired | failed`) — the attempt lifecycle is a named vocabulary, not a boolean.
- **Surprising:** `AccountBonusNotification.expiresAt` is `string`, and "An empty string means the notice never expires" — the *absence* of an expiry is encoded as an empty string rather than `null`, because the field crosses a wire that admits no unconstrained data.

### `packages/identity/anonymous-user-id/src/index.ts`
- **Purpose:** one anonymous, harness-home-scoped id shared by telemetry, feedback, and DeepSeek provider requests.
- **Key abstractions:** `getOrCreateAnonymousUserId()` (`:68`), `AnonymousUserId` (`:26`), `ANONYMOUS_USER_ID_FILE_NAME` (`:29`), `AnonymousUserIdOptions` (`:34`).
- **Data flow:** resolve the home → memo lookup by **resolved file path** → read the file → validate against a UUID pattern → else mint `crypto.randomUUID()` and write with the exclusive flag `wx` → on `EEXIST` reread and adopt the winner's value → on an invalid reread, overwrite → memoize.
- **Non-obvious design decisions:**
  - **Random, never derived** (`:1-9`). "it is never derived from the hostname, network address, git remote, or any other identifying source, so anonymity is a property of the mint."
  - **Synchronous and memoized** (`:19-21`). One process touches each resolved path once; reads and writes are sync so boot-time and command consumers can use one API.
  - **Best-effort persistence** (`:96-104`). A read-only home still yields a usable id for the run, so telemetry and feedback are never blocked.
  - **The `wx` flag is the concurrency arbiter** (`:88-99`). The loser of a concurrent first launch rereads and adopts the winner's value.
- **Edge cases & failure handling:** a corrupt file is overwritten with a fresh id; an unwritable home returns a valid in-memory id and persists nothing; the memo means deleting the file mid-run does not change the process's id.
- **Surprising:** the documented race — "A reread landing in the winner's narrow create-to-write window can still yield two per-process ids for that run; the next launch converges on the persisted one" — is stated in the source rather than hidden.

### `packages/settings/settings/src/index.ts`
- **Purpose:** the `ctx.settings` service — a Config-schema projection into editable forms, with revisioned edits over Cordis profile patches.
- **Key abstractions:** `SettingsForms` (`:223`), `SettingsConflictError` (`:45`), `SettingsDescriptor` (`:20`), `SettingsPathOp` (`:81`), plus the module-private `applyPathOp` (`:86`), `cloneJsonShaped` (`:134`), `mergeLayers` (`:175`), `member` (`:194`), `inheritedConfig` (`:213`).
- **Data flow:** `describe()` walks the config editor's entries → for each active entry with a volatile form, project the *raw*, *base* (inherited) and *user* layers → redact → emit a `SettingsNamespaceView` with a monotonic `revision`. `update`/`replace`/`mutate` validate the input, check the revision, check that every touched path is volatile, and hand a merged document to `configEditor.edit()`.
- **Non-obvious design decisions:**
  - **Revision-based optimistic concurrency** (`:45-64`, `:394-399`). Every descriptor carries a `revision`; a write that sends a stale `expectedRevision` is refused with `SettingsConflictError` (code `SETTINGS_CONFLICT`, carrying both revisions) rather than silently overwriting a concurrent change. The revision increments when the raw entry's fingerprint changes *or* when the entry disappears (`:337-343`).
  - **Path mutation exists because the client never received the secrets** (`:74-80`). A wholesale `replace` rebuilt from a redacted document would silently delete every secret the wire never returned; `mutate` applies a set of path ops against the *current* document so untouched secrets survive.
  - **`cloneJsonShaped` is a hand-written JSON validator, not `structuredClone`** (`:122-171`). "structuredClone alone would admit Dates, Maps, BigInts, and cycles that YAML/JSON storage then silently distorts on the reload round-trip." It rejects non-finite numbers, cycles (with a `WeakSet` that un-marks on exit so a shared reference is not a cycle), class instances, symbols and functions; `undefined` object entries are *skipped* (sparse-patch semantics) while an `undefined` array entry is *rejected*.
  - **`mergeLayers` merges plain objects recursively and replaces everything else wholesale** (`:175-190`) — arrays included.
  - **Volatility is checked twice** (`:388-392` and `:401-408` `validatePaths`): once for the declared op paths, once over the *result*, so a write cannot smuggle a non-volatile field in through a nested object.
  - **The form schema is a plain copy with secret defaults removed** (`:19-33` `plainSchema`). A `role('secret')` node loses its `default` and its `required`; a non-secret default is run through the redactor.
  - **`describe()` can be called with or without redaction** (`:302`, `:326-330`): wire readers always request redaction, local callers may not.
  - **A failed refresh is logged, not thrown** (`:279-294` `invalidate`). A queued microtask refresh after disposal publishes nothing.
  - **The legacy `settings.yaml` import renames the file *before* the first write** (`:241-264`). A partial import therefore never repeats; a section the running composition rejects is logged and stays only in the renamed file.
- **Edge cases & failure handling:** a missing entry throws `No configurable plugin entry`; an entry with no volatile fields throws `no volatile fields`; a non-volatile path throws `not volatile`; an out-of-range array index throws `out of range`; a non-plain root throws `plain object`; a stale revision throws the conflict error. `configure()` refuses a second registration for the same fiber ("Settings presentation is already configured for this plugin instance", `:266-277`).
- **Surprising:** `inheritedConfig` (`:213-221`) catches a resolution failure and falls back to the *raw* inherited values, because "the profile override supplies fields the inherited layers lack; the form shows their raw values as the base."

### `packages/settings/settings/src/schema.ts`
- **Purpose:** derive editable forms and plain values from plugin Config schemas.
- **Key abstractions:** `plainConfig()` (`:10`), `plainSchema()` (`:19`), `volatileForm()` (`:37`), `projectForm()` (`:59`), `isVolatilePath()` (`:74`).
- **Data flow:** `volatileForm` walks the schema and keeps only the subtrees under a `volatile()` node; `projectForm` then narrows a *value* to the fields the form schema declares.
- **Non-obvious design decisions:**
  - **A `!!js` expression is one node and is kept whole** (`:50-52` `isExpression`). "Projecting it field by field would replace it with `{}` on the next write" — a Cordis config expression would otherwise be destroyed by an unrelated edit.
  - **`projectForm` drops fields the schema does not declare** (`:59-70`) but keeps the expression node intact.
- **Edge cases & failure handling:** an object schema with no declared fields projects to `{}`; `volatileForm` returns `undefined` when nothing is live, which the service treats as "no form".
- **Surprising:** `plainConfig` resolves a `volatile` runtime reference by calling `.get()` — the form shows the *current* value of a live reference, detached.

### `packages/settings/settings/src/redact.ts`
- **Purpose:** structural secret redaction — `role('secret')` fields are removed before a value crosses a wire boundary, with a sidecar recording each secret position and whether it currently holds a value.
- **Key abstractions:** `RedactedSecret` (`:27`), `RedactedValue` (`:35`), `redactSecrets()` (`:106`), the recursive `walk()` (`:51`).
- **Data flow:** `walk` descends the live schemastery node in step with the value, recording `{path, set}` for every secret node and returning a detached copy with the secret fields absent.
- **Non-obvious design decisions:**
  - **The sidecar enumerates *unset* object-property slots too** (`:55-58`, and `redact.spec.ts:33-42`). "object properties always (even unset, so a form knows the slot exists), dict entries and array items only where the value has them." A form therefore knows a secret field *exists* and whether it is filled, without ever receiving the value.
  - **The walker visits every union branch** (`:93-95`) and conservatively removes any field declared secret by a branch — the safe direction.
  - **A secret-role *container* is one opaque leaf** (`:56-59`, `redact.spec.ts:73-79`): `z.object({inner}).role('secret')` removes the whole object, not just its inner field.
  - **Keys outside the schema are preserved** (`:64-68`) — the redactor is not a whitelist; it only removes what the schema declares secret.
  - **Duplicate paths are merged with OR semantics** (`:107-113`): a slot reported by two union branches is one slot, `set` if either branch saw a value.
- **Edge cases & failure handling:** malformed containers pass through untouched (a `providers` value that is not a dict is returned as-is); structural nodes missing their relation maps are tolerated; the input is never mutated (the test freezes it).
- **Surprising:** `redactSecrets` returns `undefined` for an `undefined` value while still enumerating the object-property secret slots — so an empty section still tells the form what it could hold.

### `packages/settings/settings/src/types.ts`
- **Purpose:** the client-safe configuration form views and the change notification.
- **Key abstractions:** `SettingsNamespace`, `SettingsSecretView`, `SettingsNamespaceView`, `SettingsPathOpView`, `SettingsDescribeValue`, and the event `settings/document-updated(ns, revision)`.

## 2. Ideas worth stealing

1. **A "commit confirmation" contract for any human-in-the-loop write** — `packages/credentials/authorization/src/index.ts:361-440`. The seam does not check "is the record there?" but "did *this* attempt commit it?" (it watches the update event during the attempt and re-reads afterwards). Presence alone would let a re-auth pass a stale credential off as fresh. August Trading's skill-approval flow should refuse to report "approved" unless the notebook write was *observed during that attempt*. `UNIQUE`.
2. **"A human's no is an outcome, not a breakage"** — `packages/credentials/authorization/src/index.ts:79` and `:420-427`. A decline settles `cancelled`; a *different* prompt failure stays a failure. August Trading's approval inbox should have the same three-way split (approved / declined / broken) so a "No" never shows up as an error toast. `UNIQUE`.
3. **Diagnostics that never quote a value** — `packages/credentials/credentials-local/src/index.ts:159-165` and the file-wide rule "a key name is safe to print, a value is not"; the same discipline in `packages/credentials/deepseek-account-platform/src/protocol.ts:172-246` (a bounded stream reader, a stage label, a code — never a body) and in `tests/diagnostics.spec.ts` (a test that asserts the *absence* of a secret in the log). August Trading's provider-error mapping should never interpolate a key or a response body, and the test should assert the absence. `UNIQUE`.
4. **Reject inside the trusted boundary, never skip** — `packages/credentials/credentials-local/src/index.ts:192-240`. Inside `refs`/`records` an unparseable entry is a hard boot failure, because "a silently ignored entry reads as 'the credential I stored has no effect'". Outside them a foreign top-level key is kept and warned about *by name*. A two-tier admission rule worth copying for any persisted user configuration. `UNIQUE`.
5. **Writes patch, reloads replace** — `packages/credentials/credentials-local/src/index.ts:428-500` vs `:857-882`. Two different strategies for two different jobs: a write edits the parsed tree so human comments survive; a reload swaps the snapshot so a deleted entry never lingers. `UNIQUE`.
6. **One exclusive operation chain + a read-modify-write fold before every write** — `packages/credentials/credentials-local/src/index.ts:733-785`. Every write re-reads the document under a cross-process lock before patching, so an edit the watcher missed is folded in rather than overwritten. August Trading's `Preferences` write path has no equivalent fold. `UNIQUE`.
7. **Revision-based optimistic concurrency on a settings surface** — `packages/settings/settings/src/index.ts:45-64` and `:394-399`. Every descriptor carries a monotonic `revision`; a write that sends a stale one is refused with a machine code (`SETTINGS_CONFLICT`) and both revisions, rather than silently overwriting. August Trading's provider-config and model-menu writes have no such guard. `UNIQUE`.
8. **Path mutation instead of wholesale replace, because the client never received the secrets** — `packages/settings/settings/src/index.ts:74-80` and `:367-375`. A `replace` rebuilt from a redacted document silently deletes every secret the wire never returned; `mutate` applies path ops against the current document so untouched secrets survive. The same reasoning applies to any August Trading form that reads a redacted provider config and writes it back. `UNIQUE`.
9. **A hand-written JSON-shaped validator instead of `structuredClone`** — `packages/settings/settings/src/index.ts:122-171`. `structuredClone` admits Dates, Maps, BigInts and cycles that YAML/JSON storage then *silently distorts* on the reload round trip. The replacement rejects non-finite numbers, cycles (with a `WeakSet` that un-marks on exit so a shared reference is not a cycle), class instances, symbols and functions — and treats an `undefined` object entry as "skip" but an `undefined` array entry as "reject". `UNIQUE`.
10. **A credential lifetime is an `AbortController` that is *replaced*, not aborted** — `packages/credentials/deepseek-account-platform/src/index.ts:508-512`, `:191-203`. Every read captures the current lifetime object and compares *identity* afterwards, so a credential change mid-flight discards the result instead of publishing it. The same "capture the generation, compare identity after the await" pattern is what keeps a cached identity from answering for a rotated credential. `UNIQUE`.
11. **A cached value bound to the credential it was read with** — `packages/credentials/deepseek-account-platform/src/index.ts:101-106` and `:277-288`. The cached profile carries the grant token it was read under; a lookup for a different token misses the cache and re-reads. August Trading's provider-config cache has the same latent bug: a rotated key can leave a stale model id cached. `UNIQUE`.
12. **A stable, named lifecycle vocabulary for a long operation** — `packages/credentials/deepseek-account/src/types.ts:22-30` (`initializing | waiting-browser | exchanging | committing | succeeded | cancelled | expired | failed`) and `packages/credentials/credentials-local/src/index.ts` (`describe`/`resolve`/`set`/`unset`). A phase enum, plus the rule that a *failure* reaches its caller as a thrown error while a *refusal* is an outcome, is a vocabulary August Trading's turn-status module already half-has. `CONVERGENT` (the `pi` and `hermes-agent` repos are said to do the same; not verified in this shard).

## 3. Trading-specific findings

- **Human-in-the-loop approval:** the reference's answer is a *flow registry* + a *commit contract*. A consequential action is gated by a plugin-owned flow; the flow must **commit the durable artifact before it resolves**, and the seam refuses `NOT_COMMITTED` otherwise (`packages/credentials/authorization/src/index.ts:429-436`). The approval record *is* the committed artifact, and the audit trail is the `authorization/settled` event carrying `authorized | cancelled | failed` (`:337-353`). The same file pins the four refusal codes a UI must distinguish.
- **Structured logs the model can query:** not in this shard — the credential store is deliberately not a queryable log. The nearest thing is the seam's event stream (`credentials/reference-updated`, `credentials/record-updated`, `authorization/settled`, `deepseek-account/signed-out`, `deepseek-account/session-expired`, `settings/document-updated`), a live fan-out rather than a persisted log. **However**, the *diagnostics* discipline is directly transferable: `packages/credentials/deepseek-account-platform/src/protocol.ts:172-246` is a queryable, secret-free, machine-classified log (path, status, stage, field path, code) and `tests/diagnostics.spec.ts` proves it never leaks a value.
- **Long-lived monitoring & scheduled work:** not in this shard, but two transferable patterns are: the **watcher** in `packages/credentials/credentials-local/src/index.ts:578-604`, `:840-882` (one serialized refresh chain, a reconcile at watcher `ready` to close the setup race, wholesale snapshot replacement, and a "keep the last good snapshot and warn" policy for a failed reload) and the **bounded background revocation** in `packages/credentials/deepseek-account-platform/src/logout.ts:16-40` (at most N attempts, exponential delays, provider-lifetime abort, and a captured token so a later login is never revoked).
- **Post-mortem / reflection loops:** not in this shard — no outcome-to-rule loop exists here. The nearest analogue is the **grant-expiry → session-expired** path (`packages/credentials/deepseek-account-platform/src/index.ts:328-343`): a rejected credential is removed, the removal is announced exactly once, and *other* HTTP failures retain the grant so a transient 500 never logs the trader out.
- **Multi-agent:** not in this shard, but one ownership rule is directly relevant — an account task is cancelled by **route**, not by agent identity: `isRunningAccountTask` (`packages/credentials/deepseek-account/src/account-tasks.ts:12`) checks `session.requestContext()?.provider`, so only work that actually used the account route is interrupted, and the inbox is retained.
- **Staying simple as features accumulate:** the whole family is one vocabulary reused. Two key spaces, one document, one lock, one write chain, one redactor, one projection. The seam packages (`credentials`, `authorization`, `deepseek-account`) each expose **one** abstract service and no state of their own — "The service defines account operations without maintaining a second credential index" (`packages/credentials/deepseek-account/src/index.ts:117`).

## 4. Non-obvious decisions and gotchas

- A "credential" is a **name**, never a value, in configuration. `CredentialRef` is a POSIX identifier; `CredentialKey` is `<scope>/<id>`. The `/` is what makes the two spaces incapable of colliding (`packages/credentials/credentials/src/index.ts:19-22`; pinned by `packages/credentials/credentials-local/tests/records.spec.ts:59-70`).
- The **managed store always outranks the environment**, and `describe()` reports `writable: true` for *every* reference, because a `set` writes the top layer and an `unset` re-exposes the fallback (`packages/credentials/credentials-local/src/index.ts:634-643`).
- The environment layer is a **frozen launch snapshot**, not `process.env` — a variable exported after startup is invisible to both `resolve` and `describe` (`packages/credentials/credentials-local/src/index.ts:558-566`).
- `set('')` is **refused**, not stored. Removing a key deletes it; it never blanks it. But an api-key *record* with no key and no env is "configured" — a deliberate statement, not a blank.
- A `grant` payload must survive a **JSON round trip in both directions**; YAML-only spellings like `.inf` are refused, and so are `Date`, `bigint`, `NaN` and class instances. A payload the write path would refuse is refused *before* it is rendered, so a rejected write leaves no file behind at all (`packages/credentials/credentials-local/src/index.ts:678-712`).
- The document's **comment above the first entry belongs to that entry**, and is removed with it — the YAML parser attaches it to the section's map, so leaving it would re-annotate whoever became first (`packages/credentials/credentials-local/src/index.ts:480-497`).
- The lock wait is **sized by the slowest possible holder** (30s) because a record mutation holds the cross-process lock across a network round trip — and *every* writer of that file waits, not only the slow one (`packages/credentials/credentials-local/src/index.ts:100-115`).
- The credentials **directory** is 0700 and the **file** 0600; on POSIX the provider *refuses to load* a document other users can read, and on Windows it skips the check rather than faking it.
- **Authorization state never enters a model request prefix** — every README in the family carries a "Model Experience / KV Cache effect: none" section. The credential family is deliberately outside the model's view.
- A **business failure code** (`biz_code !== 0`) is mapped to the *generic* `protocol` failure, and a `TODO(product-error-ui)` marks the copy as undefined. The reference chose not to guess product behaviour from a backend code (`packages/credentials/deepseek-account-platform/src/protocol.ts:206-209`).
- `callerCancelled` treats a `TimeoutError` reason as **not** a cancellation, which is the single predicate that makes "a user cancel is silent, a timeout is a failure" true (`packages/credentials/deepseek-account-platform/src/protocol.ts:167-170`).
- A **`balance` failure is not a zero balance** and a **profile failure is not a blank profile** — the two queries have independent outcomes, and the failure branch supplies no amount at all (`packages/credentials/deepseek-account/src/types.ts:68-73`).
- The Platform's wallet balances are **strings, never floats**, and the original string is preserved: `0E-16` and `5.0000000000000000` stay exactly as the server spelled them, because the grammar is the one big.js accepts (`packages/credentials/deepseek-account-platform/src/details.ts:12-16`).
- A **stored grant is bound to its issuer**. A grant whose issuer differs from the configured origin is a protocol error, and at init it is deleted locally so the harness starts signed out rather than sending a foreign credential to a new environment (`packages/credentials/deepseek-account-platform/src/index.ts:167-176`).
- The **`getPlatformSession` snapshot issues no profile request.** It reuses the last successful profile read's stable ID; an unknown ID leaves `userId` null, which consumers treat as "temporary-storage mode" (`packages/credentials/deepseek-account-platform/src/index.ts:358-370`).
- A **configuration UI reads a redacted document**, so a wholesale replace would delete the secrets it never received. Path mutation exists for exactly that reason (`packages/settings/settings/src/index.ts:74-80`).

## 5. Weak spots

- The same-UID limitation is stated honestly but not solved: the agent's tool processes run as the same OS user, so a file-based store "cannot isolate secrets from the agent". The OS-keychain provider is deferred (`packages/credentials/credentials-local/README.md`, "Who can read the file" and the Dev Note).
- Concurrent writes to the **same reference** are last-write-wins — there is a lock and a read-modify-write, but no revision check (`packages/credentials/credentials-local/README.md`, Known Limitations). The `settings` seam *does* have a revision check, so the credential store is behind its own sibling.
- The 30-second lock wait is a *global* property of the document: one slow OAuth refresh makes every other writer of that file wait (`packages/credentials/credentials-local/src/index.ts:100-115`).
- A **live reload never migrates** a restored pre-release flat document — it keeps the last good snapshot until the next boot, so a user restoring an old file mid-session sees stale credentials (`packages/credentials/credentials-local/src/index.ts:786-810`).
- The `authorization` seam's in-memory test double is an acknowledged near-duplicate of the one in `credentials/tests/memory.ts` (`packages/credentials/authorization/tests/memory.ts:19-21`).
- The platform provider's `src/index.ts` is ~650 lines with the attempt lifecycle, the PKCE flow, the credential-lifetime bookkeeping, the profile cache and the sign-out path **all in one class**. The boundaries between "protocol", "lifecycle" and "cache" are legible in the comments but not in the types; a reader has to track four `AbortController`s (`logoutLifetime`, `detailsLifetime`, the attempt's own, and the deadline) to reason about cancellation.
- `deepseek-account-platform` is tied to one vendor's protocol and mixes product decisions (copy, `login_source`, bonus notification shapes) with transport code in the same package, so the reusable parts (the header builder, the diagnostics discipline, the bounded reader) are not separable from the DeepSeek specifics.
- The `settings` form schema is projected on every `describe()` and the whole document is re-validated on every write; the tests bound the composition work for 190 entries but the form projection itself has no such bound.
- `packages/identity/anonymous-user-id`'s file format has **no version marker** (the README's own Dev Note flags this), so adding a second value beside the id has no migration story.
