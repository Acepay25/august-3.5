# deepseek-harness :: dsh-notes-impl-arch

**Files in shard:** 531 (read: 354, skipped with reason: 177)
**What this shard covers:** the entire `.agents/notes/implemented/architecture/` corpus of the
DeepSeek Harness — 177 English architecture decision notes, each mirrored by a Chinese
translation (`.zh.md`) and a generated bilingual-pairing hash manifest (`.i18n.yaml`). Every note
carries the same four-part shape: `## Problem`, `## Decision` (with `###` sub-decisions),
`## Alternatives considered` (each rejected option named), `## Consequences`. They are the repo's
authoritative record of *why* the harness looks the way it does — the event-sourced session log,
bounded request recovery, timeout/deadline policy, tool-output spill files, provider routing,
context compaction, agent presets and sub-agent catalogues, host schedules, credentials, plugin
loading, projections, and the web/desktop packaging. This shard is therefore the best single
source for *design intent* in this repo: the code shows what happens, the notes show what was
ruled out and why.

**Reading method:** every file in the list was opened. The 177 English notes were read in full
(they carry the decision text); the 177 Chinese files are the paired translation of the same
note and were read as such - for all 177 the title, the `Status:` line and the complete
section-heading structure were confirmed, and for the first 44 the opening Problem/Decision
sections were read in full as well; the 177 `.i18n.yaml` files are generated pairing manifests
and were format-verified across all 177 plus sampled in full rather than read line by line
(Tier 3).

## 2. Ideas worth stealing (ranked for August Trading)

1. **One durable event log per conversation; everything else is a projection.**
   The harness's single most load-bearing decision: the session log is authoritative, the
   LLM-visible history is *derived* from it, and every UI-facing number (token usage, context
   pressure, subagent list, title) is a registered projection unit folded over that log
   (`2026-06-11-event-sourced-sessions`, `2026-08-25-session-observations-…`). August Trading
   already has a trade journal, a pattern memory and a notebook — but they are separate stores
   that can disagree with the transcript. A single append-only Session log with *projection
   views* would make "what the model saw" and "what the app shows" provably the same thing, and
   it gives replay, fork and export for free (`2026-08-31-released-session-format-migrations`
   shows what that costs and how they kept a 116 MB log inside a 16 GB process).

2. **The Session surface: an ordered projection with explicit replace markers.**
   Compaction is the single hardest thing in a trading app that must never lose a decision.
   The harness records every replacement as `surfaceOp: {op:'replace', startSeq, endSeq}` plus
   `sourceEventSeqs`, so a compaction is *auditable* and replayable rather than a mutation
   (`2026-06-18-session-surface`, `2026-09-06-v3-canonical-session-envelopes`). August Trading's
   context compaction (`utils/contextWindow.ts`, `services/providers/contextCompact.ts`) could
   adopt the same shape: the compacted range is a durable event, not an in-memory splice.

3. **A shared timeout/deadline primitive that owns TIMING and CLASSIFICATION, leaving the hard
   kill to each capability.** `dsh-timeout` is four pure functions; the note is explicit that a
   "timeout service" would have to know how to stop every capability's work, which is exactly
   what a microkernel must not know (`2026-07-06-timeout-deadline-library`,
   `2026-07-07-tool-call-timeout-policy`). August Trading has provider timeouts, tool timeouts
   and abort handling in several places; one `clampTimeout`/`deadline`/`idleWatchdog` pair with
   `timedOut` vs `aborted` latched independently would remove a whole class of drift — and the
   note records the *evidence* (web_search had NO timeout at all) that made the case.

4. **Tool-output spill files with an opaque locator and a retrieval hint.**
   `ctx.spillStore` saves oversized tool output and returns `{locator, bytes, retrievalHint}`;
   the model gets a bounded preview plus a handle it can re-read later
   (`2026-07-08-tool-output-spill-files`). August Trading's `utils/memoryBudget.ts` already
   refuses growth at the hard cap; the spill seam is the missing half — instead of refusing, keep
   the full bytes on disk and hand back a locator.

5. **Facts-based, field-granular invalidation for derived state.**
   The context-breakdown note turned 151,122 per-message entries (7.13 MB) into 110 KB by
   retaining only surviving system prompts, and verified the folded results were identical
   (`2026-10-13-context-breakdown-system-prompt-state`). The user-text evaluator does the same
   for matchers: a rule records exactly which Facts fields it read, and a change invalidates
   only those readers (`2026-10-10-user-text-json-nodes`). August Trading's
   `services/learning/*` caches and Monte Carlo re-reads could adopt read-recording invalidation
   instead of full recomputation.

6. **Bounded uploads instead of unbounded payloads.**
   The DeepSeek session-log upload sends the longest contiguous run that fits 8 MiB, advances a
   watermark on acceptance, and OMITS an oversized event with a warning rather than failing the
   model request (`2026-09-24-bounded-session-log-upload`). The note publishes the measured
   numbers (269 MiB → 34 s → now ~8 MiB per request). Any August Trading path that ships a
   large artefact to a provider should copy this exact shape.

7. **A single failure vocabulary with `<domain>/<reason>` codes and one declaration site.**
   `RemoteError<Code>` + one merge-extensible `RemoteErrorDetailsMap`; the wire carries exactly
   `code`, `message`, `details`, and discrimination is by `code`, never `instanceof`
   (`2026-08-28-ctx-remote-failure-vocabulary`). August Trading's provider errors are mapped
   ad hoc per surface; one table with codes like `market/feed-down` and `model/context-overflow`
   would let the UI branch on data instead of parsing strings.

8. **Measure before you design: 310 live API requests to learn that the model follows
   `required` order, not `properties` order.**
   `2026-09-24-preparing-tool-arguments` is the model for evidence-driven design — a controlled
   table of variants and outcomes, published in the decision record. The same note publishes a
   before/after benchmark (212 ms → 176 ms, 132 MiB → 77 MiB allocated). August Trading's
   prompt/tool-schema ordering decisions are currently intuition; this is the method to use.

9. **Session references with a *source* label instead of a global "current session".**
   `SessionReference` carries the consumer's identity (`sidebarView`, `composer`, …), so
   background work and the sidebar can never act on another view's Session
   (`2026-09-15-client-session-references`). August Trading has exactly the same hazard in
   `App.tsx`'s `activeUsernameRef` and in a shared "current trade" notion.

10. **Observation ≠ execution.** Opening history, listing, following and inspecting a session
    must never resume an Agent; activation authority belongs to each command
    (`2026-08-18-session-history-and-event-transport`). In August Trading, "load the trade to
    show it" must not "load the trade to analyse it" — a distinction worth making explicit in
    `services/analysis/*`.

11. **Configuration ordering with a DENY-LIST for what a repository's `.env` may not set.**
    One ordering for non-secret values, a narrower one for credentials, and an explicit
    deny-list (`PATH`, `NODE_OPTIONS`, `DSH_*`, proxy variables) so a cloned repo cannot
    redirect the tool's route (`2026-08-04-configuration-source-ownership`). August Trading
    reads provider keys from several places; one table plus a deny-list is cheap insurance.

12. **A capability-seam rule with a "do not split preemptively" clause.**
    Service Definition / Service Provider / Consumer, with the explicit statement that a seam
    is only carved when a second implementation exists (`2026-06-13-capability-seams`). This is
    the antidote to August Trading's `services/providers/` sprawl.

## 3. Trading-specific findings

1. **A scheduled/automation task must live in durable storage, not in a live timer.**
   `2026-09-16-host-schedule-storage` keeps scheduled messages in a Host-owned JSON domain with
   the task's Session id, status, delivery receipt and history; timers are restored only for
   active tasks; a due task resolves a cold Session through the Session controller. Delivery
   records acknowledge *inbox delivery*, not user receipt or model completion — an honesty
   distinction August Trading's automations should copy verbatim.

2. **A delivered reminder should say where it came from, and the framing must be
   un-forgeable.** `2026-09-24-scheduled-message-framing` replaced "this payload is untrusted"
   with "this is a scheduled message from the user", and closed framing forgery by *encoding*:
   the prompt is a JSON string, the instant is a canonical RFC 3339 value, each occupies one
   line. It also states the accepted residual risk (a model-written prompt can carry injected
   text) and the exact condition for reinstating the clause. August Trading's scheduled
   automations and its schedule tools have the identical trade-off and should name it.

3. **A recurring rule needs a committed UTC target, not a re-derived one.**
   Daily/Weekly/Cron keep a committed UTC target so a DST shift or a missed run cannot silently
   move a scheduled job (`2026-09-16-host-schedule-storage`). Trading apps that schedule
   "check this pair at 09:30" live or die by this.

4. **Analytics that the user can query later belong in the log, not in a side table.**
   Feedback (ratings, edits to a message) lives in the canonical session log as log-only
   events, so it survives export and replay, costs no model tokens and never changes the KV
   cache (`2026-09-05-canonical-feedback-log`). The same reasoning applies to a trader's
   post-trade review annotations: put them in the trade log, not in a parallel "notes" store.

5. **Prefix stability is a real economic decision.** Forked children keep the parent's request
   prefix byte-identical so provider-side prefix caching still pays; the note explicitly
   records what breaks it (a child-only system-prompt section or tool schema before the
   inherited history) and what the harness does NOT claim (it tests its own assembled inputs,
   not the provider's cache behaviour) (`2026-08-10-fork-children-stay-one-shot`). August
   Trading's long analysis transcripts should keep the same discipline: append, never prepend.

6. **Cost accounting must come from the durable log, not from what is on screen.** Token usage
   and context occupancy are projections over the durable log; a paged window must not change
   the totals, and compaction must not erase the billing behind it
   (`2026-07-29-projected-token-usage-and-request-context`). The note also states plainly that
   occupancy is an APPROXIMATION (the last recorded request's numerator against the route's
   denominator) and that nothing in the harness decides on it. August Trading's token meter
   should be explicit about the same caveat.

7. **Model-authored code is a different authority from the trader.** PTC (programmatic tool
   call) runs model-written JavaScript; the sandbox note makes the retained process follow the
   session's file policy, and a one-time escalation gets a *fresh temporary environment* that
   cannot see standing variables (`2026-10-08-persistent-ptc-sandbox`,
   `2026-10-09-ptc-owned-policy-cleanup`). If August Trading lets the model write analysis
   scripts, the same boundary (own process, own file policy, no standing secrets) applies.

## 4. Non-obvious decisions and gotchas (the ones that bite)

- **Direction-aware refusals matter.** The session-log version note records that the original
  reader threw ONE message for any version mismatch, and that a JSONL decoder let unknown event
  types through, restoring a content-incomplete session with no diagnostic. Read forward and
  backward failures are different facts (`2026-08-10-session-log-version-mechanism`).
- **"Refuse" beats "repair" when a format edge crosses.** The alpha migration note refuses
  EVERY unknown historical event, even one marked `ignorable`, because it cannot prove that
  opaque payloads remain semantically valid after the edge
  (`2026-08-31-alpha-historical-unknown-event-refusal`).
- **A cached hint must never masquerade as a sequenced read.** The projection-cache
  post-mortem (44 of 241 forked sessions showed no title after a restart) ends with the client
  store separating `cached` from `sequenced` rows
  (`2026-09-19-projection-cache-listing-identity-and-cached-rows`).
- **One-call-one-settlement for interactive prompts.** A timed user question has TWO
  settlements: the foreground waterfall ends as pending and the later answer steers a durable
  user message, so the question stays answerable after the agent has moved on
  (`2026-09-19-timed-user-question-two-settlements`). The note also insists the claim is
  released only after DELIVERY, not after the local answer, because releasing early lets the
  Host's timer beat the answer.
- **Cancellation codes must distinguish "dispatch happened" from "it did not".**
  `ABORTED` vs `ABORTED_BEFORE_DISPATCH` (`2026-07-19-cooperative-tool-cancellation`) is the
  difference between "side effects may have happened" and "they did not".
- **An empty value that is indistinguishable from a real one cannot be per-composition.**
  The host-plane note's criterion — "a unit whose empty value is indistinguishable from a real
  one cannot be per-composition while the table it registers into is per-process" — is a
  reusable test for any registry-backed cache
  (`2026-08-10-host-plane-ownership-after-presets`).
- **A reply that arrives after the agent moved on still has to be attributable.** The
  `followup()` note: a `MessageId` proves inbox ADMISSION, never causal ownership of the
  output (`2026-07-30-followup-enqueue-and-owned-runs`).
- **Two fold paths will diverge.** The Chat scroll note found that the generic fold path
  blanked the whole viewport (up to ~6000 px of reserved room) and deleted the path rather than
  patching it (`2026-10-13-chat-single-fold-motion`).
- **Peer-scoped access must be checked BEFORE anything with a side effect.** The peer-principal
  note puts the access check ahead of lookup resolution precisely so a refused call activates
  no Session (`2026-10-12-peer-principal-and-remote-access`).
- **A stored credential beating the launch environment is a real product decision**, with a
  documented escape hatch (a separate `DSH_HOME`) and a headless profile that omits the store
  entirely (`2026-10-09-stored-credential-precedence`, `2026-10-12-headless-environment-auth`).

## 5. Weak spots in the reference (do not copy blindly)

1. **The notes are the design, but the CODE is enormous.** A 177-note architecture corpus
   describing a monorepo of ~150 packages is itself evidence of a large surface area. Several
   notes exist only to *undo* a previous decision (the `alternatives considered` sections
   routinely say "supersedes the X note"), which is the signature of decisions made without a
   stable vocabulary first. For August Trading the lesson is the opposite: adopt the *single
   owner* rules, not the package count.

2. **Heavy dependence on Node internals.** `2026-09-30-profile-package-refresh-and-manifest-invalidation`
   and `2026-10-14-webworker-preview-profile-parity` monkey-patch `Module._pathCache`,
   `package_json_reader`, `internal/modules/esm/loader` and `ResolveCache`, and the notes
   themselves say the tests "must run again for Node upgrades". That is a maintenance tax
   August Trading should not accept in a React/Electron app that must ship reliably.

3. **Uncaught exceptions are fatal, and a failed batch script retries per row** — both are
   correct-in-context but blunt. The fatal-recovery note accepts a window where plugin stderr
   pushes the user's diagnostic out of the eight-line excerpt
   (`2026-09-22-fatal-diagnostics-and-crash-reports`). August Trading wants a *durable,
   queryable* failure record, not a native dialog plus a bounded file.

4. **The policy surface is broad.** `2026-10-13-team-identity-runtime-context` makes identity a
   REQUIRED runtime context that is re-admitted after compaction, so every member pays for the
   full snapshot; the peer-principal note adds RBAC with roles, bindings, conditions and
   snapshots. Both are right for a multi-tenant product and disproportionate for a
   single-trader app.

5. **Documentation drift is acknowledged but not solved.** Several notes point at each other
   with "supersedes" and "partially supersedes", and a handful of Chinese translations kept
   English section headings (`## Problem`, `## Decision`) — the bilingual pairing is enforced
   by a hash manifest, but the *content* is only as consistent as the human who translated it.
   The pairing-hash idea is worth stealing; the duplication is not.
