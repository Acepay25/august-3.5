# deepseek-harness :: dsh-web-deliverables-feedback

**Files in shard:** 225 (read: 206, skipped with reason: 19 — all nineteen are generated `README.i18n.yaml` bilingual-pair hash records; each was opened to confirm what it is, and none is analysed as prose)
**What this shard covers:** Five capability families of the DeepSeek Harness monorepo, all read as text and never executed.
1. **attachment** — durable image and generic-file attachments: a content-addressed local store with an fsync-chain durability proof, provider-independent image normalisation, a per-route request-image cache, and a strict admission vocabulary.
2. **deliverables** — what a turn hands to the user: the `present` tool (explicit file delivery as a durable Session event) and the `workspace-changes` recorder (per-turn changed files derived from git working-tree snapshots plus whole-file captures, with on-demand per-file diffs).
3. **document** — the Office→PDF provider: a bounded admission queue, two-level dedup (source alias and content digest), foreground/background scheduling, and a generation-stamped PDF cache.
4. **feedback** — human feedback that never reaches the model: a session-level `/feedback` command and a canonical per-message rating store with optimistic concurrency over the Session log.
5. **web** — the `ctx.web` capability seam: order-independent provider selection, a model-facing `web_search`/`web_fetch` tool pair, a hardened anonymous HTTP fetcher (public-address pinning, DNS64-aware), and four search backends behind one vocabulary.

Everything below is a **read** of a third-party reference repository, not a review of August Trading. Claims carry `path:line` references into that repository.


## 1. File-by-file

### Tier 1 — load-bearing source: full entry

#### `packages/attachment/attachment/src/index.ts`
- **Purpose:** the abstract `AttachmentStore` service seam (`ctx.attachments`) that every deployment mounts to store durable image and generic-file attachments.
- **Key abstractions:** `AttachmentStore` (extends Cordis `Service`, `packages/attachment/attachment/src/index.ts:53`), abstract `imageLimits`, `validateImage`, `saveImage`, `readImage`, concrete `saveImages` (`:100`), `validateImageBatch` (`:80`), `admitPromptContent` (`:118`), `admitEncodedFile` (`:143`), `isAttachmentError` (`:150`).
- **Data flow:** a Host prompt arrives as `PromptContentPart[]` → `admitPromptContent` → base64 images are decoded and handed to `admitEncodedImages` → `saveImages` validates the *whole batch* (count, aggregate bytes, media types) → validates each member (full raster decode) → saves each member in input order → returns durable `ImageAttachmentRef[]`; text and already-resolved file references pass through untouched.
- **Non-obvious design decisions:** (a) **the default `saveImages` validates every member before saving any member** (`:104-105`) so a refused image cannot leave a half-published batch; (b) **the default `saveFile`/`saveFileStream`/`readFileStream` reject** with `ATTACHMENT_FILES_UNSUPPORTED` (`:163`, `:175`, `:196`) rather than throwing "not implemented" — a provider that cannot store verbatim files fails loudly instead of silently dropping bytes; (c) `readImageRequest` defaults to `ATTACHMENT_PROJECTION_UNSUPPORTED` (`:229`); (d) `imageHostPath`/`fileHostPath` return `undefined` by default (`:157`, `:211`) so a non-file-backed backend cannot leak a host path.
- **Edge cases & failure handling:** all failures are `AttachmentError` with a stable `code`; `saveImages` returns **no partial references** when a later member fails to store, although already-published content-addressed objects may linger until a retention policy collects them (documented at `:104-106`). Cancellation is preserved through `signal.throwIfAborted()`.
- **Surprising:** the abstract class is a *seam* with no implementation — the actual storage lives in `attachment-local`. The JSDoc is unusually long and reads as the contract; the README even says "the exact per-operation contracts live in `src/index.ts`".

#### `packages/attachment/attachment/src/error.ts`
- **Purpose:** the stable, machine-routable failure vocabulary for attachments.
- **Key abstractions:** `ImageAdmissionErrorCode` (`:3`), `AttachmentErrorCode` (`:18`), `AttachmentError` (`:46`), `isAttachmentError` (`:67`), `isImageAdmissionError` (`:79`).
- **Data flow:** any thrown failure gets a `code`; consumers switch on the code, never on the prototype chain.
- **Non-obvious design decisions:** `AttachmentError` **re-implements** the `HarnessError` shape instead of extending it, because `HarnessError` lives in `dsh-llm`, which itself depends on this package — extending it would create a dependency cycle (`:38-43`). `isAttachmentError` therefore recognises a foreign error from another copy of the package purely by `code` membership in a `Set` (`:35`, `:67-72`), and refuses a bare object without `Error` ancestry (`:72`).
- **Edge cases & failure handling:** the caller-correctable subset (`isImageAdmissionError`) is separable at runtime so each protocol adapter can map its own vocabulary; storage faults (`ATTACHMENT_CORRUPT`, `ATTACHMENT_WRITE_FAILED`) are deliberately excluded.
- **Surprising:** the "copy the shape rather than share the base" trick is the only place in the shard that a dependency cycle is explicitly designed around — worth stealing for any cross-package error type in August Trading.

#### `packages/attachment/attachment/src/admission.ts`
- **Purpose:** wire-form admission of base64 uploads — the shared entry point for every RPC endpoint accepting browser uploads.
- **Key abstractions:** `decodeCanonicalBase64` (`:15`), `admitEncodedImages` (`:49`), `admitEncodedFile` (`:66`).
- **Data flow:** base64 string → `Buffer.from(data,'base64')` → re-encode and compare byte-for-byte (`decoded.toString('base64') !== data`) → decoded bytes → store.
- **Non-obvious design decisions:** **canonical base64 is enforced by re-encoding**, so `'AAA'` (non-canonical padding) and `'!!!!'` are rejected before the store is ever touched (`:16-22`); an empty payload is *rejected* for images but *accepted* for files (a zero-byte file is legal) — the `empty: 'reject' | 'accept'` parameter (`:15`).
- **Edge cases & failure handling:** failures are `INVALID_IMAGE_BASE64` / `INVALID_FILE_BASE64`; the store's own rejection propagates unchanged (`:61`).
- **Surprising:** the canonical-base64 rule means a client that base64-encodes with a different line-wrapping will be refused; this is a deliberate anti-ambiguity contract for a durable content-addressed store.

#### `packages/attachment/attachment/src/request-projection.ts`
- **Purpose:** pure geometry shared by model routes and provider-side request pricing.
- **Key abstractions:** `requestImageDimensions` (`:19`), `longEdgeDimensions` (`:53`).
- **Data flow:** `(width, height, budget)` → integer dimensions that respect the budget exactly.
- **Non-obvious design decisions:** the pixel-budget projection **rounds the long edge down and the short edge to nearest, then walks the long edge back one pixel at a time** until `w*h <= maxPixels` (`:33-38`, `:44-49`). It is a fixpoint loop rather than a floating-point clamp, because a naive `Math.round` on both axes can overshoot the budget by a pixel.
- **Edge cases & failure handling:** small images are never enlarged (`scale = Math.min(1, …)` at `:23`); dimensions are floored at 1.
- **Surprising:** `longEdgeDimensions` exists purely so an encoder that resizes by the long edge produces *exactly* the dimensions the route predicted — a cache-key correctness requirement, not an image-quality nicety.

#### `packages/attachment/attachment/src/types.ts`
- **Purpose:** the durable, serialisable vocabulary of the attachment family.
- **Key abstractions:** `ImageAttachmentRef` (with `originalDimensions` recorded only when normalization downscaled), `FileAttachmentRef`, `EncodedImageAttachment`, `EncodedFileAttachment`, `SaveImageAttachment`, `SaveFileAttachment`, `SaveFileStreamAttachment`, `ImageAttachmentLimits`, `PromptContentPart` / `AttachmentAdmissionPart` / `AdmittedPromptContentPart`, `ImageRequestTarget`, `RequestImageAttachment`.
- **Data flow:** wire → store → durable reference → request variant.
- **Non-obvious design decisions:** `PromptContentPart` (raw base64), `AttachmentAdmissionPart` (files already resolved), and `AdmittedPromptContentPart` (everything a durable reference) are **three separate types for three states of the same prompt** (`:104-146`) — a wire caller can never cite an attachment it did not upload, because the type system stops it.
- **Edge cases & failure handling:** `RequestImageAttachment` carries the *proven* facts (`depth:'uchar'`, `space:'srgb'`, `hasAlpha`) rather than the requested ones, so a provider adapter never has to re-derive them (`:163-180`).
- **Surprising:** `ImageAttachmentRef.originalDimensions` is present **only** when normalization reduced the raster — an absent field is meaningful, not merely unset.

#### `packages/attachment/attachment/src/brand.ts`
- **Purpose:** opaque branded identifiers (`AttachmentId`, `ImageVariantId`) so a raw string cannot be passed where a validated id is required.
- **Key abstractions:** `AttachmentId(value)`, `ImageVariantId(value)` (`:11`, `:23`).
- **Data flow:** backend-produced string → brand.
- **Non-obvious design decisions:** the brand function does **no** validation at all (`:9-11`) — the trust boundary is the backend that produced the string; branding only makes the intent type-level visible.
- **Surprising:** `ImageVariantId` lives in the same file but is produced by the *provider side* of the seam, which the JSDoc calls out (`:19`).

#### `packages/attachment/attachment-local/src/index.ts`
- **Purpose:** the concrete `LocalAttachmentStore` — content-addressed storage below `DSH_HOME/attachments/v1`.
- **Key abstractions:** the exported default limits (`:34-58`), `Config` (`:61`), `LocalAttachmentStore` (`:147`), and the private `SharedRequest` class (`:99`) implementing single-flight with waiter-scoped cancellation.
- **Data flow:** config → resolved `imageLimits` + `normalizationPolicy` (frozen) → `saveImages` prepares every image through the `CompressionLimiter` → commits each prepared object in order; `readImageRequest` computes a deterministic `variantId`, checks the on-disk cache, otherwise encodes and writes it.
- **Non-obvious design decisions:** (a) **`SharedRequest` shares one transform across callers but gives each caller its own cancellation**: the shared `AbortController` is only aborted when the *last* waiter cancels (`:135-139`), so one caller abandoning a slow image encode does not kill the other (`:203-243`); (b) the in-flight map is keyed by `variantId` and an aborted entry is evicted and replaced (`:216-219`); (c) `imageCompressionConcurrency` is validated *twice* — by the schemastery schema and by an explicit `Number.isSafeInteger` guard in the constructor (`:177-186`), because the constructor is also reachable from tests that bypass the schema.
- **Edge cases & failure handling:** `saveImages` validates the whole batch before any commit (`:203-206`); `validateImage` is a pure "no storage touched" check (`:199`); every cancellation path re-checks the signal before and after the I/O.
- **Surprising:** the `durableHomes` cache (`store.ts:23`) means the fsync-to-filesystem-root proof happens **once per process per home**, and the README admits the design assumption that "existence is not durability" is not enough — this is one of the most unusual pieces of engineering in the shard.

#### `packages/attachment/attachment-local/src/store.ts`
- **Purpose:** content-addressed, owner-private local storage with a crash-durability proof.
- **Key abstractions:** `normalizedImagePath` (`:51`), `validateImageFile` (`:76`), `prepareImageFile` (`:99`), `commitPreparedImageFile` (`:191`), `publishImmutableObject` (`:214`), `publishImmutableObjectStream` (`:245`), `publishImmutableAlias` (`:272`), `stageImmutableObject` (`:309`), `publishStagedObject` (`:350`), `readImageFile` (`:431`).
- **Data flow:** bytes → `prepareImageFile` (decode, normalise, verify) → digest → staged temp file (`O_CREAT|O_EXCL`, `0o600`) → `fsync` the file → **hard-link** into the final path (atomic, `EEXIST` = dedup) → `chmod 0o400` → `fsync` every ancestor directory up to the durable boundary → only then is the reference returned.
- **Non-obvious design decisions:** (a) **durability is an fsync chain, not existence** — `ensureDurableDirectory` (`:156`) re-syncs ancestors even when `mkdir` reports "already existed", because a concurrent creator may not have synced its own entry yet; (b) `ensureDurableHome` (`:176`) proves the whole chain to the filesystem root **once per process**; (c) publication uses `link()` rather than `rename()` so an `EEXIST` race is a *deduplication* signal rather than a silent overwrite, and the winner is verified by digest (`:365-370`); (d) on Windows the staging name is unlinked *before* the read-only chmod, because Windows shares the read-only attribute across hard links and refuses to unlink either name afterwards (`:374-378`).
- **Edge cases & failure handling:** digest mismatch at publication → `ATTACHMENT_CORRUPT` and the staging file is removed (`:216-220`); a missing object on read → `ATTACHMENT_NOT_FOUND`; unreadable → `ATTACHMENT_READ_FAILED`; a corrupted object → `ATTACHMENT_CORRUPT`; `syncDirectory` is a documented no-op on Windows because NTFS metadata journaling owns entry durability there (`:132-135`).
- **Surprising:** the `readImageFile` path **re-probes the header but never re-decodes the raster** (`:452-459`), because the digest already proved the bytes are the ones admission fully decoded. That is a deliberate cost optimisation with a clear stated reason.

#### `packages/attachment/attachment-local/src/file-store.ts`
- **Purpose:** verbatim (byte-for-byte) file storage — the opposite policy to images.
- **Key abstractions:** `fileLeafName` (`:45`), `storedFilePath` (`:75`), `saveFileVerbatim` (`:91`), `saveFileStreamVerbatim` (`:113`), `readFileStreamVerbatim` (`:147`).
- **Data flow:** bytes → sha256 → one canonical object at `file-objects/<prefix>/<digest>` → a read-only **hard-link alias** at `files/<prefix>/<digest>/<name>` per display name.
- **Non-obvious design decisions:** (a) the display name is sanitised **by hand**, stripping *both* separator styles, because a POSIX host treats `\` as an ordinary character and `path.basename` would therefore keep a Windows client's entire local path and leak it into the session log (`:36-42`); (b) the Windows reserved-device-name check (`CON`, `NUL`, `com1`…) prefixes an underscore (`:17-21`, `:48-49`); (c) the name is truncated on a **UTF-8 byte** budget of 255, not a character count (`:23-33`); (d) `ensureFileReference` re-validates that `ref.name === fileLeafName(ref.name)` — a reference whose name was not produced by the sanitiser is *rejected* (`:58-64`), so a hand-crafted reference cannot escape the directory.
- **Edge cases & failure handling:** `readFileStreamVerbatim` yields chunks and only then checks the total byte count and digest (`:180-183`) — a truncated or changed object fails the *consumer* rather than producing a complete export with different bytes; ENOENT → `ATTACHMENT_NOT_FOUND`; other read errors → `ATTACHMENT_READ_FAILED`; `finally { stream.destroy() }` (`:174`) releases the fd on early exit.
- **Surprising:** different display names for equal bytes share **one inode** (a hard link), so the "two names, one object" case costs no disk.

#### `packages/attachment/attachment-local/src/normalization.ts`
- **Purpose:** deterministic, provider-independent image normalisation.
- **Key abstractions:** `NormalizationPolicy` (`:12`), `NormalizedImage` (`:22`), `canPassThroughNormalization` (`:36`), `normalizeImage` (`:109`).
- **Data flow:** source bytes + decoded facts → pass-through check → (rotate, to sRGB, resize) → quality ladder 85/75/60 → first candidate under `maxBytes`, else the smallest → **verify the output by re-decoding it** (`:52-70`).
- **Non-obvious design decisions:** (a) **byte-identical pass-through** when the source is already clean, single-frame, 8-bit sRGB and inside every limit (`:36-47`) — no pointless re-encode, and the digest of a clean image equals the digest of its source; (b) **the output is re-decoded and checked** against the encoder's own claim (`verifyNormalizedImage`, `:52`) so a lying encoder cannot smuggle in 16-bit or metadata-bearing bytes; (c) the dimension budget is **total pixels first, then long edge**, so an extreme aspect ratio keeps its short-edge resolution instead of collapsing (`:87-101`); (d) GIF is *always* re-encoded to a still frame (`:117`, `:143`).
- **Edge cases & failure handling:** an encoder fault is mapped to `ATTACHMENT_WRITE_FAILED` with a **human-readable** description of the source form ("The 16-bit PNG could not be converted to the normalized 8-bit sRGB form.", `:135-138`) — the raw encoder error is kept only as `cause`; `verifyNormalizedImage` failure produces "Image normalization did not produce a single-frame 8-bit sRGB image with matching metadata.".
- **Surprising:** `canPassThroughNormalization` requires `depth === 'uchar'` *and* `space === 'srgb'` — a 16-bit PNG is always re-encoded even when it would fit, so the stored object is always one of a small set of forms.

#### `packages/attachment/attachment-local/src/encoding.ts`
- **Purpose:** the shared quality ladder and lazy candidate execution used by both the normaliser and the request encoder.
- **Key abstractions:** `IMAGE_ENCODING_QUALITIES = [85, 75, 60]` (`:6`), `WEBP_ENCODING_EFFORT = 0` (`:8`), `EncodedImage` (`:11`), `encodingLadder` (`:33`), `encodeFirstWithinLimit` (`:56`), `isExhaustedEncoding` (`:79`).
- **Data flow:** a prepared Sharp pipeline → a list of *lazy* encoder closures → each candidate is a clone of the pipeline → the first candidate under `maxBytes` wins.
- **Non-obvious design decisions:** (a) **the ladder is lazy and short-circuits** — the fallback qualities are never even executed if the first fits (`:57-71`); (b) when nothing fits, the **smallest** completed candidate is returned and flagged as `ExhaustedEncoding` rather than throwing — the provider's byte cap is enforced at the *route* that transmits the bytes, not at storage time; (c) WebP keeps the source alpha channel and everything else becomes JPEG (`:33-38`); (d) `WEBP_ENCODING_EFFORT = 0` is documented as "deeper search costs 3-4x encode time for about 5% size" (`:7`).
- **Edge cases & failure handling:** an empty candidate list throws (`image encoding requires at least one candidate`, `:59`); the "smallest" tracking compares byte lengths, not quality order.
- **Surprising:** the same three constants serve two different purposes (durable normalised bytes and per-request bytes) — one ladder, two call sites, so the two never disagree.

#### `packages/attachment/attachment-local/src/request-image.ts`
- **Purpose:** deterministic, cached, route-sized image versions for model requests.
- **Key abstractions:** `REQUEST_IMAGE_TRANSFORM_VERSION = 'request-image-v6'` (`:26`), `requestImageVariantId` (`:79`), `readRequestImageFile` (`:179`), `descriptor` (`:56`).
- **Data flow:** durable attachment + route target → deterministic `variantId` (sha256 over a JSON descriptor of *every* transform input) → cache lookup at `request-images/<prefix>/<hash>` → on a miss, encode → verify → write the cache entry atomically (temp file + `rename`, `0o600`).
- **Non-obvious design decisions:** (a) the **cache key includes the encoder settings and a transform version**, so upgrading sharp or changing the ladder produces a *new* address rather than serving stale bytes (`:56-77`, `:26`); (b) the resize is done **by the long edge only**, so the encoder derives the short edge exactly the way the route predicted (`:87-91`) — the geometry function in the core package and the encoder must agree; (c) a cached entry is **re-probed** on every read and regenerated when it is oversized, 16-bit, CMYK, too wide, has unexpected alpha, or is malformed (`:124-142`); (d) `withoutEnlargement: true` means a target above the source keeps the source size.
- **Edge cases & failure handling:** a cache hit that fails validation silently regenerates (never a hard error); a *newly encoded* result that fails verification throws `ATTACHMENT_WRITE_FAILED` (`:144-158`); the cache write is atomic (`:160-168`) and removes the temp file in a `finally`.
- **Surprising:** `readRequestImageFile` does not re-verify a **pass-through** result (source already under the target), because the source was already verified at admission — the verification cost is paid once, not per request.

#### `packages/attachment/attachment-local/src/image.ts`
- **Purpose:** raster inspection — full decode at admission, header-only probe on verified reads.
- **Key abstractions:** `DetectedImage` (`:9`), `encodedAlphaIsCompatible` (`:36`), `probeImage` (`:92`), `DecodedImageLimits` (`:103`), `detectImage` (`:116`).
- **Data flow:** bytes → `sharp(...).metadata()` → `DetectedImage`; `detectImage` additionally does `image.raw().toBuffer()` (`:129`) to prove the raster decodes completely.
- **Non-obvious design decisions:** (a) **EXIF orientations 5-8 transpose the stored raster**, so the reported width/height are the *perceived* axes, and every limit and coordinate advice downstream uses them (`:70-74`); (b) `encodedAlphaIsCompatible` tolerates WebP output that **omits an all-opaque alpha plane**, because libvips may do that — but treats any other alpha change as incompatible (`:36-43`); (c) `carriesRetainedMetadata` is a whitelist of the metadata kinds that force a re-encode (`:52-61`).
- **Edge cases & failure handling:** unsupported format or malformed bytes → `INVALID_IMAGE`; pixel and per-side limits are checked *before* the full decode (`:120-126`); `limitInputPixels: false` is passed so the harness's own limit is the only limit in force.
- **Surprising:** the split between `probeImage` (header only) and `detectImage` (full decode) exists purely for cost: admission pays the full decode once, and every later read pays only a header probe.

#### `packages/attachment/attachment-local/src/compression-limiter.ts`
- **Purpose:** an instance-owned FIFO concurrency bound for native image transformations.
- **Key abstractions:** `compressionFailure` (`:8`), `CompressionLimiter` (`:15`).
- **Data flow:** `run(task)` → if a slot is free, start now; otherwise queue the starter callback → on settle, release the slot and shift the next waiter.
- **Non-obvious design decisions:** (a) the task is invoked through `Promise.resolve().then(task)` so a **synchronous throw** inside `task` still releases the slot (`:32-33`) — a classic limiter bug this one avoids; (b) non-`Error` rejections (native bindings reject with strings) are normalised into an `Error` with the original as `cause` (`:8-11`).
- **Edge cases & failure handling:** a non-Error rejection is preserved as `cause`; the slot is released on both resolve and reject paths (`:35-43`).
- **Surprising:** the limiter is *instance*-owned, not global — two stores in one process each get their own budget, which is the right call for a service that may be mounted twice.

#### `packages/attachment/attachment-local/src/sharp.ts`
- **Purpose:** lazy, process-realm access to Sharp's CommonJS-compatible entry.
- **Key abstractions:** `requireSharp` (`:8`).
- **Data flow:** first raster operation → `createLazyRequire('sharp', import.meta.url)` loads the native binding → the callable export is retained.
- **Non-obvious design decisions:** the load is **lazy** so a deployment that never touches an image never pays the native-binding cost or the failure; `lazy-sharp-failure.spec.ts` pins that a load failure is *not* reclassified as "invalid image data".
- **Edge cases & failure handling:** a load failure propagates as the original error (`tests/lazy-sharp-failure.spec.ts:20-33`).
- **Surprising:** a 336-byte file carries a real architectural decision (don't fail at import time; fail at first use, with the real cause).

#### `packages/deliverables/tool-present/src/index.ts`
- **Purpose:** a scoped tool (`present`) that lets a model declare existing filesystem files as final deliverables to the user, recorded as a durable Session event.
- **Key abstractions:** `Config` (`:16`), `Config` schema with `maxFiles` default 8 (`:22`), `inject = ['tools','fs','sessionProjections','workingDirectory']` (`:27`), `apply` (`:34`).
- **Data flow:** the model calls `present` with `files: [{path, description?}]` → the tool requires an agent Session and an **open turn** (read from the `turnBoundary` session projection, `:44-46`) → each path is `lstat`ed (must be a regular file, not a symlink), then `fs.resolve`d against the Session working directory, then `stat`ed again → the **absolute** resolved path is recorded → on a *successful* `tools/result` the plugin appends `deliverables/presented` to the Session (`:96-104`).
- **Non-obvious design decisions:** (a) **the delivery is committed from the `tools/result` event, not from `execute`** — the pending delivery lives in a `WeakMap<ToolExecution, …>` (`:37`) and is only published when the final result is not an error (`:99`); a later enclosing program failure does not revoke an already-completed declaration, and a *blocked* result publishes nothing (`:100`); (b) the recorded path is the **absolute resolved path**, so a later `cd` cannot redirect a delivered file (README: "validates paths against the Session's current working directory and records absolute paths"); (c) the tool description tells the model to *prefer the final response* and to declare at most 4 files per call (`:41-46`); (d) `maxFiles` is validated at mount, not at call time (`:35-37`).
- **Edge cases & failure handling:** missing file → `FsError` with code `FS_NOT_FOUND` and an actionable message ("Check the path, create the file if needed, and retry", `:57`); a directory or a final symlink → refused (`:53`, `:58`); an empty path or a count outside `1..maxFiles` → refused (`:48`, `:52`); the whole call aborts on the first bad file, so a partial delivery never happens.
- **Surprising:** the plugin uses a `WeakMap` keyed by the tool execution, so a scoped tool with the same name mounted twice records only the calls *it* executed — no cross-instance leakage (README: "Each plugin instance records only calls it executed").

#### `packages/deliverables/tool-present/src/types.ts`
- **Purpose:** the pure vocabulary of a delivery, plus the Session-event declaration.
- **Key abstractions:** `PresentedFile` (`:7`), and the `SessionEventMap` augmentation for `'deliverables/presented'` (`:16-18`).
- **Data flow:** the tool's `execute` result → `PresentedFile[]` → the durable event.
- **Non-obvious design decisions:** the module declares the Session event through **declaration merging** into `SessionEventMap`, so the event type is known to the whole Session system without importing runtime code; the README notes the `./types` entry is deliberately runtime-free so the Web client can validate persisted declarations without booting the Host.
- **Surprising:** the event carries `{turn, callId, files}` — the `callId` lets a consumer tie the delivery back to the exact tool call.

#### `packages/deliverables/workspace-changes/src/index.ts`
- **Purpose:** the plugin entry — observes top-level turns of every eligible Session, captures file-tool edits, announces a `workspace/changes` event, and serves summaries and per-file comparisons through `ctx.workspaceChanges`.
- **Key abstractions:** `Config` (`:34`) with five bounds (`timeoutMs` 30 s, `outputMaxBytes` 8 MiB, `maxFiles` 500, `maxFileBytes` 2 MiB, `diffTimeoutMs` 100 ms) (`:51-57`), `eligible` (`:59`), `resolveGit` (`:72`), `apply` (`:95`).
- **Data flow:** `session/event` → `turn/start` starts a recorder, `tool/result` marks the last result seq, `turn/end` records if results settled after the last attempt; `agent/turn-stopping` records inside the turn; `fs/write-intent` and `fs/edit-intent` waterfalls capture the resolved mutation target *before* the mutation (`:167-181`); `tools/pre-execute` waits for the recorder's queue so no mutation can precede its baseline (`:182-190`).
- **Non-obvious design decisions:** (a) **`eligible()` excludes subagent Sessions** (`origin === 'subagent'` or `delegationDepth > 0`) — a nested agent's edits are attributed to the parent turn, not double-counted (`:59-62`); (b) **git is resolved once** and the "git is unavailable" message is logged exactly once (`:130-134`); (c) on macOS the `/usr/bin/git` **Xcode stub is treated as absent** until `xcode-select -p` succeeds, because the stub opens an installer dialog instead of running (`:74-83`); (d) every config field is re-validated as a positive integer at load, not just by the schema (`:100-105`); (e) the plugin provides `ctx.workspaceChanges` as a service whose `summary`/`diff` return `undefined` once the Session is disposed (`:122-125`).
- **Edge cases & failure handling:** a missing working directory, a missing git, or a failed snapshot degrades the summary to "file-tool edits only" rather than failing the turn; disposal (session or plugin) aborts queued work and removes the temporary directory (`:117-120`, `:161-165`).
- **Surprising:** the whole plugin is **log-only** — the README states "Model Experience: None", so nothing here enters a model request and provider cache reuse is unaffected.

#### `packages/deliverables/workspace-changes/src/recorder.ts`
- **Purpose:** the per-Session turn recorder — snapshots, whole-file captures around file-tool edits, the turn-end diff, and the records kept until disposal.
- **Key abstractions:** `RecorderEnvironment` (`:15`), `TurnState` (`:63`), `TurnRecorder` (`:107`), `ContentSource` / `FileSources` (`:47`, `:56`), `TurnRecord` (`:60`).
- **Data flow:** `start(turn)` (`:131`) queues a baseline snapshot → `capture(path)` (`:155`) copies the pre-mutation content of a path → `observe(tool/result)` (`:171`) remembers the last result seq → `stopping(turn)` (`:181`) or `end(turn)` (`:191`) produces the summary → the `workspace/changes` event is appended and the summary + per-file content sources are kept under the event's sequence (`:340-364`).
- **Non-obvious design decisions:** (a) **all work is serialised through one promise chain** (`this.chain`, `:108`) and every tool execution waits on it (`settled()`, `:198`), so a capture can never race a mutation; (b) **each turn gets a fresh state object** (`freshState`, `:86`), so an interrupted turn's still-running record keeps its own turn's files when the next turn starts (README: "Each turn holds its own state object"); (c) `baseline` has **three** states — `null` (no repository / no git), a `Baseline` (snapshot succeeded), and the literal `'failed'` (repository exists but the snapshot failed) — and `'failed'` means the turn records *nothing*, rather than pretending there was no repository (`:141-146`, `:271`); (d) `end(turn)` only records when **tool results settled after the last attempt** (`attemptedAfterSeq >= lastToolResultSeq` → skip, `:191-195`), which covers aborted/failed/steered turns without repeating a failed attempt; (e) an **empty** file list after an earlier in-turn record **supersedes** it (`:333-334`); (f) comparisons are computed **on demand**, not at record time, and the summary stores only the two *content sources* per file (a snapshot path or a copy) — so recording a turn is cheap and the expensive diff work happens only if a client asks (`:219-241`).
- **Edge cases & failure handling:** a failed turn records nothing and the next turn retries (the `warn` callback, `:16-18`); a failure after disposal is treated as expected cancellation and stays **silent** (`:275-277`); a read that races disposal returns `undefined` instead of throwing (`:235-238`); `captureFile` returning `undefined` (not a regular file) simply is not tracked.
- **Surprising:** the snapshot coverage rules are intricate and are the real design: tracked files come from git; files matching an ignore pattern, files outside the repository, and every file-tool edit when there is no snapshot come from the whole-file copies; files under `/tmp` are excluded; nested repositories (gitlinks) are excluded; a path whose content is unchanged at turn end is **not listed**; a path whose only difference is a missing final newline compares as unchanged while git still counts the line.

#### `packages/deliverables/workspace-changes/src/git.ts`
- **Purpose:** git working-tree snapshots, tree diffs and ignore checks, run through the subprocess capability.
- **Key abstractions:** `GitRunResult` (`:14`), `GitRunOptions` (`:23`), `GitLimits` (`:33`), `GitRunner` (`:41`), `GitWorkspace` (`:95`), `locateGitWorkspace` (`:127`), `snapshotTree` (`:154`), `treeBlob` (`:190`), `blobText` (`:212`), `diffTrees` (`:231`), `gitlinkPaths` (`:251`), `ignoredPaths` (`:270`).
- **Data flow:** `rev-parse --show-toplevel --absolute-git-dir --git-path objects` locates the repository → the Session's private object directory is created and the repository's own objects are attached **read-only** via `GIT_ALTERNATE_OBJECT_DIRECTORIES` while `GIT_OBJECT_DIRECTORY` points at the private store (`:141-146`) → `add --all --ignore-errors` into a **temporary index seeded from the repository's index** → `write-tree` yields a tree id → `diff-tree -r -M -z --numstat` between two trees yields the per-file counts.
- **Non-obvious design decisions:** (a) **the repository's index, object store, work tree and refs are never written** — the snapshot is a full copy of the work tree into a private object store, which is why the user's earlier uncommitted changes never enter a summary; (b) `GIT_CONFIG_COUNT=0` is set explicitly because the subprocess credential scrub removes the *keys* of ambient indexed config but not the count, so an inherited `GIT_CONFIG_KEY_n` would otherwise leak through (`:66-70`); (c) `GIT_LITERAL_PATHSPECS=1` is used for `ls-tree` so a file literally named `a[1].txt` is not treated as a glob (`:193`); (d) a private directory that lies *inside* the work tree is excluded from every snapshot with a `:(exclude)` pathspec (`:148`, `:167`); (e) a nonzero exit is a **result, not an exception** — `ok()` turns it into an error carrying git's stderr (`:89-93`).
- **Edge cases & failure handling:** `git add` exiting 1 (unreadable files skipped) is **accepted** — the index is still complete (`:165-167`); a missing repository index (fresh `git init`) starts from scratch, but an index that *exists and cannot be copied* is a hard failure rather than a silent empty index (`:158-163`); `check-ignore` exiting 1 means "nothing ignored" (`:277`); a diff listing that exceeds the output cap throws rather than truncating (`:239`); a timeout or an external abort becomes an error naming which one it was (`:73-76`).
- **Surprising:** the whole design exists so a turn's diff can be attributed to *the turn* rather than to the working tree's accumulated dirt — the user's pre-existing uncommitted work is invisible to the summary by construction.

#### `packages/deliverables/workspace-changes/src/capture.ts`
- **Purpose:** whole-file captures around file-tool edits, stored content-addressed under the Session's temporary directory.
- **Key abstractions:** `Capture` (`:15`) — the three-way union `absent | oversized | file`, `captureFile` (`:38`), `sameCapture` (`:81`).
- **Data flow:** path → open → read at most `maxBytes + 1` bytes → if longer, `{kind:'oversized'}` → otherwise write the bytes to `<dir>/<sha1>` with the `wx` flag (EEXIST keeps the existing copy) → `{kind:'file', file, binary}`.
- **Non-obvious design decisions:** (a) the read is bounded by **`maxBytes + 1`**, so a file that grows past the cap while it is being read costs no more memory than the cap (`:45`); (b) the content-addressed name means **identical content across paths and turns shares one copy** (`:71-76`); (c) `binary` is decided by a NUL byte in the first 8000 bytes — the same probe git uses (`:12`, `:77`); (d) `sameCapture` says an **oversized side is never known to match anything**, because its content was not read — two oversized sides are *not* the same (`:81-88`).
- **Edge cases & failure handling:** ENOENT → `{kind:'absent'}`; a path that is not a regular file → `undefined` (not tracked at all); a read error other than absence propagates (`:39-44`).
- **Surprising:** the "unread content is never known to be unchanged" rule is why a file that is oversized on both sides still appears in the changed-files card instead of silently disappearing.

#### `packages/deliverables/workspace-changes/src/compare.ts`
- **Purpose:** line comparison of two whole-file texts, bounded by a timeout that degrades to whole-file replacement.
- **Key abstractions:** `CONTEXT_LINES = 3` (`:6`), `Comparison` (`:9`), `compareText` (`:38`).
- **Data flow:** two texts (or `null` for "the file did not exist") → each side is terminated with a newline so the last line compares by content alone → `structuredPatch` from the `diff` package with `context: 3` and a `timeout` → hunks, `coarse` flag, and the added/deleted totals.
- **Non-obvious design decisions:** (a) the **timeout degrades rather than fails** — `structuredPatch` returns `undefined` when it exceeds `timeoutMs`, and the code then synthesises one hunk that deletes every old line and adds every new line, flagged `coarse` (`:45-56`); (b) `terminated()` treats empty text as *zero* lines and ensures the last line is compared by content, so "a missing final newline" is not a change (`:20-23`); (c) the added/deleted totals are computed from the hunk bodies by their `+`/`-` prefixes (`:58-65`).
- **Edge cases & failure handling:** `null` on either side means the file did not exist; two equal texts produce **no hunks at all** (not one empty hunk).
- **Surprising:** the default `diffTimeoutMs` is **100 ms** — a deliberately tight budget, because the diff is computed for a UI card and a slow diff is worse than a coarse one.

#### `packages/deliverables/workspace-changes/src/paths.ts`
- **Purpose:** path classification and the two display forms of a changed file.
- **Key abstractions:** `toPosix` (`:11`), `isInside` (`:21`), `temporaryRoots` (`:33`), `canonicalPath` (`:49`), `isTemporaryPath` (`:72`), `displayPathOf` (`:84`), `durablePathOf` (`:96`), `compareDisplay` (`:107`).
- **Data flow:** an absolute canonical path → `display` (cwd-relative → repo-relative `../` → `~/` → absolute) and `path` (cwd-relative or absolute).
- **Non-obvious design decisions:** (a) **`canonicalPath` resolves a path that does not exist yet through its nearest existing ancestor**, so a file created through a directory symlink has the same canonical spelling *before and after* it exists (`:49-68`); (b) `temporaryRoots` keeps **both** the raw and the symlink-resolved spelling of `/tmp` and the platform temp dir, so `/tmp` and `/private/tmp` match alike (`:33-43`); (c) `displayPathOf` and `durablePathOf` are *different* projections of the same path — the display form is for humans and ordering, the durable form is what the client opens (`:84-101`); (d) `compareDisplay` sorts by **code unit**, which places `../` and absolute paths before letters and matches git's own listing order (`:104-109`).
- **Edge cases & failure handling:** `isInside` uses `relative()` and rejects `..`-prefixed and absolute results (`:21-24`); a path with no existing ancestor keeps its spelling entirely (`:61`).
- **Surprising:** two separate path fields in the durable record is the trick that lets a client both *open* a file (needs the durable path) and *show* a readable label (needs the display path) without recomputing anything.

#### `packages/deliverables/workspace-changes/src/numstat.ts`
- **Purpose:** parsing of `git diff-tree --numstat -z` output.
- **Key abstractions:** `NumstatEntry` (`:4`), `parseNumstat` (`:20`).
- **Data flow:** NUL-separated stdout → records split on the **first two tabs only** (a file name may itself contain tabs) → rename records (empty path) pull two more fields.
- **Non-obvious design decisions:** (a) **only the first two tabs separate fields**, because a file name can contain tabs (`tests/numstat.spec.ts:26-33`); (b) the output must be NUL-terminated — a truncated output throws "numstat output is not NUL-terminated" rather than silently dropping the last record (`:23-24`); (c) a binary file (`-`/`-`) becomes `added:0, deleted:0, binary:true` rather than an error (`:44-48`).
- **Edge cases & failure handling:** every malformed shape throws with a message naming the offending record — truncation is a loud failure, not a silent partial list.
- **Surprising:** the parse is deliberately paranoid because the caller uses the result to *attribute* changes; a silently truncated list would mis-attribute a turn.

#### `packages/deliverables/workspace-changes/src/types.ts`
- **Purpose:** the durable vocabulary of the workspace-changes family plus the Service and Session-event declarations.
- **Key abstractions:** `WorkspaceChangedFile` (`:9`), `WorkspaceChangesSummary` (`:27`), `WorkspaceDiffHunk` (`:50`), `WorkspaceFileDiff` (`:65`), `WorkspaceChanges` service (`:82`), plus the `SessionEventMap` and `Context` augmentations (`:106-124`).
- **Data flow:** the recorder produces a summary → the event carries only `{turn}` → the summary itself is served by `ctx.workspaceChanges.summary(sessionId, seq)` while the Session lives.
- **Non-obvious design decisions:** (a) **the event carries only the turn number** — the payload stays on the Host, because the summary can be large and the Host already has it; (b) `WorkspaceFileDiff` is a **three-way discriminated union** (`text | binary | oversized`), so "no lines are served" is a *type*, not an empty diff; (c) `total`, `added` and `deleted` count **every** changed file, while `files` is capped — the summary can honestly say "500 of 812" (`:30-40`).
- **Surprising:** the summary explicitly notes "A conversation reopened after a Host restart therefore has no card, and no comparison, for its earlier turns" — the decided behaviour is that a card whose content the Host can no longer open is *not shown*.

#### `packages/document/office-to-pdf/src/index.ts`
- **Purpose:** the Host LibreOffice-kit provider — Office bytes in, complete PDFs out, with reusable converters and private disk I/O.
- **Key abstractions:** `Config` (`:31`) with **17** bounds, the schemastery `Config` schema (`:73`), `OfficeToPdf extends TypertRemoteService` (`:101`), `convert` (`:147`), the `@Remote render` method (`:160`), the `@Remote('generation') getGeneration` (`:175`), `renderFile` (`:177`), `convertBytes` (`:233`).
- **Data flow:** `render(scope, path, priority)` → the extension is checked against the six supported ones → `workspaceFiles.readBytes(scope, path, {range:{offset:0,length:1}})` performs the **authorisation probe** → `workspaceFiles.stat` gives the version → a deferred `source.read()` re-checks the version before *and* after the bounded read → the `ConversionQueue` admits, dedupes, converts → the PDF bytes are returned with the original path/version and the provider's `generation`.
- **Non-obvious design decisions:** (a) **authorisation is re-checked before the cache is consulted** — a cached PDF is only served after the source is still readable and authorised (`:196-203` in `renderFile`; the `remote.spec.ts` case "refuses a cached PDF when source metadata remains readable but content access is denied"); (b) the **source version is verified twice** — once before the read and once after — so a file replaced mid-read is classified `source-changed` rather than converted; (c) a provider **`generation`** is a random UUID that changes whenever the provider is re-created, and it is part of the cache key, so a replacement engine or font set never reuses an old PDF (`:103`, `:162-166`); (d) **each concurrency slot lazily creates and reuses one kit converter** (`:236-244`); (e) the input is written into a **private `mkdtemp` directory** with `flag:'wx'` and mode `0o600`, and the directory is removed in a `finally` before the call settles (`:246-253`, `:271-274`); (f) a kit factory failure **deletes the cached slot promise** so the next call retries initialization (`:237-241`).
- **Edge cases & failure handling:** every engine failure is mapped to one of the classified `OfficeToPdfErrorCode`s (`:258-268`); an unclassified error becomes `failed` with the original as `cause`; a cancelled Remote call becomes `gateway/cancelled` and a conversion failure becomes `document-render/failed` carrying only the classified `reason` — **never engine diagnostics** (`:225-231`); disposal aborts the remote lifetime, disposes the queue, joins outstanding Remote requests and **joins every converter disposal**, reporting a cleanup failure as an `AggregateError` (`:128-143`).
- **Surprising:** the provider validates `maxSourceBytes >= maxInputBytes` and `fontDirectories` absoluteness in the **constructor**, not only in the schema (`:116-117`) — the constructor is reachable directly in tests.

#### `packages/document/office-to-pdf/src/queue.ts`
- **Purpose:** bounded source admission, shared content conversion, and caller-owned PDF delivery — the whole scheduling policy of the provider.
- **Key abstractions:** `ConversionQueue` (`:28`), `Job` / `Reader` (`:17-27`), `read` (`:57`), `dispose` (`:109`), `release` (`:123`), `cancel` (`:135`), `fail` (`:143`), `reservation` (`:147`), `drain` (`:149`), `execute` (`:176`), `finish` (`:211`), `retain` (`:222`).
- **Data flow:** `read(request, signal)` → an alias lookup on `[source.key, source.version, extension]` → a ready PDF is returned with **no reader slot consumed** (`:60-72`) → otherwise a reader slot is taken and the job is queued or joined → `drain()` picks eligible jobs → `execute()` reads the source, digests the bytes, and either reuses a ready PDF, **joins an identical running conversion by digest**, or converts → the result is retained (LRU) and every reader receives an independent copy.
- **Non-obvious design decisions:** (a) **two levels of dedup**: a *source alias* (key+version+extension → cache key) avoids re-reading the file, and a *content digest* (`extension + sha256(bytes)`) shares the conversion across **different source paths** (`:179-208`); (b) **the reader slot is reserved for foreground work**: a background reader's limit is `maxReaders - 1` (`:74`); (c) **foreground admission may evict queued speculation** — a queued background job is failed with `busy` to make room (`:79-84`); (d) a **foreground reader promotes a queued background job**, and when its last foreground reader leaves the job **demotes** back to background (`:86`, `:123-134`); (e) a background job **waits while any foreground job is queued**, even if the foreground job is itself waiting for source capacity (`:150-152`); (f) source capacity is **reserved before the read** and held until the conversion actually settles, including after cancellation (`:147`, `:186-191`); (g) **the final reader cancels the shared work** (`:96-98`); (h) a **ready alias hit consumes no reader slot** and bumps LRU (`:60-72`).
- **Edge cases & failure handling:** a changed source version → `source-changed`; a read that exceeds its reservation → `input-too-large`; a queue overflow → `busy`; disposal → `unavailable` for every outstanding reader (`:110-116`); every reader receives an **independent copy** of the PDF and the font list (`copy`, `:120-122`), so one caller mutating its buffer cannot corrupt another's.
- **Surprising:** `execute` will **join an already-running conversion with the same digest** and move all readers onto it (`:194-205`) — two different files with identical content cost one conversion, and the second file's bytes are still read (the digest is only known after the read).

#### `packages/document/office-to-pdf/src/output.ts`
- **Purpose:** read only the bounded, regular PDF created inside a private task directory.
- **Key abstractions:** `readPdf(path, limit, signal)` (`:13`).
- **Data flow:** `lstat` → must be a regular file → `open(path, O_RDONLY | O_NOFOLLOW)` → `fstat` the **opened handle** (not the path) → size checked against the limit → read at most `size + 1` bytes → the `%PDF-x.y` header and the trailing `%%EOF` are both required.
- **Non-obvious design decisions:** (a) `O_NOFOLLOW` refuses a symlinked output (`:17`); (b) the size is checked **twice** — once from `fstat` and once from the actual number of bytes read — because the file may grow between the two (`:26`, `:33`); (c) the file is closed in a `finally` (`:38`); (d) the completeness check is **both** a header match and a trailing `%%EOF` within the last 1024 bytes (`:35-37`), so a truncated PDF is refused rather than returned.
- **Edge cases & failure handling:** a missing/odd output → `invalid-output`; an oversized output → `output-too-large`; an abort during the read throws the signal's reason.
- **Surprising:** the `output.spec.ts` test replaces the *path's* metadata with a directory's metadata to prove the code uses `fstat` on the **opened handle**, not the path — a genuine TOCTOU defence.

#### `packages/document/office-to-pdf/src/types.ts`
- **Purpose:** the authorised-Office vocabulary, the result shape and the classified failure codes.
- **Key abstractions:** `OfficeExtension` (`:8`), `OfficeToPdfPriority` (`:11`), `OfficeToPdfRequest` (`:14`), `OfficeToPdfResult` (`:33`), `OfficeToPdfErrorCode` (`:43`), `RenderedDocumentBytes` (`:48`), plus the `RemoteErrorDetailsMap` augmentation for `'document-render/failed'` (`:52-55`).
- **Data flow:** request (metadata + a deferred `read`) → result (PDF bytes + missing fonts + cache key + generation).
- **Non-obvious design decisions:** (a) **the source is a deferred `read(signal, maxBytes)` closure**, not bytes — the file is not read until the queue has admitted the job (`:19-25`); (b) the `read` contract says "read at most this plus one overflow sentinel byte" — a one-byte overflow sentinel is how the provider detects a file that grew beyond its reservation without reading it all (`:21`); (c) the read returns the **actual version** it observed, so a changed file is caught by comparison, not by a stat (`:23`); (d) `OfficeToPdfErrorCode` is a **flat ten-member union** a consumer can present without engine diagnostics (`:43-45`).
- **Surprising:** `OfficeToPdfPriority` is a **two-value** union — `foreground` (an explicit preview the user is waiting for) and `background` (speculative pre-warming) — and the whole queue policy is written around that distinction.

#### `packages/document/office-to-pdf/src/identity.ts`
- **Purpose:** three branded identities that keep the source locator, the provider lifetime and the content identity distinct.
- **Key abstractions:** `OfficeSourceKey` (`:5`), `OfficeToPdfGeneration` (`:14`), `OfficeToPdfKey` (`:25`).
- **Data flow:** the caller encodes an *authorisation scope + execution world + canonical path* into the source key; the provider mints a generation; the content key is `generation:digest`.
- **Non-obvious design decisions:** the JSDoc states plainly that **source authorisation remains the caller's responsibility** — the brand is a labelling device, not a permission check (`:7-11`); the content key "must not be parsed" by consumers (`:22`).
- **Surprising:** three separate brands for what a naive implementation would treat as "an id" — the separation is what makes "the engine changed" and "the file changed" and "this is the same content" three different questions.

#### `packages/document/office-to-pdf/src/errors.ts`
- **Purpose:** the single classified failure class shared by the converter and its consumers.
- **Key abstractions:** `OfficeToPdfError` (`:7`) with a `readonly code: OfficeToPdfErrorCode`.
- **Data flow:** engine failure → classified code + a diagnostic message + the original as `cause`.
- **Non-obvious design decisions:** the class keeps the **engine details in `cause` only** — the message and the code are safe to show (`:2`, `:12-15`).
- **Surprising:** a tiny file that exists purely so the *code* (not the message) is the contract.

### Tier 1 — load-bearing source: full entry

#### `packages/feedback/command-feedback/src/index.ts`
- **Purpose:** Session-level feedback — the `/feedback` command, a command-independent producer, and the `sessionFeedback` Host Remote — all without a model turn.
- **Key abstractions:** `FEEDBACK_CATEGORIES` (`:30`), `recordFeedback` (`:58`), `executeFeedbackCommand` (`:73`), `SessionFeedbackService` (`:85`), `apply` (`:117`).
- **Data flow:** any trigger (slash command, Web dialog, an integration) → `recordFeedback(session, entry)` → the text is trimmed, blank becomes absent → **one** `feedback/record` event is appended to the Session log (`:58-67`) → the command path adds an acknowledgement line, the Remote path answers `{ok:true, value:{recorded:true}}`.
- **Non-obvious design decisions:** (a) **the fact is owned by the event, not by the trigger** — the command's own bookkeeping (`command/run`) carries **no** `args`, so the remark text exists in exactly one place in the log and a second trigger (the dialog) writes the identical event (README "Design concept"); (b) **the append is eager but unflushed** — the acknowledgement means "the entry reached the log", not "it reached disk" (`:1-7`, `:78-81`); (c) the Remote's `record` resolves the **live** Session by id and answers `session-not-found` when no live owner carries it (`:102-111`); (d) the `/feedback` command sets `recordInput: false` (`:124`) so the raw text is not duplicated into command bookkeeping; (e) `FEEDBACK_CATEGORIES` is a `satisfies readonly FeedbackCategory[]` tuple — the runtime list and the type are one declaration (`:30-38`).
- **Edge cases & failure handling:** empty or whitespace-only command input is a **usage error** and records nothing (`:74-76`); an entry with neither text nor category is still recorded (`:64-66`); the remark is kept **exactly as typed** apart from trimming — `/feedback /plan felt slow` records that literal text (`:59-60`, README); each command records its own entry — nothing is merged or replaced.
- **Surprising:** the categories are **durable log vocabulary shared with per-message feedback** — the message-feedback package imports `FEEDBACK_CATEGORIES` from here, so the two feedback kinds share one taxonomy by construction, not by convention.

#### `packages/feedback/command-feedback/src/types.ts`
- **Purpose:** the public vocabulary of Session-level feedback — the taxonomy, the event payload and the Remote request/result types.
- **Key abstractions:** `FeedbackCategory` (`:15`), `FeedbackRecord` (`:29`), the `SessionEventMap` augmentation for `'feedback/record'` (`:37-41`), `SessionFeedbackRecordRequest` (`:44`), `SessionFeedbackRecordValue` (`:54`), `SessionFeedbackSessionNotFound` (`:60`), `SessionFeedbackRecordResult` (`:67`).
- **Data flow:** a caller builds a request → the Remote resolves a live Session → the record is appended.
- **Non-obvious design decisions:** **both members of `FeedbackRecord` are optional**, and the JSDoc says why: "a submission with neither still records that the human asked for the Session to be reviewed, which is what authorizes log delivery" (`:26-28`). The `feedback/record` event carries **no `surfaceOp`**, so it never reaches the ordered surface, `deriveMessages()` or a system prompt (`:37-41`).
- **Edge cases & failure handling:** the Remote result is a discriminated union (`ok:true` / `ok:false` with a stable `code`) rather than an exception, so a browser surface can render the failure in its own words (`:67-70`).
- **Surprising:** the module is **types only** — the runtime category tuple lives in the package entry, "because a browser plugin imports types alone and its bundle may not carry Host values" (`:3-8`).

#### `packages/feedback/message-feedback/src/index.ts`
- **Purpose:** canonical Session-log ratings, categories and notes for finalized assistant messages.
- **Key abstractions:** `Config` (`:40`), the `Events` augmentation for `'feedback/committed'` (`:52-64`), `currentItems` (`:97`), `MessageFeedbackService` (`:118`), `list` (`:155`), `put` (`:167`), `delete` (`:207`), `withSession` (`:227`), `resolveNote` (`:286`), `enqueue` (`:300`).
- **Data flow:** a `put`/`delete`/`list` → the note is validated **before** the Session is even looked up (`:168-170`, `:286-295`) → the operation is serialised per Session by a promise-tail queue (`:300-311`) → a **live** Session path appends via `Session.append`, awaits `sessions.flush`, then **re-reads the persisted prefix through a read handle and compares it** to the live log (`:238-266`) → a **cold** Session path holds a persistence **write** handle across read → validate → compare → append → flush → close (`:267-283`) → the current state is always **derived** from the event log; there is no second store (`:97-113`).
- **Non-obvious design decisions:** (a) **optimistic concurrency with a real version token**: `ifVersion` must equal the current item's `version` (a fresh UUID minted on every material change) or the operation fails with `version-conflict` and the current item (`:184-188`); (b) a **matching put is a no-op** — it returns the same item and appends **no** event (`:189-193`); (c) deleting an absent item **succeeds regardless of the supplied version** and appends nothing (`:214-218`) — the postcondition `{absent:true}` is stable across retries; (d) the **target must be a non-empty, append-origin assistant message** — user messages, empty assistant placeholders and replacement-origin messages are `target-not-found` (`:177-183`); (e) the live path **verifies the durability checkpoint after the flush** — a mismatch, a missing tail or a different header throws "feedback prefix is not durable" (`:246-262`); (f) every returned item is a **frozen, detached snapshot** (`:84-86`, `:88-95`); (g) the durable payloads are **validated with zod on read**, so a corrupted or hand-written log is refused rather than trusted (`:100-109`, `:52-61`); (h) disposal **closes the admission gate and drains** the admitted operations before releasing the service (`:143-149`).
- **Edge cases & failure handling:** a note that is blank → `note-blank`; a note over the byte limit → `note-too-large` with `maxBytes` and `actualBytes`; a stale version → `version-conflict` with the current item; **persistence failures reject rather than becoming business failures** (so a caller can distinguish "your request was wrong" from "the disk failed"); a failed flush does **not** roll back an accepted event — the caller can `list` and retry with the item's version (README).
- **Surprising:** the service distinguishes a **live** Session from a **cold** one and *cold operations never construct a Session or an Agent* — `list`/`put`/`delete` work on a session that has not been opened in this process, which is what lets the Web client read feedback for a closed conversation without waking an agent.

#### `packages/feedback/message-feedback/src/types.ts`
- **Purpose:** the request, value and failure vocabulary for per-message feedback — types only, so a generated Remote client can consume it without importing Host runtime code.
- **Key abstractions:** `MessageFeedbackVersion` (`:12`), `MessageFeedbackRating` (`:15`), `MessageFeedbackItem` (`:19`), `MessageFeedbackPut` (`:40`), `MessageFeedbackDelete` (`:47`), the two `SessionEventMap` entries (`:52-58`), `MessageFeedbackListRequest/Value` (`:61`, `:66`), `MessageFeedbackPutRequest` (`:72`), `MessageFeedbackDeleteRequest` (`:85`), and the failure union `MessageFeedbackFailure` (`:131`).
- **Data flow:** request → service → durable event → derived item.
- **Non-obvious design decisions:** (a) the **`version` token is described as "equality-only"** — "replaced by every material create or update" (`:27-28`), i.e. it is a compare-and-set token and nothing else; (b) `MessageFeedbackPut` carries the **complete current value**, not a patch (`:37-41`), so the log is replayable without a patch vocabulary; (c) the delete event carries **only the owner and the message id** — the deletion is a tombstone, and "earlier ratings and notes remain in the log" (`:52-54`).
- **Edge cases & failure handling:** the failure union is a **five-member discriminated union** (`session-not-found`, `target-not-found`, `version-conflict`, `note-blank`, `note-too-large`) and each operation's result type names exactly which failures it can return (`:135-166`); `MessageFeedbackVersionConflict` carries the **authoritative current item**, so a client can retry without a second round trip (`:121-125`).
- **Surprising:** "inherited feedback in a fork belongs to its parent" — the `MessageFeedbackPut.sessionId` is the **owner**, and `currentItems` ignores events belonging to another Session (`:38-39`, `:100-110`), so a fork starts with no owned feedback even though its inherited prefix contains the parent's.

#### `packages/web/web-fetch-http/src/provider.ts`
- **Purpose:** the anonymous public HTTP(S) fetch provider — safe retrieval with pinned addresses, same-origin redirects and hard caps.
- **Key abstractions:** `HttpFetchLimits` (`:19`), `HttpFetchResolver` (`:33`), `LOCAL_FETCH_PROVIDER_ID = 'http'` (`:36`), `HttpFetchProvider` (`:39`), `followAndRead` (`:66`), `requestOnce` (`:117`), `readBody` (`:147`), `readCapped` (`:185`), `translateAbortOrNetwork` (`:266`).
- **Data flow:** `fetch(url)` → `deadline(signal, timeoutMs, 'WEB_FETCH_TIMEOUT')` → `validateFetchUrl` → resolve + pin the address set → request → follow same-origin redirects (re-validating each target) → classify the content type → resolve the decoder → read under the byte cap → decode → truncate to the character cap.
- **Non-obvious design decisions:** (a) **only DROPPED bytes count as truncation** — a chunk that exactly fills the remaining capacity keeps all its bytes and the read continues to observe EOF, "so an exactly-at-cap body is not falsely flagged truncated" (`:205-214`); (b) the **redirect budget is checked before the target is resolved or validated**, so an over-limit hop reports "exceeded" rather than "cross-origin" (`:71-77`); (c) a **redirect target is re-validated with the same policy** a direct request gets — "a redirect must not be a back door to a credentialed, non-http(s), or over-long URL" (`:85-104`); (d) **the response body is cancelled on every error path** (missing `Location`, blocked redirect, unsupported charset) so no socket leaks (`:79-81`, `:92`, `:99-103`, `:151-153`); (e) `translateAbortOrNetwork` classifies **by the deadline signal, not the thrown value**, because the request phase rejects with the abort reason while the read phase surfaces a bare `AbortError` (`:256-265`).
- **Edge cases & failure handling:** `Content-Length` over the cap is rejected (`WEB_FETCH_TOO_LARGE`) while a stream that grows past the cap is **cut short** and marked truncated — "a server that under-reports still yields a bounded usable body" (`:186-193`); a redirect with no `Location` is `WEB_PROVIDER_ERROR`; the decoder is resolved **before** the body is read so an unsupported charset fails without consuming the stream.
- **Surprising:** a **proxied** hop skips public-address resolution and pinning (the proxy does the origin's DNS), but **an IP literal the address checks would refuse never takes that shortcut** — "the proxy would resolve nothing … so the shortcut would spend the checks for nothing and let a proxy on this machine reach the very service they keep out of reach" (`:117-140`).

#### `packages/web/web-fetch-http/src/network.ts`
- **Purpose:** public-network resolution and address-pinned HTTP transport.
- **Key abstractions:** `PublicAddress` (`:18`), `PinnedResponse` (`:26`), `AddressResolver` (`:34`), `isPublicIpAddress` (`:54`), `resolvePublicAddresses` (`:75`), `discoverNat64Prefixes` (`:113`), `isNonPublicIpLiteral` (`:171`), `requestPinned` (`:191`), `requestVia` (`:229`), `publicHttpNetwork` (`:242`), `createPinnedLookup` (`:260`), `raceWithSignal` (`:288`).
- **Data flow:** hostname → one DNS answer set (`all: true, order: 'verbatim'`) → every address checked → the validated set is handed to a **per-request undici Agent whose `connect.lookup` returns only those addresses** → the connection cannot re-resolve to a private address.
- **Non-obvious design decisions:** (a) **the whole answer set is rejected if any member is non-public** — "reject the complete answer set if any destination is not public" (`:78-84`); (b) **DNS64 is handled** — the RFC 7050 `ipv4only.arpa` discovery hostname is resolved to find the active NAT64 prefixes, and an IPv6 address that translates to a **non-public** IPv4 is refused (`:108-135`); (c) IPv4-mapped IPv6 is classified by its embedded IPv4 (`:66-70`); (d) **the pinned Agent is per-request, not process-wide** — "an operator-configured MCP server or model endpoint on loopback is a supported destination, and only the URLs this tool fetches are the model's to choose" (`:180-190`); (e) `undici` is **dynamically imported** so a browser worker can load the provider without evaluating it (`:197-198`); (f) the DNS lookup is **raced against cancellation** even though the OS lookup itself cannot be cancelled (`:288-297`).
- **Edge cases & failure handling:** an empty answer set, an invalid family, and a family/address mismatch are all `WEB_PROVIDER_ERROR`; a non-public address is `WEB_BLOCKED_URL`.
- **Surprising:** the whole DNS64 discovery is a **security control**, not an optimisation — without it a NAT64 network could smuggle a private IPv4 past a "public unicast" check.

#### `packages/web/web-fetch-http/src/policy.ts`
- **Purpose:** the pure, network-free half of the fetch provider — URL validation and content-type classification.
- **Key abstractions:** `WEB_FETCH_MAX_URL_LENGTH = 2048` (`:12`), `FetchableKind` (`:15`), `parseFetchUrl` (`:25`), `validateFetchUrl` (`:49`), `isSameOrigin` (`:65`), `classifyContentType` (`:78`), `parseCharset` (`:96`), `decoderForCharset` (`:111`).

- **Key abstractions:** `DeepSeekWebAuth` (`:21`), `DeepSeekWebGuidance` (`:33`), `deepSeekWebAuth` (`:71`), `hasDeepSeekWebCredential` (`:102`), `isRecord` (`:110`), `invalidResponse` (`:117`), `dispatchDeepSeekWeb` (`:135`), `accountRejectedError` (`:209`), `searchEndpointError` (`:225`), `authHeaders` (`:246`), `resolveApiKey` (`:269`), `abortable` (`:314`).
- **Data flow:** the provider hands over an endpoint, a JSON body and a **decoder function**; the transport resolves the credential, dispatches with `redirect:'error'`, and hands the parsed JSON to the decoder.
- **Non-obvious design decisions:** (a) **the provider supplies the decoder**, so the transport is provider-agnostic and the response validation lives next to the provider that knows the shape (`:56`, `:135`); (b) the transport **repeats** the credential/cancellation helpers from `dsh-web-search-deepseek` on purpose — "so neither plugin depends on the other" (`:1-7`); (c) `recordRequest` runs **before** the dispatch and a throw prevents it (`:140-143`); (d) the **guidance object names the settings page, the field and the label**, so the failure message can tell the *model* exactly where the user must go (`:33-46`, `:225-243`).
- **Edge cases & failure handling:** an abort during the success-body parse is `WEB_ABORTED`, not a provider error; a 401 on an account-authenticated request gives sign-in guidance; a missing credential gives `WEB_PROVIDER_CREDENTIAL_MISSING` with a three-way remediation message (`:269-290`).
- **Surprising:** `hasDeepSeekWebCredential` checks **whether a resolver exists, not whether it resolves** — the provider can therefore be "available" and still fail the operation.

#### `packages/web/web-deepseek-api/src/search.ts`
- **Purpose:** the DeepSeek Search API provider — one direct request per search, no auxiliary model request.
- **Key abstractions:** `DEEPSEEK_SEARCH_API_PROVIDER_ID` (`:13`), `DEEPSEEK_WEB_API_BASE_URL` (`:16`), `DEEPSEEK_DEFAULT_COUNT = 10` (`:19`), `ORIGINAL_QUESTION_MAX_CHARS = 128` (`:22`), `DEEPSEEK_WEB_API_GUIDANCE` (`:25`), `mapSearchResponse` (`:45`), `DeepSeekSearchApiProvider` (`:65`), `boundedQuestion` (`:102`).
- **Data flow:** `search(query)` → `count = min(configured, request.maxResults)` → body `{query, count, need_content:false, ori_question?}` → `POST {baseURL}/search` → `mapSearchResponse` validates every field of every result.
- **Non-obvious design decisions:** (a) **`need_content: false`** — the provider asks for snippets only, deliberately not consuming `summary`/`site_name`/`site_icon`/full content (`:86-88`); (b) `ori_question` is the **latest human prompt** with whitespace collapsed and cut to 128 characters — and it is cut **by code point**, so a surrogate pair is never split (`:102-108`); (c) the response validation is **field-by-field** — a wrong type on one optional field rejects the whole response rather than being coerced (`:45-63`); (d) an empty results array is a **success** (`:60-63`).
- **Edge cases & failure handling:** a blank or unparseable `baseURL` makes the provider unavailable; a `count` outside 1–50 makes it unavailable too.
- **Surprising:** the provider reads the initiating Session's derived messages to find the human prompt — `latestUserQuestion` filters on `source.kind === 'user'` so injected user-role context is not mistaken for the trader's question (`index.ts:60-68`).

#### `packages/web/web-deepseek-api/src/fetch.ts`
- **Purpose:** the DeepSeek Fetch API provider — page Markdown through one direct request.
- **Key abstractions:** `DEEPSEEK_FETCH_API_PROVIDER_ID` (`:14`), `DeepSeekFetchApiOptions` (`:17`), `DeepSeekFetchApiProvider` (`:27`).
- **Data flow:** `fetch(url)` → `POST {baseURL}/fetch` with `{url}` → the Markdown string becomes `{kind:'text'}`.
- **Non-obvious design decisions:** (a) **a success is reported as HTTP 200** because "the API reports neither the target's status nor a final URL, and it fails when the target yields no usable content" (`:23-25`); (b) the returned URL is the **requested** URL, not a final one; (c) the API's page title is **discarded**.
- **Edge cases & failure handling:** a non-success Fetch API status is a **retrieval failure**, not a target-page status — an important distinction the README states explicitly.
- **Surprising:** a fetch provider that cannot report the target's status still satisfies the seam's `WebFetchResult` contract by reporting 200 — the contract's "non-2xx is a result" rule does not survive this backend, and the README says so.

## 2. Ideas worth stealing

1. **A durable-write protocol that is *durability*, not existence.** `ensureDurableDirectory` re-fsyncs every ancestor of a published object, up to a process-proven boundary, because "a concurrent first save can create a level this process then merely observes, so 'already existed' is not 'already durable'" (`packages/attachment/attachment-local/src/store.ts:156-174`). **CONVERGENT** — the same instinct appears in the git snapshot work (a private index so the repository's own index is never touched, `packages/deliverables/workspace-changes/src/git.ts:154-172`) and in the office converter (a per-request private scratch directory removed before the call settles, `packages/document/office-to-pdf/src/index.ts:246-274`). **Why it transfers:** August Trading writes trade journals, analysis caches and notebook files; an append that "succeeded" but whose directory entry never reached disk is exactly the failure that loses a logged trade on a crash. A cheap `fsync` chain, plus the honest comment *why*, is directly portable.
2. **Split one store into two policies: normalised images vs. verbatim files.** Images are decoded, re-oriented, stripped of metadata and normalised to 8-bit sRGB before storage; generic files are committed byte-for-byte with no admission limits and are only ever *verified* on read (`packages/attachment/attachment-local/src/normalization.ts:36-47`, `packages/attachment/attachment-local/src/file-store.ts:91-145`). **UNIQUE** to this repo. **Why it transfers:** August Trading stores chart screenshots (PNG/JPEG) *and* CSVs of trades. One size cap and one byte-format assumption for both is wrong; a "normalise what the model will see, keep verbatim what the user will own" split is the right shape.
3. **A deterministic cache key that includes every transform input — including a transform *version*.** `requestImageVariantId` hashes the attachment id, the target dimensions, the byte budget, the encoder settings *and* `REQUEST_IMAGE_TRANSFORM_VERSION = 'request-image-v6'` (`packages/attachment/attachment-local/src/request-image.ts:26`, `:56-77`). **CONVERGENT** — the office converter does the same with its `generation` UUID folded into the content key (`packages/document/office-to-pdf/src/queue.ts:179-183`), and the attachment README states the rule plainly ("an encoder or transform-version upgrade re-addresses future variants while existing objects remain valid"). **Why it transfers:** any cache in August Trading that depends on a formatter, a prompt template, or a model version must be re-addressed by that version, or it will serve stale output after an upgrade.
4. **Verify-on-read, and let the *cost* of verification fall where it belongs.** The image store verifies the digest on every read but only **re-probes the header** rather than re-decoding the raster, because "the digest proves these are the exact bytes admission fully decoded" (`packages/attachment/attachment-local/src/store.ts:452-459`); the office converter likewise verifies the PDF's header *and* its trailing `%%EOF` from the **opened handle**, not the path (`packages/document/office-to-pdf/src/output.ts:17-37`). **CONVERGENT** — the file store verifies the digest *after* the last chunk so a truncated export fails the consumer rather than producing a "complete" wrong file (`packages/attachment/attachment-local/src/file-store.ts:180-183`). **Why it transfers:** August Trading re-reads persisted analysis and journal rows; verifying "the digest matches" once and "the metadata matches" cheaply on each read is the same cost/assurance trade.
5. **Two-level dedup: a source alias *and* a content digest.** The office queue holds a bounded "source version → cache key" index so a known file is not re-read, and separately dedupes **by content digest across different paths** so two identical documents cost one conversion (`packages/document/office-to-pdf/src/queue.ts:60-72`, `:186-208`). **CONVERGENT** — the attachment file store does the same idea with hard links: one canonical object, many display names, one inode (`packages/attachment/attachment-local/src/file-store.ts:81-89`). **Why it transfers:** August Trading re-analyses the same chart or the same strategy across sessions; a content-addressed analysis cache plus a path alias is the same win.
6. **A "foreground vs background" scheduling priority with explicit promotion and demotion.** The office queue reserves one reader slot for foreground work, promotes a queued background job when a foreground reader joins, demotes it when the last foreground reader leaves, and evicts queued speculation to make room (`packages/document/office-to-pdf/src/queue.ts:74-98`, `:123-134`). **UNIQUE** to this repo. **Why it transfers:** August Trading has exactly this shape — a user's foreground analysis must not queue behind a background sweep of every symbol. The promotion/demotion rules and the "final reader cancels the shared work" rule are the hard part and are worth copying verbatim.
7. **Attribute a turn's changes to the turn, not to the working tree.** The recorder takes a git snapshot at turn start and turn end through a **private index and a private object store**, with the repository's own object store attached read-only, so the user's pre-existing uncommitted work never enters the summary and the repository is never written to (`packages/deliverables/workspace-changes/src/git.ts:141-172`). **CONVERGENT** — the same "isolate the observation from the user's state" idea appears in the attachment store's "normalize once, project per route". **Why it transfers:** August Trading runs tools that write files; a turn-level diff that excludes the trader's own pre-existing edits is the difference between a useful audit trail and a misleading one.
8. **Compare on demand, not at record time.** The recorder stores only the *sources* of each file's two sides (a path in a snapshot tree, or a copy) and computes the diff when asked (`packages/deliverables/workspace-changes/src/recorder.ts:219-241`, `:340-364`). **CONVERGENT** — the office queue keeps the PDF bytes and re-derives nothing, while the web tool memoises its HTML→markdown conversion per result (`packages/web/tool-web/src/fetch.ts:302-326`). **Why it transfers:** a trade-journal "what changed in this analysis" card should be computed when it is opened, so the expensive path is paid only by the user who looks.
9. **A compare-and-set token for every human-authored mutation, derived from the log.** Per-message feedback carries a `version` UUID; a stale mutation returns `version-conflict` *with the current item* so the client can retry without a second round trip (`packages/feedback/message-feedback/src/types.ts:27-28`, `:121-125`). **CONVERGENT** — the same optimistic-concurrency shape appears in the attachment request-image cache key and the office queue's digest sharing. **Why it transfers:** if August Trading lets a trader edit a journal entry or a strategy note, a version token is the cheapest way to stop two windows clobbering each other.
10. **Log-only facts that never enter model context.** The feedback events carry **no `surfaceOp`**, so `deriveEventMessage` returns null, `foldSurface` is empty and `deriveMessages()` is empty — proven by a test, not by a convention (`packages/feedback/command-feedback/src/types.ts:37-41`, `packages/feedback/command-feedback/tests/command-feedback.spec.ts` "keeps every recorded event out of model context"). **CONVERGENT** — the workspace-changes event is likewise "log-only" and "registers nothing model-facing". **Why it transfers:** a trade's feedback, the trader's own annotations, or an internal audit event must not silently consume context or steer the model. Making that a *type-level* property plus a test is the transferable part.
11. **A closed union for the model's view of the world, with `assertNever` at every consumer.** `WebFetchBody` is `html | text`, owned by the seam, and adding an arm breaks compilation at every consumer until handled (`packages/web/web/src/types.ts:84-98`, enforced at `packages/web/tool-web/src/fetch.ts:257-259`). **UNIQUE** to this repo. **Why it transfers:** August Trading renders several kinds of analysis artefact (table, chart, narrative, diff). A closed union plus `assertNever` forces the renderer to deal with the new kind instead of silently dropping it.
12. **Provider selection that is never order-dependent, with the ambiguity spelled out.** A configured id wins; without one, exactly one usable provider runs; with several, the call fails with `WEB_PROVIDER_AMBIGUOUS` rather than picking arbitrarily (`packages/web/web/src/index.ts:176-199`). **UNIQUE** to this repo. **Why it transfers:** August Trading will have more than one analysis backend (a local model, a remote one, a cached one). "Which one ran?" must never depend on plugin load order — and failing loudly beats a silent coin flip.
13. **Harden the model-facing surface against hostile input.** The web fetcher removes active and hidden HTML, bounds the DOM nesting depth with a hand-written lexical preflight (measured: depth 512 ≈ 0.15 s, 20 000 ≈ 5 s, during which the cooperative timeout cannot fire), and returns a **fixed omission marker** instead of raw markup when conversion is unsafe (`packages/web/tool-web/src/fetch.ts:31-49`, `:110-120`, `:156-241`, `:245-259`). **UNIQUE** to this repo. **Why it transfers:** August Trading renders model- and web-produced content into the UI; an HTML-conversion path with no depth bound is a denial-of-service vector against the trader.
14. **Refuse to let a provider's *shape* leak into the seam's promises.** The Exa adapter **drops** a result that has no non-blank highlight rather than inventing a snippet, and omits `content` entirely because Exa returns no answer — "inventing one would lie" (`packages/web/web-search-exa/src/provider.ts:47-53`, `:78-81`); the DeepSeek adapter refuses to scrape URLs out of model prose and throws instead of degrading (`packages/web/web-search-deepseek/src/provider.ts:157-176`). **CONVERGENT** — the Perplexity adapter falls back to URL-only citations precisely because the seam's fields are optional. **Why it transfers:** an analysis summary that fills in a missing price or a fabricated data source is worse than an empty field; make "absent" a first-class, honest value.
15. **Pin the connection to the address you validated.** The fetch backend resolves the hostname once, rejects the *whole* answer set if any address is non-public, discovers the active DNS64 prefix and refuses a translation to a private IPv4, and then serves a per-request undici Agent whose `lookup` returns only the validated addresses (`packages/web/web-fetch-http/src/network.ts:75-112`, `:113-135`, `:191-227`, `:260-286`). **UNIQUE** to this repo. **Why it transfers:** any URL-fetching feature in August Trading (a news feed, a broker status page, a documentation link) has the same DNS-rebinding hole.
16. **A per-call budget that belongs to the deployment, never to the model.** The web tools carry no timeout argument; the budget is config, attached to the tool definition and enforced by a separate timeout-policy plugin, while the provider keeps its own longer backstop for direct callers — and the two failure codes are deliberately different (`WEB_FETCH_TIMEOUT` vs `TOOL_TIMEOUT`) so the owner of the failure is visible (`packages/web/tool-web/src/index.ts:76-82`, `packages/web/web-fetch-http/README.md` "Two timeout layers"). **CONVERGENT** — the office converter does the same with a 60 s conversion deadline that "excludes the DSH queue". **Why it transfers:** a model-supplied timeout is a model-supplied footgun; the trader owns the budget and the code says who failed.
17. **One shared taxonomy owned by one package, imported by its siblings.** The seven feedback category ids live in `command-feedback` and are imported by `message-feedback` (`packages/feedback/command-feedback/src/index.ts:30-38`, `packages/feedback/message-feedback/src/index.ts:17`). **CONVERGENT** — the same "one owner, many consumers" rule governs the `WebFetchBody` union, the `WebError` taxonomy and the `AttachmentError` codes. **Why it transfers:** August Trading already has a `Reference` type and a `Message` type; the habit to look for a *shared vocabulary owner* before adding a second copy is the transferable part.
18. **Copy the error class rather than share the base when the dependency would cycle.** `AttachmentError` deliberately re-implements the `HarnessError` shape instead of extending it, because `HarnessError` lives in a package that depends on this one; consumers then identify the error **by code**, not by the prototype chain (`packages/attachment/attachment/src/error.ts:36-72`). **UNIQUE** to this repo. **Why it transfers:** in a TypeScript monorepo, error types are a classic source of import cycles; "duplicate the shape, route on the code" is a clean escape.
19. **A single immutable notice that keeps external text outside the instruction stream.** One 306-byte module exports `EXTERNAL_WEB_CONTENT_NOTICE` and both web tools prepend it (`packages/web/tool-web/src/trust.ts:6`). **UNIQUE** to this repo. **Why it transfers:** August Trading ingests broker messages, news and model output; one shared "this is data, not instruction" marker beats each surface inventing its own.

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work: not in this shard.** No cron, no scheduler, no catch-up-on-restart and no breaker appear in these 225 files. The closest neighbours are *bounded, resumable work queues* rather than schedulers: the office conversion queue reserves source bytes, holds them until the work actually settles, and cancels shared work when the last reader leaves (`packages/document/office-to-pdf/src/queue.ts:147`, `:123-134`); and the workspace recorder re-records a turn at `turn/end` **only when tool results settled after the last attempt**, which covers aborted, failed and steered turns without repeating a failed attempt (`packages/deliverables/workspace-changes/src/recorder.ts:191-196`). That "re-attempt only if something changed since the last attempt" rule is the closest thing here to an idempotency guard, and it is worth copying for any scheduled August Trading sweep.
- **Human-in-the-loop approval: essentially absent, and the absence is documented as a risk.** The `present` tool gates on a *structural* precondition (an open turn, a regular file) rather than on human consent, and publishes its declaration **only from a successful final `tools/result`** (`packages/deliverables/tool-present/src/index.ts:44-46`, `:96-104`). The web README is explicit that "public fetches do not request approval — the shipped `cordis`, `code`, and `standard` presets expose `web_fetch` in every sandbox and approval mode", and that a deployment needing per-call confirmation must add a `tools/pre-execute` policy (`packages/web/tool-web/README.md`, Known Limitations). The one approval-shaped artefact in the shard is the **audit trail**: the office converter's `recordRequest` hook appends the exact secret-free request body to the Session log *before* dispatch, and a throw in it prevents the dispatch (`packages/web/web-search-deepseek/src/provider.ts:105-111`, `:238-244`; `packages/web/web-deepseek-api/src/transport.ts:140-143`). For August Trading: there is **no approval gate and no durable decision record** for a consequential action anywhere in this shard — which is precisely the gap a proposal could fill.
- **Post-mortem / reflection loops: not in this shard.** Nothing here turns outcomes into rules, expires rules, or retires them. The *feedback* packages are the closest: they capture a human's verdict on a turn or on one assistant message (`packages/feedback/command-feedback/src/index.ts:58-67`) but offer **no retrieval, aggregation, amend or withdraw surface** — "a mistaken entry stays recorded and can only be superseded by a later one", and delete "removes current feedback, not earlier ratings or notes from the append-only log; it is not a privacy-erasure operation" (`packages/feedback/message-feedback/README.md`, Known Limitations). That is the honest shape of a *capture-only* feedback log; a rule-promotion loop with expiry and retirement is a different mechanism and lives elsewhere.
- **Multi-agent: out of scope, but the shard shows how subagent work is *attributed*.** The workspace recorder **explicitly excludes subagent Sessions** — `origin === 'subagent'` or `delegationDepth > 0` returns no working directory (`packages/deliverables/workspace-changes/src/index.ts:59-62`) — so a child's edits are charged to the parent turn instead of being double-counted. That is the single most transferable multi-agent idea here: decide, once, **who owns a change**, and make the exclusion explicit rather than emergent. The feedback packages are likewise agent-agnostic — `feedback/record` carries no `surfaceOp` and no actor.
- **Structured logs the model can query: a strong, and surprising, answer.** The shard's answer is **"the Session log is the database"**. Every durable fact is an append-only event with a declared payload type: `feedback/record`, `feedback/message-put`, `feedback/message-delete`, `workspace/changes`, `deliverables/presented`, `web/deepseek-search-llm-request` (`packages/feedback/message-feedback/src/types.ts:52-58`, `packages/deliverables/workspace-changes/src/types.ts:106-120`, `packages/deliverables/tool-present/src/types.ts:16-18`). Current state is **derived** from the log by a pure function, and there is "no second feedback store or cache" (`packages/feedback/message-feedback/README.md`, Canonical log and durability). Durability is bought with an explicit **checkpoint verification**: a live append is flushed and then the persisted prefix is re-read through a persistence handle and compared byte-for-byte against the live log, and a mismatch throws "feedback prefix is not durable" (`packages/feedback/message-feedback/src/index.ts:246-262`). For August Trading, this is a direct answer to "how do we keep a trade log the model can query without a heavy database": **JSONL/append-only events + derived state + a post-write durability check**.
- **Staying simple as features accumulate: the repo's own answers.** Four patterns recur. (a) **Enablement, not availability, drives registration** — a tool stays visible when its provider is missing and fails with a structured error at execution time, so plugin load order, credential state and HMR timing never enter the model-facing contract (`packages/web/tool-web/src/index.ts:6-9`, `:83-93`). (b) **The consumer owns the model-facing contract; the provider owns the transport** — the web tools never call a provider's `available()` and never enumerate providers (`packages/web/tool-web/README.md`, Design philosophy). (c) **Duplication is preferred over a shared abstraction when the contracts differ** — the Exa and Perplexity providers keep their own availability check and their own `isAbortError`, with the duplication explicitly marked, because "a shared base class would obscure which fields make this backend usable" (`packages/web/web-search-perplexity/src/provider.ts:90-95`). (d) **The seam refuses to grow vendor-specific knobs** — Exa's livecrawl/filters and Perplexity's domain filters are deliberately withheld "until provider-neutral service fields exist", so the family adds one coordinated control rather than a vendor argument (`packages/web/web-search-exa/README.md`, Future). The counter-example is instructive too: `max_results` was a *model argument* and was **deferred**, "because a model-facing bound would move cost control into the prompt" (`packages/web/tool-web/README.md`, Dev Note).

## 4. Non-obvious decisions and gotchas

A reader would get these wrong without being told:

- **`packages/attachment/attachment-local/src/store.ts:156-174`** — `ensureDurableDirectory` walks *up* to the boundary and re-syncs every ancestor, deliberately ignoring what `mkdir` reports. "Already existed" is not "already durable", because a concurrent creator may not have synced its own entry.
- **`packages/attachment/attachment-local/src/store.ts:374-380`** — on Windows the staging name is unlinked **before** the read-only chmod, because Windows shares the read-only attribute across hard links and then refuses to unlink either name.
- **`packages/attachment/attachment-local/src/file-store.ts:36-42`** — the filename sanitiser strips **both** separator styles by hand, because a POSIX host treats `\` as an ordinary character and `path.basename` would therefore keep a Windows client's entire local path and leak it into the session log.
- **`packages/attachment/attachment-local/src/file-store.ts:58-64`** — `ensureFileReference` re-validates `ref.name === fileLeafName(ref.name)`; a reference whose name was not produced by the sanitiser is *rejected*, so a hand-crafted reference cannot escape the directory.
- **`packages/attachment/attachment-local/src/store.ts:23`, `:176-188`** — the fsync-to-filesystem-root proof happens **once per process per home** and is cached in a module-level `Set`. A reader who assumes it runs per write will misjudge the cost model.
- **`packages/attachment/attachment-local/src/index.ts:135-139`, `:216-243`** — the shared request is aborted **only when its last waiter cancels**. One caller abandoning a slow image encode does not kill the other; an aborted in-flight entry is evicted and replaced.
- **`packages/attachment/attachment-local/src/request-image.ts:87-91`** — the request resize is done **by the long edge only**, so the encoder derives the short edge exactly the way the route predicted. A resize by both edges would break the cache key.
- **`packages/attachment/attachment-local/src/image.ts:36-43`** — `encodedAlphaIsCompatible` tolerates WebP output that *omits* an all-opaque alpha plane (libvips does that) but treats any other alpha change as incompatible.
- **`packages/deliverables/tool-present/src/index.ts:96-104`** — the delivery is published from the `tools/result` **event**, not from `execute`. A later enclosing failure does not revoke an already-completed declaration; a *blocked* result publishes nothing.
- **`packages/deliverables/workspace-changes/src/recorder.ts:141-146`, `:271`** — `baseline` has three states, and `'failed'` (a repository exists but the snapshot failed) means the turn records **nothing** — it is not summarised as if it had no repository.
- **`packages/deliverables/workspace-changes/src/recorder.ts:333-334`** — an **empty** file list after an earlier in-turn record *supersedes* that record, so a turn that reverted its own changes ends with an empty card rather than a stale one.
- **`packages/deliverables/workspace-changes/src/capture.ts:81-88`** — `sameCapture` says an oversized side is **never known to match** anything. That is why a file too large on both sides is still listed instead of silently disappearing.
- **`packages/deliverables/workspace-changes/src/compare.ts:20-23`, `:45-56`** — the diff's timeout **degrades** to a whole-file replacement hunk rather than failing, and an unterminated last line compares by content alone, so "a missing final newline" is not a change.
- **`packages/deliverables/workspace-changes/src/git.ts:66-70`** — `GIT_CONFIG_COUNT=0` is set explicitly because the subprocess credential scrub removes the *keys* of ambient indexed config but not the count, so an inherited `GIT_CONFIG_KEY_n` would otherwise leak through.
- **`packages/document/office-to-pdf/src/queue.ts:60-72`** — a **ready alias hit consumes no reader slot** and bumps the LRU. The reader bound therefore limits *work in flight*, not *cache hits*.
- **`packages/document/office-to-pdf/src/queue.ts:194-205`** — a second source with the same content digest **joins the running conversion** and moves its readers across; the second file's bytes are still read (the digest is only known afterwards).
- **`packages/document/office-to-pdf/src/queue.ts:147`** — an unknown source size reserves the **entire** input limit, not a guess.
- **`packages/document/office-to-pdf/src/output.ts:26`, `:33-37`** — the PDF's size is checked twice (from `fstat`, then from the bytes actually read) and the file must carry both a `%PDF-x.y` header and a trailing `%%EOF`.
- **`packages/document/office-to-pdf/src/index.ts:158-160`** — the Fetch API provider reports **HTTP 200** for every success, because the API reports neither the target's status nor a final URL. The seam's "a non-2xx is a result" rule does not survive this backend, and the README says so.
- **`packages/feedback/command-feedback/src/index.ts:58-67`** — blank text is recorded as **absent**, and an entry with neither text nor category is still recorded: "a submission with neither still records that the human asked for the Session to be reviewed, which is what authorizes log delivery".
- **`packages/feedback/message-feedback/src/index.ts:167-205`** — note validation happens **before** the Session lookup, and a put that repeats the stored rating, note and category is a **no-op that appends no event** but still flushes.
- **`packages/feedback/message-feedback/src/index.ts:246-262`** — a live write is only reported as successful after the persisted prefix is re-read and compared; a missing tail, a different tail or a different header all throw.
- **`packages/web/web/src/index.ts:176-199`** — "multiple usable providers" is a **failure**, not a coin flip.
- **`packages/web/tool-web/src/fetch.ts:205-214`** — only **dropped** bytes count as truncation; a chunk that exactly fills the remaining capacity keeps all its bytes and the read continues to observe EOF.
- **`packages/web/tool-web/src/fetch.ts:318`** — the HTML conversion is memoised in a `WeakMap` keyed on the frozen result, because the registry calls `render` and `presentationMeta` with the same value; without the memo the page is parsed and converted twice.
- **`packages/web/web-fetch-http/src/provider.ts:71-77`** — the redirect budget is checked **before** the target is validated, so an over-limit hop reports "exceeded the maximum of N redirects", not "cross-origin".
- **`packages/web/web-fetch-http/src/provider.ts:117-140`** — a proxied hop skips address resolution (the proxy does the DNS) but an **IP literal the checks would refuse never takes that shortcut**.
- **`packages/web/web-fetch-http/src/network.ts:75-112`** — the **whole** DNS answer set is rejected if any member is non-public, and DNS64 discovery (`ipv4only.arpa`) is a security control, not an optimisation.
- **`packages/web/web-search-deepseek/src/provider.ts:220-226`** — the options are snapshotted **once per operation**, so a settings write landing during credential resolution cannot send the old key to the new origin.
- **`packages/web/web-search-deepseek/src/provider.ts:75-84`** — `thinking` is always `disabled` because the generated text is discarded and reasoning tokens would have no consumer.
- **`packages/web/web-deepseek-api/src/search.ts:102-108`** — `ori_question` is cut to 128 characters **by code point**, so a surrogate pair is never split.

## 5. Weak spots

- **The office converter's queue is the most intricate object in the shard.** `packages/document/office-to-pdf/src/queue.ts` carries five interacting maps (`ready`, `aliases`, `sources`, `digests`, `jobs`), three counters (`cachedBytes`, `sourceBytes`, `readers`) and a `drain()` whose eligibility predicate encodes foreground/background fairness, byte reservation and demotion in one expression (`:149-174`). Its own test file is 29 KB. The behaviour is right and thoroughly pinned, but the *readability* cost is high, and the alias/digest two-level scheme buys a saving that a single content-addressed map would give for most deployments.
- **Deliberate duplication in the DeepSeek web providers.** `packages/web/web-deepseek-api/src/transport.ts:1-7` states outright that the credential resolution, cancellation helpers and dispatch logic **repeat** `dsh-web-search-deepseek` so that neither plugin depends on the other, with `jscpd:ignore` markers around the copies. It is an honest trade (no coupling between siblings), but the two copies can drift: the Messages provider and the Search/Fetch provider already differ in their guidance text, their header sets and their abort wording.
- **The "no observation surface" gap in the web seam is a real hole.** `packages/web/web/README.md` (Known Limitations) records that there is no provider-change event and no capability-status query: "availability is observable only by running a search or fetch and routing the thrown code". A UI that wants to grey out a provider button has to *call the provider* to find out. The archived note says the surface was deliberately dropped, which makes it a decision rather than an oversight — but it is the kind of decision a user notices.
- **The abort taxonomy is inconsistent across providers.** The DeepSeek providers classify an abort by `signal.aborted` *or* error shape, while Exa and Perplexity classify **only** by error shape (`packages/web/web-search-exa/src/provider.ts:163-165`) — their own READMEs concede that "an abort carrying a custom reason (such as `dsh-timeout`'s `TimeoutReason`) surfaces as `WEB_PROVIDER_ERROR`". A timeout therefore reads as a provider failure in two of the four backends. The `dsh-timeout` utility that the HTTP provider uses correctly (`timeoutOf(signal, 'WEB_FETCH_TIMEOUT')`) is exactly the tool the search providers are not using.
- **The per-operation scan cost of the feedback store is acknowledged and unfixed.** "Each `list`, `put`, or `delete` that reaches an existing Session scans its full event log to derive current feedback; cold operations also read the full log from persistence. Work grows with total Session history, not just the number of feedback items" (`packages/feedback/message-feedback/README.md`, Known Limitations). For a long-running trading session with thousands of events, every thumbs-up becomes an O(history) operation.
- **Two git features still write into the repository during a snapshot.** `core.splitIndex` writes `sharedindex.*` files and git-lfs runs its clean filter and stores objects under `.git/lfs` — both inside the user's own `.git`, despite the recorder's otherwise scrupulous isolation (`packages/deliverables/workspace-changes/README.md`, Known Limitations). It is a small leak in an otherwise airtight "the repository is never written to" claim.
- **A missed truncation can be reported as "not truncated".** In `packages/web/web-fetch-http/src/provider.ts:205-214`, a chunk that exactly fills the remaining byte capacity is kept whole and the read continues — correct — but the same logic means a body that is *exactly* at the cap is indistinguishable from one that was cut, and the `truncated` flag is false for both. A caller that needs to know whether the source was clipped cannot tell.
