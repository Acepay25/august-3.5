# deepseek-harness :: dsh-docs-user

**Files in shard:** 64 (read: 60, skipped with reason: 4)
**What this shard covers:** the end-user and plugin-developer documentation of the DeepSeek Harness under `docs/user/**`. Two trees: **develop** (a plugin tutorial — first plugin, config, tool, packaging — then the Cordis framework: lifecycle, events, services; then a practice tree on three-role capability design, LLM adapters and prompt-driven configuration) and **guide** (end-user operations: model/provider configuration, plugin markets, third-party memory MCP servers, reverse-proxy deployment, network proxying, GitHub-webhook review sessions, the Python SDK, and the schedule/reminder subsystem). Every English page has a `.zh.md` Chinese mirror (20 pairs = 40 files) and every page carries a generated `*.i18n.yaml` translation-pairing sidecar (20 files). Four PNG screenshots illustrate the Models settings page and the custom-provider form.

This shard contains **no implementation code**. Its value is in the *contracts* the docs state: the configuration layering rules, the provider-compatibility model, the reasoning-effort vocabulary, the scheduling/catch-up semantics, the credential and proxy postures, and the approval surfaces. Those contracts are the stealable part.

### 1.1 Cross-cutting analysis of the pages listed above

*(This subsection analyses the documents already enumerated in §1. It is not a second file entry.)*

**The configuration layering model is the spine of the whole product.** Four ordered layers compose over an empty root (`basic/publish.md:120-127`), later layers win *per row*, and a patch **replaces a row's entire `config` value** rather than deep-merging keys (`basic/publish.md:131`). This is a genuinely different philosophy from a deep-merge config: a deep merge silently keeps stale sibling keys, so a later layer can never *remove* a key it did not set. The row-replacement model makes "the effective configuration" a function of exactly one layer per row, and it makes the failure mode loud — you find out that your override dropped three sibling fields, and the doc says so explicitly ("must restate every key the row needs, not just the changed one"). The layer order is also *user-readable*: bundles → profile → machine → argv.

**The provider page is really a spec for "declaring capabilities you cannot verify".** Three separate passages say the same thing in different registers: `input`/`inputModalities` "state a claim about your endpoint rather than checking it" (`providers.md:113`); `compat` switches "state a claim about your endpoint rather than checking it: setting one your gateway does not actually need simply sends a different request" (`providers.md:211`); and model discovery "reads the listing formats common gateways publish, but not every endpoint answers in one of them, so treat it as a convenience rather than a guarantee" (`providers.md:37`). The harness never pretends a declaration was verified; it says the check happens later, at the provider, and it designs the vocabulary so the failure is diagnosable.

**The inheritance ladder for capability declarations is carefully shaped.** For a model's input modalities: an explicit non-empty list wins; an omitted or empty list inherits the installed catalog; the catalog falls back to the route's `defaultInput`; `defaultInput` defaults to `[text]` — and critically, on a built-in provider it "answers only for models its catalog does not describe, so it never removes images from a catalog model that has them" (`providers.md:77-99`). A *fallback* is not an *override*. The same ladder appears for compat switches (`providers.md:209`: "What neither sets keeps the installed catalog's value for that model, and what the catalog does not describe falls to pi-ai's detection") — and the one rule that makes the ladder safe is that **an empty value is refused rather than ignored**, because an empty value "would erase what the catalog knows while saying nothing in its place" (`providers.md:209`).

**The reasoning-effort vocabulary solves a problem August also has.** Effort is not a core enum of four levels; it is a *menu* of adapter-owned ids plus display names, with the wire spelling stored alongside (`max: xhigh` renames a level for a gateway with its own vocabulary) and the adapter's authoritative list preserved rather than promoted into a core type (`llm-adapter.md:116`). The subtle part is `off`: **empty `off` sends nothing**, which only stops a model that thinks on request; a *valued* `off` sends that value as `reasoning_effort` (`providers.md:157`). And a model that thinks *unless told not to* needs a different switch entirely (`compat.thinkingFormat: deepseek`, which makes `off` send `thinking: {type: disabled}`) — a case that a naive "off = 0" ladder gets wrong (`providers.md:157-165`).

**The scheduling page is unusually honest about what a scheduler cannot promise.** It states, in order: reminders persist independent of the open Session; a due reminder restores the original Session and queues a follow-up *without interrupting current work*; a restart sends an overdue one-shot or **only the latest missed occurrence** of each recurring task; a delivery record proves **the message persisted, not that the model did the work**; **exactly-once is not guaranteed** (a crash after inbox persistence but before the task write repeats the delivery); records are pruned by a `deliveryHistoryDays` window and a `deliveryHistoryRecords` count with the latest receipt always surviving; and **pause and new-session-per-run are not supported** (`schedule.md:61-69`). Every one of those is a decision, and each one is a place where a less careful implementation would have silently promised something it could not keep.

**The docs systematically explain *surprises* rather than just rules.** The proxy page's three-mechanism table (`network-proxy.md:20-30`) exists because "this is the most common surprise"; the provider page's troubleshooting list is written as *symptom → cause* ("Only reasoning models fail — pi-ai sends their system prompt as the `developer` role, which the gateway rejects", `providers.md:222`); the schedule page separates "an empty record view means a successful query returned no saved records" from "Loading, request failure, a missing task, and an invalid older-record cursor" (`schedule.md:35`). The rule is: **if a user will hit it, the doc says what it looks like, not only what to do.**

## 2. Ideas worth stealing

*(All marked `UNIQUE` for the reason given in the convergence caveat at the top of this report. "Steals to" names the August Trading surface.)*

1. **Per-row replacement instead of deep-merge in layered configuration** — four ordered layers, later layer wins *per row*, and a patch replaces the row's whole `config`, forcing an author to restate every key (`docs/user/develop/basic/publish.md:120-135`). *Steals to:* August's `ProviderConfigService` + any `cordis.yml`-shaped settings layering; makes "what is the effective config" answerable by one layer per row, and makes a dropped sibling field loud instead of silent.
2. **A per-route "compat profile" with named, protocol-scoped switches and a no-empty-values rule** — `supportsDeveloperRole`, `maxTokensField`, `thinkingFormat`; route default, model override, catalog fallback, and an empty value is **refused** rather than ignored (`docs/user/guide/providers.md:180-215`). *Steals to:* `shared/providerRequestPolicy.cjs` — promote it from one wire policy to a per-provider profile that can express "this gateway rejects the developer role" without a code edit.
3. **Capability declarations are claims, and the doc says so** — `input`, `compat`, and model discovery are all explicitly "a claim about your endpoint, not a check" (`docs/user/guide/providers.md:113`, `:211`, `:37`). *Steals to:* August's model catalogue / `contextWindow` / `maxTokens` declarations — label them in the UI as claims and route the verification failure to a named error, exactly as DSH routes it to the provider.
4. **The fallback-is-not-an-override inheritance ladder** — model list > catalog > route default > `[text]`, where the route default can never *remove* a capability a catalog model has (`docs/user/guide/providers.md:77-99`). *Steals to:* August's `utils/*` single-source modules and the per-provider context-window defaults; gives one rule for "who answers when two sources disagree".
5. **Effort as adapter-owned opaque ids, with two different `off` semantics** — ids + display names + a configurable wire spelling, `off`-empty means "send nothing" and `off`-valued means "send this", plus a separate `thinkingFormat` for models that think by default (`docs/user/guide/providers.md:136-170`, `docs/user/develop/practice/llm-adapter.md:116`). *Steals to:* August's `ReasoningEffort` union — which is currently a core enum; the DSH model generalises to per-provider vocabularies without a new core type.
6. **The "anything two deployments may want to set differently must be a configuration field" rule, with a one-line acceptance test** — "can `cordis.yml` change the value without a code edit?" (`docs/user/develop/basic/config.md:78-88`). *Steals to:* August's hardcoded provider timeouts/retries — make the rule a checklist item in the plan's open-items.
7. **Three-role capability split, with the anti-premature-splitting guard** — Definition owns the Request/Result types, Provider and Consumer depend only on the Definition and not on each other, the *seam is the whole capability*, and "do not split preemptively" (`docs/user/develop/practice/index.md:149-151`). *Steals to:* August's `GenericProviderService` / `GenericAnalysisService` / per-provider clients — a definition package owning the analysis Request/Result types would let a provider be swapped without touching a consumer.
8. **"Explicit > implicit: resolve defaults in an explicit `resolve(request): Spec` step rather than hiding `?? default` inside `run()`"** (`docs/user/develop/practice/index.md:151`). *Steals to:* August's analysis pipeline and any place a default is currently applied deep inside a service — one named resolution step makes the effective spec inspectable.
9. **A durable, typed session-event stream distinct from in-process events** — `turn/*`, `step/*`, `tool/call`, `tool/result`, `compaction/*` are *persisted* session-event types observed through a single `session/event` channel by inspecting `event.type` (`docs/user/develop/framework/events.md:106`). *Steals to:* August's trade log and skill-notebook — one typed, queryable event vocabulary that the model can read back, distinct from React state.
10. **The model-queryable log rides along with the request, capped and switchable** — unaccepted log events are uploaded with model requests, at most `maxBytes` (8 MiB) per request, and `session-log-deepseek.enabled: false` turns it off (`docs/user/guide/python-sdk.md:177`). *Steals to:* August's journal/learning payloads — a bounded, per-request context attachment with a single switch, rather than an always-on dump.
11. **Delivery records are persistence receipts, not execution receipts** — "Saved delivery records confirm messages persisted in the conversation inbox, not that the model completed the requested work"; a failed write adds no record; **exactly-once is not guaranteed** (`docs/user/guide/schedule.md:65`). *Steals to:* August's `services/automation` run history — separate "the run was recorded" from "the run produced a verdict", and say so in the UI.
12. **Restart catch-up that replays only the latest missed occurrence** — no replay storm; an overdue one-shot is sent once, a recurring task sends only its latest missed occurrence (`docs/user/guide/schedule.md:61`). *Steals to:* August's scheduled analyses/automations — a bounded catch-up policy instead of a "run everything missed" backlog.
13. **A history-pruning rule that is a window *and* a count, with the latest receipt inviolate** — `deliveryHistoryDays` window measured back from the appended receipt's `deliveredAt`, plus `deliveryHistoryRecords` cap, "the latest receipt always survives", and a pruned window is *marked unavailable* rather than silently empty (`docs/user/guide/schedule.md:67`, `:41`). *Steals to:* August's skill/pattern memory growth control — the "mark earlier records unavailable" trick is better than deleting them silently.
14. **A three-step memory acceptance test** — write in session A → recall in a *fresh* session B → **use** the value in B; a new session is required, a host restart is not (`docs/user/guide/mcp-memory.md:74-82`). *Steals to:* August's skill/pattern memory: adopt exactly this test for "the memory loop works", including the "use" step that a naive test skips.
15. **Tools stay listed during an outage, calls fail, and after the reconnect budget the tools are unregistered and reconnection stops** (`docs/user/guide/mcp-memory.md:82`). *Steals to:* August's provider degradation: prefer "listed but failing" over "silently absent" while the budget lasts, then a definite stop.
16. **Delegated subagents get a *deny list*, not an inherited tool surface** — the four reminder tools are declared by the presets, the presets' delegation rows **deny** them, and a call that reaches one anyway is refused (`docs/user/guide/schedule.md:22`). *Steals to:* August's bot roster / subagents — make the delegate's tool surface an explicit policy row.
17. **`202` means "accepted", deliberately weaker than the effect** — the webhook response promises signature + JSON acceptance and in-memory scheduling, and explicitly "does not mean this rule matched or that a Session was created" (`docs/user/guide/github-review.md:69`). *Steals to:* August's automation run-history and notification layer — an ack that cannot be mistaken for an outcome.
18. **Inbound authentication grants no outbound authority** — the webhook secret authenticates GitHub data only; it grants neither the rule code nor the created agent outbound GitHub access, which "must be configured separately" (`docs/user/guide/github-review.md:99`). *Steals to:* August's provider keys and any "webhook → agent" path — the credential that admits the event must not be the credential the agent acts with.
19. **Untrusted payload labelling inside the prompt** — the PR JSON is "label[ed] as untrusted metadata" and the prompt forbids file, branch, PR or GitHub mutation (`docs/user/guide/github-review.md:65`). *Steals to:* August's `utils/harnessMarks.ts` vocabulary — a named "untrusted" prefix for externally supplied data, the mirror image of `DATA_UNAVAILABLE`.
20. **Machine-triggered work picks a permission preset explicitly** — the Session request selects the `standard` agent preset *and* the `read-only` permission preset (`docs/user/guide/github-review.md:67`). *Steals to:* August's automation runs — a scheduled run should *name* its permission level in the request, not inherit the operator's.
21. **Credentials are write-only with a redacted descriptor, and settings keep only a reference** — the key lives in `$DSH_HOME/.credentials.yaml`; the page receives a redacted descriptor, never the literal secret (`docs/user/guide/providers.md:13`). *Steals to:* August's `ProviderConfigService` on web/Capacitor, where keys are plaintext today — the "descriptor + reference" contract is what a shared-settings UI would need.
22. **Identity is not a display field** — the Provider ID is permanent because requests, saved sessions, model defaults and credential references all use it; to rename, add a new provider and delete the old one (`docs/user/guide/providers.md:31`). *Steals to:* August's `ProviderConfig.id` — make the permanence rule explicit, and give the UI a rename path that is really "create + delete".
23. **A single "recommended version" rule, prerelease fallback included** — highest compatible non-prerelease, else the highest compatible prerelease (`docs/user/guide/plugin-market.md:30`). *Steals to:* August's model menu / provider catalogue — one stated rule for which entry a picker shows by default, instead of per-surface heuristics.
24. **Install is gated by a confirmation that shows the source** — npm package + registry, or git repository + commit + directory; "nothing is installed without that confirmation" (`docs/user/guide/plugin-market.md:30`). *Steals to:* August's skill-draft approval ("Save as skill") — the confirmation must show *the exact source* that will be written, not just a title.
25. **A whole-config rejection that names the offending value's path** — a bad index is rejected entirely, and the error carries the **JSON path** of the offending value (`docs/user/guide/plugin-market.md:82`). *Steals to:* August's zod boundary schemas — surface `issue.path` in the error the trader sees, not "invalid configuration".
26. **An explicit permission grant, named as a permission** — pnpm's `allowBuilds` is reframed as "permission to execute the package's code on your machine at install time, outside any sandbox the agent runs under", with a pinned commit recommended (`docs/user/develop/basic/publish.md:175-181`). *Steals to:* August's Electron installer / any skill that writes files — name the grant, scope it, and default to pinning.
27. **A translation-parity gate by content hash** — per heading section, a hash of the EN and ZH blocks outside code blocks; regenerate with `pnpm run verify-translation-pairing --write <file>`; a one-sided edit changes one hash and fails the check (`docs/user/develop/basic/config.i18n.yaml:1-9`). *Steals to:* August's `check-flow-doc-anchors` gate — the same *shape* (hash the content that must move together) can detect a **rewording** that leaves line numbers intact.
28. **A minimal profile as an explicit inclusion/exclusion table** — the `sdk-minimal` table names every property, the sole bundle inserts the whole tree over an empty root and does **not** include `dsh-base` so later base tools cannot appear implicitly (`docs/user/guide/python-sdk.md:168-181`). *Steals to:* August's "minimum viable trading analysis" — a table of what is in and out, enforced by construction rather than by discipline.
29. **No silent reads of the user's real home** — the SDK "never silently read `~/.dsh`"; a fresh home isolates profiles, plugins, credentials, settings and sessions, and a fresh session id is required for independent work (`docs/user/guide/python-sdk.md:94`, `:183`). *Steals to:* August's backups/exports — an explicit, non-defaulting home/path, and "fresh id for independent work" as a rule for the trade journal.
30. **The "waterfall" short-circuit as the interception primitive** — a listener that does *not* call `next()` intercepts the chain, "enabling interception and gateway behavior" (`docs/user/develop/framework/events.md:66-82`). *Steals to:* August's tool-policy hooks (approve/deny before execution) and provider request policy — one interception point, no per-call-site checks.
31. **Plugin/service disappearance disposes dependents instead of leaving them calling a dead service** — a plugin whose required service vanishes is disposed and reloaded when it returns (`docs/user/develop/framework/index.md:38-45`, `docs/user/develop/framework/service.md:102`). *Steals to:* August's provider swap — dependent capabilities (analysis services, desk tools) should be torn down and rebuilt, not left pointing at a replaced provider.
32. **The disposer-order caveat, documented rather than papered over** — disposers *start* in reverse registration order but async ones run concurrently with no serial guarantee, so order-dependent cleanup must be one disposer (`docs/user/develop/framework/index.md:63`). *Steals to:* August's `clearDeskToolCache` / cache-write path / hook teardown — say which orderings you actually guarantee.
33. **Service isolation for multi-agent groups** — two plugin groups can each see their own instance of the same service (`docs/user/develop/framework/service.md:111-140`). *Steals to:* August's per-bot desks and per-agent memory scopes.
34. **A generated configuration catalogue as the single source for what a plugin accepts** — "lists every supported field and default for every plugin", and the generated reference "is derived from the source, so it cannot fall behind what the adapter accepts" (`docs/user/guide/providers.md:47`, `:213`). *Steals to:* August's `constants/` + `types/` single-source rule — generate the reference from the same declaration the code validates against.
35. **Isolated realms for a second listener** — the webhook overlay mounts a **second WebServer in an isolated realm** where only `POST /github` is registered and every other path returns 404, while the main UI and `/api` stay on 3080 (`docs/user/guide/github-review.md:39`). *Steals to:* August's Electron/Capacitor surfaces and any local callback server — a narrow, isolated listener is much easier to reason about than one big server with a route table.

## 3. Trading-specific findings

Answers only for this shard; where a question belongs to another shard, this is stated rather than guessed.

**1. Long-lived monitoring & scheduled work.** This shard contains the **user-facing contract** of the scheduler (`docs/user/guide/schedule.md`), not its implementation. What it decides: reminders are stored independently of the open Session and survive it; while the Host runs, a due reminder **restores the original Session and queues a follow-up without interrupting current work** (`:61`); on restart the Host "sends an overdue one-shot or only the latest missed occurrence of each recurring task" (`:61`) — i.e. **bounded catch-up, no replay storm**; a one-shot becomes inactive only *after* its message is durably written; DST holes are skipped and DST overlaps take the earlier instant; **exactly-once is not guaranteed** and a crash after inbox persistence but before the task write can repeat a delivery (`:65`); records are pruned by a day-window plus a record-count, the latest receipt always survives, and a pruned window is *marked unavailable* rather than shown as empty (`:67`, `:41`); **pause and a new Session per run are not supported** (`:69`). For August this is the contract to write down for `services/automation` — and it is the same family as August's existing "three runs that produced nothing" streak breaker, which this shard does not cover.

**2. Human-in-the-loop approval.** The approval *record* is not in this shard (it lives in the agent/permission packages, another shard). What is here are three approval **surfaces**: the plugin-market install confirmation that must show the exact source before anything is written (`docs/user/guide/plugin-market.md:30`); the `allowBuilds` grant, explicitly framed as permission to execute a package's code at install time outside any sandbox (`docs/user/develop/basic/publish.md:175-181`); and the machine-triggered Session that names its permission preset (`read-only`) rather than inheriting one (`docs/user/guide/github-review.md:67`). The strongest transferable idea is the *split of authority*: the credential that authenticates an inbound event grants no outbound authority to the agent it spawns (`docs/user/guide/github-review.md:99`).

**3. Post-mortem / reflection loops.** Not in this shard — no skill/rule lifecycle appears here. The nearest and most useful negative finding is a warning about **misreading a run log as an outcome log**: "Saved delivery records confirm messages persisted in the conversation inbox, not that the model completed the requested work… they do not describe model execution results" (`docs/user/guide/schedule.md:65`, `:33`). If August's journal rows are going to be read as post-mortems, that distinction must be designed in, not apologised for later.

**4. Multi-agent.** Mostly not in this shard, but two transferable facts: a **delegated subagent's tool surface is an explicit deny list** in the presets' delegation rows, and a call that reaches a denied tool anyway is refused (`docs/user/guide/schedule.md:22`); and **service isolation** lets two plugin groups hold separate instances of the same service (`docs/user/develop/framework/service.md:111-140`) — the natural shape for per-agent memory/tool scopes. Nothing here shows debate adding value over a single agent.

**5. Structured logs the model can query.** Yes, and the answer is *file-per-session JSONL plus a typed event vocabulary*: the durable session-event types are `turn/*`, `step/*`, `tool/call`, `tool/result` and `compaction/*`, observed through one `session/event` channel by inspecting `event.type` (`docs/user/develop/framework/events.md:106`); the session log is **uncompressed JSONL** under `<dsh_home>/sessions` (`docs/user/guide/python-sdk.md:175`); automatic compaction "preserves the complete Session log" (`docs/user/guide/python-sdk.md:177`); and the log contributor rides along with model requests, capped at 8 MiB per request and switchable off (`docs/user/guide/python-sdk.md:177`). ## 4. Non-obvious decisions and gotchas

Things a reader would get wrong.

1. **A `waterfall` listener that forgets `next()` silently swallows the rest of the chain.** The doc says it is "by design, enabling interception and gateway behavior" (`docs/user/develop/framework/events.md:80`) — i.e. a typo in a policy hook looks exactly like a deliberate veto. Any August port of this pattern needs the "did you call next?" case tested explicitly.
2. **A configuration patch replaces a row's whole `config`; it does not deep-merge.** Restating one key erases its siblings (`docs/user/develop/basic/publish.md:131`). The failure is invisible until a defaulted field reverts.
3. **Disposers start in reverse order but do not *complete* in reverse order.** Async disposers run concurrently with no serial guarantee (`docs/user/develop/framework/index.md:63`).
4. **An empty value is refused, not ignored** — for a compat switch, `supportsDeveloperRole:` with nothing after the colon is an error, "because an empty value would erase what the catalog knows while saying nothing in its place" (`docs/user/guide/providers.md:209`, `:226`).
5. **`off` has two meanings.** Empty `off` = send nothing (works only for a model that thinks on request); a valued `off` = send that value as `reasoning_effort` (`docs/user/guide/providers.md:157`). A model that thinks *unless told not to* needs `compat.thinkingFormat: deepseek` instead, or `off` will not stop it (`docs/user/guide/providers.md:224`).
6. **`NO_PROXY` does not accept CIDR ranges**, and SOCKS is unsupported — a `socks5://` value is *reported at startup and skipped*, and that scheme then goes **direct** rather than erroring (`docs/user/guide/network-proxy.md:42`, `:48`). A misconfigured proxy therefore yields unproxied traffic, not a failure.
7. **Model-authored code gets no proxy settings** — deliberately, so a model-written script cannot read a proxy URL carrying a password (`docs/user/guide/network-proxy.md:69`). The same reasoning applies to any secret DSH puts in the environment of code it executes.
8. **An image attached to a session stays in the session log**, so the same failing request repeats until the session moves off it (`docs/user/guide/providers.md:227`). A sticky input, not a transient one.
9. **The webhook's `202` is weaker than the agent's outcome on purpose** (`docs/user/guide/github-review.md:69`), and the runtime stores no delivery state, so a repeated delivery may create a second Session (`docs/user/guide/github-review.md:97`).
10. **A record without a saved instruction never shows the current instruction in its place** (`docs/user/guide/schedule.md:33`) — history is a snapshot, not a projection of the present. "The current instruction is not substituted for a missing saved instruction" (`docs/user/guide/schedule.md:41`).
11. **A delegated subagent's denied tool is refused, not ignored** (`docs/user/guide/schedule.md:22`).
12. **Model discovery on a built-in provider always answers from the installed catalog, even when its base URL points at a gateway** — to see what the gateway really serves you must fetch through a *custom* provider (`docs/user/guide/providers.md:37`).
13. **"Authentication status" in the UI is a three-state thing, not a boolean**: a green hint = an environment variable was *detected* (not validated), a yellow hint = no credential variable was detected, an unconfirmed hint = the status read itself failed; and detection does not validate the credential or test the connection (`docs/user/guide/providers.md:19`).
14. **`--public-url` is display only.** It advertises an address; the fence admits authorities named by `--trusted-host`. A browser arriving under any other authority gets **403 on every API call** however correct the proxy is (`docs/user/guide/public-deployments.md:25`).
15. **A patch file contributes configuration but does not change the profile directory** the loader resolves module paths from — so a plugin path in a patch must be absolute (`docs/user/develop/basic/index.md:37`).
16. **`ctx.get()` for an optional service, `inject` for a required one.** A plugin that declares a required service does not load while it is absent, and is disposed if it disappears (`docs/user/develop/framework/service.md:90-107`).

## 5. Weak spots

1. **The scheduler refuses several things a user will ask for, and the refusals are documented but not fixed**: no pause, no new Session per run, reminders recorded only in an older Session log are *not* scheduled automatically, and exactly-once delivery is explicitly not guaranteed (`docs/user/guide/schedule.md:65-69`). The honesty is admirable; the capability gap is real, and the "old Session log" rule is a trap for anyone who assumes the log is the schedule.
2. **The UI cannot express the two most common gateway incompatibilities.** "The form has no field for either" (`docs/user/guide/providers.md:182`) — `developer` role and `max_completion_tokens` vs `max_tokens` must be fixed by hand-editing `cordis.patch.yml`. The escape hatch is documented well, but it is a UX cliff exactly where self-hosted gateways are most common.
3. **The minimal SDK profile is not sandboxed.** It "pins `danger-full-access`", so the persistent shell can modify any path visible to the runtime, and the mitigation is advice to the operator — "use a disposable checkout or container" (`docs/user/guide/python-sdk.md:177`). The "minimal" product is minimal in *features* and maximal in *reach*.
4. **Documentation duplication is 2× and the parity gate only proves co-editing, not correctness.** Twenty EN/ZH pairs (40 files) plus 20 hash sidecars; the hashes detect a one-sided edit but say nothing about whether the translation is accurate (`docs/user/develop/basic/config.i18n.yaml:1-9`).
5. **Several pages end with a template artefact `## Dev Note — None.`** (`docs/user/guide/plugin-market.md`, `docs/user/guide/schedule.md`), a leftover from a doc template that adds nothing.
6. **The proxy's silent SOCKS degradation is a security-relevant default** even though it is reported at startup: an operator who misses that line runs with unproxied traffic and no error (`docs/user/guide/network-proxy.md:48`).
