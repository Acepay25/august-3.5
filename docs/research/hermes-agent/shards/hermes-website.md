# hermes-agent :: hermes-website

**Files in shard:** 839 (read: 795, skipped with reason: 44)
**What this shard covers:** the entire Docusaurus documentation site of the Hermes Agent repo — 757 Markdown/MDX pages (developer guide, user guide, reference, tutorials, a ~250-page generated skill catalogue) plus its Chinese (`zh-Hans`) mirror, the build-time generators that produce the site's data (`skills.json`, `plugins.json`, `llms.txt`, per-skill pages), the React catalog hubs (`/skills`, `/plugins`), the Docusaurus config/sidebar, and the static assets. The shard contains **no product logic** — it is the repo's *documentation and catalog-publishing* layer — but it is unusually opinionated about how an agent's skills, tools, memory and scheduled work are *described*, *versioned* and *discoverable*, and several of its generator designs (pinned-commit catalog entries, a "everything is in the index" llms.txt, MDX escaping for untrusted skill bodies, a Curator that prunes its own skill library) transfer directly to August Trading.

Read depth: every `source` and `config` file was read in full. English documentation was read as *frontmatter (title/description) + every `##` heading with its line number + the opening paragraphs*, and 40 decision-dense documents were additionally read in depth (head 60–110 lines). The 293 `zh-Hans` files are translations of the English pages; each was opened and its title/description/headings read, and the row below states the English page it mirrors. The 43 binary image/video assets and the 724 KB `package-lock.json` were confirmed on disk and their headers peeked, but not read line by line.

## 1. File-by-file

### Tier 1 — load-bearing source: full entry

#### `website/docusaurus.config.ts`
- **Purpose:** the single Docusaurus site config (routes, i18n, search, redirects, theme tokens).
- **Key abstractions:** `Config` object; `relativeDocLinks` remark plugin wired at `docusaurus.config.ts:89`; `@docusaurus/plugin-client-redirects` list at `docusaurus.config.ts:52`.
- **Data flow:** Docusaurus reads `docs/` + `sidebars.ts`, emits static pages under `baseUrl: '/docs/'`; the local plugin `./plugins/plugin-catalog-pages` adds `/plugins/<name>` and `/plugins/by/<slug>` routes at build time.
- **Non-obvious decisions:** `onBrokenLinks: 'warn'` (`docusaurus.config.ts:17`) — a broken doc link does not fail the build; Algolia DocSearch replaced a local search plugin because the local one shipped a ~16 MB client-side lunr index (`docusaurus.config.ts:101-107`), and the search-only API key is committed on purpose; `contextualSearch: true` scopes results to the active locale via crawler-recorded `docusaurus_tag/lang` facets; four static redirects exist for guessed short URLs (`/quickstart`, `/installation`, …) because GitHub Pages cannot do server-side redirects (`docusaurus.config.ts:50-51`).
- **Edge cases:** `i18n.locales = ['en','zh-Hans']` with `htmlLang: 'zh-Hans'`; a missing `zh-Hans` page falls back to the English source, which is why the remark plugin exists.
- **Surprising:** the site is served at `/docs/` but the navbar's "Skills"/"Plugins" hubs are React pages outside the docs tree — `sidebars.ts` compensates with two `{type: 'link'}` entries so they stay reachable on mobile.

#### `website/sidebars.ts`
- **Purpose:** the hand-maintained navigation tree (~1,100 doc ids) for the whole site.
- **Key abstractions:** `SidebarsConfig` with nested `{type: 'category', label, items}` nodes; per-skill categories carry an explicit `key` (`skills-bundled-apple`, `skills-optional-mlops`) so Docusaurus' i18n key derivation cannot collide.
- **Data flow:** doc ids are strings resolved against the docs tree; the per-skill subtrees are *regenerated* by `generate-skill-docs.py`, the rest is hand-written.
- **Non-obvious decisions:** the top of the sidebar is `user-stories` + two external links to `/skills` and `/plugins` ("On mobile Docusaurus opens the drawer on the doc sidebar … so without these links the hubs are undiscoverable on a phone"); the Developer Guide is split into Architecture / Extending / Internals / Packaging & Releases, and the Plugins subcategory is nested under Extending.
- **Edge cases:** the generator locates the `Skills` block by an exact string match and rewrites it in place (`generate-skill-docs.py:656`), so a hand-edit of that block shape breaks the generator loudly (`RuntimeError`) rather than silently.
- **Surprising:** `website/docs/developer-guide/gateway-command-parity.md` is marked `GENERATED by scripts/gen_gateway_command_parity.py — DO NOT EDIT` — a generated doc living inside a hand-maintained sidebar.

#### `website/src/remark/relativeDocLinks.js`
- **Purpose:** a remark plugin that makes relative `.md` links resolve across the `zh-Hans` fallback boundary.
- **Key abstractions:** `MARKDOWN_LINK` regex (`relativeDocLinks.js:19`), `contentRoot()` (`relativeDocLinks.js:22`).
- **Data flow:** for every `link`/`definition` node whose URL matches a relative Markdown path, the plugin rewrites the URL to a content-root-absolute path (`/user-guide/profiles.md`) so Docusaurus resolves it against *every* content path.
- **Non-obvious decisions:** only URLs with a Markdown extension are touched; routes, assets and external URLs pass through unchanged.
- **Edge cases:** a link that would resolve outside the docs tree is left alone (`relToRoot.startsWith('../')`), so Docusaurus handles it.
- **Surprising:** this exists because the docs are authored with relative file links so they also work on GitHub — a "read the docs on GitHub" affordance that costs a build-time plugin.

#### `website/plugins/plugin-catalog-pages/index.js`
- **Purpose:** a Docusaurus plugin that generates one static page per plugin-catalog entry and one per maintainer.
- **Key abstractions:** `getPathsToWatch()`, `loadContent()`, `contentLoaded()`; `mapLimit()` worker pool; `groupAuthors()` (`index.js:49`).
- **Data flow:** `static/api/plugins.json` → entries; each entry with `readme: true` gets its README fetched at the **pinned commit** and rendered to allow-listed HTML → `createData()` JSON per page → `addRoute()`.
- **Non-obvious decisions:** one data source (`plugins.json`) feeds both the grid and the pages, so "a merged catalog PR is the only way a page appears, changes or disappears"; the site *degrades, never fails* — a missing `plugins.json` produces zero pages with a warning (`index.js:71`).
- **Edge cases:** README fetching is bounded at 12 concurrent requests (`index.js:21`); a README that cannot be fetched leaves that section off the page rather than failing the build.
- **Surprising:** plugin pages are not hand-written — they are a build product of the *catalog JSON*, which is itself generated from YAML in the repo.

#### `website/plugins/plugin-catalog-pages/readme.js`
- **Purpose:** renders third-party READMEs into safe HTML at build time.
- **Key abstractions:** `ALLOWED_TAGS` (`readme.js:26`), `ALLOWED_ATTRS` (`readme.js:31`), `safeUrl()` (`readme.js:50`), `fetchReadme()`, `renderReadme()`, `readmeCandidates()`.
- **Data flow:** markdown → mdast (remark-parse + GFM) → hast (`remark-rehype` **without** `allowDangerousHtml`) → a hand-written serializer emitting only allow-listed tags/attributes and only `http(s):/mailto:/#` URLs; relative image/link paths are rewritten to the pinned commit on the forge.
- **Non-obvious decisions:** the remark packages are Docusaurus' *own* copies, resolved through `@docusaurus/mdx-loader`, so the site adds no dependency and the pipeline moves with the Docusaurus pin; heading ids are prefixed `readme-` so they cannot clash with page chrome.
- **Edge cases:** `MAX_README_BYTES = 512 KB` (`readme.js:22`) — an oversized README is skipped, not truncated; only `raw.githubusercontent.com` and `gitlab.com` are fetchable hosts (`readme.js:24`); a cache hit is exact because the URL embeds the sha.
- **Surprising:** unknown elements are *unwrapped* (children kept) rather than dropped, so a README rarely loses content; `input` is allowed but only with `type=checkbox`.

#### `website/scripts/prebuild.mjs`
- **Purpose:** the `prestart`/`prebuild` hook that materialises every generated site input.
- **Key abstractions:** `writeEmptyFallback()` (`prebuild.mjs:46`), `runPython()` (`prebuild.mjs:55`), `ensureUnifiedIndex()` (`prebuild.mjs:72`).
- **Data flow:** pulls a fresh `skills-index.json` from the live site (24 h freshness window) → runs `extract-skills.py` → `generate-llms-txt.py` → `extract-automation-blueprints.py` → `fetch-plugin-stars.py` → `extract-plugins.py`, writing `static/api/*.json` and `static/llms*.txt`.
- **Non-obvious decisions:** every step is *non-fatal*; if `python3` or `ruamel.yaml` is missing, an **empty** `skills.json` is written and the build still succeeds (the Skills Hub page then shows an empty state) — a local dev box without Python must not break `npm run build`.
- **Edge cases:** the unified index download is validated (`parsed.skills` must be an array) before it is trusted; a failed fetch falls back to the on-disk copy.
- **Surprising:** it re-fetches the *deployed* site's index so a local build does not have to crawl every skill source (several minutes, GitHub API quota) — the live site is used as a cache.

#### `website/scripts/extract-skills.py`
- **Purpose:** builds `static/api/skills.json` (the Skills Hub payload) and `skills-meta.json` from two sources.
- **Key abstractions:** `extract_local_skills()` (`extract-skills.py:256`), `extract_unified_index_skills()` (`extract-skills.py:367`), `_guess_category()` (`extract-skills.py:587`), `_consolidate_small_categories()` (`extract-skills.py:617`), `CATEGORY_LABELS`, `TAG_TO_CATEGORY`.
- **Data flow:** local `skills/` + `optional-skills/` SKILL.md frontmatter → full metadata (overview prose, version, license, env vars, commands, install command, curated artwork); the unified multi-source index (`skills-index.json`) → community entries with only name/description/tags. The two lists are merged, categorised, collapsed and sorted; a minified JSON array is written to `static/api/skills.json` so the browser can lazy-fetch it.
- **Non-obvious decisions:** output is served from `static/api/` rather than bundled into the JS chunk because at 50 k+ skills the bundled payload was ~26 MB; the JSON is written *minified* because it is served over the wire, not read by humans; `_guess_category` only accepts curated buckets — the old fallback (`tags[0]`) produced hundreds of junk one-off categories such as "Doramagic Crystal" and version strings (`extract-skills.py:587`); categories with fewer than 4 members are collapsed into "Other" unless the source explicitly declared them (`fixedCategory`).
- **Edge cases:** a missing unified index falls back to the deprecated `skills/index-cache/` and prints a WARNING naming the fallback source; `description` is truncated to 280 chars with an ellipsis; the installer identifier differs per source (`official/<cat>/<slug>` vs `NousResearch/hermes-agent/skills/<rel>`).
- **Surprising:** `_source_url()` refuses to synthesise a ClawHub URL without an owner handle and returns `""` rather than a broken link — the card then simply omits the "View source" button.

#### `website/scripts/extract-plugins.py`
- **Purpose:** turns `plugin-catalog/*.yaml` into `plugins.json`, `plugins-meta.json` and `plugin-catalog.json`.
- **Key abstractions:** `readme_url()` (`extract-plugins.py:85`), `load_git_dates()` (`extract-plugins.py:137`), `load_catalog_entries()` (`extract-plugins.py:196`), `_cosmetic()` (`extract-plugins.py:71`), `CATALOG_TIERS`, `CATALOG_CATEGORIES`.
- **Data flow:** one YAML file per entry → validated entry (name/repo/sha required, sha must be 40 hex) → star count merged from `plugin-stars.json` → `addedAt`/`updatedAt` derived from the catalog's *git history* → sorted by stars then name → three JSON files.
- **Non-obvious decisions:** *cosmetic* fields (version, image) that fail validation are **dropped, never fatal** (`extract-plugins.py:71`) — "the site must not lose an entry a reviewer merged"; the commit dates come from **committer** dates, not author dates, because a rebase-merged PR is stamped when it lands on main, which is when the entry became installable; renames carry the old file's history forward so a renamed entry keeps its original `addedAt`.
- **Edge cases:** a shallow checkout is detected (`git rev-parse --is-shallow-repository`) and the dates are skipped entirely, because a depth-1 clone would report every entry as added in the tip commit — "worse than no dates"; a missing `plugin-catalog/` directory yields an empty catalog and exit 0.
- **Surprising:** the docs deploy **is** the publish step for the live catalog: `plugin-catalog.json` is emitted in the loader's own schema so installed clients can refresh without a new release.

#### `website/scripts/fetch-plugin-stars.py`
- **Purpose:** refreshes GitHub star counts for catalog repos, at most once a day.
- **Key abstractions:** `load_previous()` (`fetch-plugin-stars.py:77`), `probe_stars()` (`fetch-plugin-stars.py:120`), `_BATCH = 100` (`fetch-plugin-stars.py:100`).
- **Data flow:** one batched **GraphQL** query (aliased `repository` fields, 100 per request) instead of one REST call per repo → `plugin-stars.json` → merged into `plugins.json` by the extractor.
- **Non-obvious decisions:** docs deploys run with `--reuse-only` and never touch the API — only the scheduled twice-daily workflow probes GitHub and uploads the result as an artifact; the probe takes the **newest** of {live-site copy, on-disk copy} so a deploy never regresses counts to zero; on failure the previous counts are kept and `probed=False`, and `fetched_at` is *not* re-stamped over stale counts (the page would otherwise claim "today" over week-old numbers).
- **Edge cases:** a missing token keeps the previous counts; per-repo errors (a renamed/deleted repo) keep that repo's previous count.
- **Surprising:** `_BATCH = 100` exists because a single request for the whole catalog (~300 repos) exceeded GitHub's per-query resource limit and returned partial data plus an error, with stale counts kept *silently*.

#### `website/scripts/generate-llms-txt.py`
- **Purpose:** generates `llms.txt` (index) and `llms-full.txt` (whole docs concatenated) for LLM ingestion.
- **Key abstractions:** `SECTIONS` (`generate-llms-txt.py:49`), `ABSORB` (`generate-llms-txt.py:179`), `iter_docs()` (`generate-llms-txt.py:240`), `emit_llms_index()` (`generate-llms-txt.py:286`), `SKILL_CATALOG` (`generate-llms-txt.py:174`).
- **Data flow:** `iter_docs()` is the *one* enumeration of the docs tree; every slug is assigned to a section by `ABSORB` (first match wins) and emitted; curated pages lead their section, the rest follow.
- **Non-obvious decisions:** `SECTIONS` curates **order and grouping, never membership** — the file was rewritten after the section list also decided membership and drifted to 53 % coverage, with Bot Mode, the desktop app, computer use, web search and 22 messaging platforms absent from the index every LLM reads; "no path can drop a page out of the index" — a path matching nothing lands in `MISC_SECTION`.
- **Edge cases:** the ~195 per-skill pages are deliberately excluded from both files ("would bury the product docs in the index and add ~1.4 MB of duplicative material"); MDX import/export lines are stripped from `.mdx` bodies.
- **Surprising:** the file documents that the `/docs/` prefix on the canonical URLs "is not a mistake" — clients probing the classic root `/llms.txt` will miss them.

#### `website/scripts/generate-skill-docs.py`
- **Purpose:** generates one Docusaurus page per `SKILL.md`, plus the two catalogue tables, plus the sidebar subtree.
- **Key abstractions:** `mdx_escape_body()` (`generate-skill-docs.py:68`), `build_sidebar_items()` (`generate-skill-docs.py:584`), `write_sidebar()` (`generate-skill-docs.py:656`), `prune_stale_pages()` (`generate-skill-docs.py:730`).
- **Data flow:** `skills/**/SKILL.md` → frontmatter + body → an MDX-escaped page with a "Skill metadata" table, the verbatim SKILL.md body and the rewritten relative links → `docs/user-guide/skills/<bundled|optional>/<cat>/<cat>-<slug>.md`; catalogues and sidebar rewritten in the same run.
- **Non-obvious decisions:** `mdx_escape_body()` escapes `{`, `}`, and non-whitelisted `<tag>` **outside** fenced code only, preserving inline code runs and a whitelist of safe HTML — skill bodies are untrusted input that must not become MDX; a fenced block containing box-drawing characters is wrapped in `<!-- ascii-guard-ignore -->` markers so the repo's diagram linter does not reject a skill's own ASCII art; relative links to sibling files are rewritten to absolute GitHub URLs because those files are not copied into `docs/`.
- **Edge cases:** `prune_stale_pages()` deletes generated pages whose skill no longer ships **and their zh-Hans twins** — a moved skill otherwise keeps advertising a name nobody can install; only the generated subtrees are swept, never hand-authored neighbours.
- **Surprising:** the generator edits `sidebars.ts` in place with brace-depth scanning and a hard-coded block shape; the i18n key collision it had to solve is why every per-skill category carries an explicit `key`.

#### `website/scripts/check_doc_links.py`
- **Purpose:** a linter that keeps cross-page links resolvable on **both** GitHub and the rendered site.
- **Key abstractions:** `GENERATED_PREFIXES` (`check_doc_links.py:38`), `NON_DOC_ROUTE_PREFIXES` (`check_doc_links.py:42`), `iter_links()` (`check_doc_links.py:112`), `process_tree()` (`check_doc_links.py:128`).
- **Data flow:** scans EN + `zh-Hans` trees for route-style links (`](/some/route)`) outside code fences, maps routes to files via the frontmatter `slug:` (or the path), and either reports them or rewrites them to relative file links with `--fix`.
- **Non-obvious decisions:** route-style links work on the site but 404 on GitHub's file viewer, so the docs are authored as relative file links; a link inside inline code is skipped (odd backtick count) and a target that maps to no doc file is a hard error ("fix the target first") rather than a rewrite.
- **Edge cases:** generated pages are exempt by prefix and by exact filename; the `zh-Hans` relative path is computed as if the target sat in the same tree, which is how both Docusaurus (locale content paths) and GitHub (EN files) resolve it.
- **Surprising:** this is a whole script for one rule: "links must be relative file links" — the cost of making the docs browsable on GitHub.

#### `website/scripts/check-live-search.mjs`
- **Purpose:** probes the **deployed** docs site the way a visitor uses search, and fails CI if search is broken.
- **Key abstractions:** `readDeployedConfig()`, `checkAlgolia()`, `checkHitPagesOpen()`, `checkBrowser()`; `QUERIES`/`MIN_HITS` (`check-live-search.mjs:25-26`), `PROBE_DEADLINE_MS` (`check-live-search.mjs:31`).
- **Data flow:** fetch the live HTML → regex the `main.<hash>.js` bundle → extract the Algolia `appId`/`apiKey`/`indexName` from the *compiled* config (field order and quoting independent) → query Algolia with the site's `Origin` → open the top hits → drive the real DocSearch modal in headless Chromium.
- **Non-obvious decisions:** the script exists because search broke in production **twice with a green build** (deleted key, Vercel access control) and CI never talks to the deployed site; the `Accept-Encoding` header is set to Chrome's exact value because Vercel caches one entry per exact encoding string, so a request without it reads a different copy of the page than visitors do; a cached HTML naming a bundle a later deploy removed is reported as "the page cannot run any JavaScript".
- **Edge cases:** every request carries a 20 s deadline and the whole probe a 240 s deadline "so a slow-drip server fails the check with time left to retry and alert"; Vercel's firewall/`x-vercel-mitigated` response is named as such instead of "bad status"; failures are emitted as `::error::` GitHub Actions annotations so alert receivers see the reason.
- **Surprising:** the search-only Algolia key is read out of the *served bundle* rather than from CI secrets — the probe tests the credentials the visitors actually have.

#### `website/scripts/extract-automation-blueprints.py`
- **Purpose:** emits `static/api/automation-blueprints-index.json` from the single-source blueprint catalogue.
- **Key abstractions:** `build_index()` importing `cron.blueprint_catalog.CATALOG`.
- **Data flow:** repo-root Python module → flat JSON array (title, schedule, copy-paste slash command, `hermes://` deep link) → the Automation Blueprints page renders cards.
- **Non-obvious decisions:** it imports the *product's* catalogue module rather than re-listing the blueprints in the website, so the docs cannot drift from the product; on any import/build failure it writes an **empty array** so "the docs build never hard-fails on a generator hiccup".
- **Edge cases:** failure path is a warning on stderr, exit 0.
- **Surprising:** the same pattern (website generator imports the product's source of truth) appears again in `extract-plugins.py` (reads `apps/shared/src/catalog-curation.json` for the curated hero rank).

#### `website/src/components/PluginCatalog/catalog.ts`

#### `website/src/pages/skills/index.tsx`
- **Purpose:** the Skills Hub — a client-rendered catalogue of tens of thousands of skills.
- **Key abstractions:** `Skill`/`IndexMeta` interfaces, `SOURCE_CONFIG` (16 source palettes), `CATEGORY_ICONS`, `SkillCard`, `StatCard`, `buildSearchHaystack()` (`skills/index.tsx:510`).
- **Data flow:** on mount, `fetch` the two JSON files from the CDN → stamp a lowercase `_search` haystack on each row → filter (debounced 150 ms) → paginate 60 at a time (`PAGE_SIZE = 60`, `skills/index.tsx:496`) → "Show more".
- **Non-obvious decisions:** the catalog is **streamed** and aborted only after 45 s *without bytes* (`CATALOG_STALL_TIMEOUT_MS`, `skills/index.tsx:506`) — "slow-but-alive downloads keep resetting the timer and are never cut off"; the 22 MB-in-JS-chunk problem is solved by lazy-fetching `skills.json`; the search haystack is precomputed once instead of per keystroke per skill; the filter is debounced because per-keystroke filtering over 50 k rows "felt like the page had hung".
- **Edge cases:** the mobile filter drawer is a real focus-trapped `role="dialog"` with `aria-modal`, restores the previously focused element on close, locks body scroll, and closes itself when the viewport leaves the mobile band so `aria-expanded="true"` is never left on a hidden toggle; `Escape` blurs the search and closes the drawer.
- **Surprising:** the page doubles as a **picker embed** (`?embed=picker`): in that mode the chrome is hidden and each card posts a `hermes-skill-pick` message to the parent window; the page never installs anything and the comment says "there is no origin to trust in this direction; parents must validate `event.origin` themselves".

## 2. Ideas worth stealing

> Tag convention used here: **UNIQUE** = only this repo does it (as far as this shard's evidence goes); **CONVERGENT** = the same decision also appears in August Trading already, or in a second independent surface of this repo. Cross-repo convergence with `pi` / `deepseek-harness` is **not** claimed — those repos were not read in this shard.

1. **A "completion contract" for a standing goal instead of a vague one-liner.**
   *What:* a goal may carry five optional fields — what "done" means, how to prove it, what not to break, what is in scope, when to stop — and a judge model decides `done` / `continue` / `blocked` after every turn against that contract (`website/docs/user-guide/features/goals.md:81`).
   *Why it transfers:* August Trading's outcome autopilot and trade-plan validation already have gates; a *contract* the trader writes once is the difference between "the model decided it was finished" and "the model's own goal statement was satisfied".
   `UNIQUE`

2. **Micro-compaction that never compacts the trader's words.**
   *What:* after each turn, exactly one *exchange* (assistant message + tool results) is folded into a running summary; the walk deliberately starts at the assistant message so **user messages stay verbatim forever** (`website/docs/developer-guide/micro-compaction.md:68`, `:92`).
   *Why it transfers:* `services/providers/contextCompact.ts` already prioritises tool payloads, but the "never summarise the source of truth" asymmetry is sharper and is a one-line change: in a trading app the trader's instruction ("risk 1 %, no overnight holds") is exactly the text that must not be paraphrased.
   `UNIQUE`

3. **A scheduled-job status vocabulary where "ok" does not mean "delivered".**
   *What:* `last_status` has five literals — `ok`, `delivery_queued`, `error`, `delivery_failed`, `blocked_config` — and the doc states outright that "a consumer must never test `== "ok"` for 'the user got their result'" (`website/docs/developer-guide/cron-internals.md:66`).
   *Why it transfers:* August Trading's scheduled automations write a run row; a settled-delivery state distinct from "the run produced output" is the difference between a truthful "entry/TP hit delivered" badge and a lying one.
   `CONVERGENT` (August's automation settlement already distinguishes run outcome from delivery — see `tests/automationSettlement.test.tsx` in the target repo's own plan).

4. **A durable, claim-once delivery queue for scheduled work.**
   *What:* a run with a delivery target hands its output to a per-profile SQLite queue keyed by `execution_id`; a gateway tick drains it, each row moves `pending → delivering → delivered | failed | suppressed`, and a row whose claiming gateway died is fenced `unknown` and **never retried** (`website/docs/developer-guide/cron-internals.md:82`).
   *Why it transfers:* this is the exact "entry hit but the notification never landed" case in a trading app. The "never retried, but recorded as unknown" rule is the part worth copying.
   `UNIQUE`

5. **A curator that prunes the agent's own learned-rule library.**
   *What:* skills move `active → stale → archived` by usage; a zero-use skill gets a grace floor ("zero uses is absence of evidence, not proof the skill is disposable"); pinned skills and skills referenced by *any* cron job — even a paused one — are exempt; the LLM consolidation pass is opt-in; the worst outcome is archival into `.archive/`, never deletion (`website/docs/user-guide/features/curator.md:17`, `:39`, `:40`).
   *Why it transfers:* August Trading's `services/learning` (skills, pattern memory, rules) has exactly the "dozens of narrow near-duplicates" failure mode; the grace floor and the cron-reference exemption are directly applicable.
   `UNIQUE`

6. **Self-paced monitoring loops with change detection.**
   *What:* a loop that omits an interval starts at a 1-minute floor and backs off exponentially (2m → 4m → 8m, ceiling 15m) **while the agent's replies stop changing**, snapping back to the floor the moment a reply differs; a change is detected by a local digest comparison that ignores timestamps (`website/docs/user-guide/features/loops.md:48`).
   *Why it transfers:* the outcome autopilot's poll cadence is a good fit: while the position is unchanged, poll rarely; the first material change restores responsiveness.
   `UNIQUE`

7. **An idle-only heartbeat that coalesces missed ticks and refuses to invent work.**
   *What:* the heartbeat only fires between turns, missed intervals collapse into **one** turn, a queued user message always wins, the injected prompt is an ordinary user message (so the prompt cache survives), and the prompt itself tells the agent to "reply briefly and stop when nothing meaningful changed" (`website/docs/user-guide/features/heartbeat.md:42`).
   *Why it transfers:* the "don't-invent-work guard" is the missing piece in most "monitor this" features: a monitor that produces a message every tick trains the trader to ignore it.
   `UNIQUE`

8. **Prompt assembly ordered so the *longest* prefix is cacheable.**
   *What:* the cached system prompt has three tiers — stable, context, volatile — and the project context files are placed **before** anything naming the current worktree, so sessions of one project in different worktrees share a longer prefix; the runtime environment block always ends the volatile tier (`website/docs/developer-guide/prompt-assembly.md:27`, `:47`).
   *Why it transfers:* `utils/composePrompt.ts` / `constants/promptRegistry.ts` already layer the prompt; the ordering rule ("everything cwd-dependent goes last") is a cheap cache win.
   `CONVERGENT` (August already treats the system prompt as a stable cached prefix).

9. **One model-facing tool per domain, with action verbs instead of one tool per action.**
   *What:* a single `cronjob_manage` tool exposes `create | list | update | pause | resume | run | remove` (`website/docs/developer-guide/cron-internals.md:21`, `website/docs/user-guide/features/cron.md:11`); the same shape appears in `skill_manage` (`action=delete` with an `absorbed_into` target) and in the tool registry's `register(name, toolset, schema, handler, check_fn, …)` contract (`website/docs/developer-guide/tools-runtime.md:30`).
   *Why it transfers:* August's desk tool surface has one tool per action in places; the "one tool, many verbs" pattern shrinks the model's tool-choice space and the schema count.
   `UNIQUE`

10. **Fail-closed quarantine of a corrupt store instead of retrying writes.**
    *What:* on a structural SQLite error the handle is quarantined — later writes fail immediately, the connection never reopens, and the explicit WAL checkpoint is skipped; the field note explains why: a handle that kept writing for ~50 minutes "checkpointed 15 pages under the wrong page numbers on shutdown and turned a damaged-but-readable file into one that no longer opened at all" (`website/docs/developer-guide/state-db-recovery.md:35`). Separately, a corrupt FTS index is *detached* and searches fall back to `LIKE` over canonical rows — a live `FTS5('rebuild')` is never run (`website/docs/developer-guide/state-db-recovery.md:20`).
    *Why it transfers:* `services/infrastructure/SqliteService` and `BackupService` are the same surface; "stop writing, preserve the file for forensics" is the behaviour to copy.
    `UNIQUE`

11. **An LLM-facing index whose curation decides *order* but never *membership*.**
    *What:* `llms.txt` lists every doc; the curated `SECTIONS` table only decides which page leads which section, and an `ABSORB` prefix table guarantees that a page matching nothing still lands in a "More" section. The file records the failure that produced the design: when the section list also decided membership, coverage silently drifted to 53 % (`website/scripts/generate-llms-txt.py:179`, `:20`).
    *Why it transfers:* the same "curated order, guaranteed membership" rule is what a capability index or an internal agent-facing doc index needs.
    `UNIQUE`

12. **A catalogue entry pinned to an exact commit, with its README rendered behind a tag/attribute allowlist.**
    *What:* the build fetches the README at the **pinned sha** (never a branch tip) and renders it through remark → hast *without* `allowDangerousHtml` → a hand-written serializer that emits only allow-listed tags and only `http(s)/mailto/#` URLs (`website/plugins/plugin-catalog-pages/readme.js:26`, `:50`, `:161`).
    *Why it transfers:* August's `toolForge` accepts user/model-authored tools; pinning the revision and sanitising any imported content at a single boundary is the missing safety rail.
    `UNIQUE`

13. **A supply-chain age gate expressed in 25 lines of npm config.**
    *What:* `min-release-age=14` with a named exclusion list, each entry annotated with the advisory it fixes and the release date (`website/.npmrc:5`).
    *Why it transfers:* a policy-as-code file the repo can diff in review — cheap, auditable, and it does not require a lockfile bump.
    `UNIQUE`

14. **A probe of the *deployed* site for the feature users actually notice.**
    *What:* `check-live-search.mjs` reads the served HTML, extracts the hashed bundle, pulls the Algolia credentials **out of the compiled bundle**, queries the index with the site's `Origin`, opens the hits, and drives the real search modal in a headless browser — because search "broke in production twice with a green build" (`website/scripts/check-live-search.mjs:64`, `:20`).
    *Why it transfers:* August's `render-probe` already reaches the same conclusion from the app side; the complementary move is to probe the *deployed* artefact.
    `CONVERGENT` (with August Trading's `render-probe` / `boot-probe` gates).

15. **A one-page map of "which file does what, who writes it, when the agent sees it".**
    *What:* `which-file-does-what.md` answers "why did it forget what I just said?" with a master table for `SOUL.md` vs `USER.md` vs `MEMORY.md` vs `AGENTS.md` (`website/docs/user-guide/which-file-does-what.md:11`).
    *Why it transfers:* August has the same class of files; a one-page table with an explicit "who writes it" column is the cheapest way to stop a trader from putting a rule in the wrong store.
    `UNIQUE`

## 3. Trading-specific findings

- **Long-lived monitoring & scheduled work.** The cron subsystem is the single best-specified thing in this shard. Four schedule formats (relative delay, interval, 5-field cron, ISO timestamp) are normalised into one job record in `~/.hermes/cron/jobs.json` written atomically (temp file + rename); the record carries `skills`, `deliver`, `repeat.{times,completed}`, `state`, `enabled`, `next_run_at`, `last_run_at`, `last_status` and optional `model`/`provider`/`script` (`website/docs/developer-guide/cron-internals.md:21`, `:34`). Reliability comes from four things August can copy: (a) a **durable, claim-once delivery queue** with an `unknown` fence for dead gateways; (b) **admission recovery** — unfinished receipts are reconciled on every tick and after an owner restart, a known terminal result is handed to the delivery queue *without re-running the agent*, and an interrupted execution stays paused for operator review rather than being retried (`website/docs/user-guide/features/cron.md:45`); (c) **pre-dispatch validation** that can refuse to burn a run (`blocked_config`); (d) a **no-agent mode** where a script runs on a schedule and its stdout is delivered verbatim with zero LLM cost (`website/docs/guides/cron-script-only.md:1`). Two safeguards matter for a trading app: a cron-run session cannot create further cron jobs (`website/docs/user-guide/features/cron.md:42`), and a job's model is resolved **at fire time** (per-job pin → `cron.model` → the main model at that moment) while the *agent may pin but not repoint* a job at a different model — inference pins are user-owned (`website/docs/user-guide/features/cron.md:28`).
- **Human-in-the-loop approval.** The approval surface is a *pattern* inside the tool registry: the `DANGEROUS_PATTERNS` approval flow is part of the dispatch contract (`website/docs/developer-guide/tools-runtime.md:184`), destructive slash commands carry confirmation prompts (`website/docs/reference/slash-commands.md:326`), and the messaging layer splits commands into an **admin/user permission split** (`website/docs/reference/slash-commands.md:16`). Crucially, the *agent* is not the approver: `/goal gate add` (a shell command that must pass before a goal may be judged done) requires an explicitly configured gateway admin, while listing/removing/clearing gates stays available for recovery (`website/docs/user-guide/features/goals.md:79`). The audit trail is the job ledger itself: `last_status`, `last_error`, `last_delivery_error` and the `execution_id`-fenced delivery outcome are written back onto the run, idempotently, so a decision can never overwrite a later run's status (`website/docs/developer-guide/cron-internals.md:102`).
- **Post-mortem / reflection loops.** The Curator is the reference implementation of "outcomes become new rules, and bad rules do not accumulate": deterministic pruning (stale at 14 days, archive at 30) runs with no model cost; the opinionated LLM consolidation pass (merge overlapping skills into umbrellas, patch drift) is **opt-in** because it costs aux-model tokens and makes broad structural changes on every run; pinned skills and cron-referenced skills are exempt from *both* passes; a consolidation must treat a skill as a whole package (keep it standalone, re-home its `references/`/`templates/`/`scripts/`, or archive it unchanged — never flatten half of it); and there is an **audit ledger with single-edit rollback** plus an archive TTL purge (`website/docs/user-guide/features/curator.md:39`, `:40`, `:154`, `:185`). The second reflection surface is the trajectory writer: conversations are appended as ShareGPT-format JSONL with `tool_stats` and `tool_error_counts` normalised to include every possible tool with zero defaults, so the schema stays stable for later dataset work (`website/docs/developer-guide/trajectory-format.md:55`).
- **Multi-agent — where delegation actually adds value.** The docs state the division of labour bluntly: delegate for "reasoning-heavy subtasks", tasks that "would flood your context with intermediate data", parallel independent workstreams, and fresh-context work; do **not** delegate for a single tool call, mechanical multi-step work (`execute_code` instead), tasks needing user interaction (a subagent cannot use `clarify`), quick edits, or work that must survive a restart (`website/docs/guides/delegation-patterns.md:15`). Mechanically, a child gets a **completely fresh conversation** — its only context is the `goal` and `context` strings the parent writes (`website/docs/user-guide/features/delegation.md:80`) — and only its final summary returns. The pattern that is most transferable is the `output_schema` contract: the child sees the schema up front, the parent validates, and on a miss the parent sends **exactly one bounded correction turn carrying the validation errors verbatim**; a second miss does **not** discard the work — the result keeps `status: completed`, the raw text, `schema_valid: false` and the errors, and the parent extracts what it needs (`website/docs/user-guide/features/delegation.md:55`). Debate is modelled as Mixture of Agents, and its economics are spelled out: reference models see only the conversation text (no system prompt, no tool schemas) and advise once per turn, while the **aggregator is billed for the whole run** because it drives the tool loop (`website/docs/user-guide/features/mixture-of-agents.md:11`). The "board of many tasks" alternative is Kanban (SQLite-backed, worker lanes, PR completion contracts), and the boundary is stated explicitly: "`/goal` is single-session … the overlap is deliberate, and small" (`website/docs/user-guide/features/goals.md:24`).
- **Structured logs the model can query, without a heavy database.** Everything lands in SQLite: `state.db` holds `sessions`/`messages` as the canonical transcript with `messages_fts*` as a *derived* index, and the failure policy is the interesting part — a corrupt FTS index is detached (triggers removed) and searches fall back to `LIKE` over canonical rows rather than rebuilding live (`website/docs/developer-guide/state-db-recovery.md:20`); a structurally corrupt file is quarantined so the bytes survive for forensics (`website/docs/developer-guide/state-db-recovery.md:35`). Around it sit a per-profile `cron/deliveries.db` ledger, a `pending_messages/` spool, a `sessions/<id>.jsonl` fallback, and `state-snapshots/`. The queryable surface for the model is a `session_search` tool plus the `MEMORY.md`/`USER.md` stores — the latter **frozen** at session start (a mid-session write is persisted to disk but invisible to the model until the next session, to protect the prompt cache) and **hard-capped** (2,200 and 1,375 characters) with *no* auto-compaction: an overflowing write returns an error and the agent must make room itself (`website/docs/user-guide/features/memory.md:21`, `:36`).
- **Staying simple as features accumulate.** The repo fights feature sprawl with four mechanisms. (1) A **codebase-ownership map** with the rule "changes should stay inside their subsystem" and "when two subsystems are involved, the narrower one owns the change — the core is a narrow waist" (`website/docs/developer-guide/codebase-ownership.md:28`). (2) A **link linter** whose whole job is to keep one rule — relative file links, so the docs also work on GitHub (`website/scripts/check_doc_links.py:1`). (3) An **index that cannot lose a page** (`generate-llms-txt.py:179`). (4) A **category taxonomy kept small** (9 plugin categories, ~34 skill categories) with small categories auto-collapsed into "Other" and junk tags rejected, because the previous tag heuristic produced hundreds of one-off categories (`website/scripts/extract-skills.py:587`, `:617`). The trading-adjacent skill catalogue in this shard shows the house style for financial work: a "Data Source Priority (READ FIRST)" section in comps analysis, "CRITICAL PRINCIPLES — read before populating any template" in the 3-statement model, formula-over-hardcode and balance-check conventions in the Excel author skill, and bear/base/bull plus 5×5 sensitivity tables in the DCF skill (`website/docs/user-guide/skills/optional/finance/finance-comps-analysis.md:40`, `.../finance-3-statement-model.md:42`, `.../finance-excel-author.md:50`, `.../finance-dcf-model.md:44`). Two of them are directly useful to a trading product: `productivity-product-price-monitor` ("watch product, flight, or listing prices; alert on target") and `devops-watchers` ("poll RSS, JSON APIs, and GitHub with **watermark dedup**") — the latter is the standard trick for a polling monitor that must not re-deliver what it already saw (`website/docs/user-guide/skills/bundled/productivity/productivity-product-price-monitor.md:36`, `website/docs/user-guide/skills/optional/devops/devops-watchers.md:42`).

## 4. Non-obvious decisions and gotchas

1. **`last_status == "ok"` does not mean the user got the result.** Five literals exist and every renderer must map them explicitly (`website/docs/developer-guide/cron-internals.md:66`).
2. **The delivery write-back is fenced on `execution_id`**, so it is idempotent and can never rewrite a later run's status; both the drain and the run call it, because a drain can finish before the run's own bookkeeping lands (`website/docs/developer-guide/cron-internals.md:102`).
3. **A cron job's model is resolved at fire time, and the agent may only *pin*, never repoint** — "inference pins are user-owned" (`website/docs/user-guide/features/cron.md:28`). The reasoning-effort pin is deliberately *not* exposed on the `cronjob_manage` tool.
4. **Cron runs cannot create cron jobs** — the cron management tools are disabled inside cron executions to stop runaway scheduling loops (`website/docs/user-guide/features/cron.md:42`).
5. **Memory is a frozen snapshot.** A write during a session is persisted immediately but does not appear in the system prompt until the next session; the tool response always shows the live state (`website/docs/user-guide/features/memory.md:36`).
6. **Memory never auto-compacts.** A write that would exceed the cap returns an *error*; the agent must consolidate or remove entries in the same turn. A `patch` that lengthens an entry can also overflow (`website/docs/user-guide/features/memory.md:21`).
7. **Do not point two agent processes at one Hermes home** — memory writes load back at session start, so two writers compound each other's entries into state neither authored (`website/docs/user-guide/features/memory.md:24`).
8. **Subagents know nothing.** No history, no prior tool calls; only `goal` + `context` (`website/docs/user-guide/features/delegation.md:80`).
9. **A schema-invalid subagent result is not thrown away** — it keeps the raw text and the errors and the parent extracts what it needs (`website/docs/user-guide/features/delegation.md:55`).
10. **The prompt's runtime boundary is a marker, not a heading.** `_stored_prompt_matches_runtime()` reads the first host-info paragraph after a closing marker, so examples in project/memory/plugin text cannot masquerade as the current working directory; `Platform:` is deliberately *not* an identity field, so a desktop↔TUI switch keeps the cached prefix and delivers the new surface's guidance as a one-shot note (`website/docs/developer-guide/prompt-assembly.md:55`).
11. **The skills index rides the same one-shot note channel.** Each turn compares the live index with the one the session would build now; a difference (new or removed skill) is sent as a one-shot user-message note so the cached prefix survives (`website/docs/developer-guide/prompt-assembly.md:60`).
12. **A corrupt database is quarantined, not retried** — and the WAL checkpoint is skipped so the `-wal` sidecar survives for forensics (`website/docs/developer-guide/state-db-recovery.md:50`).
13. **Never run a live `FTS5('rebuild')`** on a live transcript; detach the index and serve `LIKE` instead (`website/docs/developer-guide/state-db-recovery.md:20`).
14. **A plugin may not shadow a built-in tool from a different toolset** without `override=True` *and* an operator opt-in `plugins.entries.<id>.allow_tool_override` (`website/docs/developer-guide/tools-runtime.md:43`).
15. **`schema["description"]` is the authoritative model-facing text**; the separate `description=` registry argument does not reach the model (`website/docs/developer-guide/tools-runtime.md:45`).
16. **Tool discovery is AST-based** — only *top-level* `registry.register()` calls count, so helper modules in `tools/` are never imported (`website/docs/developer-guide/tools-runtime.md:62`).
17. **A catalogue card hides the "Disclosure — …" sentences**; the plugin's own page shows them. The disclosure is a convention parsed out of the description, not a separate field (`website/src/components/PluginCatalog/catalog.ts:184`).
18. **A README is fetched at the pinned commit, never a branch tip**, so the published page shows exactly what the reviewer read; it changes only when the author re-pins through a reviewed PR (`website/plugins/plugin-catalog-pages/readme.js:11`).
19. **The `llms.txt` index's curation decides order, never membership** — the previous design drifted to 53 % coverage and lost whole product areas (`website/scripts/generate-llms-txt.py:15`).
20. **The Skills Hub aborts a stalled catalog fetch only after 45 s without bytes**; a slow-but-alive transfer keeps resetting the timer and is never cut off (`website/src/pages/skills/index.tsx:506`).
21. **The "featured" pick is computed by a shared module** (`apps/shared/pickFeatured`) so the website and the desktop app always feature the same entry, and it rotates weekly (`website/src/components/CatalogFeatured/index.tsx:8`).
22. **A card is the link.** Nothing in the catalogue expands in place; in the desktop picker iframe the card opens a new tab so the in-frame navigation cannot leave the host's embed (`website/src/pages/plugins/index.tsx:102`).
23. **The picker embed never installs anything.** It posts a `hermes-skill-pick` / `hermes-plugin-pick` message and the comment is explicit that "there is no origin to trust in this direction; parents must validate `event.origin` themselves" (`website/src/pages/skills/index.tsx:537`).
24. **The Curator's first run is deferred by a full interval** so a new install can be reviewed before anything is touched, and `hermes curator run --dry-run` shows what it *would* do (`website/docs/user-guide/features/curator.md:33`).
25. **The Curator's LLM pass is only offered skills it can actually read and write** — bundled built-ins and disabled skills are excluded so the pass cannot burn its budget on refused reads (`website/docs/user-guide/features/curator.md:56`).
26. **Zero-use skills are not archived** until they are at least `stale_after_days` old — "zero uses is absence of evidence, not proof the skill is disposable" (`website/docs/user-guide/features/curator.md:40`).
27. **A skill referenced by a paused cron job is exempt from archival**, so a slow schedule cannot have its skill archived out from under it (`website/docs/user-guide/features/curator.md:40`).
28. **A heartbeat is owned by the surface that set it** — set from a chat, it fires from the gateway and replies into that chat even while the same session is open in the desktop app (`website/docs/user-guide/features/heartbeat.md:42`).
29. **A heartbeat tick is refunded if the attempt never entered the agent runner** — but once the runner is entered the fire counts even if execution fails (`website/docs/user-guide/features/heartbeat.md:42`).
30. **`/loop`'s backstop budget** (`loops.max_ticks`, default 100) pauses an unattended loop so it cannot burn tokens forever; and an unreachable `--until` condition *pauses* the loop rather than re-firing ("fail-open: a broken judge never wedges the loop") (`website/docs/user-guide/features/loops.md:64`).
31. **Delivery failures never regress to zero**: a failed star probe keeps the previous counts and does not re-stamp `fetched_at`, because the page would otherwise claim "today" over week-old numbers (`website/scripts/fetch-plugin-stars.py:120`).
32. **Cosmetic catalogue fields are dropped, never fatal** — "the site must not lose an entry a reviewer merged" (`website/scripts/extract-plugins.py:71`).
33. **Catalogue dates come from committer dates**, not author dates, because a rebase-merged PR becomes installable when it lands on main (`website/scripts/extract-plugins.py:137`).
34. **A shallow clone yields no dates at all**, because a depth-1 history would report every entry as added in the tip commit — "worse than no dates" (`website/scripts/extract-plugins.py:137`).
35. **Skill bodies are escaped as untrusted input**: `{`, `}` and non-whitelisted tags are escaped outside code fences only, and inline code runs are preserved (`website/scripts/generate-skill-docs.py:68`).
36. **Generated skill pages are pruned, including their zh-Hans twins**, so a renamed skill cannot keep advertising a name nobody can install (`website/scripts/generate-skill-docs.py:730`).
37. **The `zh-Hans` mirror is not a source of truth** — it is consistently shorter than the English page and several pages are stale (see the section header above).
38. **`onBrokenLinks: 'warn'`** means a broken link never fails the build; the repo compensates with `check_doc_links.py` in CI (`website/docusaurus.config.ts:17`).
39. **Search broke in production twice with a green build**, which is why a live-site probe exists at all (`website/scripts/check-live-search.mjs:4`).
40. **Vercel caches one entry per exact `Accept-Encoding` string**, so the probe must send Chrome's value or it reads a different copy of the page than visitors do (`website/scripts/check-live-search.mjs:36`).

## 5. Weak spots

1. **The taxonomy is duplicated three ways and kept in sync by a comment.** The plugin category list exists in Python (`CATALOG_CATEGORIES`, `website/scripts/extract-plugins.py:49`), in TypeScript (`CATEGORY_CONFIG`, `website/src/components/PluginCatalog/catalog.ts:118`) and implicitly in the sidebar. The instruction is literally "keep it in sync with …" — an unenforced invariant that will drift the first time someone adds a category.
2. **`CopyButton` is implemented three times** — `website/src/components/PluginCatalog/CopyButton.tsx`, a second copy inside `website/src/pages/skills/index.tsx`, and a third inside `website/src/components/AutomationBlueprintsCatalog/index.tsx` — with slightly different behaviour (the skills copy has no clipboard failure handling note, the blueprint one has none at all). The site has a `components/shared/` convention everywhere else, so this is an inconsistency, not a pattern.
3. **The Chinese mirror is stale and only partially translated.** `zh-Hans/.../developer-guide/browser-supervisor.md` is still the original design document, `.../features/image-generation.md` still advertises 8 models where the English page lists 11, and `.../features/web-dashboard.md` still describes a much smaller admin surface. There is no freshness check in the build, so the drift is invisible until a reader notices.
4. **The generated skill pages duplicate their sources wholesale.** Each of the ~250 pages embeds the complete upstream `SKILL.md` inside a `:::info` block, so the site carries multiple megabytes of content the agent already has in the repo — it inflates the search index (Algolia) and the build, and makes "half the results are skill pages" a likely outcome for a documentation query.
5. **`generate-skill-docs.py` rewrites `sidebars.ts` in place** using a hard-coded block shape and brace-depth scanning (`website/scripts/generate-skill-docs.py:656`). A hand-edit of the Skills block makes the generator throw a `RuntimeError` at build time, which is at least loud — but it means the sidebar is a generated file that humans also edit, which is the usual way generated files rot.
6. **The `llms.txt` output lives at `/docs/llms.txt`, not `/llms.txt`**, and the file itself admits that "clients and IDE plugins that probe the classic `/llms.txt` root will miss these" (`website/scripts/generate-llms-txt.py:30`). A large, carefully-built index that many clients will simply not find.
7. **Skill pages are generated, but their "generated" status is only a comment in the body** (`{/* This page is auto-generated from the skill's SKILL.md … */}`). Nothing in the build or the linter prevents a hand-edit from being silently overwritten on the next run.
