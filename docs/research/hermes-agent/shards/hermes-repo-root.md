# hermes-agent :: hermes-repo-root

### `hermes_constants.py`
- **Purpose:** the single authority for *where Hermes state lives* and *how a profile is scoped* — plus a grab-bag of small shared primitives (reasoning-effort parsing, model-name normalisation, Windows/WSL path translation).
- **Key abstractions:**
  - `get_hermes_home()` (`hermes_constants.py:188`) — the home resolution chain: **context-local override → `HERMES_HOME` env var → platform default**. The override is a `ContextVar` (`_HERMES_HOME_OVERRIDE`, `:19`), deliberately *not* `os.environ`, because the env var is shared by every thread in the process (`:36-38`).
  - `set_hermes_home_override` / `reset_hermes_home_override` (`:33`, `:44`) — a token-based scope for a single task.
  - `pin_process_hermes_home` / `get_routing_process_hermes_home` (`:281`, `:294`) — the *host's own* identity vs. the *task's* scope. This is the distinction that keeps a multiplexed gateway from mistaking a routed profile for its launch profile.
  - `hermes_home_key()` (`:206`) — a stable registry key for a home/profile dir, memoised per input path. `Path.resolve()` is a syscall and this sits under every tool-registry lookup, so the memo saves a syscall per lookup. Non-existent dirs resolve leniently and are **not** cached, because the answer can change once the dir appears (`:213-219`).
  - Profile identity: `named_profile_has_identity` (`:389`), `named_profile_has_servable_identity` (`:399`), `named_profile_is_live` (`:411`), `named_profile_is_deleted` (tombstone) (`:379`), `PROFILE_ID_RE` (`:387`).
  - `mkdir_under_hermes_home()` (`:455`) — the only directory-creation chokepoint; it *refuses* to materialise a deleted profile.
  - `get_scratch_dir()` (`:972`), `prune_scratch_dir()` (`:998`), `apply_scratch_tmp_env()` (`:1053`) — the scratch/temp discipline (see below).
  - `apply_secure_dir_policy()` (`:936`) — one permission policy (owner-only `0700` by default; managed installs left alone; containers only honour an explicit `HERMES_HOME_MODE`; `HERMES_UID`/`HERMES_GID` chown applied).
  - `parse_reasoning_effort()` (`:1080`), `resolve_per_model_reasoning_effort()` (`:1144`), `_canonical_model_variants()` (`:1107`), `resolve_reasoning_config()` (`:1180`) — the reasoning-tier resolution chokepoint, with spelling-tolerant model matching.
  - `openrouter_variant_base()` (`:1310`) — strips a *request-time routing* suffix (`:nitro`, `:floor`, `:exacto`, `:online`) but **not** a real catalog SKU (`:free`, `:batch`, `:thinking`, `:extended`).
  - `normalize_scope()` (`:1476`) — a deliberately-scope-sensitive key normaliser with a long docstring warning that write-side and read-side scopes have *different* meanings and must not be unified.
  - `hermes_root_for_environment()` (`:122`) — resolves the Hermes root for *another* process's environment, used by sudo/profile isolation.
  - `apply_ipv4_preference()` (`:1288`), `windows_path_to_wsl()` / `wsl_unc_path_to_posix()` (`:1250`, `:1257`), `find_node_executable()` (`:569`), `node_tool_runnable()` / `agent_browser_runnable()` (`:508`, `:620`).
- **Data flow:** every consumer calls `get_hermes_home()` (or a sibling) instead of touching `~/.hermes` literally. The profile resolution goes: context override → env var → platform default (`%LOCALAPPDATA%\hermes` on Windows, `~/.hermes` elsewhere). The *registry scope key* is derived from the resolved path and memoised.
- **Non-obvious design decisions:**
  - **The profile fallback warning is one-shot on the FIRST check, not on the warning branch** (`:181-187`). The old code latched only when it warned, so with no active profile the stat+read re-ran on *every* `get_hermes_home()` call. This is a performance bug they fixed and documented.
  - **`_account_home()` reads the password database, never `$HOME`** (`:79-88`). A harness that repoints `HOME` (root under `sudo` has uid 0 too) must not be able to redirect the account's real home. `sudo_invoker_default_home()` (`:136`) does the same for the sudo case.
  - **A "profile" is a directory that carries an identity marker** (`config.yaml`, `.env`, `SOUL.md`, `profile.yaml`, `auth.json`, `state.db`) (`:383-387`). A directory under `profiles/` with no marker is *not* a profile — it is runtime side-effect litter, and must never be listed, served, ticked, or seeded with credentials.
  - **An empty `.env` is not enough to count as a servable tenant** (`:399-409`). A crashed `hermes profile create` leaves an empty `.env`; counting it as a second tenant flips the whole host's credential reads fail-closed at the next boot.
  - **The scratch dir is Hermes' own temp space, never the system `/tmp`** (`:815-824`). System temp is tmpfs on most Linux, so browser profiles and download spools eat RAM and vanish on reboot. `HERMES_HOME/cache/scratch` is real storage with an **idle** retention: an entry lives while anything inside it is still being written and goes 24h after the last write *anywhere in its subtree* (`SCRATCH_MAX_IDLE_HOURS = 24`, `:824`). The comment explains why a fixed age was wrong both ways: a directory's own mtime only moves on a direct child change, so a lane writing deep inside a tree looked untouched and lost its worktree at the deadline.
  - **`socket_safe_tmpdir()`** (`:838`) — a separate, shorter temp root for AF_UNIX sockets only (104/108-byte cap), because Chrome's `SingletonSocket` plus a 49-char RPC socket name overflows a deep profile home.
  - **Per-model reasoning overrides match spelling-tolerantly**: dots↔dashes are interchangeable, provider/aggregator prefixes are stripped *and* added, and there is a **reverse lookup** so a key like `ollama-local/qwen3.6:27b` still matches a bare `qwen3.6:27b` fed by a fallback swap (`:1144-1180`).
  - **A typo'd reasoning effort warns but does not fail** (`:1188-1192`): unknown value → default medium + a warning.
- **Edge cases & failure handling:**
  - Invalid timezone / unknown model → warn, fall back, never crash.
  - `mkdir_under_hermes_home` raises `FileNotFoundError` for a tombstoned profile *before* creating anything (`:440-448`).
  - `secure_parent_dir` refuses to chmod `/` or a top-level dir, and refuses the install tree entirely (chmod `0700` there breaks the Docker UID-10000 user) — it warns instead (`:668-693`).
  - `_legacy_path_has_content` treats a non-`FileNotFoundError` `OSError` as "occupied" — never orphan legacy data (`:637-651`).
  - `find_node_executable` **never falls back to the user's PATH copy**; callers `pm.ensure` on `None`, because mixing toolchains breaks native-addon ABIs (`:571-575`).
  - `node_tool_runnable` / `agent_browser_runnable` probe with `--version` rather than trusting presence, because a dangling npm symlink still passes `shutil.which` and exec fails with 127 (`:620-633`).
- **Surprising:**
  - `normalize_scope`'s docstring (`:1478-1492`) is a warning about a *past* bug: using the write-side normaliser on a read path hid every scoped registration. Two contracts, one registry, deliberately not unified.
  - `partial_update_hint` / `emit_partial_update_hint` (`:1424`, `:1436`) live here — a half-updated install is detected by "the missing module's root is first-party" and the user gets a `hermes update` hint instead of a raw `ModuleNotFoundError`.
  - `project_venv_dir` (`:1352`) has a three-paragraph comment about a *different* install's venv being adopted — the fix is to consult the running interpreter plus `direct_url.json`, never a path heuristic.

### `hermes_logging.py`
- **Purpose:** the centralised logging subsystem — rotating files, redaction, per-component routing, per-profile routing, and an async queue so an agent's event loop never blocks on file I/O.
- **Key abstractions:**
  - `setup_logging()` (`:351`) — idempotent (`force=True` to re-apply). Produces `logs/agent.log` (INFO+), `logs/errors.log` (WARNING+), `logs/gateway.log` (INFO+, `mode="gateway"`), `logs/gui.log` (INFO+, `mode="gui"`). All are driven through **one** `QueueListener`.
  - `COMPONENT_PREFIXES` (`:306`) — the logger-name→file routing table. `gateway` covers `gateway`, `hermes_plugins`, `plugins.platforms`, `agent.memory_caller_scope`; `gui` covers `hermes_cli.web_server`, `hermes_cli.pty_bridge`, `hermes_cli.desktop`, `tui_gateway`, `uvicorn`.
  - `_install_session_record_factory()` (`:263`) — replaces the **global** `LogRecord` factory so `%(session_tag)s` exists on *every* record, including third-party-handled ones (a `Filter` would miss propagated records). It also stamps `record.hermes_home` — the resolved home of the *emitting* task — because the `QueueListener` formats later, on another thread, where the profile `ContextVar` is gone.
  - `_ProfileRoutingFileHandler` (`:640`) — routes each queued record to the log file of *its own* profile home, keeping per-home rotation, redaction, and managed perms.
  - `_ManagedRotatingFileHandler` (`:428`) — stdlib `RotatingFileHandler` plus (a) managed-mode `0660` chmod, (b) **external-rotation detection** (compares the path's dev/ino against the open stream's on every emit, reopening on mismatch — the `WatchedFileHandler` pattern), (c) rollover ownership restoration.
  - `flush_log_queue()` (`:861`) — blocks until every queued record is written (stop+restart the listener).
  - `drain_log_queue(timeout=1.0)` (`:876`) — the **bounded** variant for hard-exit paths, where an unbounded join would re-freeze shutdown because the listener may be wedged on the rotation lock.
  - `release_profile_log_handlers()` (`:890`), `enable_profile_log_routing()` (`:919`).
  - `redact_detached_stdio()` (`:182`) — a `_RedactingStdio` proxy on `sys.stdout`/`sys.stderr`, because a detached gateway's stdio *is* a persisted log and provider error echoes reach it through `print`, never through `RedactingFormatter`.
  - `_portalocker_probe()` (`:44`) and `_WINDOWS_CLH_FALLBACK` — a startup probe of whether `portalocker` can actually take a lock on this box.
- **Data flow:** `logger.info(...)` → the global record factory adds `session_tag` + `hermes_home` → a `QueueHandler` enqueues an **unformatted shallow copy** → the `QueueListener` thread applies each handler's own level/filter → the profile router picks the home handler → the file handler reopens if the file was rotated underneath it → writes.
- **Non-obvious design decisions:**
  - **On Windows only, `RotatingFileHandler` is swapped for `ConcurrentRotatingFileHandler`** (`:85-107`). Windows `os.rename()` fails with `PermissionError [WinError 32]` whenever *any* other process holds an append handle on `agent.log` — in Hermes that is *always* (TUI, gateway, memory server, MCP servers, CLI commands all log). The file pins at the size threshold and spams stderr on every emit. POSIX keeps stdlib: renames of open files work, and managed mode (NixOS) relies on stdlib's exact `_open()`/`doRollover()` lifecycle for the `0660` chmod and eager file creation.
  - **If `portalocker` cannot take a lock, they fall back to stdlib rotation with rollover DISABLED** (`:101-106`, `:657-663`). The alternative (CLH's behaviour) is to silently drop *every* record: CLH retries 20× and then suppresses the "Cannot acquire lock" `RuntimeError`, so the failure is invisible. A probe at import time catches this; the fallback warns exactly once.
  - **The record factory, not a filter** (`:263-275`).
  - **The queue handler returns a shallow copy** (`:755-763`): stdlib's `prepare()` formats and strips `args`/`exc_info` for cross-process pickling, but this queue is in-process, so targets get the unformatted record. The copy is because the emitting thread's synchronous handlers may mutate `record.message` concurrently.
  - **File logging is routed through a queue, not attached to root** (`:915`): an `emit` can block on the cross-process rotation lock, and on an asyncio thread that stalls the event loop and drops WebSocket clients.
  - **Redaction is per-profile at format time**: the router binds the target home with `set_hermes_home_override` around the write (`:794-802`) so `RedactingFormatter` applies *that* profile's policy and vault values, not the launch profile's.
  - **The profile-liveness recheck is throttled to 2s** (`:637-638`, `:676`): the check is two stats per record per router on the listener thread, which nearly doubles the syscalls of every live-profile emit. A deleted home only needs catching within a couple of seconds; an `rmtree` is caught at once by the write that finds the directory gone.
- **Edge cases & failure handling:**
  - `handleError` (`:560`) suppresses exactly one known error (the Windows CLH lock timeout), warns **once** through the logging system (so a wedged lock is visible in the logs instead of a black hole), and separately handles an unavailable log stream by naming the path once and dropping the stale stream.
  - `_reopen_if_externally_rotated` (`:515`) is silent and best-effort: any error falls back to the existing stream so logging keeps working rather than dying on a stat failure.
  - `doRollover` (`:578`) restores the previous owner/mode of the new base file — the stdlib rollover creates a fresh file owned by whichever process crossed `maxBytes`, and with one rotating handler per profile that is usually the long-lived root gateway, so an unprivileged worker on another uid can never reopen its own `agent.log`. "A log that cannot be chowned is still a working log."
  - `_line_buffer_piped_stdout()` (`:116`) — Python block-buffers stdout when it is not a TTY, so a headless run looks stalled for minutes while the work is actually progressing. Reconfiguring the interpreter's own stdout to line-buffering fixes it. A closed/detached stream raises `OSError`/`ValueError` — buffering is observability, not correctness, so it never crashes setup.
  - `_safe_stderr()` (`:141`) — wraps stderr with `errors='replace'` so un-encodable characters become `?` instead of crashing the process.
- **Surprising:**
  - The `agent.log` handler's `emit` compares dev/ino **on every record** — a stat per emit — but only when the file exists, so a healthy emit pays a sub-microsecond stat.
  - `setup_logging` calls `_adopt_secondary_home` (`:429-449`) *before* the "already initialised" check: a process that serves a second home gets profile routing enabled rather than a duplicate file handler that would take every profile's records.

### `utils.py`
- **Purpose:** shared low-level utilities — atomic file writes, YAML/JSON persistence, change detection, proxy normalisation, and URL-origin comparison.
- **Key abstractions:**
  - `file_signature(st)` (`:40`) — the change-detection key `(st_mtime_ns, st_size, st_ino, st_ctime_ns)`. mtime+size alone miss a replacement that preserves both (`cp -p`, `rsync -t`, a tar restore, a script pinning the timestamp with `os.utime`); the inode changes on an atomic replace and ctime cannot be backdated from user space.
  - `mtime_is_racy(mtime_ns)` (`:61`) — filesystem timestamps tick coarsely (~4 ms; whole seconds on some filesystems), so a write in the same tick as a stat leaves the signature unchanged. A signature this fresh is "racily clean" (as in git's index) and must not be trusted as "nothing changed since".
  - `atomic_replace(tmp, target)` (`:179`) — symlink-preserving `os.replace` with a Windows-contention retry budget and a cross-device copy fallback.
  - `mkstemp_beside(target)` (`:226`) — stages the temp file in the directory the rename will land in.
  - `_atomic_write(...)` (`:290`) — the one temp+fsync+replace primitive; `atomic_write_text` (`:350`), `atomic_write_bytes` (`:371`), `atomic_json_write` (`:391`), `atomic_yaml_write` (`:449`) all route through it.
  - `atomic_roundtrip_yaml_update(path, key_path, value)` (`:472`) — update one dotted key while preserving comments, ordering, quoting, Unicode.
  - `atomic_roundtrip_yaml_save(path, new_state)` (`:540`) — the **on-disk primitive for `config.yaml`**: merges a full state dict onto the ruamel round-trip document so comments, key order, quotes, blank lines survive; only changed nodes are reassigned; **keys absent from `new_state` are deleted** ("explicit absence").
  - `read_json_or_empty(path)` (`:420`) — the read half of every `read → merge → atomic_json_write` config store; a corrupt sidecar degrades to defaults instead of taking the provider down.
  - `warn_if_credential_file_broadly_readable(path)` (`:436`) — warns when a credential file is group/world-readable.
  - `load_yaml_file_readonly(path)` (`:618`) — cached by `file_signature`; returns the cached object, which callers must never mutate.
  - `base_url_hostname` / `base_url_path` / `base_url_origin` / `base_url_host_matches` (`:762`, `:768`, `:775`, `:788`).
  - `normalize_proxy_url` / `sanitize_no_proxy_entries` / `normalize_proxy_env_vars` (`:690`, `:707`, `:720`).
  - `model_forces_max_completion_tokens(model)` (`:761`).
- **Data flow:** a caller produces a value → `_atomic_write` opens a `mkstemp` fd in the target's directory (0600 from creation) → optionally `fchmod`s the *mode* onto the temp fd **before** the replace → writes → `fsync` → `atomic_replace` → re-applies owner/mode → optionally fsyncs the parent directory. The temp file is removed on any failure, `BaseException` on purpose, so `KeyboardInterrupt`/`SystemExit` still clean up.
- **Non-obvious design decisions:**
  - **The mode is fchmod'd onto the temp fd BEFORE the replace, so the target never transits through mkstemp's 0600** (`:302-311`). fchmod is Unix-only; on Windows the post-replace chmod is the sole path. A secret is never readable at process umask, not even between create and chmod.
  - **A NEW target gets the mode `open(path, "w")` would have given it** (`default_new_file_mode()`, `:115-131`), not mkstemp's 0600. Silently tightening every fresh cache/state file to 0600 breaks shared Docker/NAS volume mounts.
  - **A symlink target is resolved before the rename** (`_publish_path`, `:222-224`) so `os.replace` writes the real file in place and the symlink survives.
  - **`mkstemp_beside` stages next to the *resolved* target** (`:226-243`): a temp staged next to a symlink whose target lives on another filesystem turns the publish rename into EXDEV, and the copy fallback then rewrites the file in place — torn on a crash. If that directory is not writable, it falls back to staging beside the link, accepting the non-atomic path rather than failing the save.
  - **Windows rename contention is a bounded, jittered retry, then an in-place rewrite** (`:135-177`, `:195-217`). The three candidate winerrors are 5, 32, 33 — CPython opens files without `FILE_SHARE_DELETE`, so `os.replace` onto an open file is denied. The budget is ~200 ms recovered atomically; the cap matters as much as the count because `gateway_state.json` is rewritten every turn, so a permanently-held target pays the full budget per write. Jittered so concurrent writers do not retry in lockstep.
  - **The in-place rewrite preserves the target's ACL**, which `os.replace` does not (the temp file's inherited ACL wins there) (`:157-160`).
  - **YAML 1.1 ambiguous words are force-quoted at every depth** (`_YAML11_AMBIGUOUS_WORDS`, `:520-530`): ruamel's round-trip dumper resolves plain scalars under YAML 1.2 (only true/false/null reserved), so a string like `"off"` is emitted unquoted — and every other config reader here parses under YAML 1.1, where `on/off/yes/no` are booleans. An unquoted `approvals.mode: off` would silently round-trip back as `False`. The set is applied inside lists too, not just at the top level.
  - **The dotted-key path honours escaped dots and prefers existing literal dotted keys** (`:474-480`): otherwise `/model` + TUI persistence wrote `glm-5: {'3': ...}` phantom siblings.
  - **`base_url_origin` returns scheme + hostname + effective port**, not just the host (`:775-786`): `https://h` vs `http://h` and two ports on one host are different trust boundaries, so handing a bearer secret to a new URL must compare all three — hostname alone would authorise an HTTPS→HTTP downgrade.
  - **`base_url_host_matches` compares hostnames, never substrings** (`:788-793`): `evil.com/moonshot.ai` and `moonshot.ai.evil` must not match.
- **Edge cases & failure handling:**
  - `_dump_json` (`:384-405`) survives surrogate-escaped strings: `os.fsdecode` of a non-UTF-8 filename yields lone surrogates, which a utf-8 text handle rejects with a `UnicodeEncodeError` — a `ValueError`, which callers guarding `except OSError` never see. Serialising to a str first keeps the failure before any byte reaches the file, so no partial payload is left behind. The fallback re-serialises with `ensure_ascii=True` for that payload only.
  - `rmtree_readonly` (`:250-288`) clears the write bit on the failing path *and its parent* and retries the exact operation. Git marks loose objects read-only on Windows; Nix/deb installs copy `r--r--r--` into `0555` dirs where unlinking needs a writable *parent*. Only `PermissionError` is retried — every other failure keeps `shutil.rmtree` semantics.
  - `read_json_or_empty` reads with `utf-8-sig` (`:424`) — a Windows-editor BOM must not wipe the config.
  - `warn_if_credential_file_broadly_readable` is a no-op on non-POSIX (Windows ACLs do not map onto group/other bits).
- **Surprising:**
  - `atomic_roundtrip_yaml_save` has a `extra_content_on_create` parameter that is appended **only when the file is being created** (`:562-566`). Re-appending it on every rewrite is how the stock boilerplate replaced users' own comments.
  - `_unchanged` (`:571-573`) treats a bool↔int flip as a real change — `True == 1` in Python, but a bool↔int flip matters to a YAML reader.
  - `sanitize_no_proxy_entries` degrades bracketed/CIDR IPv6 to the bare literal because httpx 0.28.1 routes bracketed entries through its wildcard branch and cannot compile IPv6 CIDR bypasses at all. The portless literal still bypasses every port — the operator's intent superset.

### `hermes_yaml.py`
- **Purpose:** the one YAML 1.1 policy for config, manifests, and frontmatter — the module every other config-touching file imports instead of using `ruamel` or `PyYAML` directly.
- **Key abstractions:** `safe_load(stream)` (`:28`), `safe_dump(data, stream=None, ...)` (`:55`), `roundtrip_yaml()` (`:89`), `ROUNDTRIP_YAML_WIDTH` (`:86`), `_Yaml11Resolver` (`:18`).
- **Data flow:** `safe_load` → try the C (libyaml) parser → on `YAMLError` re-read with the pure Python parser. `safe_dump` → a **pure** emitter with a custom resolver. `roundtrip_yaml` → a fresh comment/quote-preserving editor.
- **Non-obvious design decisions:**
  - **The C parser is tried first, then falls back to pure** (`:32-36`): the pure parser defines what parses. Windows ARM64 has no C extension, and libyaml rejects documents the pure parser accepts (`[{url: http://h}]`).
  - **Every operation owns its parser/emitter; instances must not be shared by threads** (module docstring, `:6-7`).
  - **A custom resolver pins YAML 1.1 without emitting a `%YAML` directive** (`:18-23`), so `"off"` is quoted without littering every config with a version header.
  - **The emitter is pure** (`:67`): the C emitter ignores sequence offsets and escapes astral Unicode.
  - **`ROUNDTRIP_YAML_WIDTH = 2**31 - 1`** (`:86-88`): ruamel's emitter can change a double-quoted value when it folds a long line right after an escaped backslash (`D:\\Cent…` → `D:\\` + a bare newline); the fold reloads as a literal space and a **no-op save mutates the stored value**. Config writes must be value-preserving, so every round-trip emitter keeps scalars on one line instead of folding. The comment is emphatic that `None` does **not** disable folding on 0.18.x — only a large width does.
- **Edge cases & failure handling:** a `YAMLError` from the C parser is not an error — it triggers the pure re-read. A `YAMLError` from *both* propagates.
- **Surprising:** `safe_dump` uses `sort_base_mapping_type_on_output = sort_keys` and `indent(mapping=2, sequence=4, offset=2)` — indented block lists, not the ruamel default.

### `hermes_time.py`
- **Purpose:** the timezone-aware clock for the whole product.
- **Key abstractions:** `now()` (`:146`), `get_timezone()` (`:129`), `get_timezone_name()` (`:134`), `reset_cache()` (`:140`), `safe_strftime()` (`:52`), `_repair_surrogates()` (`:35`).
- **Data flow:** resolution order is `HERMES_TIMEZONE` env var → `timezone` in `~/.hermes/config.yaml` → server-local time. An invalid timezone logs a warning and falls back — never crashes.
- **Non-obvious design decisions:**
  - **The cache is keyed by timezone *source* identity, not by the timezone name** (`:27-30`, `:96-99`): this process can multiplex profiles by switching `HERMES_HOME`, so one unkeyed global would leak the first profile's timezone into later profile-scoped work (e.g. the desktop multiplex cron ticker persisting another profile's `next_run_at`). Entries are published atomically under `_cache_lock` as one `identity -> (name, ZoneInfo | None)` value, so racing resolvers can never publish a mixed identity/value pair.
  - **The env var is ignored when multiplexing is active** (`_env_timezone`, `:78-86`): under the multiplexed gateway the env var holds only the *default* profile's value, so every routed profile must read its own `config.yaml`.
  - **The config read prefers the shared cached effective-config loader** (`:105-113`): a direct `safe_load` of a large `config.yaml` costs ~100 ms and this ran inside the **first system prompt build**.
  - **`safe_strftime` exists because `datetime.strftime` splices `tzname()` into the format as UTF-8**, so a zone name carrying surrogates raises `UnicodeEncodeError` *before any string exists*. On that failure `%Z` is rendered from the repaired name instead.
  - **The output for valid locale text is byte-identical to `strftime`** — explicitly, because **the system prompt must stay cache-stable** (`:54-56`). Any change in the rendered timestamp changes the prompt prefix and breaks prompt caching.
- **Edge cases & failure handling:** `_repair_surrogates` (`:35-51`) recovers the bytes of a Windows ANSI-codepage zone name (`heure d'été` decoded as UTF-8 with `surrogateescape`) by re-encoding with `surrogateescape` and decoding with the ANSI code page; when that is impossible, each surrogate becomes U+FFFD. A no-op on valid text (it returns the *same object*).
- **Surprising:** the cache is cleared only by an explicit `reset_cache()` — callers must call it after an in-place config change.

### `hermes_constants_scratch.py`
- **Purpose:** idle detection and the reaping an idle scratch tree needs *before* it is deleted.
- **Key abstractions:** `prune_idle_entries(root, max_idle_hours, skip_names, log_file)` (`:353`), `subtree_touch_state(path, cutoff)` (`:107`) → `"touched" | "scan-failed" | "idle"`, `subtree_touched_since` (`:161`), `reap_processes_rooted_in(scratch_root, doomed, audit)` (`:235`), `release_git_worktrees(repos)` (`:338`), `_registered_live_pids(home)` (`:178`), `_owned_by_hermes(proc, registered)` (`:216`), `_linked_worktree_repos(entry)` (`:311`).
- **Data flow:** scan each top-level entry's subtree for a recent mtime → collect `doomed` → reap processes rooted in doomed entries → release git worktree registrations → **re-validate each entry one last time** → collect the size → delete → audit-log every removal, rescue, and signalled process.
- **Non-obvious design decisions:**
  - **The idle scan is a tri-state, and "scan-failed" is NOT activity** (`:107-158`). An unreadable entry is kept (an incomplete scan cannot establish idleness), but a failed scan is not reported as a touch. `subtree_touched_since` returns True for "touched **or** uninspectable" — the mid-prune audit uses the tri-state to tell the two apart.
  - **Symlinks are never followed** (`:161-168`): a link into the repo would make the target's activity keep the entry alive.
  - **A hardlinked file (`st_nlink > 1`) does not count as touched** (`:133-134`): its mtime is the inode's, and `git clone --local` hardlinks packs that git freshens from the source repo.
  - **The scan stops at the first recent entry** (`:161-166`): a live tree costs one hit; only a truly idle tree pays for the full walk, once, right before it is deleted.
  - **Ownership comes from two registries Hermes writes, not from a marker file a lane must remember to drop** (`:4-8`): the machine spawn ledger (`spawn-ledger.json`) and the background-process checkpoint (`processes.json`). A recorded start time that no longer matches is a *reused pid*, not ownership.
  - **A process Hermes owns is never signalled** (`:235-280`): each doomed entry it works inside is dropped from `doomed` *in place* and recorded as kept. Only the **cwd** is consulted — a process merely holding a file open inside scratch is not ours to kill, but one *living* in a directory we are about to delete has nothing left to run for. pid 1 is excluded as an ancestor (a Hermes running as a container init adopts every orphan).
  - **TERM, then a 3-second grace, then KILL** (`:34`, `:288-300`). A zombie already exited; only its parent has not collected it yet, so it is skipped.
  - **The doomed list is a candidate list, never a verdict** (`:369-401`): anything touched since selection is *rescued*, not deleted, and the audit names the reason. A re-scan that cannot read the entry is also fail-closed, but "the activity re-scan failed" is reported as such — not as an invented touch.
  - **The size is collected *before* the re-check, not after** (`:386-390`): a full-tree walk between the re-check and `rmtree` reopens the window for a write landing during that walk to be destroyed.
  - **Only an explicit `lstat` proves absence** (`:402-414`): `lexists()` swallows `OSError` from `lstat`, so an entry that stayed (rmtree left residue) but cannot be inspected would be counted and recorded as removed.
- **Edge cases & failure handling:** every `OSError` around a walk is contained; a failed scan keeps the entry. The prune log uses `%r` for paths and process names so a control character (a newline in a legal POSIX name) cannot split or forge a record (`:38-40`).
- **Surprising:** `_PruneLogHandler` (`:44-56`) tolerates a concurrent prune of the same home rotating first — its rename can land between this handler's existence check and its own rename; the rotation is then already done, so the record goes to the new file instead of being dropped with a `FileNotFoundError`.

### `hermes_constants_scratch_stuck.py`
- **Purpose:** the ledger of scratch entries the prune *cannot* delete as this user — remembered once, skipped until fixed.
- **Key abstractions:** `STUCK_STATE_NAME = ".prune_stuck.json"` (`:28`), `STUCK_LOCK_NAME` (`:29`), `RECHECK_AFTER_SECONDS = 7 * 24 * 3600` (`:35`), `_MAX_BLOCKERS = 16` (`:38`), `load_skips(root)` (`:121`), `record(root, entry, blockers, audit)` (`:172`), `rmtree_collecting_permission_errors(entry)` (`:141`), `removal_hint(entry)` (`:159`), `stuck_entries(root)` (`:198`), `tracking_supported()` (`:41`).
- **Data flow:** the prune records an undeletable entry (fingerprint + uid + blocking dirs) into a JSON file under an exclusive `flock`; later passes read the file under the same lock and skip those entries *before walking them*; a record is dropped when the entry is gone, its top directory changed, every recorded blocker became accessible, it was made by another uid, or a week elapsed.
- **Non-obvious design decisions:**
  - **The problem it solves is a log-volume problem, not a correctness problem** (`:3-14`): `rmtree(ignore_errors=True)` removes what it can, the entry stays idle, and every hourly pass re-walked the whole subtree and logged the same "could not fully remove" line again — **218 times per entry on one host**. Now the user gets ONE line naming the command that clears it, and later passes skip it before walking it.
  - **A record is fingerprinted by `(st_ino, st_mtime_ns, st_ctime_ns)`** (`:46-53`): ctime too, because `sudo chown -R`/`chmod -R` fixes the entry without touching its mtime.
  - **The recheck window is bounded at one week** (`:34-35`): even a record whose blockers still look inaccessible is re-judged weekly, so a fix this module cannot see (ACLs, a sticky bit cleared, a changed group) is never skipped forever.
  - **The state file is published via a unique temp file + `os.replace`** (`:96-113`): a reader sees old or new, never torn. A torn or hand-edited file reads as empty — the worst case is one re-walk and one line.
  - **The read-merge-write is under an exclusive `flock`** (`:115-121`): two prunes of one home (separate processes past the `.last_prune` throttle together) would otherwise overwrite each other's records from stale snapshots.
  - **Nothing is escalated or shelled out to** (`:13-15`): the hint is for the user to run. `removal_hint` (`:159-169`) offers both `sudo rm -rf` and a containerised alternative when `docker` is present.
  - **POSIX only** (`:16-18`): without `os.getuid` (Windows) a `PermissionError` is usually a transient open handle, so the prune keeps retrying there exactly as before.
- **Edge cases & failure handling:** the blocker list is capped at 16 (`:38`) — checking a subset can only re-judge early, never skip longer. `os.access` is called with `effective_ids=True` where supported (`:57-61`), so a root-run prune does not mistake a root-readable directory for a user-accessible one.
- **Surprising:** `_read` (`:88-94`) filters to dict values only, so a hand-edited file with a non-dict entry degrades to "that entry is not stuck" rather than crashing the prune.

### `hermes_startup_watchdog.py`
- **Purpose:** respawn a gateway that wedges *before* its event loop runs.
- **Key abstractions:** `arm_startup_watchdog(timeout_s=None, exit_code=SERVICE_RESTART_EXIT_CODE)` (`:424`), `disarm_startup_watchdog()` (`:462`), `report_startup_progress(expected_s, phase)` (`:494`), `kick_startup_watchdog(extra_s)` (`:485`), `StartupWatchdogHandle` (`:184`), `DEFAULT_STARTUP_WATCHDOG_TIMEOUT_S = 300.0` (`:43`), `_MIN_TIMEOUT_S = 30.0` (`:44`), `SERVICE_RESTART_EXIT_CODE = 75` (`:51`), `_MAX_CPU_EXTENSIONS = 3` (`:69`), `_MAX_LEASE_S = 900.0` (`:74`), `_CPU_PROGRESS_MIN_S = 1.0` (`:66`), `_LEDGER_JOIN_TIMEOUT_S = 5.0` (`:79`), `_FIRE_EXIT_BOUND_S = 10.0` (`:85`).
- **Data flow:** a daemon thread is armed at process entry → it polls in 5-second slices → on deadline expiry it checks (1) a phase lease, (2) CPU progress, (3) otherwise it fires → `_fire` starts an **exit escort thread first**, writes a JSON metadata record, dumps all thread stacks via `faulthandler`, marks the lifecycle ledger on a helper thread, and exits with code 75.
- **Non-obvious design decisions:**
  - **Import-lightness is a correctness property** (`:16-25`): the module is top-level and stdlib-only. Arming must precede importing `gateway` (hundreds of modules; an import-time deadlock is in scope), and at fire time the wedged main thread may hold the import lock — so the fire path does **no imports on its own thread**; the ledger write runs on a helper thread joined with a timeout. Config is env-only (`HERMES_STARTUP_WATCHDOG=0`, `HERMES_STARTUP_WATCHDOG_TIMEOUT_S`) because `config.yaml` parsing is itself in scope.
  - **Order of authority: phase lease > CPU progress > fire** (`:11-15`, `:366-404`).
    - A **phase-owned progress lease** is authoritative: it proves the *startup path itself* is alive, and works for I/O-bound phases (schema migration, corruption repair in `SessionDB.__init__`) with ~zero CPU. A phase that needs longer renews — the renewal is the liveness evidence. Per-call duration is clamped to 15 minutes so one buggy caller cannot silence the watchdog indefinitely.
    - **CPU progress is process-wide**, so it may only stretch the runway to (1+cap)×timeout (3×300 s = 20 min); anything longer must hold an explicit phase lease. An unrelated thread burning CPU must not hide a parked startup thread forever.
  - **The exit escort thread starts FIRST** (`:264-277`): everything producing forensics (logging, the dump record, `faulthandler`, the ledger) can block — the wedged main thread may hold the logging handler lock, the disk may be hung. The escort deliberately uses no log handlers, no filesystem access, no module loads, and no lock shared with application code: only a sleep, an `Event` check, and the exit seam. `os._exit` is lock-free by design.
  - **The exit code is a copy of `gateway.restart.GATEWAY_SERVICE_RESTART_EXIT_CODE`** (`:48-51`): a parity test exists, and this module must not import `gateway`.
  - **The state transition is atomic** (`:196-206`, `:411-415`): `armed → disarmed` or `armed → firing`, under a state lock, so a disarm and a fire can never both "win". A disarm landing before the fire sequence is never lost.
  - **The durable copy is written before the in-process `faulthandler` dump** (`:294-303`): a detached service can have a blocked stderr.
- **Edge cases & failure handling:** a non-numeric or non-positive timeout env var warns and uses the default (`:118-133`); a timeout below 30 s is floored (`:132`). `kick` is for blocking-with-zero-CPU waits (e.g. the respawn-storm backoff sleep) that would otherwise be indistinguishable from a parked deadlock. A **spinning** startup deadlock earns the capped CPU extensions before firing — the observed class is parked-thread deadlocks (`:15-16`).
- **Surprising:** the known limitation is stated in the module docstring rather than hidden: a spinning deadlock gets 20 minutes of grace before the respawn. MCP discovery's 120-second wait sits inside the 300-second default.

### `hermes_dir_acl.py`
- **Purpose:** directories an elevated Windows process creates must stay usable by the same user unelevated.
- **Key abstractions:** `make_user_dir(path, mode=0o777, ...)` (`:407`) — the ONE place Hermes state/lock/log directories are created; `grant_user_access(path, ...)` (`:275`); `grant_tree_user_access(root, ...)` (`:341`); `process_elevation(pid=None)` (`:75`) — the ONE elevation probe; `process_is_elevated()` (`:112`); `is_reparse_point(path)` (`:59`); `ReparsePointRefused(OSError)` (`:55`); `unusable_dir_remedy(path)` (`:425`); `iter_tree_without_reparse_points(root, skipped)` (`:305`).
- **Data flow:** `make_user_dir` → (unelevated or non-Windows: plain `Path.mkdir`) → (elevated: `mkdir`, then grant the token's user an inheriting full-control ACE on every directory this call created, plus the existing leaf once per verified object identity) → repair children of an existing leaf.
- **Non-obvious design decisions:**
  - **Since CPython 3.13, `os.mkdir(path, 0o700)` on Windows applies a protected DACL of exactly SYSTEM, Administrators, and OWNER RIGHTS** (`:4-11`). An elevated process's default owner is `BUILTIN\Administrators`, so OWNER RIGHTS resolves to Administrators too, and the user's own *non-elevated* token (where Administrators is deny-only) gets `WinError 5` on the directory and on everything created inside it. A plain `mkdir` inherits its parent's ACL instead, which under `%LOCALAPPDATA%` names the user — so the `mode=0o700` sites are exactly the ones that strand the user.
  - **The grant never follows a junction, symlink, or other reparse point** (`:13-21`): same-user medium-integrity code can swap any entry under the home for a junction to e.g. `C:\Program Files\X`, and a grant that followed it would hand the user full control of the target across the UAC boundary. The path is lstat-checked first, and the pywin32 grant opens it with `FILE_FLAG_OPEN_REPARSE_POINT` and re-checks the handle, so a swap *after* the check is not followed either. The icacls fallback passes `/L`.
  - **The grant is written on the HANDLE, never the name** (`:135-138`): `GetFileSecurity`/`SetFileSecurity` resolve a junction or symlink to its target, so a swap after the lstat check would still redirect the grant.
  - **The pywin32 write does not propagate** (`SetKernelObjectSecurity`), so a written dir's existing children are owed; the icacls fallback *does* propagate and therefore refuses a dir holding a link.
  - **The DACL is never grown on a repeat call** (`:163-169`): an existing inheriting full-control ACE for the user SID short-circuits the write.
  - **A hardlinked file is refused** (`:253-257`, `:157-160`): its other names may be outside the home, and the inherited ACE would land on them.
  - **The recursive walk is a hand-written stack, not `os.walk`** (`:305-336`): `os.walk` follows directory junctions (`os.path.islink` is False for one). Unreadable directories are skipped silently, like `icacls /C`.
  - **Grants are memoised by object identity, not by name** (`:392-405`): `(path, st_dev, st_ino)`. Media release deletes a digest dir and the next capture recreates it at the same path — a name-keyed set would skip the new object's grant.
- **Edge cases & failure handling:** `make_user_dir` on an existing leaf *without* `exist_ok` still raises `FileExistsError` (the `Path.mkdir` contract) — but the directory is *repaired* first, so the caller's error is never the reason a non-elevated Hermes stays locked out. A `ReparsePointRefused` produces one warning naming the path, and the remedy line (`icacls "<path>" /reset /t` on Windows, `sudo chown -R` elsewhere).
- **Surprising:** `make_user_dir`'s default is `mode=0o777` — it matches `Path.mkdir`'s signature exactly, and the caller chooses the mode. Off Windows and unelevated, it is *exactly* `Path.mkdir` and nothing else.

### `registration_lifecycle.py`
- **Purpose:** ownership leases for replaceable runtime registrations.
- **Key abstractions:** `same_registration(left, right)` (`:16`) — identity only, element-wise for tuples; `ReplacementLease` (`:26`); `ReplacementCoordinator` (`:40`) with `transaction()` (`:47`), `acquire(...)` (`:53`), `dispose(lease)` (`:63`); the module singleton `replacement_coordinator` (`:95`).
- **Data flow:** a caller acquires a lease for a slot, naming the *current* and *previous* registration and a `restore` callable; on dispose, the coordinator restores the nearest still-live predecessor.
- **Non-obvious design decisions:**

  - **A `predecessor` chain is walked backwards past dead generations** to find the nearest still-live one (`:80-84`).
- **Edge cases & failure handling:** the whole coordinator is under an `RLock`; `dispose` on an already-inactive lease is a no-op (`:67-68`).
- **Surprising:** this 96-line file is the cleanest "replaceable registration" model in the shard, and it exists because the naive version broke. The docstring is three lines long and the class is 60.

### `trajectory_compressor.py`
- **Purpose:** post-process agent trajectories into a token budget — the standalone research tool that mirrors the in-product context compressor.
- **Key abstractions:** `CompressionConfig` (`:112`) with `from_yaml` (`:151`); `TrajectoryMetrics` (`:170`); `AggregateMetrics` (`:201`); `TrajectoryCompressor` (`:270`) with `_find_protected_indices` (`:361`), `_snap_boundary` (`:376`), `_plan_compression` (`:494`), `_assemble_compressed` (`:535`), `compress_trajectory` (`:555`), `compress_trajectory_async` (`:564`), `_generate_summary` (`:456`), `_finish_summary` (`:436`); `_effective_temperature_for_model` (`:65`); `_response_finish_reason` (`:45`); `_YAML_SECTIONS` (`:97`).
- **Data flow:** a JSONL of trajectories in → tokenise each turn → find the protected head/tail → compute the overage → accumulate middle turns until the savings cover the overage *plus* the summary → snap both boundaries off tool turns → summarise → replace the region with one `human` summary turn → write JSONL + a metrics file.
- **Non-obvious design decisions:**
  - **The head and tail are protected; only the middle is summarised, and only as much as needed** (`:2-5`). The protected head is the *first* occurrence of each role (`system`, `human`, `gpt`, `tool`), not the first N turns.
  - **A boundary is never allowed to split a `<tool_call>`/`<tool_response>` pair** (`:376-397`). A `tool` turn always directly follows the `gpt` turn it answers, so a boundary landing *on* a tool turn cuts the pair; only the end of the trajectory or a non-`tool` turn is clean. Forward is preferred (folds an orphaned `tool` turn into the region that holds its `gpt` turn); backward only when nothing clean lies ahead.
  - **The region must be large enough to beat the summary that replaces it** (`:512-514`): a region no larger than the summary cannot shrink the trajectory.
  - **A `length` finish reason is a failure, not a truncated summary** (`:436-443`): storing a truncated summary silently corrupts the trajectory's memory, so it raises and the retry/backoff loop handles it.
  - **The summary prompt asks for a neutral perspective** — what the assistant did and learned (`:408-427`), targeting a token count, and requiring a `[CONTEXT SUMMARY]:` prefix that `_finish_summary` enforces exactly once.
  - **The summarisation input is elided in the middle** (`elide_middle(value, 1500, 500)`, `:403`): each turn over 3000 chars is head+tail truncated before it goes into the prompt.
  - **The summary notice is appended to the *system* turn** (`:539-542`), not the summary turn.
  - **`_effective_temperature_for_model` returns `None` to mean "omit the kwarg entirely"** (`:65-79`): some model contracts (Kimi) manage temperature server-side. The dict form `{"enabled": true, "effort": "<level>"}` in `hermes_constants.py` is the same pattern — a "no value" that must not be coerced to a default.
  - **`_detect_provider` matches hostnames, not substrings** (`:335-341`), using `base_url_host_matches` from `utils.py` — the same helper the trajectory runner uses, so the two agree.
- **Edge cases & failure handling:** a failed summary falls back to an explicit, visible `_SUMMARY_FALLBACK` string (`:254`) rather than silently dropping the region. `max_retries: 3` with jittered backoff (`:449-454`). `per_trajectory_timeout: 300` seconds per trajectory (`:136`); a timeout **drops the entry** and is counted in the metrics (`:597-607`) — a deliberate choice, since a half-compressed trajectory is worse than a missing one. On any other error the **original** entry is kept (`:608-614`).
- **Surprising:** `AggregateMetrics.to_dict` inserts `"compression_region"` at a *specific* position in the dict to preserve a historical key order (`:189-193`) — the metrics file is consumed by something that cares about the shape.

### `cli.py`
- **Purpose:** the interactive terminal interface — the `HermesCLI` REPL, the slash-command dispatcher, the shutdown/cleanup sequence, and the worktree-isolation block.
- **Key abstractions:**
  - `HermesCLI` (`:880`) — a **16-way mixin composition** (`CLIInitMixin`, `CLITuiRuntimeMixin`, `CLIProcessNotificationsMixin`, `CLIAgentSetupMixin`, `CLICommandsMixin`, `CLIBillingMixin`, `CLITuiMixin`, `CLIStatusBarMixin`, `CLIVoiceMixin`, `CLIModelSwitchMixin`, `CLISessionMixin`, `CLIStreamMixin`, `CLIModalMixin`, `CLITerminalMixin`, `CLIInfoMixin`, `CLILoopsMixin`, `CLIChatTurnMixin`).
  - `_SLASH_DISPATCH` (`:1126`) — the canonical-command → `(method name, pass cmd_original?)` table; an absent command resolves by convention to `_handle_<name>_command(cmd)`.
  - `process_command(command, *, redispatch=False)` (`:1161`) — the single dispatch point.
  - `_process_unregistered_slash` (`:1211`) — the five-level precedence chain for an unknown slash command.
  - `_expand_slash_prefix` (`:1351`) — unique-shortest-match prefix expansion, deliberately agreeing with tab-completion.
  - `_run_cleanup(*, notify_session_finalize=True)` (`:471`) — the once-only cleanup sequence.
  - `_lazy_shim(module, name, alias=None)` (`:245`) — import-on-first-call, so `cli.<name>` stays the patchable seam in tests while heavy imports stay off startup.
  - `format_duration_compact` (`:257`) / `format_token_count_compact` (`:281`) — compact human-readable durations and token counts.
  - `_reverse_alias_for_display(model_name)` (`:268`) — the shortest configured alias for a model, from a process-lifetime cache.
  - `main(...)` (`:1424`) — the `fire`-driven entry point.
  - `_ChatTurn` (`:831`) — the per-turn dataclass shared between the `chat()` phases and the agent worker thread.
- **Data flow:** `main()` → configure stdio → set `HERMES_INTERACTIVE` → claim the active session → build the worktree (optionally, in the background, overlapping tool prewarm) → `_build_cli_from_args` (resolves toolsets, starts the background skills preload) → join the worktree → `cli.run()` or `_run_single_query_mode`. Inside `run()`: build the prompt_toolkit application, install the key bindings, patch the renderer's `_output_screen_diff` (to stop prompt_toolkit scrolling chrome into scrollback on a column shrink), start the spinner/loop/wake threads, `app.run()`, then the exit summary and the relaunch for `/update`.
- **Non-obvious design decisions:**
  - **The file is a facade in practice**: it imports and re-exports ~300 names from 20+ `hermes_cli/cli_*_mixin.py` siblings, deliberately, so `cli.<name>` remains the seam every test patches (the `AGENTS.md` "facade + siblings" rule). A reader looking for behaviour in `cli.py` will find very little.
  - **The `meta_path` finder that neuters `AsyncHttpxClientWrapper.__del__`** (`:316-360`): the `__del__` schedules `aclose()` on the running loop (prompt_toolkit's, during idle), closing transports bound to dead worker loops ("Event loop is closed" / "Press ENTER to continue..."). The finder patches `openai._base_client` at first import — eager import costs ~166 ms/30 MB cold, and the patch is guaranteed to land before instantiation. It is disarmed after the first match and removes itself.
  - **Cleanup resets the terminal input modes FIRST** (`:498-502`): "teardown below can take seconds and a later step raising must not skip the reset." The reset writes to stdout when it is the terminal, else `/dev/tty` (the TUI may have run with stdout redirected), and it is gated on `_tui_input_modes_active` so a non-TUI one-shot run never emits codes for modes it never enabled.
  - **Every cleanup step is individually `suppress`ed** (`:504-506`): the steps come from a `_CLEANUP_STEPS` table of `(step name, swallow)` pairs, so one failing step cannot abort the rest.
  - **A handed-off session must NOT be finalised by the CLI** (`:415-420`): "/handoff sessions belong to the gateway… doing this sets `end_reason` on a row the gateway just reopened and is actively writing to (#88234). The race made the handoff leg vanish from session history and broke session_search recall."
  - **A worktree that is dirty or has unpushed commits is kept, and the message does not hint at `--force`** (`:441-455`): "Uncommitted work: say so, and don't hint at `remove --force`, which would destroy it." A shallow clone's unpushed verdict is explicitly called unreliable.
  - **The tool prewarm overlaps the worktree setup** (`:1409-1416`): both are I/O-bound and the banner hits a warm cache (~0.4 s). The worktree is joined with a 120 s timeout.
  - **The skills preload runs in a daemon thread** (`:1467-1481`): `skill_view` walks the full skills tree per skill (~0.5 s for a large library) and the result is only consumed at agent init, not by the banner. `finalize_preloaded_skills()` joins the thread before any consumer reads `cli.system_prompt`.
  - **A missing skill warns; only a *fully* missing set fails loudly** (`:1005-1012`): "a typo'd name must not crash a kanban worker."
  - **The prompt-toolkit renderer is patched at runtime** (`:1290-1308`): prompt_toolkit's renderer explicitly moves the cursor to the bottom of the canvas after painting, which scrolls chrome into scrollback on every render; when the terminal column-shrinks the emulator reflows the rows into duplicates. The fix inflates `previous_screen.height` so the branch does not fire.
  - **The slash dispatcher records a metric only for user-typed commands** (`:1170-1173`), and `redispatch=True` marks an internal re-entry (quick-command alias, prefix expansion) so the user's command is counted once.
  - **A bare `/resume` prompt is one-shot** (`:1176-1183`): any other command disarms it, so a later number is not swallowed as a stale selection.
  - **`_looks_like_slash_command`** (`:722-726`): "`/help` yes, `/Users/x/file.md` no: a command's first word has no further `/`."
- **Edge cases & failure handling:**
  - `Ctrl+C`/SIGTERM arm a *separate* backstop the moment the signal arrives (`:437-465`): the graceful unwind has wedge points **before** `_run_cleanup` arms its own watchdog (the main thread parked in a syscall, a prompt_toolkit teardown that never returns). The leash is 2× the cleanup timeout, so a progressing cleanup is never cut short. It is never armed at startup — "the timer exits unconditionally."
  - A `KeyError`/`OSError` from the stdin selector is distinguished from a real crash (`:1338-1352`): `errno.EIO` is suppressed; `EINVAL`/`EBADF` or "is not registered" prints a "stdin unusable" message; anything else re-raises.
  - `run_in_terminal` may return a coroutine/Future (prompt_toolkit ≥ 3.0) — the code explicitly avoids the bare call, the bare `_pt_print` fallback, and the double-print, because "run_in_terminal already invoked the lambda in that case."
  - The exit summary is printed after the screen is cleared, and the plugin `on_session_finalize` text is queued into it (`:507-513`).
- **Surprising:**
  - `os.environ["HERMES_QUIET"] = "1"` is set at import (`:37`) — before the modules that would otherwise print startup chatter are imported.
  - The `hermes_bootstrap` import is wrapped in a `try/except ModuleNotFoundError` that re-raises unless the missing module *is* `hermes_bootstrap` (`:7-13`): "the bootstrap exists but cannot load: skipping it would skip PM activation."
  - `show_config` (`:1053`) reads the *live agent's* API key rather than `self.api_key` (which the constructor seeds from the env before provider resolution, so on a non-OpenAI provider it can be a different vendor's key) and displays a **label** for a callable bearer provider rather than invoking it (invoking would mint a token just to mask it).
  - `_expand_slash_prefix` breaks an ambiguous match by *shortest* name — `/qui` resolves to `/quit` (5 chars) over `/quint-pipeline` (15) — and on a genuine ambiguity prints "did you mean" with the candidates sorted.

## 2. Ideas worth stealing

1. **A startup-liveness watchdog with phase-owned progress leases.** `hermes_startup_watchdog.py:424` arms a daemon thread at process entry; a startup phase that will legitimately take 3 minutes calls `report_startup_progress(180, "state.db migration")` (`:494`) and the watchdog honours the lease instead of killing a slow-but-alive process. The lease is the *authoritative* signal (it proves the startup path itself is alive, even with zero CPU); process-wide CPU progress is only a weaker fallback, capped at 3 extensions (`:69`). The exit path is bounded twice over: an **exit escort thread starts first** (`:270-277`) and hard-exits after 10 s so that a wedged logger or a hung disk can never prevent the respawn. *Why it transfers*: August Trading runs an Electron main process, a Vite dev server, and a worker; a hung boot is exactly the failure a user reports as "the app is broken." The lease mechanism also generalises to long background jobs (a backtest, a market-data sync): "this phase owns the next N seconds" is a better liveness contract than "the CPU counter moved."
2. **Fail-loud-at-integration-boundaries, stated as a doctrine.** `CONTRIBUTING.md` (fail-loud section): "reject it where it is read and name the problem: a clear error at startup or at the write path, never a silent no-op that turns the confusion into a debugging session later… there is intentionally no shared `fail_loud` helper, because one call-site shape does not fit all — the rule is about the behavior the user sees, not the function you call." *Why it transfers*: August Trading already has a "fail loud" instinct in places but no stated rule; a one-paragraph doctrine in `AGENTS.md` would make the "silently swallow a bad provider" class of bug a reviewable violation rather than a matter of taste. *CONVERGENT* — `pi` and `deepseek-harness` both express a similar "never swallow at the boundary" rule in their own contributor docs.
3. **A footprint ladder that decides where a new capability lives.** `AGENTS.md`: extend existing code → CLI command + skill → service-gated tool → plugin → MCP server in the catalog → new core tool, with the stated reason: "the core is a narrow waist… Every model tool is sent on every API call, so the bar for a new *core* tool is high." *Why it transfers*: August Trading's tool surface (`services/tools/toolForge`) is already the wide waist; the ladder gives a principled answer to "should this be a tool, a skill, a component, or a constant?" — and, like Hermes, it keeps the *per-request* tool payload small. *CONVERGENT* — the "capability at the edges" shape appears in all three reference repos.
4. **Soft warnings for interactive surfaces, hard stops for unattended ones.** `cli-config.yaml.example:644-659`: the same loop detector (`exact_failure` / `same_tool_failure` / `idempotent_no_progress`) warns twice by default everywhere, but hard-stops after 5/8/5 only in unattended gateway/cron runs, because "nobody is present to interrupt a model that ignores loop warnings." *Why it transfers*: August Trading's automated analyses and the in-app chat have the same asymmetry. A trader watching a screen wants a warning and a chance to intervene; a nightly run wants a deterministic stop and a recorded failure.
5. **Compression that fails CLOSED unless a durable checkpoint exists.** `cli-config.yaml.example:693` (`checkpoint_required`): "the compaction attempt errors with `BLOCKED_MISSING_PREREQUISITE` and the uncompressed transcript is preserved for a later retry. The gate binds to every compaction authority." *Why it transfers*: this is the *exact* shape of the rule August Trading needs for its notebook and journal. Compacting a session must never destroy the record of a trade decision that has not been written anywhere else. The "binds to every compaction authority" clause matters — Hermes had to suppress three different compaction paths to make the gate real.
6. **A prompt-cache hysteresis gate.** `cli-config.yaml.example:845` (`proactive_prune_min_reclaim_tokens: 4096`): a deterministic, no-LLM prune of old tool payloads is allowed to break the provider's cached prefix only if it reclaims at least 4096 tokens, so cache breaks are "episodic (like a compression boundary) instead of per-turn." *Why it transfers*: August Trading re-sends its conversation history on every turn. The economics of a cached prefix are the same as Hermes's; this is a one-setting way to keep them.
7. **The "real user messages" tail guarantee.** `cli-config.yaml.example:751` (`min_tail_user_messages`): "blank platform echoes, compaction handoffs, and synthetic continuation rows never count toward N. **The tail can exceed the token budget when this pulls the cut back; the guarantee wins over the budget by design.**" *Why it transfers*: this is the difference between a compaction algorithm that counts messages and one that counts *meaningful* turns — and it says out loud which one wins when they conflict.
8. **A scratch/temp directory with an idle-retention rule and a "rescue before delete" last check.** `hermes_constants_scratch.py:353` + `:369-401`: the doomed list is a *candidate* list; anything touched since selection is rescued, and the size is collected *before* the re-check so the walk cannot reopen the deletion window. *Why it transfers*: August Trading's backtest artefacts, exported CSVs, and cached candles are the same category. A naive "delete everything older than N days" will eventually eat a run in progress.
9. **A "stuck" ledger that remembers what it cannot fix, so it stops complaining.** `hermes_constants_scratch_stuck.py`: the same undeletable entry was logged **218 times per entry on one host**; now it is fingerprinted, recorded once under an `flock`, skipped before walking, and re-judged weekly. *Why it transfers*: this is a directly reusable pattern for August's "a provider key is invalid" or "the backup directory is read-only" cases — a condition that will not fix itself should produce one actionable line, not one per run.
10. **Atomic writes that never transit through a permissive mode.** `utils.py:290-340`: fchmod the mode onto the temp fd *before* the rename; a new target gets the mode `open(path, "w")` would have given it; a symlink target is resolved first; EXDEV falls back to copy; Windows rename contention gets a bounded jittered retry and then an in-place rewrite that preserves the target's ACL. *Why it transfers*: the trade log, the backup, and the export all need this, and the ACL-preserving in-place rewrite is the detail most implementations get wrong.
11. **Round-trip YAML editing that preserves comments, quotes, and order, with explicit absence.** `utils.py:540` + the YAML 1.1 ambiguous-word force-quoting at `:520-530` (a bare `off` in a list reads back as `False`). *Why it transfers*: August's `config.yaml` is user-edited; a settings write that strips comments destroys the file's documentation value, and the `off`/`yes`/`no` trap is a real, silent, data-changing bug.
12. **A session-tag injected by the global `LogRecord` factory, not by a filter.** `hermes_logging.py:263`: a filter would miss records that propagate from third-party loggers; a factory sees every record in the process. The record also carries the *emitting task's* home, because the queue listener formats later, on a thread where the scope is gone. *Why it transfers*: August Trading's agent runs in multiple windows/workers; a per-request tag on every log line is the cheapest possible correlation id.
13. **A replacement-registration coordinator that models generations, not identities.** `registration_lifecycle.py:40`: the same provider singleton may be registered again after an older generation was unloaded, so a CAS on value identity cannot tell them apart — only the latest live generation may mutate the slot, and dispose restores the nearest still-live predecessor. *Why it transfers*: this is the correct model for "the user swapped the provider config while a turn was in flight."
14. **Model-name matching that tolerates spelling.** `hermes_constants.py:1107-1180`: dots↔dashes interchangeable, provider/aggregator prefixes stripped *and* added, and a reverse lookup so a key like `ollama-local/qwen3.6:27b` still matches a bare `qwen3.6:27b`. *Why it transfers*: August's provider/model registry has the same problem, and the reverse-lookup case is the one that actually bites (a fallback swap feeds the bare slug).
15. **A refusal to mix two contracts on one registry — spelled out in the docstring.** `hermes_constants.py:1476-1492`: the write-side scope key (`None` = process-global) and the read-side scope key (`None` = the active home) are different, and unifying them "hides every scoped registration — the exact bug fixed after e66a627aa5." *Why it transfers*: August's `services/infrastructure` and `services/tools` have scope notions; the lesson is to write the two contracts down at the function, not to unify them.
16. **A dependency-release-age quarantine, with a documented expiry per exception.** `.npmrc` (`min-release-age=14` + per-package exclusions each carrying the reason and the removal condition) and `pyproject.toml` (`exclude-newer = "3 days"`, with the single exemption that a CA-trust store must be able to ship the day it revokes a root). *Why it transfers*: a two-line npm setting plus a CI check gives most of the supply-chain protection of a full audit, at near-zero cost.
17. **A dependency-pinning policy with a *scope* rule, not just a version rule.** `pyproject.toml`: exact `==X.Y.Z` for core deps, `>=floor,<next_major` for everything else, and "only packages used by EVERY hermes session belong here. Anything that's provider-specific belongs in an extra. Smaller `dependencies` = smaller blast radius for the next supply-chain attack." *Why it transfers*: August's `package.json` is not exact-pinned; the *scope* rule is the more valuable half.
18. **An install-script allowlist.** `package.json` `allowScripts` — a short, explicit list of the seven packages permitted to run install scripts; everything else is denied by default. *Why it transfers*: directly applicable to August's Electron/Electron-builder dependency tree.
19. **A lint gate that fails on the *class* of bug, with a frozen legacy baseline.** `pyproject.toml` `[tool.ruff.lint]`: `PLW1514` (explicit encoding) and `ASYNC210/220/221/251` (no blocking calls in `async def`), each selected with the incident that motivated it; the pre-existing violations are listed file by file with "do NOT add new files here." *Why it transfers*: this is the shape of a ratchet that actually gets adopted — a new rule with a named incident, a frozen baseline, and no new entries.
20. **A code-health ratchet whose switch is read from `main`, not from the branch.** `CONTRIBUTING.md`: "it is always read from main… never from the branch under test, so a one-line commit to main reaches every open PR on its next CI run… and a PR cannot relax its own check." *Why it transfers*: this is the one detail that makes a ratchet enforceable rather than advisory.
21. **A "not from the name alone" rule for every destructive operation.** `hermes_constants_scratch.py:402-414`: only an explicit `lstat` proves absence, because `lexists()` swallows `OSError` from `lstat` and would report a still-present, uninspectable entry as "removed" — "the same invented reason the audit exists to prevent." *Why it transfers*: the audit-log discipline (never record a reason you did not observe) applies to any deletion report in August's trade history.
22. **Ask the model to name the tool, not the shell command.** `CONTRIBUTING.md`'s skill-authoring rules include an explicit do-not-name table (`grep`→`search_files`, `cat`→`read_file`, `sed`→`patch`, `curl`→`web_extract`, `echo > file`→`write_file`) with the reason: it keeps the transcript and the tool-availability story coherent, and it means a skill works the same when the shell is unavailable. *Why it transfers*: August's skills/agent prompts should name `readFile`/`writeFile`/etc., not `cat`/`tee`.
23. **A voice spec as a file.** `SOUL.md`, 667 bytes: match length to weight; no filler; no restating the request; no narrating tool calls; plain claims over adjectives; "when unsure, say so plainly"; "Agree because it's right, not because the user said it"; "Depth is earned." *Why it transfers*: August Trading's answer voice is currently implicit in prompts. This is a *five-line* file that would make the register consistent across the chart panel, the dock, and the CLI.
24. **Two logout paths with different `HOME` semantics.** `hermes_constants.py:748-800`: `get_real_home` (the OS account's home, never the profile's) vs `get_subprocess_home` (per `TERMINAL_HOME_MODE`: `auto`/`real`/`profile`). *Why it transfers*: August's Electron main and its renderer have different filesystem reach; the "real HOME vs profile HOME" distinction is the same problem, and the fallback chain (`HERMES_REAL_HOME` → `HOME` → passwd → `USERPROFILE` → `HOMEDRIVE`+`HOMEPATH` → `~` → tempdir) is a good template.
25. **A "catch-up" switch for scheduled work after downtime.** `cli-config.yaml.example:428`: `cron.catch_up_missed: true` — "False skips past-grace recurring misses after planned downtime." *Why it transfers*: August's scheduled analyses (the ones that check a position against a target) need to decide explicitly what happens after the laptop was asleep — replay the missed run, or skip it. Making it a config key rather than an implicit behaviour is the point.

## 3. Trading-specific findings

*Scope note:* this shard is the repository root of a general-purpose agent, not a trading product. The six questions are answered only where the root actually contains the answer; where the mechanism lives in a sibling directory (`cron/`, `agent/`, `tools/`, `gateway/`, `hermes_cli/`, `pm/`), this shard says so and points at the *contract* the root defines.

1. **Long-lived monitoring & scheduled work — partially in this shard, via the contract layer.** The scheduler itself (`cron/jobs.py`, `cron/scheduler.py`) is in another shard, but the root pins three things about it. (a) **Catch-up after downtime is a config key, not an accident**: `cli-config.yaml.example:428` `cron.catch_up_missed: true` — "False skips past-grace recurring misses after planned downtime." (b) **An interrupted cron run is a permanent failure** (`:1253-1259`): "A cron run has no such safety net — it is recorded in `jobs.json` as a permanent failure, nobody is waiting on it, and a recurring job simply skips to its next schedule." That is why cron gets its own `cron_drain_timeout: 30` while chat turns get `restart_drain_timeout: 0` — the drain budget is set by *who is waiting*, not by the cost of the work. (c) **The unattended surface is where hard stops live**: `tool_loop_guardrails.non_interactive_hard_stop_enabled: true` (`:647`). The reliability machinery that *is* in this shard is the **startup watchdog** (`hermes_startup_watchdog.py`) — a missed-run/restart story for the *process*, with a phase lease as the liveness contract and a bounded, escort-guarded exit so the supervisor can respawn. For August Trading the direct transfer is: a scheduled analysis needs the same three-part contract — a lease ("this run owns the next N seconds"), an idempotency key (the run id, so a catch-up does not double-count), and a distinct exit code for "wedged" versus "failed", so a supervisor can tell a crash from a bad result.
2. **Human-in-the-loop approval — the policy layer is here; the gate is in another shard.** `tools/approval.py` is not in this shard, but `SECURITY.md` §2.4 defines what the approval gate *is* and is not: "The approval gate detects common destructive shell patterns and prompts the operator before execution. Shell is Turing-complete; a denylist over shell strings is structurally incomplete. The gate catches cooperative-mode mistakes, not adversarial output." Three transferable decisions: (i) **fail-closed on transport failure** — `cli-config.yaml.example:586` `transport_fallback: deny` ("Set builtin to opt into fallback on transport failure"); (ii) **some files always ask, even under the blanket override** — `:591` `protected_instruction_files: true`: writes to `AGENTS.md`/`CLAUDE.md`/`SOUL.md` "always ask for human approval, even under `--yolo`, and are refused when nobody can answer" — the direct analogue in August Trading is *any file that steers the agent's own future behaviour* (the learned-rules store, the prompt overlay, the tool allowlist) and, in a trading app, any file that changes a live position or a risk limit; (iii) **an unattended approver must resolve, and the resolution is audited** — `:1852` `subagent_auto_approve`: "The parent TUI owns stdin, so blocking would deadlock; non-interactive resolution is required. Both choices emit a `logger.warning` audit line." The audit trail that survives a decision is *the log line plus the decision itself*, not a separate database. August Trading's `services/approvals` and its `docs/plan` ledger would benefit from the same shape: a decision record that names who/what resolved it, under what policy, and what it was allowed to do.
3. **Post-mortem / reflection loops — the *shape* is here, the implementation is in another shard.** `cli-config.yaml.example:1179` `skills.creation_nudge_interval: 15` ("Every N tool-calling iterations, remind the model to consider saving a skill") and `:1038` `memory.nudge_interval: 10` ("Nudge every 10 user turns (0 = disabled)"), plus `:1007` `background_review` — "Post-turn memory/skill self-improvement review fork. Runs after a turn when the nudge intervals fire; writes skills/memories in a daemon thread." The mechanism is **nudge-based, not trigger-based**: a periodic reminder to consider persisting, not an automatic rule-extraction pipeline. The anti-accumulation control is a **character budget, not a rule-count budget**: `:1033` `memory_char_limit: 2200` (~800 tokens) and `:1035` `user_char_limit: 1375` (~500 tokens) — "The agent manages pruning — when at the limit, it must consolidate or replace entries." That is the single most transferable idea for August's learning loop: bound the *size* of the persisted knowledge and force consolidation, rather than counting rules and hoping. The same idea appears in Hermes' memory store as "a character limit, not a rule limit, because the model can consolidate two entries into one." A trading analogue would be a bounded "post-mortem card" store — a fixed number of characters of accumulated lessons — where adding a new lesson forces merging an old one, and where the *value* rules (risk limits, position sizing) are kept in a separate, non-consolidatable store.
4. **Multi-agent — the cost model and the depth cap are here; the runtime is elsewhere.** `cli-config.yaml.example:1844-1878`: `max_spawn_depth: 1` (flat by default; a worker spawning workers requires `role="orchestrator"` on the intermediate agent and an explicit `orchestrator_enabled` kill switch); `max_concurrent_children: 10` with "WARNING: values above 10 multiply API cost linearly"; and the cost tip — "keep the parent on a frontier model and pin `delegation.model` to an inexpensive one — children carry the vast majority of tokens, so this is where spend is cut while planning quality stays with the frontier parent." The fallback chain is also separated: pinned children use a declared child chain, unpinned children inherit. The transferable principle: **the parent's model is the quality model; the children's model is the cost model**, and the delegation depth is capped at one by default because each level multiplies both cost and error propagation. For August Trading, a desk of parallel subagents (one per analysis module) should have its depth capped at one, its parallelism budgeted, and its children's model explicitly pinned to a cheap tier.
5. **Structured logs the model can query — the storage decision is visible from the root.** The root does not contain the session database, but it pins the storage shape: SQLite with **FTS5** is canonical for sessions (`CONTRIBUTING.md`: "All conversations are stored in SQLite (`hermes_state.py`) with full-text search… Automatic per-session JSON snapshots have been removed… `state.db` is canonical"), the Docker build **asserts at build time** that FTS5 with the trigram tokenizer works (`Dockerfile`), the schema choice is documented as a WAL-vs-DELETE decision with a "will not live-downgrade a database already open in WAL" rule (`cli-config.yaml.example:20-38`), and the *queryable side* is `session_search` ("Search past conversations with FTS5 + anchored windows"). Alongside it sits a **file-per-record** layer for the operational log: `logs/agent.log`, `errors.log`, `gateway.log`, `gui.log`, `logs/tool_calls.log`, `logs/scratch-prune.log`, plus a JSONL trajectory per session (`logs/session_YYYYMMDD_HHMMSS_UUID.json`). The lesson for August's trade log: **one SQLite file with FTS5 for the searchable record, plus plain rotating files for the operational breadcrumb** — no second database, and the rotate-on-size discipline (`utils.py` `atomic_replace`) applied to the trade-log writer.
6. **Staying simple as features accumulate — the shard contains the actual mechanism.** Four mechanisms, all in this shard: (i) the **footprint ladder** (`AGENTS.md`) with the narrow-waist invariant; (ii) the **closed catalogue** — new memory providers and third-party product integrations "do not land in this repo", stated as "a coupling-and-maintenance decision", not a quality bar (`CONTRIBUTING.md`); (iii) the **skill authoring standard** (`description` ≤ 60 chars, a fixed section order, a "use the native tool, not the shell command" table, a required test file) — a *format* constraint that makes a growing skill library reviewable; and (iv) the **code-health ratchet** with the "move a function into a sibling to offset growth" mechanic, so growth has to be *paid for* rather than merely discouraged. The one that transfers most directly to August Trading is (i)+(ii) combined: a written ladder that says "most new capability should arrive as a UI affordance plus a service, not as a new agent tool", plus an explicit "this does not live in the core tree" category for anything that would otherwise become the core's problem forever.

## 4. Non-obvious decisions and gotchas

1. **The system prompt must stay byte-stable.** `hermes_time.py:54-56` — `safe_strftime` exists because `datetime.strftime` splices `tzname()` into the format as UTF-8 and raises `UnicodeEncodeError` on a Windows ANSI-codepage zone name. The fallback renders `%Z` from the repaired name, and the docstring is explicit that "Output for valid locale text is byte-identical to `strftime` (**the system prompt must stay cache-stable**)". A reader would assume the fallback could differ slightly; it may not.
2. **`get_hermes_home()` is a `ContextVar`, not an env var.** `hermes_constants.py:36-38` — "Deliberately does not mutate `os.environ` (shared by every thread in the process)." But `pin_process_hermes_home` *is* process-global on purpose (`:281-287`), because it names the process's own identity, not a per-task value. Two different scopes, one module, easy to confuse.
3. **The two scope contracts on one registry.** `hermes_constants.py:1476-1492` — write-side `None` means "process-global" and must stay `None`; read-side `None` means "the active home's scope". Using the wrong one "hides every scoped registration — the exact bug fixed after e66a627aa5." The normalisation is not idempotent between the two sides.
4. **A profile is a directory with an identity marker, and an empty `.env` is not enough.** `hermes_constants.py:383-409` — listing such a shell is harmless; counting it as a second tenant "flips the whole host's credential reads fail-closed at the next boot."
5. **The account's home comes from the password database, never `$HOME`.** `hermes_constants.py:79-88` — a harness that repoints `HOME` (root under `sudo` has uid 0 too) must not redirect the real home.
6. **The profile-fallback warning latches on the first *check*, not on the warning branch.** `hermes_constants.py:181-187` — the old code re-ran a stat+read on every `get_hermes_home()` call whenever no profile was active.
7. **Windows `os.mkdir(path, 0o700)` breaks the user.** `hermes_dir_acl.py:4-11` — since CPython 3.13 it applies a protected DACL of exactly SYSTEM/Administrators/OWNER RIGHTS; an elevated process's owner *is* Administrators, so the user's own unelevated token gets `WinError 5` on the directory and everything inside it.
8. **An elevated ACL grant never follows a link.** `hermes_dir_acl.py:13-21` — the lstat check, the `FILE_FLAG_OPEN_REPARSE_POINT` open, the handle re-check, and the `/L` flag on the icacls fallback all exist for this one reason: "a grant that followed it would hand the user full control of the target across the UAC boundary."
9. **`os.kill(pid, 0)` is a silent killer on Windows.** `CONTRIBUTING.md` cross-platform rule 1 — CPython maps `sig=0` to `CTRL_C_EVENT` and broadcasts Ctrl+C to the *entire console process group*. "Any hit in non-test code is presumptively a Windows silent-kill bug." The prescribed answer is `psutil.pid_exists`.
10. **`.gitignore` ignores the live database because `hermes update` stashes untracked files.** The `/*.db*` rules exist so "hermes update's `git stash push --include-untracked` cannot sweep the live `state.db`/-wal into the stash and unlink it under the running gateway (#110648)." A reader would think those lines were hygiene; they are a data-loss fix.
11. **The `node_modules` ignore has no trailing slash, on purpose.** `.gitignore` — "also matches node_modules SYMLINKS (worktrees often symlink node_modules to the main checkout; the dir-only pattern let one slip into a commit and break `npm ci` on CI with ENOTDIR)."
12. **`.dockerignore` excludes `*.md` but the Dockerfile `touch`es a placeholder README.** `Dockerfile` — `pyproject.toml`'s `readme =` field makes uv's build frontend stat the readme path during dependency resolution, and the real README is restored by `COPY . .` later.
13. **`Dockerfile` uses `curl` for every tarball, not `ADD`.** — "`ADD` evaluates its URL at parse time (no ARG / TARGETARCH substitution) and — critically for CI reliability — cannot retry, so a single GitHub-release CDN blip fails the whole 15-45 min build."
14. **`s6-overlay`'s `/init` cannot be the entrypoint directly.** — under a platform that wraps the image in its own PID-1 init it would abort with "can only run as pid 1", so the image uses a dispatcher that falls back.
15. **The `docker-compose.windows.yml` is the one file that enables the documented break-glass path** — `0.0.0.0` + `--insecure` for the dashboard, which `SECURITY.md` §3.2 explicitly classes as "not a vulnerability — that's the flag's job." A reader comparing the two compose files might think the Windows one is a mistake; it is a deliberate, platform-specific trade-off.
16. **The `security` policy says the allowlist must not fail open.** `SECURITY.md` §2.6 rule 2 — "Adapters must refuse to dispatch agent work, resolve approvals, or relay output until an allowlist is set. Code paths that fail open when no allowlist is configured are code bugs in scope under §3.1." Most projects write the opposite (fail open for local dev); Hermes writes the bug into its *security* scope, which is a strong forcing function.
17. **`max_concurrent_sessions` fails OPEN.** `cli-config.yaml.example:1053-1057` — "Hermes fails open if the local runtime lease registry cannot be read or locked." So the *session* cap fails open while the *adapter allowlist* must fail closed. The asymmetry is deliberate (availability vs. authorisation) but easy to misread.
18. **`group_sessions_per_user: true` is the secure default** — "Set false only if you explicitly want one shared 'room brain' per group/channel."
19. **A `key_cmd` is not `secrets.command`.** `cli-config.yaml.example:223-274` — `key_cmd` runs *per request* (cached until shortly before expiry) for one provider; `secrets.command` runs *once at startup* and populates env vars for many. "A startup-time env var cannot be re-minted during a session, because it must be re-minted after it expires."
20. **A model alias's credential is resolved from the alias HOST.** `cli-config.yaml.example:2138-2145` — "never from whatever provider was active before the switch, which would send that provider's secret to an unrelated third party."
21. **The whole telemetry consent model is two separate switches.** `cli-config.yaml.example:2177-2186` — `enabled` and `send`; "Nothing is uploaded unless you also set `send: true`. That is a separate opt-in and requires `enabled`; it never turns collection on by itself." Plus consent *windows*: "only packages whose entire collection period falls within one continuous recorded consent window are ever sent."
22. **Replacing a provider while a turn is in flight needs a generation, not a value.** `registration_lifecycle.py:63-90` — an older generation can share the exact object identity of a newer one, so registry-level CAS cannot tell them apart.
23. **The CLI is a facade of 300 re-exports and 16 mixins.** `cli.py:1-250` — the module-level `from hermes_cli.cli_shutdown import (...)` block alone re-exports ~26 names, and `cli_render` re-exports ~90. It exists so `cli.<name>` stays the patchable seam in tests. A reader looking for logic in `cli.py` will find almost none.
24. **The `_SLASH_DISPATCH` table is a dictionary, not a ladder.** `cli.py:1126-1147` — a canonical-command → (method, pass-the-original-arg?) map, resolved via `getattr` at dispatch time so monkeypatching works. An absent command resolves to `_handle_<name>_command(cmd)` by convention.
25. **Unknown slash commands have a five-level precedence chain.** `cli.py:1211-1240` — quick_commands → plugins → bundles → skills → prefix expansion, with a `GONE` marker for a plugin command that was removed.
26. **Cleanup runs terminal-mode reset FIRST.** `cli.py:471-505` — "Reset terminal input modes FIRST: teardown below can take seconds and a later step raising must not skip the reset." And every cleanup step is individually `suppress`ed by a per-step flag, so one failure cannot abort the rest.
27. **`_run_cleanup` must not finalize a handed-off session.** `cli.py:415-420` — "/handoff sessions belong to the gateway… doing this sets `end_reason` on a row the gateway just reopened and is actively writing to (#88234). The race made the handoff leg vanish from session history and broke session_search recall."
28. **The `hermes` command is a shell function, and it refuses to run outside its worktree.** `activate` — "the installed command is hidden while this checkout is active." A user with a global `hermes` installed will find it *stopped working* inside a checkout; this is the intent.
29. **`setup.py` deliberately fails the build.** — pip and Homebrew are no longer supported distribution methods, and the wheel would ship without bundled assets. The guard fires for `uv build`, `pip wheel`, `python -m build`, and direct `setup.py` alike.
30. **The root `py_modules` list is derived, not declared.** `setup.py:88-107` — "A static list in `pyproject.toml` drifted each time the tree layout changed (missing modules broke installed wheels with `ModuleNotFoundError`), so there is no list to maintain here."
31. **`ruff.toml` and `ruff.pre-commit.toml` are the same file with one line changed.** — `TID251` is commented out in the pre-commit copy. Nothing keeps them in sync, and `pyproject.toml` carries a *third* ruff configuration with a completely different `select` list.
32. **The `TID251` banned-API rule exists because the installer executable is private.** `pyproject.toml` — "Use PM's semantic Python operations, not an installer executable." The same rule appears in `ruff.toml` and `pyproject.toml` with the same six messages, and `pm/**` and the Desktop E2E fixtures are exempt.
33. **The Docker image asserts the SQLite version and the FTS5 trigram tokenizer at build time.** `Dockerfile` — a build that would ship the WAL-reset bug fails instead of shipping.
34. **The `.npmrc` release-age quarantine's exceptions are dated.** — "remove this when 8.3.0 is > 2wks old", "remove when 3.4.17 is > 2wks old (rel 2026-10-12)". Each exception states when it may be withdrawn, so the list cannot become permanent by neglect.
35. **`README.es.md` and `README.ur-pk.md` are behind `README.md`** — six terminal backends instead of seven, no Windows-Defender section, and the Urdu one contains a Windows detail (pywinpty/ConPTY) the English one lacks. Translated docs are not synchronised; the English one is the source of truth.

## 5. Weak spots

1. **The `hermes_constants.py` docstrings are an accreted changelog, not a specification.** The module is 1191 lines and its comments repeatedly narrate past bugs ("the isolation is often the design", "Previously the latch was only set on the warning branch, so… (#90065)", "the exact bug fixed after e66a627aa5"). A reader cannot tell which of several statements is current without reading all of them, and the file mixes six unrelated concerns (path resolution, profile identity, temp policy, permission policy, reasoning-effort parsing, model-name normalisation, OpenRouter variant suffixes, WSL path translation, IPv4 preference). It needs siblings in the same way `cli.py` got them — and it does not have them.
2. **Three ruff configurations, no synchronisation.** `ruff.toml` (≈350 hand-curated selectors), `ruff.pre-commit.toml` (the same file with one line commented out), and `pyproject.toml`'s `[tool.ruff.lint]` (six selectors, a completely different set). The repo-wide `ruff.toml` and the `pyproject.toml` block also *contradict* each other: the repo config selects `E722`, `F401`-family rules and 350 others, while `pyproject.toml` selects six and says "All other lints are intentionally disabled." Which one governs a given `ruff` invocation depends on the working directory and the `--config` flag — and `lefthook.yml` passes `--config ./ruff.pre-commit.toml` explicitly while the `justfile` does not. This is a live footgun.
3. **The `cli-config.yaml.example` comment density has crossed the point of diminishing returns.** 2231 lines to configure roughly 120 live keys, with historical reasoning ("the previous arrangement dated to the package's uv exclude-newer quarantine, which has long expired", "the comment at the top of the file was written for a different thing"). The file is the best documentation in the repo, but it is also a single point of failure for every future reader and for any tooling that wants to diff config versions — and the "this is what we did and why" content has no home other than the config file itself. There is no `docs/configuration-decisions.md`.
4. **The scratch-prune subsystem is four interacting pieces for a housekeeping problem.** `hermes_constants_scratch.py` (424 lines) + `hermes_constants_scratch_stuck.py` (158) + the "stuck" state file + the `.last_prune` stamp + the cross-process `flock` + the spawn ledger + the process registry. The failure mode it solves (218 identical log lines per entry) is real, but the machinery is disproportionate, and the correctness rests on a *fingerprint* heuristic (ino/mtime/ctime) that cannot distinguish "fixed" from "replaced by a different file with the same metadata". A simpler design — record the path and the uid, re-check access, and accept a weekly re-walk — would cover most of it.
5. **`trajectory_compressor.py` and `mini_swe_runner.py` are research scripts living at the repo root, and one of them deliberately duplicates production logic.** `trajectory_compressor.py:45-58` carries a *local copy* of `_response_finish_reason` from `agent/context_compressor.py` — "Local copy… this standalone CLI deliberately avoids importing the heavy context compressor." That is a drift hazard by construction: the production compressor's finish-reason handling can change and the copy will not. `mini_swe_runner.py` also has two different default models in two places (`:136` vs `:322`), which is already a small instance of the same disease.
