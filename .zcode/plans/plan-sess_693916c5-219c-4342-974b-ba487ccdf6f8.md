# Implementation Plan: Accuracy Bug Fixes + ThinkingStore

Based on the deep audit of prompts, debate system, and learning/memory system, I'll fix 5 critical accuracy bugs and build a full reasoning-storage pipeline for model training.

## Part A — Critical Accuracy Bug Fixes

### Fix 1: Wire up dead weighted-voting in 3-way debate
**Bug:** `useAnalysisPipeline.ts:948` passes `undefined` for `enabledProviders`, so `generateWeightedVotingContext` never runs — models on hot/cold streaks get identical treatment.

**Fix:** Pass the actual `enabledProviders` array and `loggedTrades` to `conductThreeWayDebate`. Also wire it into `conductTwoWayDebate` (which currently omits it entirely).
- File: `hooks/useAnalysisPipeline.ts:942-956`
- File: `services/providers/ensembleService.ts` (add `weightedVotingContext` to 2-way path)

### Fix 2: Stop corrupting JSON with `truncateTextToTokens`
**Bug:** `utils/analysisUtils.ts:388-396` does a hard `text.slice(0, maxChars)` on analyst JSON output before the moderator sees it, corrupting the JSON mid-token.

**Fix:** Create a `truncateJsonSafely` function that parses JSON, truncates long string values (e.g., `thoughtProcess`) and drops trailing array elements instead of raw slicing. Replace the call at `ensembleService.ts` truncation sites.
- File: `utils/analysisUtils.ts` (new function)
- File: `services/providers/ensembleService.ts` (replace `truncateTextToTokens` calls on JSON inputs)

### Fix 3: Programmatically enforce the Gate confidence cap
**Bug:** The Gate's `confidenceCap` is only delivered as prompt text. The moderator can emit 85% probability despite a 50% Gate cap, and nothing clamps it.

**Fix:** After `extractLastJson` parses the moderator's verdict, clamp `finalAnalysis.probability` to `Math.min(probability, gateResult.confidenceCap * 100)`. Also clamp by R:R grade thresholds.
- File: `hooks/useAnalysisPipeline.ts` (~line 1040-1059, after JSON extraction)
- File: `utils/analysisUtils.ts` (new `clampProbabilityToGate` function)

### Fix 4: Fix the doubled JSON code fence in SCENARIO_EVALUATION_PROTOCOL
**Bug:** `ensembleService.ts:87-91` emits ` ```json\n```json\n{schema}\n```\n``` ` (doubled fences), corrupting the dualScenarioAnalysis schema example.

**Fix:** Replace the doubled fence with a single ` ```json\n${DUAL_SCENARIO_JSON_SCHEMA}\n``` `.
- File: `services/providers/ensembleService.ts:86-92`

### Fix 5: Remove the "AIM FOR 70%+" pressure that conflicts with the honesty cap
**Bug:** `debatePrompts.ts:169-176` says "WORK HARD to achieve Grade A/B" which directly conflicts with the anti-hallucination cap at line 166 ("cap confidence at 69% if conditions missing"). This pressures the model to rationalize past the gate.

**Fix:** Replace the "AIM FOR 70%+" section with "Assign the grade the evidence supports; do not inflate confidence to reach a target."
- File: `constants/prompts/debatePrompts.ts:169-176`

## Part B — ThinkingStore: Full Reasoning Pipeline

### Goal
Store how each model thinks — per-analyst reasoning, the moderator's synthesis, and every debate turn — per trade, in a dedicated SQLite table. Make it viewable in the Journal UI and exportable for model training.

### 1. New SQLite table: `thinking_records`
**File:** `services/infrastructure/SqliteService.ts`
```sql
CREATE TABLE IF NOT EXISTS thinking_records (
    id TEXT PRIMARY KEY,
    tradeId TEXT NOT NULL,
    username TEXT NOT NULL,
    provider TEXT NOT NULL,        -- 'gemini' | 'deepseek' | 'moderator' | etc.
    role TEXT,                     -- 'analyst' | 'moderator' | 'debate_turn'
    modelName TEXT,
    reasoning TEXT,                -- the thoughtProcess / synthesis text
    analysisJson TEXT,             -- the structured TradeAnalysis JSON (for analysts)
    debateTurnIndex INTEGER,       -- for debate turns, the turn number
    debateTurnSpeaker TEXT,        -- 'Gemini' | 'DeepSeek' | 'Moderator' | etc.
    confidence TEXT,               -- 'High' | 'Medium' | 'Low' | 'Avoid'
    probability REAL,
    outcome TEXT,                  -- filled when trade resolves (WIN/LOSS)
    createdAt TEXT,
    FOREIGN KEY (tradeId) REFERENCES trades(id)
);
CREATE INDEX idx_thinking_trade ON thinking_records(tradeId);
CREATE INDEX idx_thinking_provider ON thinking_records(provider);
CREATE INDEX idx_thinking_outcome ON thinking_records(outcome);
```

### 2. ThinkingStore service
**File:** `services/infrastructure/ThinkingStoreService.ts` (new)
- `saveThinkingRecord(record: ThinkingRecord): Promise<void>`
- `saveThinkingBatch(records: ThinkingRecord[]): Promise<void>` (transaction)
- `getThinkingByTrade(tradeId: string): Promise<ThinkingRecord[]>`
- `getThinkingByProvider(provider: string, options?: { limit, outcome }): Promise<ThinkingRecord[]>`
- `getAllThinkingForExport(username: string): Promise<ThinkingRecord[]>` — returns JSONL for training
- `getProviderReasoningStats(provider: string): Promise<{ total, wins, losses, avgConfidence }>` — aggregates for the UI
- Cross-platform: SQLite on native, IndexedDB on web (same pattern as dbService)

### 3. Wire ThinkingStore into the analysis pipeline
**File:** `hooks/useAnalysisPipeline.ts`
After the debate completes (~line 1040), collect:
- Each analyst's `thoughtProcess` + `analysis` JSON (from the `results` array)
- The moderator's synthesis text (`fullResponseText`)
- The parsed `debateTurns` array (already split by `turnRegex`)
Save them as a batch via `ThinkingStoreService.saveThinkingBatch`, keyed by the new message's analysis `createdAt` (which becomes the `tradeId` when logged).

### 4. Wire ThinkingStore into trade logging
**File:** `hooks/useTradeLogging.ts`
When a trade is logged with an outcome, update the `thinking_records` rows for that trade's `tradeId` with the `outcome` field. This enables outcome-correlated reasoning analysis.

### 5. Stop discarding debate turns
**File:** `hooks/usePostMortem.ts:361`
Currently sets `postMortemDebateTurns: undefined` — instead, persist them to ThinkingStore before clearing from the message.

### 6. Add `debateTurns` to LoggedTrade type
**File:** `types/trade.ts`
Add `debateTurns?: DebateTurn[]` and `moderatorSynthesis?: string` to `LoggedTrade` so the debate transcript travels with the trade record (stored in the `meta` JSON blob).

### 7. ThinkingStore UI in Journal
**File:** `components/journal/TradeLog.tsx`
Add an expandable "Reasoning" section to each trade row that shows:
- Per-analyst reasoning (collapsible cards, one per provider, color-coded)
- Moderator synthesis
- Debate turns (if available)
- Outcome correlation badge

### 8. Export feature for model training
**File:** `components/journal/Journal.tsx` (add export button)
- "Export Reasoning Data" button that calls `ThinkingStoreService.getAllThinkingForExport`
- Downloads as JSONL (one record per line) — the standard format for LLM fine-tuning
- Each record includes: provider, reasoning, analysis JSON, outcome, confidence
- This gives you a training dataset of (reasoning → outcome) pairs per model

### 9. Reasoning analytics dashboard
**File:** `components/dashboards/ReasoningDashboard.tsx` (new)
- Per-provider reasoning stats: total analyses, win rate when reasoning included pattern X
- Confidence calibration per provider (predicted vs actual)
- Reasoning quality scores (if outcome is known)
- Accessible from the Journal tabs
