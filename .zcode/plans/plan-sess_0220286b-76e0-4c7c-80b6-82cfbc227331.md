# Plan: User-Configured Providers (remove hardcoded providers, fix ensemble, settings list)

## Goal
Make `ProviderConfig` the **single source of truth** for all providers. No hardcoded/default providers — the app starts empty and the user adds every provider. No "custom" label anywhere. Enabled providers appear in the ensemble selection and actually execute. Settings shows a list of providers with enable/disable/delete.

## Target architecture
- **Identity** = `ProviderConfig.id` (string). Remove the `AIProvider` enum entirely; replace all usages with string ids.
- **Enabled** = `ProviderConfig.isEnabled` (global, not per-conversation). `readyProviders` (enabled + has apiKey) drives the ensemble.
- **Runtime** = one extended `GenericProviderService` + one consolidated analysis service, both keyed by `ProviderConfig`. Delete the 9 per-provider services + 9 accuracy services + their env-var key reads.
- **Empty start** = `getDefaultConfigs()` returns `[]`.

---

## Phase 1 — Extend the generic runtime client (`GenericProviderService.ts`)
Add capabilities the ensemble needs (currently missing):
- `streamChatRequest(config, messages, opts) → AsyncGenerator<string>` — streaming for the moderator (OpenAI-compat `stream: true`; Gemini via its OpenAI-compat endpoint so we can drop the `GoogleGenAI` branch).
- Multimodal message content (array of `{type:'text'|'image_url', ...}` parts) for vision/OCR.
- JSON mode option (`response_format: {type:'json_object'}` for `chat_completions`; prompt-only enforcement for `messages`/`responses`).
- `AbortSignal`, `temperature`, `maxTokens` options.
- Keep `testConnection` / `getQuickResponse`.

## Phase 2 — Consolidated analysis service (replaces 9 accuracy + 9 main services)
Create `services/providers/GenericAnalysisService.ts` implementing the existing `AIProviderService` interface, parameterized by `ProviderConfig`:
- `analyzeTradingView(config, params)` — reuse the shared prompt-building logic currently duplicated across the accuracy services (they are near-identical). Returns `{ analysis, thoughtProcess, sources }` with `response_format` JSON.
- `conductPostMortem(config, params)`, `getQuickResponse(config, params)`, `summarizeChartImage(config, image, model, signal)`.
- Vision: `summarizeChartImage` sends `image_url` parts via the generic client.
- Register instances in the existing (currently-dead) `providerRegistry` keyed by config id, OR pass config directly from the pipeline (preferred — no global registry state).

Then **delete**: `geminiService`, `deepseekService`, `zhipuService`, `groqService`, `groqNewService`, `groqAlt2Service`, `openrouterService`, `openaiService`, `grokService`, and all 9 `accuracy/*AccuracyService.ts`, plus `ensembleAccuracyService.ts` shim.

## Phase 3 — Migrate the ensemble runtime (`ensembleService.ts`)
- Remove `getGeminiClient`…`getGrokClient`, `getModeratorClient` switch, and all `process.env.*_API_KEY` reads.
- `getModeratorAnalysisStream(provider, model, prompt)` → `streamChatRequest(config, messages, {temperature:0.1})`. Change `provider: AIProvider` params to `config: ProviderConfig` (or `providerId: string` + lookup) on `conductDebate`, `conductTwoWayDebate`, `conductThreeWayDebate`, `recalculateProbabilities`, and the post-mortem debate generators.
- `analystProviders` / `enabledProviders` args become `string[]` (config ids).

## Phase 4 — Types: remove `AIProvider` enum, rekey coupled types
- `types/enums.ts`: delete `AIProvider`.
- `types/provider.ts`: drop `isBuiltIn` (or keep always `false`); remove "custom"/"built-in" language from comments.
- `types/trade.ts` (`Conversation`): remove `isGeminiEnabled`…`isGrokNativeEnabled`, `geminiModel`/`deepseekModel`/… per-provider model fields. Change `moderatorProvider: AIProvider` → `moderatorProviderId: string`. Keep `ocrModel`/`moderatorModel` as strings. `LoggedTrade.provider`/`moderatorProvider` → `string` (existing serialized enum values like `'gemini'` remain valid strings; historical perf entries map by name).
- `types/lens.ts`: `assignedProvider: AIProvider | null` → `string | null` (config id).
- `types/message.ts`: `geminiModelUsed` etc. → generic `modelUsed?: string` (or leave optional strings).

## Phase 5 — `ModelPerformanceService` dynamic keying
- Replace the fixed `Record<AIProvider, ModelPerformance>` with `Record<string, ModelPerformance>` (keyed by config id), lazy-initialized per provider. `generateWeightedVotingContext(enabledProviders: string[], …)`. `dominantModel`/`providerA/B`/`tieBreaker` → `string | null`. Historical trades with unknown ids degrade gracefully (no entry → neutral weight).

## Phase 6 — Hooks: single source of truth
- `useProviderConfigs.ts`: `addCustomProvider` → rename concept to `addProvider` (no "custom"); id scheme stays `custom-<ts>` or `prov-<ts>`. `removeCustomProvider` allows removing any provider (no `isBuiltIn` guard). `getDefaultConfigs()` → `[]`; `loadProviderConfigs` no longer merges built-ins.
- `useConversations.ts`: remove all `isXxxEnabled`/`selectedXxxModel` derivations + setters + `handleToggleProvider`. Replace `moderatorProvider` with `moderatorProviderId` (default = first ready provider). Add `selectedModels: Record<string,string>` (per-provider selected model) stored on conversation, OR rely on `ProviderConfig.selectedModel` directly (preferred — model selection lives in settings).
- `useAnalysisPipeline.ts`: build `enabledProviders` from `readyProviders` (each entry = `{ config, name: config.name, model: config.selectedModel }`). Call `GenericAnalysisService.analyzeTradingView(config, …)`. Moderator from `moderatorProviderId` config. Remove the 9 accuracy-service imports. Remove hardcoded 3-provider cap? (Keep cap but base on readyProviders count.)
- `usePostMortem.ts`: same migration.

## Phase 7 — UI: ensemble selection + settings list
- `ChatInput.tsx`: delete hardcoded `AI_PROVIDERS` + `providerStates`. Render ensemble list from a new `providers: ProviderConfig[]` prop (readyProviders). Toggle calls `onToggleProvider(id)`. Lens role-assignment dropdowns list enabled providers by config id/name. Vision-model selector lists models from enabled providers. `enabledCount`/`globalLimitReached` computed from the list.
- `ChatArea.tsx`: replace the 9 `isXxxEnabled`/`setIsXxxEnabled` props with `providers` + `onToggleProvider`. Forward `isAnyProviderEnabled`.
- `App.tsx`: pass `readyProviders` + `handleToggleProviderConfig` to `ChatArea`. Recompute `isAnyProviderEnabled = readyProviders.length > 0`. Build `enabledProviders` (string ids) for Journal/Analytics from `readyProviders`. Remove legacy per-provider props to SettingsMenu. Pass `providerConfigs`/CRUD to `useAnalysisPipeline` + `usePostMortem`.
- `SettingsMenu.tsx` (`renderModelsView`): **delete the legacy 9-card toggle UI** (lines ~513-760). `ProviderManager` becomes the only provider UI. Moderator selector lists enabled providers + their models. Vision provider/model selector.
- `ProviderManager.tsx`: remove "Built-in"/"Custom" optgroup split — show **all providers in a flat list** with enable/disable toggle + delete (delete allowed for all). Keep the add-provider form (rename "Add Custom Provider" → "Add Provider"). Keep edit fields (key, baseUrl, format, model) + Test.
- `utils/imageProcessor.ts`: OCR dispatch by config id (resolve the vision provider's config) instead of model-name prefix.

## Phase 8 — Cleanup
- `constants/models.ts`: remove `ALL_SUPPORTED_MODELS`, per-provider arrays, `modelIdToName`, `ACCURACY_MODE_DEFAULTS`. Keep/replace `OCR_MODELS` with a dynamic model list sourced from enabled providers.
- `services/learning/LLMRuleExtractionService.ts`: replace its per-provider `getQuickResponse` switch (lines 83-108) with the generic client.
- `.env.example` / `AGENTS.md`: remove the provider env-var docs.
- `PreferencesService.ts`: remove the legacy per-provider `PREF_KEYS`/`getApiKey`/`setApiKey` for providers (keep non-provider prefs).
- Run `npm run build` (type-check gated) and fix all resulting errors.

## Risk / notes
- **Largest, riskiest pieces:** Phase 2 (consolidating prompt logic from 9 near-duplicate accuracy services) and Phase 3 (ensembleService is 2,580 lines). I'll preserve prompt text verbatim where possible.
- **Persisted data:** `LoggedTrade.provider`/`moderatorProvider` already serialize as strings (`'gemini'`, etc.); changing the type to `string` is backward-compatible. `ModelPerformanceService` historical entries for ids the user hasn't re-added simply carry neutral weight — no data loss.
- **Gemini vision:** the analyst path currently sends raw image bytes only via `GoogleGenAI`. Routing through the OpenAI-compat endpoint with `image_url` works for Gemini's OpenAI-compat API; I'll verify and keep a native fallback if needed.
- **3-provider ensemble cap** in Standard mode is preserved (now based on `readyProviders`).

## Out of scope (unless you say otherwise)
- Accuracy-mode-specific debate service differences beyond routing them through the generic client.
- Migrating `LiveStreamView`'s per-provider model-name display beyond adapting it to read from configs.
